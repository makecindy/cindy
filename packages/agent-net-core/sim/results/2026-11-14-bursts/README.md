# 一阵一阵的大数据跑不满线路（2026-11-14）

核心指纹 `d0394c1b62ac`（`src/*.rs` 按 LF 逐个 SHA-256 后再取 SHA-1），逐文件见 `source-sha256.json`。
环境：Windows x64，rustc 1.98.1，Node v24.22.1。核心 `[dependencies]` 仍为空，线格式不变。

用户 2026-11-14 的要求：Agent-Net 要在速度和稳定性上超过原来的 Device Link，「速度能跑起来，不该被限速」。
端到端压测（[`benchmarks/agent-net-session-2026-11-13`](../../../../../docs/benchmarks/agent-net-session-2026-11-13/README.md)）里，
每秒 1 MB 加 0–30 毫秒抖动的线路上，V1 传 1 MiB 要 1.4 秒，Agent-Net 要 10–15 秒。

## 原来的问题

Cindy 的大数据（任务列表、历史、附件）是一阵一阵来的，两端平时只有零星小消息。模拟器里照这个用法复现
（`exp/exp_burst.rs`：每 500 毫秒各发 200 字节；B 先传 1 MiB，停 2 秒，A 再传三次 1 MiB，中间停 2 秒、5 秒），
逐毫秒看 A 的带宽估计、节奏、在途量，查出四个原因：

1. **空闲后被当成撞上了限速。** 限速判断看最近 4 轮的平均送达速率（`pacing_rate` 的 `limited_elsewhere`），空闲时零星小消息那几轮
   （每秒几百字节、一阵数据的尾巴）也算在里面。新一阵一开始平均只有 13 KB/s，节奏被压到 10 KB/s，头 4 个不等节奏的包把下一次发送
   排到 0.57 秒以后；这期间每个往返只能发 4 个包，又不算「应用没数据」，十轮后带宽估计从 1000 KB/s 被挤成 131 KB/s，之后每 8 轮涨
   四分之一。干净的每秒 1 MB 线路上停 2 秒后的一阵要 4.04 秒（线路上 1.05 秒）。
2. **只发过小消息的一端提前结束了启动。** 抖动让某个小消息的往返偏高，就被当成排队，启动阶段带着每秒 3 KB 的估计结束；
   下一阵按 2 KB/s 排节奏，头几个包的等待排到 2.4 秒以后，同样卡在每个往返 4 个包。
3. **不打乱先后的抖动被当成排队。** Wi-Fi 聚合、经 TCP 中转时，一个包被耽搁，后面的都要等它；连续发包时几乎每个包都碰上
   最近最大的那次耽搁，往返整体抬高约 30 毫秒（模拟器新增 `LinkProfile::jitter_fifo`）。排队判断的余量最多 16 毫秒，
   启动一两轮就结束，带宽估计停在线路的三成以下。
4. **产品用的窗口是 128 个分片（约 179 KB）。** 在途量不能超过它，100 Mbit/s、30 毫秒只能跑到约 6 MB/s，往返 200 毫秒只有约 0.9 MB/s。

## 做法

1. 限速判断只看发送方一直有数据可发的轮次（`busy_round_rates`）。其它用到最近几轮速率的地方不变。
2. 应用没数据可发时发的包不结束启动（`!sample.app_idle`）：这些包排不出队。
3. 抖动大到排队余量盖不住时（三倍抖动超过余量上限 16 毫秒），满负荷发送的还要带宽有一轮没涨够四分之一才算排队。
   抖动小的线路照旧，浅队列上不多冲一轮；零星消息照旧。
4. Desktop/Host 的 wasm 初始化把收发窗口改成 1024、每条流发送缓冲 4 MiB（`wasm/src/lib.rs`）。核心的 `Config::default()` 不变。
   对端的接收窗口照样限着这一端，旧版对端仍按 128 收，互通不受影响。手机的原生库（`agent-net-native`）还是 128，等原生库重编时一起改。
   （同日下一轮 [`2026-11-14-auto-window`](../2026-11-14-auto-window/README.md) 把产品窗口改成 8192、发送缓冲跟着拥塞窗口走，取代这里的 1024 和 4 MiB。）

## 结果

一阵一阵的传输（`exp/exp_burst.rs`，4 个种子平均的线路利用率；反向 / 第一阵 / 停 2 秒后 / 停 5 秒后）：

| 线路 | 改动前，窗口 128（产品现状） | 改动后，窗口 128 | 改动后，窗口 1024（产品） |
| --- | --- | --- | --- |
| 每秒 1 MB，往返 40 毫秒 | 95 / 95 / 26 / 85 | 95 / 95 / 96 / 97 | 95 / 95 / 96 / 97 |
| 同上，抖动 30 毫秒不乱序 | 34 / 14 / 27 / 38 | 69 / 75 / 89 / 91 | 69 / 74 / 89 / 91 |
| 同上，抖动 30 毫秒乱序 | 27 / 37 / 58 / 52 | 53 / 85 / 89 / 85 | 53 / 85 / 89 / 85 |
| 2 Mbit/s，往返 100 毫秒 | 93 / 89 / 52 / 92 | 93 / 93 / 88 / 90 | 93 / 93 / 88 / 90 |
| 512 kbit/s，往返 200 毫秒 | 92 / 93 / 87 / 39 | 93 / 94 / 91 / 92 | 93 / 94 / 91 / 92 |
| 4G 20 Mbit/s 70 毫秒 抖动 20 丢 1.5% | 13 / 9 / 10 / 17 | 29 / 28 / 38 / 38 | 31 / 41 / 61 / 63 |
| Wi-Fi 50 Mbit/s 20 毫秒 抖动 4 丢 0.5% | 53 / 40 / 21 / 26 | 53 / 63 / 79 / 77 | 56 / 50 / 66 / 67 |
| 家宽 100 Mbit/s 30 毫秒 | 33 / 33 / 32 / 30 | 33 / 33 / 41 / 40 | 45 / 45 / 83 / 82 |

基线核心在窗口 1024 下是 57 / 54 / 45 / 50：只开大窗口救不了一阵一阵的传输，四条要一起做。
1 MiB 在高带宽线路上只有几个往返，起步那几轮占了大头，所以家宽、Wi-Fi 的数字偏低。

**原有矩阵**（`matrix/`，`before-*` 是改动前的核心，`after-*` 是最终代码；`compare.cjs`、`share.cjs` 是比较脚本）：

## 试过没留的

- **不等节奏放行的包最多把下一次推后一个间隔。** 两条连接挤同一个 5.6 Mbit/s 限速器时丢包 21.9% → 29.5%（12 个种子）：
  短往返的限速器上，正是这笔账让它不超速。
- **收到确认时作废按过时低速排下的等待**（节奏涨 2 倍或 4 倍以上时）。2 倍：地铁场景慢 8%、换网断 6.5 秒后恢复超过 0.4 秒；
  4 倍：四条连接挤 20M、随机丢 10% 时公平指数掉到 0.7 以下。第 2、3 条修好以后，这笔账只在极端情况下出现，就不要了。
- **抖动时不看抖动大小、一律等带宽停涨。** 平均利用率还能高几个点，但浅队列、低抖动的换网场景多冲一轮：
  断网 3 秒后恢复 408 毫秒（门槛 400），被抢先复制时下载慢 1.06 倍（门槛 1.05）。

## 没做的

- 巡航阶段仍按往返判断排队：不乱序的抖动线路上巡航按带宽估计的 90% 发（`QUEUE_DRAIN_GAIN`），少跑一成。
- 手机原生库的窗口，见上。
- 1 MiB 在高带宽、长往返线路上主要花在起步：家宽第一阵 45%。

## 复现

```sh
cd packages/agent-net-core
cargo test --profile sim --workspace
PYTHONIOENCODING=utf-8 python sim/mutants.py 一阵一阵
cp sim/results/2026-11-14-bursts/exp/exp_*.rs sim/tests/          # 实验，跑完删掉
AGENT_NET_WINDOW=1024 cargo test --profile sim -p agent-net-sim --test exp_burst -- --nocapture
AGENT_NET_POLICY=auto cargo test --profile sim -p agent-net-sim --test exp_compare -- --nocapture
cargo test --profile sim -p agent-net-sim --test exp_interactive -- --nocapture
cargo build --release -p agent-net-sim --bin share
SHARE_MODE=full SHARE_TIMER_US=1 ./target/release/share           # 默认 3 个种子；SHARE_SEEDS=12 加种子
node sim/results/2026-11-14-bursts/matrix/compare.cjs <改动前.txt> <改动后.txt>
```

`AGENT_NET_TRACE=线路名 AGENT_NET_SEED=n` 打印 A 每 50 毫秒的带宽估计、节奏和往返，`AGENT_NET_FINE=开始-结束`（毫秒）在这段里逐事件打印。
