# 手机真机换网：Wi-Fi 和蜂窝来回切（2026-11-05）

上一次真机换网（`../../2026-11-05-migration/real-switch/`）换网的是电脑：电脑在有线网和手机热点之间切。这一次换网的是手机自己。

## 怎么测的

- **手机**：一台小米手机，Android 17，插中国移动的卡（5G），同时连着公司 Wi-Fi。用数据线接到 Windows 电脑，打开 USB 调试。
  没有装 App：把测试程序放进手机的 `/data/local/tmp`，用 adb 的 shell 身份运行，跑完删掉。
- **测试程序**：`sim/src/bin/migrate.rs`，核心指纹 `8e8947f3a654`（这一轮的最终代码）。手机上的是 aarch64 Linux 静态程序，
  在官方 `rust:1.97-slim-bookworm` 容器里用 Debian 的 aarch64 交叉编译器编出来（`build-android.sh`），SHA-256 `b1d48573bd6133009d457082a5018fdfa5e4b8327db1275366ebd35be95a5e9d`。
  服务端在上海云主机上，同一份源码编的 x86_64 Linux 程序，SHA-256 前 16 位 `f06b1ccace80a068`。跑完已删掉服务端程序和日志目录。
- **切换**：电脑通过 adb 执行 `cmd wifi set-wifi-enabled disabled / enabled`。关 Wi-Fi 时手机切到蜂窝，开 Wi-Fi 时连上后切回 Wi-Fi。
  数据线不走网络，切换时 adb 不断。客户端不知道自己换了网络（`--notice no`）：驱动还没接系统的换网通知。
- **记录**：手机上每 0.25 秒用 `ip -4 route get` 记一次去服务器走哪块网卡（`wlan0` 是 Wi-Fi，`wwan*` 是蜂窝），
  客户端和服务端各自打印每秒送达速度、最长的送达中断、服务端跟到新地址的时刻。时间都从客户端启动算起，手机和电脑的时钟差零点几秒，
  所以“出口切换”偶尔比“关 Wi-Fi”的时刻还早一点。驱动脚本是 `case.sh`，原始输出在 `logs/`。地址都已替换。
- 第一台手机没有 SIM 卡，换了这一台。

## 结果

6 次带换网的传输、共 10 次换网，加 2 次对照和 1 次连通检查，**全部传完、数据完整（`error=None`），每次换网服务端都跟到了新地址，没有一次验证失败**。

| 传输 | 手机出口（秒） | 服务端跟到新地址（秒） | 接收方最长中断 | 用时 |
| --- | --- | --- | --- | --- |
| 下载 15 MB，Wi-Fi → 蜂窝 | 3.08 关 Wi-Fi，3.47 换到蜂窝 | 4.27 | 1.0 秒 | 35.00 秒 |
| 下载 15 MB，蜂窝 → Wi-Fi | 3.11 开 Wi-Fi，4.80 换到 Wi-Fi | 4.83 | 0.1 秒 | 20.98 秒 |
| 下载 15 MB，Wi-Fi → 蜂窝 → Wi-Fi，第 1 轮 | 3.37 蜂窝，16.34 Wi-Fi | 4.25，16.59 | 1.0 秒；切回时没有超过 0.1 秒的中断 | 25.08 秒 |
| 同上，第 2 轮 | 3.04 蜂窝，16.59 Wi-Fi | 4.02，16.53 | 1.0 秒；切回时 0.2 秒 | 21.97 秒 |
| 上传 24 MB（按 8 Mbit/s 写），Wi-Fi → 蜂窝 → Wi-Fi，第 1 轮 | 3.97 蜂窝，15.51 Wi-Fi | 4.32，15.58 | 0.1 秒 | 24.03 秒 |
| 同上，第 2 轮 | 4.26 蜂窝，16.07 Wi-Fi | 4.50，16.04 | 0.2 秒 | 24.01 秒 |
| 对照：一直在蜂窝上下载 15 MB | 一直蜂窝 | — | 无 | 35.61 秒 |
| 对照：一直在蜂窝上上传 16 MB（按 8 Mbit/s 写） | 一直蜂窝 | — | 无 | 25.81 秒 |

- **Wi-Fi → 蜂窝、在下载时，中断约 1 秒**（三次都是 1.0 秒）。手机在 Wi-Fi 断开后 0.5 秒以内就有了蜂窝出口，
  但它只在收数据、没有包要发，服务端的数据还发往 Wi-Fi 那边的旧地址；手机安静 1 秒后发出探测，服务端从新地址收到、验证、跟过来。
  这正是这一轮改过的地方：以前没有回音时探测间隔会翻倍，丢包重的网络上要等更久。驱动接上系统的换网通知以后，
  知道换了网络就马上发包，模拟里 0.4 秒以内恢复。
- **在上传时、或者切回 Wi-Fi 时，几乎没有中断**（0.2 秒以内）：手机一直在发包，服务端马上看到新地址。
  切回 Wi-Fi 时服务端看到的又是原来那个地址和端口（公司出口的映射还在），直接换回原来那条路径。
- **切到蜂窝以后的速度和一直在蜂窝上差不多。** 下载切换后每秒 1.8–8.8 Mbit/s，一直在蜂窝上稳定后 2.4–3.5（Wi-Fi 上也只有约 5.5，
  和第 5 步公网记录里云主机往外发得慢一致，原因没查）。上传切换后每秒 3.0–4.2 Mbit/s，一直在蜂窝上 3.6–6.7、平均约 4.6，略低一些，样本少，没细查。
  切回 Wi-Fi 后上传会在一两秒里补上在蜂窝时落下的部分（每秒 16.7、37.1、57.2 Mbit/s），然后回到 8 Mbit/s。
- 这几次一共用了约 70 MB 手机流量（按传输量估算）。

## 没测的

- 手机 App 里的情况：Cindy App 还没接入这套网络。App 进后台、被系统冻结、锁屏，这里都没有。
- 系统的换网通知：驱动还没接，所以“知道换了网络”的情况只在模拟里测过。
- 别的品牌和 iOS；IPv6 出口（中国移动的蜂窝这次给的是 IPv4 地址）；信号弱、在移动中的蜂窝。
