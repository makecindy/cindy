# BlueBubbles 本地接入

此适配器连接现有 BlueBubbles Server，供伙伴消息平台使用。Cindy 在本机运行统一
`LocalWebhookReceiver`，不依赖 Cindy 云端 Webhook，也不使用自动化触发服务。

## 连接与边界

- BlueBubbles 必须能直接访问用户填写的本机私网地址与端口；回环地址仅适合同机部署。
- 密码、配置和随机回调令牌进入宿主账号隔离的安全存储。模型工具不提供凭证或回调管理。
- 每个回调使用独立随机路径，并核对 BlueBubbles 主机解析出的源 IP。收到事件后从 API
  回查消息；不信任回调提供的作者和正文。兼容 `iMessage;…` 与现用 `any;…` 对话标识，
  入站仍要求回查消息的 `handle.service = iMessage`，不接收 SMS，过滤自身回声与反应事件。
- 以 API 回查的地址与配置的主人地址匹配身份，主人单人私聊进入伙伴主任务，其余聊天进入专线。
- 群默认响应 `@伙伴名称`（连接时保存），引文中的提及不触发；全响应沿用伙伴群参与设置。
- 同一 BlueBubbles origin 在当前账号内只归属一位伙伴，可绑定多个聊天；不会接管独立桥接。

## 恢复与结果确认

入站 GUID 在返回 HTTP 202 前持久化。回调触发后下载原消息与附件；每五分钟分页补漏，
每页 100 条，固定上界时间，游标回叠五分钟，GUID 去重。首次启用以后的消息才会触发任务，
更早历史仍可由原生工具显式查询。失败的页不推进该聊天游标；单条消息或附件失败不会挡住
其它消息，失败项继续留在待处理账本。历史异常重复页或超出单轮 100,000 条时明确失败，不跳过。

启动、周期补漏与手动核对共用恢复边界：先完成历史枚举和待处理消息回查，期间实时回调
只持久登记，不抢先派发；并发恢复合并为同一次操作。
可回查的待处理输入按 API 发送时间排序，包含游标窗口之外的旧收据；回查结果在本轮派发复用，
不再重复请求。回查等待期间新增的 GUID 也先回查并纳入排序，未知发送时间不抢先派发。
这样实时停止命令会排在停机期间的旧输入之后，纳入同一聊天的撤队边界。
未能回查的输入仍保留待处理，不盲目执行。
运行中的历史查询失败会保留错误状态和未完成游标，同时释放已经持久接收的实时消息，
停止或确认不必等新回调来唤醒；停止边界也覆盖以后才补漏出的旧输入。忙碌队列中已准备
好的输入同样按核实发送时间判断先后，不能因较晚消息先准备好而挡住补漏的旧消息。

单条回查、下载或暂存失败不会关闭已注册的监听器，其他聊天、确认回复及停止命令仍可进入。
失败输入各自记录 30 秒后的重试期限，其它回调和忙碌队列的每秒重试不会提前触发它。
重试共用计时器，不重建监听或重新注册回调。配置、历史枚举或收据持久化失败继续走连接恢复，
不能冒充单条准备失败。附件准备中途失败时先丢弃本次已暂存的成功前缀；清理失败则保留
清理进度，完成清理前不重新暂存，避免每次重试增加一份副本。
局部输入故障全部消退后恢复连接状态，不必等下一轮五分钟补漏；其它派发或持久化错误
不由局部重试成功清除。
首次添加时，已成功注册监听和回调后的单条准备失败保留连接、凭据和待处理账本，继续局部
重试；真正的配置或建连失败仍由宿主回滚。已持久撤销或受理的输入不会因迟到的准备异常
重新登记重试，重试索引也会清除不再待处理的 GUID。

主人停止命令先在原收据中持久记录聊天、发送时间及此前尚未确认的 GUID 边界。暂时无法
查明身份的收据恢复后，先按 API 核实聊天，再应用该边界撤销旧输入；其它聊天与停止之后
的新输入保留。元数据为现有收据格式的可选字段，旧读取器仍可读取，不记录消息正文。
以 API 核实的发送时间为准，GUID 到达顺序只用于同一发送时间的边界；迟到的停止回调
不会撤掉发送在它之后的新工作。

派发前写 `dispatching`，宿主用户消息持久落库后才写 `accepted`，不把 handler 返回或内存
排队视为受理。忙碌任务通过共享外部派发接口退回持久 `pending`，每秒尝试继续；等待时
复用已下载附件，重启后重新回查并补收。进程中断留下的实际派发不自动重放；状态页展示
结果未确认数量，用户核查原任务后再决定是否重试。发送前写随机标识及 `sending`，已确认写
`sent`；请求失败写 `unknown`，不假定未发送或自动重发。原生工具可查聊天历史帮助核对。

账本只含 GUID、聊天标识、时间、游标、停止边界及投递状态，正文与附件沿用宿主既有存储。宿主使用增量 fsync
日志与原子检查点，保留完整去重标识，不以条数滚动清除。账号路径在实例创建时固定，迟到
完成不能写入切换后的账号。附件单个最多 64 MiB，超限明确标为不支持。
总仓的永久格式拒收（例如不支持的 HEIC）标为不支持并继续派发随附文字；下载或磁盘
故障仍留待重试。不支持的格式不回落普通文件暂存。

## 生命周期

同地址端口的连接共享监听器，移除一条路由不会关闭其它连接。普通退出停止监听但保留
BlueBubbles 注册；重新启动复用精确 URL 并补漏。删除连接时先停本地收信，再尝试删除
BlueBubbles 上精确匹配的回调，保留其它 URL；远端不可达时记录清理失败，本地仍保持停止。

REST 参考：[官方文档](https://docs.bluebubbles.app/server/developer-guides/rest-api-and-webhooks)、
[v1.9.9 路由](https://github.com/BlueBubblesApp/bluebubbles-server/blob/v1.9.9/packages/server/src/server/api/http/api/v1/httpRoutes.ts)。
该版本回调查询按全量列表在本地匹配 URL，删除为 `DELETE /api/v1/webhook/:id`，成功响应可没有 `data`。

## 验证范围

传输测试通过真实本地 HTTP 接收器覆盖重复回调、重启补漏、读取失败恢复、身份回查、确认
期间继续收信、发送未知状态，以及回调注册和精确删除。宿主测试覆盖非空账本恢复、工具
作用域和新旧远程设置投影。实际 Cindy 构建验收与真实 Apple iMessage 收发应分别记录；
模拟 BlueBubbles API 与真实模型联调不等于真实 iMessage 端到端验收。
