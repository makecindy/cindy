# Expo SDK 58 本地资源对比

2026-11-07，在同一台 iOS 27.2 iPhone 真机比较 SDK 57.0.23 / RN 0.86.3 与
SDK 58.0.23 / RN 0.88.1。SDK 57 从升级分支的基线 `efbacf0e17` 导出并编译，
SDK 58 使用本次升级后的工作区。没有拿手机上较早的正式版作为 SDK 57 基准。

## 结果

| 指标 | SDK 57 | SDK 58 | 变化 |
| --- | ---: | ---: | ---: |
| App 文件逻辑大小 | 154.20 MiB | 159.94 MiB | +3.72% |
| 同参数 ZIP 压缩大小 | 51.39 MiB | 53.08 MiB | +3.28% |
| 启动后 20–30 秒物理内存中位数 | 292.81 MiB | 274.05 MiB | −6.41% |
| 同窗口 CPU 中位数（单核 100%） | 12.50% | 12.73% | +0.22 个百分点 |
| 每轮采样内存最大值的中位数 | 303.91 MiB | 275.14 MiB | −9.47% |

本次样本中，新版进程内存较低，CPU 中位数接近，包体略增。不能据此推断完整启动速度、
滚动流畅度或续航改善。内存是 `physFootprint`，不是虚拟地址空间；最大值只覆盖一秒级
采样，可能遗漏瞬时峰值。ZIP 是本地统一压缩口径，不是 App Store 下载大小。

轮次间存在波动，范围重叠：

| 指标的每轮结果范围 | SDK 57，3 轮 | SDK 58，6 轮 |
| --- | ---: | ---: |
| 窗口内存中位数 | 288.36–303.69 MiB | 269.42–295.52 MiB |
| 窗口 CPU 平均值 | 11.66–17.71% | 8.70–20.40% |

包体增长主要来自主程序（84.14 → 87.60 MiB）和动态库（17.28 → 19.19 MiB）；
Hermes 动态库增大，SDK 58 包中另有 ExpoModulesJSI 动态库。JS bundle 仅从
41.67 → 41.95 MiB，增加 0.67%。

## 方法与边界

- 两份都是相同 Xcode、Release、arm64、Global 的开发签名包，内置 JS；使用同一个
  测试 bundle ID，依次覆盖安装，保留应用数据，正式 App 不受影响。
- 测量顺序为 SDK 58 三轮 → SDK 57 三轮 → SDK 58 三轮。新覆盖安装后先运行
  20 秒预热。每轮重新启动进程，不重启手机、不清空应用或系统缓存，因此不是严格冷启动。
- 使用设备的 Apple Instruments DVT `sysmontap` 服务，请求间隔 1000 ms，每轮收集
  30 条目标进程样本，共 270 条。通过精确 PID 和可执行文件名核对版本。
- 每轮只取 `procAge` 在 20–30 秒内的样本，先计算 `physFootprint` 中位数；CPU 使用
  `Δ(cpuTotalUser + cpuTotalSystem) / ΔprocAge × 100`，按单核 100% 计。表中再取轮次中位数，
  没有把同一轮的每秒读数当作独立重复实验，也没有删除偏高轮次。
- 原始进程状态通知确认进程运行。但截图接口返回黑图，未确认两版处于完全相同的可见页面；
  后台网络、温度、系统缓存与用户数据负载也没有完全控制。因此这是进程资源的探索性对比，
  不是固定页面或手势脚本的严格交互性能基准。
- `xctrace` 的 App Launch / Activity Monitor 采集连接超时，改用 DVT 获得 CPU / 内存。
  dyld 数据只覆盖动态加载阶段，不能代表 React 首屏挂载或页面可操作时间，未纳入启动结论。
  没有有效的滚动帧时间、掉帧率、耗电数据；不以空闲显示帧率替代这些指标。
- 对比完成后恢复原来的 SDK 58 Beta 安装包，没有往正式渠道发布版本或 OTA。

原始逐轮 JSON、汇总 `comparison.json`、`runs.csv` 及采样/统计脚本保存在本任务的本地产物中。
其中设备标识和私有路径不进入仓库；本页保留方法、聚合结果和验证边界。
