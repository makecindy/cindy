## 4.6.3 给模型选择器提供模型(models)

插件可以把自己的模型放进新任务的模型选择器。对用户来说它就是一个模型:名字、说明都由你决定,Cindy 不会写「让插件选」之类的文案。怎么配置、要不要 API Key、有哪些选项,都放在你自己的设置页里。

### 声明能力

清单只声明「我提供什么类型的模型」,具体列表运行时再发布:

```json
{
  "models": { "types": ["route"] },
  "subscribe": { "hooks": ["will-start-task"] }
}
```

`route` 模型必须同时声明 `will-start-task` 钩子。用户在安装或更新确认里批准这个节点后,你发布的模型才会显示。

### 发布列表

用户配好之后再发布,**没配好就发布空列表**,选择器里就不会出现你的模型。每次发布都整体覆盖上一次;内容没变时不会有任何副作用,可以放心在每次启动时发布。

```js
await fetch('/models', {
  method: 'PUT',
  body: JSON.stringify({
    models: [{
      id: 'auto',
      name: 'Auto',
      description: 'Picks a model from your rules',
      locales: { 'zh-CN': { name: '自动', description: '按你的规则选模型' } },
      target: { type: 'route' },
    }],
  }),
});
```

| 字段 | 说明 |
| --- | --- |
| `id` | 字母、数字、`.`、`_`、`-`,最长 64,同一插件内唯一 |
| `name` | 必填,最长 64 |
| `description` | 可选,最长 200 |
| `locales` | 可选,按语言给 `name` / `description`,找不到时用同语言的其它地区,再回到默认文案 |
| `target.type` | `route`:开新任务时问你,由你返回真实模型 |

最多 16 个模型。`GET /models` 读回当前列表。格式错误返回 400,`error` 说明原因,原列表不变。清单没声明 `models` 时返回 403。这个 Cindy 不支持的 `target.type` 不算错误:那一项进 `skipped`,其余照常显示,所以旧版 Cindy 也能用你的其它模型。

Cindy 存下最新列表,打开选择器时只读这份记录,**不会调用插件**,插件没启动或卡住都不影响选择器。卸载时列表一起删除;停用时不显示但保留。

### 回答 route 模型

用户选了你的模型后,新任务第一条消息发出前 Cindy 问你一次(`will-start-task`,见 §4.6.2)。`msg.data.modelId` 是用户选的模型 id,按它决定怎么选,然后回 `route`。任务之后一直用这个真实模型,不再问。

超时、出错、不回,或选了用不了的模型,都用用户底下原来的模型把消息发出去,所以你的模型不会挡住发消息。选中你的模型时,推理强度和 Fast 不显示,因为真实模型要到发送时才定。

目前插件模型只出现在本机新任务的选择器里。定时任务、伙伴、多 Agent 协同、手机和在另一台电脑上开的任务都看不到,它们要的是一开始就确定的真实模型。
