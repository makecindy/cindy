# 独立视窗组件与几何索引：实现与测试数据

2026-10-04，Windows，Electron 41.10.3 / Chromium 146.0.7680.216。

## 结论

独立视窗组件与几何索引已落地。与上一版视窗实现相比，原生滚轮累计主线程耗时下降 15.9%，程序小步滚动下降 14.1%，大幅跳滚下降 5.0%。普通滚动已接近本批 main 基线；大幅跳滚仍约为 main 的 2.23 倍，不能说已全面追平。

## 本轮实现

1. 新增 MessageViewport，独立持有挂载集合及视窗状态。挂载范围变化不再重跑整个 MessageStream 的元数据投影和布局 effect；保留原有 DOM 结构、行 key、卡片身份与父级滚动协调。
2. 新增 MessageViewportGeometry，缓存行高、间距及上下偏移，二分查找可见范围。DOM 变化和逐行 ResizeObserver 标记脏行，只测量变化行及相邻行；结构、宽度等变化保留完整测量兜底。偏移数组重建仍是 O(N)，并非全部处理都变为 O(log N)。

保留上下 600px 缓冲、逻辑尾窗 80 项、数据分页、特殊卡片保留及文本访问规则。没有增加保留正文数量，也没有实现第三项尾行快捷更新。

拆分后曾发现重新挂载再追加消息会移动阅读位置：子组件延后的首次布局覆盖了父级恢复位置。已将连接时初始化提前到父级恢复之前，并新增精确偏移保留测试。修复后的 24 步视觉回归通过。

## 对照方法

同机、同一份 500 条合成消息、1280×800、相同 Electron、AX 关闭。每版各 3 次，顺序分别为 main→before→after、before→after→main、after→main→before；程序操作与原生滚轮分开跑。计时期间未并行运行构建、单测、类型检查或 dev 验收。

- main：此前冻结的 main 基线 25388846915a9640341c4de5feb804b3a948c8f2，本轮未重新拉取 main。
- before：上一轮两项去重优化后的 final 构建；两份核心源码备份 SHA-256 已核对匹配。
- after：本轮最终源码，392 份 renderer 源文件与构建清单 SHA-256 全部匹配。

指标为 CDP Performance.TaskDuration 增量，三次中位数，单位 ms；代表整段操作的渲染器主线程累计工作时间，包含采样开销，不是单帧延迟、墙钟耗时或整机 CPU 百分比。只有三次样本，不能保证其他设备有同样比例收益。

| 场景 | main | 优化前 | 优化后 | 较优化前 |
|---|---:|---:|---:|---:|
| 原生滚轮 240 次 | 891 | 1,030 | 867 | -15.9% |
| 程序小步滚动 240×48px | 464 | 542 | 466 | -14.1% |
| 大幅跳滚 100 次 | 809 | 1,897 | 1,802 | -5.0% |
| 流式输出 180 段 | 1,479 | 1,374 | 1,353 | -1.5% |

流式输出改善幅度很小，不能据此承诺稳定提升。原生滚轮使用 Electron sendInputEvent，±48 输入、每 60 次换向、每次等待 16ms；程序小步滚动直接写 scrollTop 后等一帧；大幅跳滚等待两帧。

脚本耗时：原生滚轮 606→447ms，程序小步 320→229ms，大幅跳滚 1,237→1,154ms。大幅跳滚布局耗时 252→252ms，main 为 66ms。这支持本轮主要减少 JavaScript 工作、没有消除重新挂载和布局成本的判断；本轮没有 CPU profile 精确分摊各组件成本。

首屏正文数 main/before/after 为 80/5/5，正文后代 DOM 节点为 1,789/292/292；GC 后 JS 堆中位数为 29.26/24.59/24.65MiB。没有通过扩大保留范围换取本轮收益。
