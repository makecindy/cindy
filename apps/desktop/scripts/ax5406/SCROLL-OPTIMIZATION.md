# 两项滚动优化：实现与实测

2026-10-04 · Windows · Electron 41.10.3 / Chromium 146.0.7680.216

## 结论

两项优化已落地。原生滚轮主线程耗时中位数下降约 4.7%，小步程序滚动下降约 8.1%；大幅跳滚与流式输出没有测到改善。它们减少重复几何检查，没有消除正文重新挂载的主要成本。

## 本轮改动

1. 缓存本次挂载范围对应的滚动区间。在消息、尺寸和 DOM 未变、滚动仍位于区间内时，跳过逐行 getBoundingClientRect 与挂载集合重建。
2. 已测量的程序滚动、原生 scroll、React 提交和 ResizeObserver 通知共享检查结果；观察器通知共用一次 rAF。保留程序滚动先通知上层位置协调器的顺序，跨挂载边界仍在绘制前同步补齐正文。

MessageStream 的 viewportEntries 改为 useMemo，避免无关重渲染导致缓存失效。新增 5 个定向测试覆盖重复通知、尺寸增长及总高度不变的行内增减。

没有增加保留正文数量、延迟卸载或修改数据分页；视窗上下 600px 缓冲、默认逻辑尾窗 80 个渲染条目及特殊卡片保留规则沿用原实现。

## 性能数据

基线是本轮优化前的视窗版，**不是 main**。同一台机器、同一份 500 条合成消息、1280×800 窗口、相同 Electron；每版运行 3 次，按 before→after、after→before、before→after 交替。正式计时期间没有同时运行类型检查、单测或 dev 构建。

下表为 CDP Performance.TaskDuration 的增量，单位 ms，取三次中位数。它是该操作序列的渲染器主线程累计工作时间，**不是单帧延迟、总墙钟时间或整机 CPU 百分比**；采样脚本开销也包含在内。

| 场景 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---:|
| 原生滚轮，240 次输入 | 1,093 | 1,042 | -4.7% |
| 程序小步滚动，240 × 48px | 596 | 548 | -8.1% |
| 大幅跳滚，100 次 | 1,886 | 1,895 | +0.5% |
| 流式输出，180 段 | 1,390 | 1,404 | +1.0% |

原生滚轮采用 Electron sendInputEvent mouseWheel，240 次 ±48 输入、每 60 次换向；程序小步滚动直接写 scrollTop，每步等待一帧，两者分别计量。大幅跳滚等待两帧后采样。

脚本耗时：原生滚轮 658→616ms（−6.3%）；程序小步滚动 370→318ms（−14.1%）。布局耗时基本不变。首屏两版均挂载 5 个正文、292 个正文后代节点，JS 堆约 24.58MiB。

三次原始总耗时（ms，按各版本运行顺序）：

| 场景 | 优化前三次 | 优化后三次 |
|---|---|---|
| 原生滚轮，240 次输入 | 1,062 / 1,093 / 1,094 | 1,042 / 1,061 / 1,038 |
| 程序小步滚动，240 × 48px | 615 / 596 / 573 | 548 / 523 / 576 |
| 大幅跳滚，100 次 | 1,885 / 1,886 / 1,891 | 1,961 / 1,886 / 1,895 |
| 流式输出，180 段 | 1,399 / 1,379 / 1,390 | 1,476 / 1,397 / 1,404 |

只有 3 次样本，且单次有波动：不能承诺所有设备固定提升这一比例。大幅跳滚 +0.5%、流式 +1.0% 不能写成性能改善。首版尝试的大幅跳滚收益也只有约 0.5%，原始结果保留在本报告目录根下 perf-all.json；最终数据使用 final-perf 与 wheel-perf。

## 回归结果

- renderer / preload / accessibilitySupportIpc：1,406 个文件，16,884 项通过、1 项跳过；Desktop 类型检查通过。类型检查曾有回调返回值被推断为字面量 true 的错误，明确标注 boolean 后重跑通过。
- 三轮程序滚动/流式对照共 3,120 次采样，原生滚轮对照共 1,440 次采样：未发现可见占位或重叠；每轮 180 段流式文本完整且顺序正确。
- 加强滚动回归：4,927 次布局采样，包含快慢滚轮、反向、键盘、滚动条拖动、程序跳转、查找接管、回到底部；3 种窗口尺寸、Light/Dark，失败项 0。
- 流式回归：3 种窗口/主题组合，各 400 段，共 1,200 段完整有序；2,573 次布局采样；520 个跟随阶段实际绘制采样无底部缺失；163 次尺寸补偿后采样无底部空隙。两次绘制前瞬态几何警告分别为 160px / 32px，实际绘制及补偿后检查均通过；不把瞬態 DOM 读数冒充绘制帧。
- 异步增高、图片、展开、卸载再挂载和窗口缩放：24 步通过。
- 文本查找：横向/嵌套滚动 2 项通过；无障碍初始关闭/开启及运行时切换 2 组通过，当前逻辑 80 行完整暴露。
- 完整 dev 隔离沙盒：7 次任务进入/切换、Light/Dark × 960×640 / 1280×800 / 1600×900，共 240 次滚轮后检查，无可见占位、重叠或页面 JS 错误。复用此前隔离沙盒的合成数据，不读取生产任务；这组作为显示回归，不与较早 main 数据混作同批性能对照。

本轮未重跑真实模型联网生成，也未重新跑原生 AX 崩溃压力对照；沿用之前稳定性调查的结论与限制，不扩大到“所有闪退均修复”。本轮没有新增针对变更卡片/文件列表的独立 dev 场景；相关单测已包含在全量 renderer 回归中，卡片保留规则未改。
