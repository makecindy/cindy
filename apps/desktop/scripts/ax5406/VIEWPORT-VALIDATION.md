## 实现

采用视口挂载与普通布局，根据消息条目和状态生命周期管理正文挂载范围：

- `useMessageViewport` 只挂载视口上下各 600px 范围内的历史普通消息正文；
  其他正文使用实测高度占位，未测量时估计 240px。占位保留稳定条目 key 与定位 id。
- 沿用既有逻辑尾窗、向前扩窗、搜索定位与滚动快照。恢复时读取已有高度缓存；
  正文与占位切换时按阅读锚点补偿；贴底时保持尾部位置。
- 工具／计划等复杂卡片、系统卡、流式消息、搜索目标保持挂载。
  点击或获得焦点的消息在本次 MessageStream 生命周期内保留，保护展开、编辑与媒体状态。
- 分享选择模式挂载当前逻辑窗口的全部正文。Tab、Ctrl/Cmd+A 或非空文本选择也会保留全部
  已加载正文，直到组件重挂载，优先保证键盘遍历与选择；因此并非任何操作后都维持低挂载数。
- 消息行仍使用 `content-visibility: visible` / `contain-intrinsic-size: none`。
  没有关闭无障碍、更新 Electron 或缩减存储／加载的消息数量。

复杂卡片保留挂载，已交互消息也不会回收；
长时间浏览时的挂载数量可以增加。浏览器原生全文查找不能依赖已卸载的正文；
应用自身基于消息数据的搜索定位继续将目标挂载。

## 画面和交互

`visual.cjs` 驱动真实 Electron 中的正式 MessageStream / UserMessage / AssistantMessage，
使用真实主题、字体及 CSS，输入 200 条合成消息；没有后端、账号或真实用户消息。
这属于真实组件集成验收，**不等同于完整已安装客户端的验收**。

运行命令：

```powershell
node apps/desktop/scripts/ax5406/run.mjs --scenario=component --workload=visual --rows=200 --ax=off --query=none --seconds=120
node apps/desktop/scripts/ax5406/visual-gallery.mjs <AX5406_ARTIFACTS>
```

通过的覆盖项：

1. 首次进入贴底、滚动至历史；正文挂载 2–9 条，不计算占位壳。
2. 连续五次大幅滚动，在每次滚动后的两帧检查视口，没有剩余空白占位。
3. 异步正文增高、图片实际解码成功；当前阅读条目偏移误差不超过 2px。
4. 顶部扩窗、搜索目标落入视口、宽窄窗口切换、Light / Dark。
5. 组件重挂载、阅读时追加消息保持位置；此处重挂载没有模拟完整任务数据恢复。
6. 长用户消息展开，滚离后仍展开，返回后状态保留。
7. 点击返回底部、继续追加消息，底部误差不超过 2px。
8. 键盘全选前恢复逻辑窗口全部正文，保持贴底。

逐阶段验证没有空视口、可见占位、行重叠或 renderer JavaScript 错误，保存原始截图与坐标。
人工查看浅色正文／图片、深色窄窗、展开长消息与深色尾部，没有发现新增的文字重叠、
异常裁切或错位。截图中的黄色／棕色背景是既有搜索定位高亮。
450ms 后的稳定截图不证明任意中间帧都没有闪动；快速滚动另有两帧检查。

## 首帧对照

`benchmark-component.mjs BwfjZy KOk7uy`，同机交替三轮，AX 均关闭，200 条数据、尾窗 80 条，
只更新最后一条助手消息，不滚动。此前 fixture 把 40 条历史助手消息都标为 streaming，
新方案会保留它们；因此该基准的新方案实际仍挂载约 42 条正文，不是正常浏览的 2–9 条。
旧冻结构建与新版共享消息生成和 steady 负载；新版 fixture 另加入视觉操作分支和深色主题导入，
属于组件方案对照，不能视为只有 hook 指令不同的微基准。

| 方案 | 三轮首次内容绘制（ms） | 中位数 |
|---|---|---:|
| 第一阶段：普通布局、全部 80 条正文挂载 | 1004 / 1072 / 1012 | 1012 |
| 本阶段：普通布局、按视口挂载并保留 streaming | 848 / 848 / 888 | 848 |

减少 164ms，约 16.2%。这个数包含独立页模块、字体和首次组件加载，**不是客户端任务切换延迟**。
六轮均正常退出，原始数据在 `cindy-ax5406-benchmark-b0v9PS/results.json`。
