## 改了什么

1. **用正文按视窗挂载替代消息行 `content-visibility: auto`。** 正常布局避开已复现的 Blink 无障碍文本序列化断言；视窗上下预留 600px，离屏正文用缓存高度占位，未测量时估高 240px。默认逻辑尾窗仍是 80 个渲染条目，数据库分页规则未改。
2. **补齐滚动协调。** 尺寸变化、异步增高、历史恢复、流式跟随、回到底部、上一条提问及搜索跳转统一保留阅读锚点；程序滚动及时挂载目标，避免先画出空白占位。历史分页投影保留变更卡片信息。
3. **保留交互内容。** 变更卡片、文件清单等非普通消息条目，以及正在操作的正文保持挂载；分享、选择、键盘遍历和查找需要时补齐当前逻辑窗口正文，不以此额外加载历史。
4. **修复 review 的两个 P1。** 查找命中先展开消息内横向／纵向滚动容器，再交给外层消息导航；增加 main → preload 的只读无障碍状态桥，初始开启及运行中开启读屏时恢复完整正文挂载，保持阅读位置。主窗口和独立侧栏均覆盖。

本轮只增加对照测试与报告，没有继续修改产品源码，没有提交或推送。

## 性能结果

组件基准：真实 MessageStream 及依赖图，合成消息，未压缩独立构建；500 条相同输入、初始逻辑尾窗 80 条；三种视窗尺寸，每版每尺寸 3 次，交替顺序 main→当前 / 当前→main，共 18 次独立 Electron 运行。性能组关闭 AX，两版条件一致；稳定性组另外启用 AX。以下均为对应三次的中位数。

| 指标（1280×800） | main | 当前版 | 变化 |
|---|---:|---:|---:|
| 消息区就绪 | 533.9ms | 440.4ms | 减少 17.5% |
| 初始正文挂载 | 80 | 5 | 减少 93.8% |
| 消息区后代 DOM 节点 | 1,789 | 292 | 减少 83.7% |
| GC 后 renderer JS 堆 | 29.26MiB | 24.58MiB | 减少 16.0% |
| 180 次流式追加的主线程累计任务耗时 | 1,494ms | 1,389ms | 减少 7.1% |
| 100 次大幅跳滚的主线程累计任务耗时 | 824ms | 1,878ms | 增加 127.9% |
| 跳滚循环 P95（每次主动等待两帧） | 33.9ms | 33.6ms | 此负载下接近 |

三尺寸就绪时间 main→当前：960×640 为 545.6→414.3ms；1280×800 为 533.9→440.4ms；1600×900 为 548.1→446.5ms。三尺寸 JS 堆均下降约 16%–18%；大幅跳滚主线程开销均增加。

完整 dev 客户端：1280×800，先首次打开，再重复六次在空任务与 500 条消息任务之间切换。两版对应轮次逻辑条目完全一致，依次为 40、60、80、100、120、140、160；当前版均只挂载 5 条正文。这种重开扩窗行为两版一致，不是本次修改引入。

| 实际客户端操作 | main | 当前版 |
|---|---:|---:|
| 首次打开（单次） | 1,195ms | 526ms |
| 后续六次切换中位数 | 801.5ms | 304.2ms |
| 每组 40 次普通滚轮输入的主线程累计耗时，中位数 | 2,374ms | 3,105ms |

完整 dev 的切换中位数减少约 62%，普通滚轮主线程耗时增加约 31%。两版分别顺序运行，未做多次交替重启；因此这组是本机实测观察，证据强度低于上面的交替组件基准。普通滚轮的历史窗口在两组窄窗口场景有不同扩展过程，不能将 31% 全部归因于虚拟化；固定输入的组件跳滚基准仍明确显示额外 CPU 成本。

**口径：**“就绪”指目标正文可用后再等待两次 rAF，不是 FCP，不是应用冷启动，也不含模型响应时间。JS 堆不是整个应用 RSS。主线程累计任务时间不是单次操作延迟；两帧测试循环不是实际 FPS，不能据此保证低配置设备没有掉帧。

## 风险与建议

保留当前方案：它避开可复现的原生崩溃触发条件，改善进入速度及正文资源占用，已测显示行为没有回归。下一步性能优化应聚焦滚动时重新挂载和同步测量的成本，并保留现有空白、锚点与流式跟随验证；不建议为省这部分 CPU 恢复已能复现崩溃的 `auto`。

启用读屏、查找／选择等完整正文模式时，资源收益会缩小或消失，这是文本可访问性所需的回退。未测试 macOS、正式安装包、真实 NVDA/VoiceOver 长期使用和低配置设备。窗口变化通过 CDP 设置视口。本次没有重新执行 50k 边界性能测试；此前两版都有门槛波动的记录仍有效，不能称所有性能门禁全绿。

测试准备曾遇到调试接口过早启用导致等待、首次协议确认导致数据库尚未就绪；修正测试脚本后重新采集，相关无效尝试未纳入正式数字。性能组三轮全部完成，未删除慢样本。
