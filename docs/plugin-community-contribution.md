# 个人社区插件发布客户端

客户端实现与权限边界说明。
两仓各自维护等价的 [HTTP / DTO 契约](plugin-community-contribution-contract.md)。

插件列表以当前最新主线为基线，原卡片、来源文案、署名布局、统计、推荐分类、筛选与排序保持一致，仅新增“发布插件”按钮。来源继续使用主线的“公开 / 团队共享 / 本地 / 自定义”，不新增“本地开发 / 本地导入”等分类，不用来源推断作者身份或发布状态。个人投稿的展示署名暂由服务端统一返回为空，作者绑定和提审昵称仍完整记录；客户端保留原有展示，不回退包内个人信息。

作者在独立源码目录开发、安装并使用插件后，满足本地基础条件的使用详情提供“发布插件”入口；来源、保留标识、组织范围、安装身份或批准条件不满足时隐藏入口。
打开普通使用详情不读取提审记录或准备发布包。点击“发布插件”复用发布页的同一个弹窗，并自动选中当前精确安装实例；弹窗内读取版本和提审状态、准备实际包，展示功能说明与存在的更新说明，允许提交后才显示“提交 {{version}} 审核”。后续版本也可沿独立管理页的本地版本区域提交。
Host 固定并再核对当前安装内容，不弹保存或选文件框，不另加确认弹窗。只有提交结果已确认后才进入该插件管理详情；提交失败留在原处显示实际原因，用户已离开时不抢回页面。作者继续开发时仍回到源码目录，不直接编辑 Host 的安装目录。
本地使用详情顶部操作区排列发布入口、使用动作与启用开关；发布检查、包准备与不能提交的原因在发布弹窗中展示。
普通列表始终进入使用详情，不自动跳入作者管理；发布结果和版本历史集中在“发布插件”独立页面。保留原三列详情头部：
宽窗图标与标题在左、操作在右，发布按钮紧随使用动作；详情内容区不足 680px 时整组转到标题下方换行。
右侧按钮较多时允许组内换行，并为标题至少保留 160px；管理页的长名称自然换行，不提供匿名发布开关。
未能查询时显示错误，不以本地版本推断线上结果。

“发布插件”是插件页常驻入口，管理页页头提供“发布插件”，空列表提供“去发布”。两个按钮都只打开当前账号的已安装插件选择，
选择框与原详情复用同一份本地条件判断，只列出可信本地精确实例；保留标识、组织/私域、
安装身份未确认或权限未批准的实例不进入选择框。没有可选项时区分未安装与没有可发布实例，
引导安装、使用自己的插件并核对详情。选择后留在当前弹窗，展示所选精确本地安装的实际名称、版本、用途、更新说明与只读预检结果，不创建上传或占用版本；点击“提交 {{version}} 审核”才开始上传。关闭弹窗保留管理列表位置，不提交。
选择框打开后独立完整读取本人插件版本事实，不受管理列表搜索和分页影响。已知当前版本已提审、插件有待审版本或无提交权时，在选项内直接说明并禁止选择；未知或读取失败时不冒充可提交。选中后的实际包预检仍是最终提交条件；限制或错误固定显示在底部按钮上方，不藏在用途、更新说明的滚动区域中。首次发布从“发布插件”页面的页头按钮选择本地版本，再提交审核，新版沿已有管理详情提交，审核结果仍在同一管理详情查看，不把 Agent 的调用步骤作为用户页面。
普通使用详情不显示“版本与更新”区块或发布限制说明，发布内容和原因集中在发布弹窗与管理页面；不能发布的实例隐藏发布入口，
安装不表示作者权，最终仍由 Main、服务端核验私域台账与 public ACL。
个人账号和组织成员均可按当前登录身份向公开市场投稿，作者和管理权归提交者本人，组织管理员不因此获得其他成员投稿的管理权。组织内部发布及私域插件继续原流程。
未登录时复用现有登录入口；登录意图只在内存保存，
恢复时必须匹配原物理实例键、安装目录和批准记录，再按当前账号重新准备。另一个账号的同 ID 安装不会
自动代替原目标。列表支持服务端搜索、筛选与分页，每行以插件为主体，分别列出本地版本、当前上架版本和最近提审；
列表只展示服务端已收到的插件提交，不把未完成上传当作插件记录。上传与提交过程留在原提交按钮中，失败原因也在该次提交时显示。
管理详情默认显示本地、已上架、待审核三份当前事实，以及本地动作、已上架内容和当前提审。
本地版本可提交时先只读准备该安装的名称、版本、用途、更新说明和预检，显示在本地版本区域；同一个提交按钮只提交这份已展示的固定包，不借用上一提审的说明，也不增加确认弹窗。发布弹窗与管理详情共用相同的准备与释放逻辑；普通对话结束不取消已经获准的本次提交，账号、任务实例、权限与安装变化仍会阻止后续写入。
已上架介绍与更新说明只读取匹配当前市场 releaseId/version 的真实公开版本，不借最新待审内容补齐。
发布记录默认收起，内部版本选择仅切换历史快照；版本号与状态分开显示，共用应用 Select，
单个历史版本不显示无用下拉框。完整退回原因保留，历史选择不改变本地版本、当前提审或提交目标。
顶部返回按固定父页面跳转：管理详情返回“发布插件”列表，再返回原插件列表，同账号保留查询、筛选和列表位置。管理读取本机安装不改变普通详情的选择；管理页不再提供实际跳往普通详情的“打开插件”按钮。普通插件详情仍沿原列表返回逻辑。

官方 public 插件不允许经客户端提审（包括 Agent 工具），即使当前账号有提交授权也不例外。请通过 GitHub 仓库提交修改，以保证仓库源码完整、便于后续维护。官方身份只取 Host 可信官方来源或服务端 publisherKind，不根据名字、包内 author 或自定义市场声明认定；普通使用详情隐藏提交入口，不展示发布限制说明，Main 在准备和实际写入前复核。普通第三方 public 插件沿既有授权流程。

## 版本更新与取消审核

首次上架不要求更新说明，插件用途写在 `description`。插件曾上架后再提审时，作者在 `ghost.json.releaseNotes` 写相对上一已上架版本的完整更新说明；从未上架的退回或取消不视为更新，下架不免除更新说明要求。
缺字段的包仍可安装，只有曾上架插件的更新缺说明时才阻止提审。摘要展示实际版本、已有说明与不可复用提示。
每次准备持有临时包；页面清理不影响已发起的提交，本次动作结束后释放包，不保存上传历史。
本地安装内容或批准变化后必须刷新摘要；AI 也读取同一摘要并按当前权限档提交。

成功提审后该插件的版本号永久占用；退回、取消、通过、下架均不能再次使用。
每插件至多一个真实待审版本。预检或上传失败未提交成功不占号。用户流程只有提交本地插件、后台审核、通过或驳回；上传中只显示提交进度，失败就显示原因，不提供独立恢复、重试或上传记录页面。相同内容的未完成请求由普通提交入口内部复用，不要求用户选择或理解操作记录。
“发布插件”按插件和版本展示真实提审时间、通过时间；历史未知时间明确未记录。
待审版本可通过原确认框“取消本次提审”，不填写原因；取消保留版本与记录，不改变当前市场。
取消与审批竞争时返回实际终局，不把已通过伪装成取消成功。
“发布插件”管理详情独立显示本地版本、已上架、待审核三个事实；本地版本指这台电脑实际安装的版本，来源沿原规则，可为“本地”或“公开”，并准确显示启停情况。管理页不支持提交时隐藏提交入口，包括待审、版本号已占用、权限或安装状态未就绪及离线；处理中保留 loading 防重复提交。不能从列表直接盲提交。

只读预检与取消审核的接口见两仓共享契约。
个人投稿复用原待审、审核和上架流程，没有额外启用开关，不要求发布基准或审核阅读令牌。

## 当前包与提交

- 包快照沿 `exportGhostPackage.ts` 和既有 inspect 校验，固定实际安装字节；系统导出保持原行为。临时包只属于当前预览或本次提交，不建立持久包历史。
- `api.ts` 沿 Main 当前账号的 Auth Access Token 与可信 issuer 核验，token 的 sub/ctx 必须匹配当前登录身份；服务端验签并判定 public 权限，不借用其他账号或 Platform 身份。
- Main 统一执行准备上传票据、上传和提交；页面及 Agent 只跟随本次进度。prepare 与 PUT 不会创建待审版本，失败后释放临时包，不保存可恢复上传任务。
- 发送 commit 前仅记录尚未确认请求的服务端 operationId、目标/包摘要及安装绑定；响应丢失后先在发布管理核对该版本是否已有提审记录。已受理的版本沿本人列表/详情查看真实审核结果，不绕过版本或待审限制再次提交；仅预检仍允许提审时，主机才先查询原请求，必要时提交同一 operation，不重复上传。确定终态后清除该记录，不保留完整回执、本地 phase/stage 或终态历史。
- 未确认记录按账号隔离，不保存 Bearer、PUT 票据或临时包路径，不读取持久文件里的路径执行清理。共用 userData 的 passive 实例不能写入；页面、登录和应用重启不自动提交。普通对话结束后当前已授权提交可继续，账号、任务权限或安装变化仍阻止后续写入。

202 只是处理中。只有服务器成功操作附带完整回执，才解释 `submitted_for_review`、`metadata_updated`
或 `unchanged`；上传包 SHA 与实际 Release SHA 分开。审核状态属于对应修订，市场可用以 `available`
为准。旧版上架而新版被退回时，两者同时保留；历史按独立 eventId 展示，不能把同修订事件压成一条。

上传动作只做有限的操作处理查询。人工审核结果在当前登录账号的应用前台按 60 秒间隔及打开、手动刷新、回到前台或网络恢复时读取；应用内保留审核结果未读标记，不发送外部消息，后台不可见时不查询。
离线保留当前账号上次查询快照及时间并标明失败；查询失败不冒充
空列表。换账号清空视图缓存，不显示旧账号原因或内容。

## 本机安装与已上架版本

“发布插件”按服务端本人 API 返回的插件展示一条管理记录。Main 以现有 `namespace + ghost.json.id`
读取这台电脑实际安装的版本；公开安装继续核对原市场台账的 pluginId、来源和批准包证据。
本地安装不要求先有提审回执，也不新增手动关联操作或持久化关联记录。
同一插件正常本地更新后直接展示新的安装版本；未安装和读取失败分别显示，不混为一谈。

本地版本、已上架版本、当前提审是独立事实。提审、审核通过和页面读取都不改变安装来源，
不自动安装或替换包。同一账号仍按现有 namespace + id 去重，不支持同身份的本地版与公开版并装；
名称相同而 ID 不同的插件不合并。发布权限与平台署名继续由服务端判定，不能从本地安装推断。
已安装旧版本无法取得可信的提审昵称时隐藏署名，不用当前市场新版昵称补齐；本地、组织和旧安装仍按原包内署名规则展示。桌面与远程详情共用公开来源的署名回退限制。

## 基础数据

“发布插件”详情在标题下方的元信息行直接复用现有 `PluginSharedUsage` 组件，和插件列表、普通详情使用相同的累计统计及悬停／聚焦交互。
复用已上架版本详情中的 `downloadStatistics.requestCount` 与 `usageStatistics.usageCount`，按插件的所有版本聚合，不限定近七天。
下载量沿既有下载地址请求口径，不等于安装完成次数；调用量沿服务端已上报的共享调用口径，不读取本机个人调用记录。
未上架不显示统计；详情读取失败或服务端缺少指标时沿现有组件逻辑隐藏对应计数，只有服务端明确返回零才显示 0。统计不随历史版本选择切换，不增加请求、IPC、服务端接口或统计组件分支。

## AI 与特权边界

`ghost_contribution_prepare`、`ghost_contribution_submit`、`ghost_contribution_status`、
`ghost_contribution_stop`、`ghost_cancel_plugin_review`、`ghost_my_plugins` 是当前登录账号向公开市场投稿的独立能力入口；个人和组织成员均可使用，旧企业 Forge 发布保持原行为。
读取工具支持列表、精确详情、历史游标和指定 submission 留存内容。提交沿当前任务 Full Access / Auto / Ask，
不再增加最后人工点击；安装许可不证明公开发布权。AI 不获得 Bearer、PUT URL、受管文件路径或审核权限。

所有新能力在调用前及返回前复核 owner 和既有 helper surface；公开写入还在确认后、最终启动前复核。
共享任务访客和 `resolveHelperSurface` 判为 restricted 的插件托管任务、errand 及其 Worker 不得借用
Host 账号。普通用户自己的 Worker 和自动任务不被泛化封禁。IPC 仅暴露精确方法和参数，拒绝任意路径、
额外主体字段和不可信 Renderer；未增加 device-link allowlist 或远程控制能力。

故障只影响当前个人发布动作：停止、断网或服务端失败不会改变已装插件、运行时或既有市场版本。
重启后不自动重新上传，也不展示上传记录；用户仍通过普通提交入口操作。未知 commit 结果保留服务端请求标识，
不由 UI 推断成功或擅自更换包。服务端不支持接口时明确失败，不回退到企业或 Platform 身份。

## 验证与维护

提交前对 Host 固定包与重复提交防护、可信 IPC、账号隔离、普通详情入口、管理页版本、审核结果未读执行相关回归；检查共享协议和开发工具包的类型及行为。
界面使用仓库 `pnpm ui:check` 验证真实组件的明暗主题与窗口尺寸，并在 PR 附截图。隔离场景不代替真实提审、审核、安装或权限验收。

`ghost.json.releaseNotes`、提审流程与平台署名规则同时维护在内置 `cindy-plugin-creator` 手册及 `cindy-tools` 工具说明中。官方插件仓的文档、示例与校验不在本次客户端改动范围内。

存量插件影响：不改变 registry 格式、批准记录、运行指纹、安装布局或启停状态；缺少 `releaseNotes` 的旧包继续可打包、安装和运行。插件基座改动仍须按仓库白名单确认门完成人工 review 后合并。
