## 网络对照

第一组：公开入口无凭证 HEAD，比较全新连接、TLS 会话缓存、完整 socket 复用。
首个 DNS 查询 430ms，此后约 2–4ms；后续新连接从开始到 TCP 完成为 527–564ms，
到 TLS 完成为 1089–1210ms。这些是相对开始的里程碑，不可累加。
复用完整 socket 的两次 HEAD 响应为 313 / 315ms。
TLS 缓存组没有观测到 `isSessionReused=true`，不据此推断服务永久不支持 TLS 恢复。

第二组：使用生产依赖 `ws` 向 `/api/voice/asr` 发无凭证升级请求。
所有请求均返回 401，**不是识别成功或已认证建连测试**。
按 cold / warm / warm / cold / cold / warm 交错执行。

| 模式             | 请求到响应           | 中位数 | socket 复用 |
| ---------------- | -------------------- | -----: | ----------- |
| 冷连接           | 1606 / 1628 / 1515ms | 1606ms | 否          |
| 先完成 HEAD 预热 | 368 / 358 / 359ms    |  359ms | 三次均是    |

点击路径候选收益约 1247ms；预热本身消耗 1525 / 1671 / 1532ms。
如果点击以后才等待预热完成，总时间反而可能更长。必须在点击之前完成并保留连接，
才能把这段等待移出点击路径。本实验没有证明认证、网关上游准备和首字时间也省同样多。

可复现第二组：

```sh
node scripts/voice-transport-benchmark.mjs wss://voice.cindy.app/api/voice/asr
```

脚本不发送认证或音频，不读取开发版登录态。默认 Node 直连，不声称复现系统代理。

仓库脚本随后复跑一次：冷连接 1373 / 1349 / 1364ms（中位数 1364ms），
预热连接 279 / 278 / 314ms（中位数 279ms），差值 1085ms。六次仍均为 401，
三次预热组仍均确认 socket 复用。两轮一致支持约 1.1–1.25 秒的网络层候选收益。

## 取舍与落地条件

1. **优先候选：普通 HTTPS 连接预热，然后同一个 Node Agent 发 WebSocket 升级。**
   可以挂现有输入框语音预热入口，不提前创建计费识别会话。只有已就绪连接才能命中；
   点击不等预热。连接会被升级消耗，下一轮需要新连接。需要明确空闲连接的回收期限，
   避免把一次实验变成无限后台请求；还需测试空闲超时、代理变化、区域切换、重连。
2. **保留提前发送缓存音频的实验。** 原日志首次响应约 564ms；允许先发音频才可能
   和这段等待重叠。之前本地服务模拟已证明这取决于服务端何时开始消费，不能承诺首字
   一定等额提速。本轮没有扩大实验的默认启用范围。
3. **不优先缓存票据。** 会话票据是一次性的，还关联会话 ID、语言和后续润色；复用
   旧票据会破坏语义，提前申请会话也超出当前“实际使用才创建”的设计。
4. **不为代理解析、TLS 缓存继续加机制。** 前者现有样本接近零，后者本轮没有实测收益。

本轮产品代码只补实际 WebSocket 的分段观测，不默认启用新的连接池。
记录 socket 分配、DNS、TCP、TLS、升级响应里程碑及复用/代理标志；不记录 URL、
地址、凭证、请求头或响应正文。代理可能交付已连接隧道，缺失阶段保留为空，不伪造 0ms。
完整认证会话对照、首字收益和代理路径收益仍待验证。
21 项握手计时与 SAUC 协议回归测试、Desktop 类型检查通过。
