# Desktop 启动时的 Agent 二进制检查

普通启动不再因为 manifest 发布了更新版本而升级已有的 Agent 运行时。清单拉取、资产与
平台校验保持原样；首次安装、缺失或无法通过已有本地探测的运行时仍走原有下载、校验和
重试流程。此改动不保证启动离线或不等待网络。

## 启动策略

- 普通启动：向二进制预检查与准备流程传入 `checkForUpdates: false`。本地存在可用运行时
  时返回其真实路径；有本地版本探针的运行时按真实版本选择候选，保留用户自更新结果。
- 用户点击应用内热更重启：确认更新可以执行后，写入目标应用版本的一次性标记；新版本
  启动时开启二进制版本检查，复用原有升级流程。
- 仅下载应用更新、后台自动更新重启、普通重启：不写该标记。
- Pi 的可选资产规则不变：清单撤回资产或无法取得清单时，不因本地残留而重新启用。
- Linux 已验证的私有运行时同样可以在普通启动时复用；更新检查开启时继续执行现有
  CDN 优先与运行时回退逻辑。
- 公共入口默认沿用本次启动的检查决定，包含 Pi 后台恢复；明确传入
  `checkForUpdates: true` 的修复或升级调用仍可检查更新，底层 provisioner 与开发模式不变。

## 一次性标记

标记位于 Electron userData 下的 `agent-binary-update-once.json`，包含目标版本与写入代次。
它不是用户偏好，不进入数据库或仓库，也不改变独立更新器的参数、协议与文件替换步骤。

首次进入二进制公共入口时读取并删除标记，仅目标版本与当前应用版本一致时开启检查。
检查模式保留在本次主进程的公共模块中，启动失败与 Pi 后台恢复的重试都不会丢失；随后普通启动不会
重复检查。版本不匹配或损坏的标记也会清理。开发模式不消费正式版的标记。

更新执行被拒绝时不写标记；写入后可观察到的执行失败会清理本次标记，旧执行的清理不
应删掉更新一代的标记。如果外部更新器失败并退出，下一次旧版启动会清除不匹配的标记。
标记文件写入失败只记录警告，不阻断既有应用更新；读取或删除失败时不开启本次版本检查。

## 代码入口与回退

- `apps/desktop/src/main/agent-binaries/index.ts`：统一决定本次启动的检查参数，启动与恢复调用无需传开关。
- `apps/desktop/src/main/agent-binaries/`：本地复用与一次性标记；Linux 在下载前查找可用的受管、私有和系统运行时。
- `apps/desktop/src/main/updateService.ts`：仅用户主动更新重启时写标记，执行失败时清理。

恢复每次启动检查，只需将公共入口的默认检查决定改为 `true`。移除整项功能
不需要迁移或删除用户已经安装的二进制。

## 验证

定向运行 `agent-binaries/__tests__`、`agentBinaryLinuxPrepare.test.ts` 和
`updateService.test.ts`；再运行根目录 `pnpm test:unit:related` 与
`pnpm --filter desktop run --if-present typecheck`。

单测不能替代 macOS、Windows、Linux 正式安装包的实际更新—替换—重启验证。
