## 0. 当前路线：自研传输层（2026-10-30 用户裁决，优先于下文）

不使用第三方网络库，从头构建，每步都充分测试。可靠 UDP 部分蒸馏自 KCP。§2 记录的是更早的 iroh 验证：
EdgeHub 接缝、局域网发现和按进展判断卡死的结论继续有效，iroh 的结果只作为性能参照。

**V2 单独部署、按设备切换（2026-11-06 用户确认，优先于 §5、§6 与第 7 步的夹带方案）**

- agent-net 是设备互联 V2，和 V1 并存，用户在 Cindy 里按设备切换；遇到没开 V2 的对端自动走 V1。
- V2 服务端单独部署（中继、查公网地址、设备证书），不借 V1 中转。UDP 被封时走 V2 服务的 443，
  第 7 步“数据报夹带在现有中转的 push 里”撤出产品路径，只留在原型里做对照；§5 的“加密 WSS 经现有中转、不用升级”同样以此为准。
- 自建中转：V2 中继拆成单独的程序，一键部署时和现有内核一起装，共用 Nginx 和证书，现有内核保持不变。
  §6 的“一个内核不变、中继能力实现在内核里”以此为准；第 7 步在内核里加的 `agent-net-relay-v1`（默认关闭）之后迁到单独的程序。
- 准入分两道门：传输核心提供通用的握手准入机制（不知道对方公钥发不出合格请求、忙时验证来源地址、限流），
  认哪张票由上层决定，Cindy 默认用登录账号后服务器签发的设备证书。用户不需要记任何密钥。
- V2 服务端在独立的服务端仓库，部署前另行授权（§15）。

2026-11-07 用户授权实施独立服务，并明确自建／本机中转须全功能、可脱离官方 Agent-Net 服务。
此项优先于早期 V1 自建方案的能力限制：沿用部署、加入与线路选择逻辑，共用 V2 内核；
设备身份、名册、配对审批、管理与业务路由不能依赖官方 `agent-net-server`。
远控、任务、文件、媒体、远程桌面、分享、共享任务、通知与恢复逐项验收，官方服务不可达时也须通过；
未接通项不声明完成。正本见 [`完整能力要求`](product-rules/agent-net.md#v2-自建与本机中转的完整能力2026-11-07-用户确认)。

**服务端构建与部署约束（2026-11-07 用户要求，独立服务已实现、环境未部署）**

- Agent-Net 独立服务在 `cindy-server` 现有 workspace 中建设，构建、部署、环境变量与 Docker 的组织方式参照已有服务。
  主要参考 `device-link-server` 的网络服务配置与镜像，以及 `heartbeat-server` 的精简镜像；具体版本跟随服务端仓当前锁定值。
- 构建沿用根锁文件、`pnpm --filter <service>` 的 build/test/typecheck/start 脚本与 frozen-lockfile 安装。
  Docker 使用仓库根构建上下文、builder/runtime 多阶段构建和 prod-only 部署产物；真实 `.env`、密钥和日志不进入构建上下文或镜像。
  仅在确需持久数据时引入本服务自有数据库与 migration，不照搬其它服务的无关依赖。
- 环境变量集中在服务配置模块解析、校验并在缺失或非法时拒绝启动，同步维护 `.env.example` 与服务文档。
  优先沿用已有配置约定，新增项需说明必要性；真实密钥由部署系统在运行时注入，示例只放中性占位值。
- 接入既有镜像构建发布 workflow、服务变更检测和 GitOps/Helm 环境注册，沿用镜像标签、环境配置及发布分支规则。
  健康检查、生产 JSON stdout 日志、入口脚本、优雅退出和回滚方式也按现有服务约定处理；本条不授权实际部署。
- Agent-Net 的 UDP 地址发现入口需显式核对容器、Helm Service 与外部网络的 UDP 端口和可达性，443 WebSocket 中继按已有反代/TLS 方式接入。
  不能只写 Docker `EXPOSE` 就视为部署完成；各目标环境的配置注入、镜像启动、健康检查和两种网络入口都要实际验证。

- 握手准入（2026-11-06，核心已实现）：不知道公钥的请求不做 DH、不回包；每秒 2 万个伪造来源的请求下 DH 不超过额度，
  同时来的正常发起方先拿 cookie 再重发，照样连得上。请求多了 32 字节校验，不忙时行为不变。
  见 `packages/agent-net-core/sim/results/2026-11-06-hardening/README.md`。
- 关闭通知（2026-11-06，核心已实现）：一端关掉时发两个加密认证的关闭包，对端马上停，不用等 15–30 秒判死；进程被强行结束时仍要等判死。
- 连接号轮换（2026-11-07，核心已实现）：握手确认后每端补齐 7 个备用号；发往新路径从验证包起用新号，
  本地换网（系统通知或收到对端验证才发现）时轮换在用路径，作废通知和补号快照在加密通道里可靠重发。
  数据包仍带 4 字节号，`Endpoint` 的上层句柄不变；缺号先保持连接并单独计数。
  128 项测试、306 个对照场景、2006 个随机换网场景、300 个随机 NAT 场景和 4 种变异检查通过，

  306 场景合计用时 −0.09%、恢复时间 +0.61%、线上字节 +0.94%，新增控制包有开销；
  详见 `packages/agent-net-core/sim/results/2026-11-07-id-rotation/README.md`。三项核心防护已齐，Desktop 私有中转的实验接入见下。

**Desktop 私有中转接线（2026-11-07，源码与本地验证）**

- `packages/agent-net` 是现有 DeviceLinkClient 的 V2 socket 适配器，使用 Rust WASM、签名设备名册、
  固定根和 Noise 传输公钥绑定，仍承载现有 link/invoke/push 协议。首次 RPC 不等 STUN 完成，
  同时拨号按已认证设备 ID 收敛，网络切换仍由核心执行。WebRTC 文件/远程桌面的既有加速器保留，
  不让通用 WebRTC data path 把已建立的 V2 业务流绕回旧路径。
- Main 从既有中转安全凭据库派生/保存设备私钥，根私钥不上传。私有配对成员持久至撤销；
  官方账号证书仍最长 14 天。公开名册按账号和中转隔离，离线信任最多原始接收后的 14 天，
  读取不续期，缓存磁盘故障不切断在线认证连接；认证拒绝/撤销不能按暂时掉线用缓存恢复。
- 本机宿主加载独立 V1/V2 内核，经只按路径转发的公共入口提供服务；打开过 V2 后，
  关闭本机传输开关仍继续服务其他设备。SSH 安装器沿用现有 Node/systemd/ACME/Nginx 工作流，
  总是安装独立 `cindy-agent-net` 程序、公开 bootstrap 和独立 UDP 入口，并在成功前验证固定根下的名册。
  没有 Nginx 时，通用 TLS 前端读取已有 V1 CLI 管理的证书并重载；V1 内核不依赖 V2 内核。
- 加入链接保留 V1 字段并增加可选 V2 码；两个持钥申请在主人侧核对配对 HMAC、设备和公钥后一次批准。
  加入不改变本机 V2 开关。已知 V2 对端掉线不立即明文降级；只有签名的 V1 能力握手表明对端旧版/关闭时才选兼容线路。
  撤销一个成员后晚到的数据报只丢弃，不关闭健康发送者的整条中转连接；访客越权仍拒绝。
- Desktop 打包暂存独立 relay bundle 和经源码/Cargo/二进制摘要验证的 WASM；正常构建不依赖 Rust。
  核心源码变更须显式刷新预编译包。此次 Node 构建包为 359804 字节，不改写早期 276 KB 原型的历史测量。
- 后续已接入：官方 App CSR/固定根/提前续签，现有媒体总仓入口的分块加密/Range，
  签名 V1 模式证明、旧版连接标记、只允许加密连接开关、已知设备的 IPv4 局域网冷启动发现。
  Rust/WASM 与加密传输运行在独立 Node worker；Main 仍负责代理和账号/线路校验，并非 utilityProcess 沙箱。
  独立服务复用其它 server 的 APNs/FCM 发送模块；客户端接收尚未接入。
- 仍未完成：Mobile 原生、utilityProcess 进程隔离、供应商分享/共享任务的端设备业务授权、原生通知接收/解密。
  跨账号业务仍保留官方兼容线路；不能称为“完全无损”独立交付。
  真实 SSH 部署、任务/文件/远程桌面等业务入口和手机后台/锁屏还须单独验收。

验证范围与复跑见 [`Desktop 接线记录`](../prototypes/agent-net-spike/results/2026-11-07-desktop-runtime/README.md)。

**性能目标与配置边界（2026-10-31 用户要求）**

- 对已发现落后于 KCP 最佳配置的用时、尾延迟、开销等项目逐项继续优化，目标是全面赶超；不能未经验证就将差距归为产品取舍，或以省流为由停止优化。
- 性能对比同时列明速度、流量、CPU 和可靠性，保留所有落后项与原始结果，不通过隐藏场景或放宽断言达标。
- 确实存在成本冲突时，拿实测结果讨论配置，不以配置替代算法优化。用户已选择默认**自动选择、支持手动覆盖**：普通用户按网络和消息大小自动选策略，用户可明确选择偏速度或偏省流；具体参数仍须实测验证，不将未经验证的策略当成已交付能力。

**边界**

- 运行时零第三方依赖。`packages/agent-net-core` 的 `[dependencies]` 必须为空。
- 真实 KCP 只在测试里当对照，源码不进仓库，也不进产品。
- **加密算法不自己写**：用系统自带的实现（Node `crypto`、iOS CryptoKit、Android 系统库、硬件厂商 SDK）。
  这些不是额外引入的依赖。握手流程按公开的 Noise 规范自己实现，核心通过 `Crypto` trait 调用调用方传入的算法，不接触长期私钥。
  测试里用 ring 和 x25519-dalek 当对照实现，只在 `sim` 里，不进产品。
- 核心用 Rust 写成不碰网络和时钟的纯状态机，经 C 接口接到各平台。
- 核心是通用的可靠 UDP 协议层，不写入任何 Cindy 专属设计，未来可以单独拿出去给其他应用使用（2026-11-01 用户要求，规则见产品规则“传输核心的边界”）。

**自研带来的变化**

- 打洞、拥塞控制、加密握手、网络切换都要自己实现并长期维护，工作量明显大于 iroh 路线。
- 中继协议自己定义，可以直接并入 `packages/device-link-relay` 内核，不需要托管 `iroh-relay`。§6 里的外部程序部分因此取消。
- 协议完全自主，不再有“换掉第三方层”的问题。核心足够小，硬件节点更容易接入。

## 1. 背景

现有 device-link 让同账号的电脑和手机经中转互相控制。下面这些问题是结构性的，继续打补丁解决不了：

- 所有设备共用一条 WSS，一台设备卡住会拖累其它设备，TCP 上又叠了一层确认和重传。
- 没有服务器就不通。直连只收集局域网地址，建立直连仍依赖中转，中转断开链路就复位。
- 内容在中转上是明文。TLS 在中转终止，只有通讯录和插件授权各自做了端到端加密。
- 模型里只有控制端和被控端，没有节点、硬件能力、服务，接不了 Cindy Friend、摄像头这类设备。
- 传输散成四套（WSS、局域网直连、文件、远程桌面），设备密钥也有四套。

目标：所有用 Cindy 登录的 App 和硬件组成一张端到端加密的网，能互相发现、互相调用，知道对方能做什么；
局域网内不依赖服务器；用户可以用自己部署的中继；能按能力分享给别人；有展示网络拓扑的界面。

## 2. 第 0 阶段结论

**可以继续。** 最关键的假设已被真实代码验证，同时发现了几处要调整的地方（§2.3）。

### 2.1 已验证

| 吞吐 | 同一链路 QUIC 10–11 MiB/s，WSS 形态 8.8 MiB/s（含 base64 开销） |

| 自建中继 | `iroh-relay` 1.4.1 + 回调准入：已加入设备可用、未加入设备被拒；只知道中继地址也能建连，并自动升级到直连 |

### 2.2 尚未验证，不能算通过

- **两台真实设备之间的局域网和公网**：以上全部在同一台 Mac 上完成，局域网测试是本机经网卡发给自己。
- **iOS / Android 真机**：iOS 只验证了编译；Android 未编译，只确认官方有预编译包。系统权限弹窗、前后台行为都没测。
- **手机待机耗电**、**国内三大运营商的 UDP 可达率和打洞成功率**：完全没有数据，这是下一步最大的未知数。
- **经中继的吞吐**、**ACME 证书和 Nginx 部署路径**、**UDP 7842 地址发现**：只用本机开发模式跑通了逻辑。
- **WSS 加密封装回退**：还没有原型。
- 模拟链路是用户态限速程序，TCP 一侧无法注入丢包；两组 QUIC 样本数量也少。这些数字说明方向，不是线上指标。

### 2.3 验证后对方案的调整

| 发现 | 调整 |
| --- | --- |
| 官方 Node 绑定的收发缓冲是 `Array<number>`，回环只有 19.7 MiB/s，慢 17 倍，并且不暴露地址查找、路径选择 | **不直接用官方绑定。** 自建薄 Rust 核心（`agent-net-core`），Mobile 用 Expo 模块，收发走 Buffer 或原生直读磁盘。Desktop 原定用 napi，2026-11-05（第 6 步）改成 WebAssembly：电脑上的加密算法用 Node `crypto`、又不引入第三方 crate，核心只能和 Node 跑在同一个线程，napi 剩下的好处不多，却要手写不安全的原生接口、每个平台各编一份；WebAssembly 所有电脑平台共用一份，不需要预编译流水线，核心出错也写不坏进程内存 |
| `libc` 0.2.190 之后把 `in6_ifreq` 限制为 macOS，`netdev` 在 iOS 编译失败，iroh 1.4.1 同样受影响 | 固定 `libc = 0.2.189`，并跟踪上游修复 |
| iroh 1.2 的核心库已不含 mDNS | 局域网发现自己做：Desktop 用组播信标（已验证），Mobile 用系统服务发现 |

| iroh 会自己找到更优路径并切换（测试时绕过了模拟瓶颈） | 自动选路无需我们实现。“只用我的中继”靠中继列表只放自己的节点实现，不依赖不稳定的路径选择接口 |

## 3. 核心判断：重写传输和身份，不重写业务

现有业务约 5.6 万行（不含测试和 Mobile），近 300 个远程通道，还沉淀了大量故障恢复规则，全部重写一定会丢功能。
所以新建的是传输层、身份层和节点模型，业务继续跑在上面。这也符合 2026-08 审计结论，以及“只更新手机、不更新电脑也必须能用”的硬性要求。

接缝：`DeviceLinkClient` 的 WebSocket 由外部注入（Desktop `device-link/index.ts`、Mobile `DeviceLinkContext.tsx` 的 `createWebSocket`），
中转语义只有约 380 行（`packages/device-link-relay/src/hub.ts`），且不解析业务内容。

**每个节点内嵌一个迷你中转（EdgeHub）。** 现有客户端以为自己还连着中转，实际上每条消息按目标设备走最优路径：

```text
业务层（近 300 个通道、任务同步、远程供应商……）        不改
DeviceLinkClient                                     不改
  │ createWebSocket()  ← 只换这里
EdgeHub：本地应答握手与心跳、合并在线状态、按目标设备选路
  ├─ 新版对端：QUIC（同机 / 局域网 / 打洞 / 中继），UDP 不通时加密封装后走 WSS
  └─ 旧版对端：原有 WSS 中转，界面标注未加密
```

服务器断开时 EdgeHub 仍在本机应答，已认识的局域网设备继续互通，业务层无感。

原来由中转执行的检查移到接收节点：来源取自已认证连接，远控开关由目标节点裁决。这两项在第 0 阶段已验证。

## 4. 关键决定

| 问题 | 决定 | 原因 |
| --- | --- | --- |
| 协议 | 自研可靠 UDP，蒸馏自 KCP | 用户裁决，见 §0 |
| 不用什么 | iroh、noq、`node:quic`、libp2p、Tailscale 类、把 WebRTC 铺满 | 用户要求不用第三方；其余见 §2 的验证 |
| 实现形态 | Rust 纯状态机 + C 接口；电脑端编成 WebAssembly 由 Node 驱动 | 见 §0、§2.3 |
| 中继 | 官方中继 + 用户自建中继 | 见 §6 |
| UDP 被封 | 走 TCP 443 中继或加密 WSS | 据 QUIC 工作组引用的测量，约 3–5% 的网络封 UDP。这种网络不会比现在差，但也不会更快 |
| 证明同账号 | 节点密钥 + 服务器签发的证书 + 签名名册；自建模式用主人密钥签证书 | 登录即互联，离线可验证。对服务器的信任程度与现在相同，并固定公钥，密钥变化直接拒绝 |
| 离线撤权 | 证书默认 14 天有效 | 这是撤权窗口上限，在线时立即生效 |
| 远程桌面画面 | 继续用 WebRTC | 编解码、抖动、iOS 画中画都已成熟，只把信令换到 agent-net |
| 分享 | 按能力勾选（用户已确认） | 远程桌面、文件、Shell 默认不可分享 |
| 硬件 | 不绑定具体硬件（用户已确认） | 一份协议规范 + 分级节点 |

## 5. 端到端加密（硬性要求）

两个 agent-net 节点之间，任何路径上的内容都只有两端能解密，中继和服务器只看得到路由信息。一旦知道对端支持 agent-net，就拒绝明文通信。

- **UDP 路径**：第 4 步已在核心实现（`SecureConnection`），尚未接入产品。Noise IK 握手，身份是节点公钥，具备前向保密；
  完整包号作 AEAD nonce，包头参与认证；每 2^20 个包换一次密钥；响应方确认对端在线之前只回一个和请求一样长的回复，不放大流量。不做 0-RTT。
  第一条消息附带的数据没有前向保密、可能被重放，上层不在里面放秘密；需要防重放的请求由上层在附带数据里放时间戳检查。
- **WSS 回退路径**：EdgeHub 把内容封装后再发（临时 X25519 + HKDF + AES-256-GCM，与 `plugin-oauth/box.ts`、`contacts-sync/crypto.ts` 同构）。
  两种中转都不解析内容，官方中转和已部署的自建中转都不用升级。封装在原生核心里完成，手机不用纯 JS 做 AES。
- 中继能看到谁和谁通信、时间和流量大小，这部分元数据无法隐藏。

现有明文要逐个处理：

| 通道 | 现状 | 处理 | 阶段 |
| --- | --- | --- | --- |
| 普通业务消息 | 中转可读 | QUIC 或加密封装 | 1 |
| 远程桌面、文件的 WebRTC | 内容已 DTLS 加密，指纹经中转传递 | 信令走加密通道后自然解决 | 1 |
| OSS 兜底（文件、附件、媒体） | 媒体上传代码里没有客户端加密 | 上传前客户端加密，密钥走加密通道 | 2 |
| 手机推送正文 | 经 APNs/FCM | 新增只推“有新消息”的模式，内容回 App 后再取 | 3 |
| 供应商分享、共享任务 | 中转逐帧授权，内容可读 | 改为节点授权后加密，此前如实标注 | 5 |
| 旧版对端 | 不支持 | 拓扑图标注“未加密（旧版）”，提供“只允许加密连接”开关，默认关闭以保证旧端可用 | 1 |

## 6. 用户自建中继（一等能力）

现有自建中转（`packages/device-link-relay`）完整保留，并成为 agent-net 的正式组成部分。

- **一个内核不变。** 现有内核继续是唯一入口，负责加入、主人审批、设备证书、Nginx、ACME 和升级，中继能力直接实现在内核里，不再托管外部程序。
  `/relay/info` 增加可选能力 `agent-net-relay-v1`，旧客户端忽略。
- **两种运行方式都支持。** 方式 A（公网服务器）和方式 B（在这台 Cindy 上）共用同一份内核。一键部署时检测 UDP 端口（协助打洞，没放通时仍可走 443 中继）。
- **只有已加入的设备能用。** 准入和移除由内核直接判断，移除设备时立即断开已有连接。
- **多台中继。** 沿用现有多服务器能力，自动选最快的，一台挂了自动切。
- **“只用我的中继”开关。** 打开后设备间数据不经官方中继；账号登录、手机推送等账号服务仍走官方，与现在一样。
- **自建模式起点更高。** 主人证书链已存在，第 1 阶段就能做完整验证。设备签名密钥为节点公钥签一份绑定即可。
- **已部署的旧版本不会被打断。** 新客户端连旧版自建中转时，局域网直连和加密 WSS 照常工作，只是没有打洞。
- 第 5 阶段授权移到节点后，自建模式下的供应商分享有望可行，这是 [`self-hosted-relay-plan.md`](self-hosted-relay-plan.md) §14 目前卡住的点。

## 7. 节点与能力

模型从“设备”扩展为“账号 → 设备 → 节点”，每个 App 实例是一个节点。节点发布能力清单：硬件、服务及版本、电量和忙碌状态。Agent 也能查询和调用。

| 等级 | 典型硬件 | 接入方式 | 能力 |
| --- | --- | --- | --- |
| 完整节点 | 电脑、手机、Cindy Friend | 内嵌核心库 | 全部路径和服务 |
| 轻节点 | 带 Linux 的摄像头、音箱、NAS | 单文件常驻程序 + 本地接口，任何语言都能接 | 全部路径，服务自行声明 |
| 微节点 | ESP32 | 精简实现（iroh 文档称有 PSRAM 才能走中继） | 局域网优先 |
| 桥接子节点 | 蓝牙、USB、Matter 等跑不了 QUIC 的设备 | 由附近节点代理，显示为它的子节点 | 权限挂在桥接节点上 |

同机 App 通过本机登记目录互相发现，走回环 QUIC，证书校验不省略。iOS 的 App 在后台被挂起，同机互访只在桌面和部分 Android 场景成立。
有屏设备正常登录，无屏设备用手机扫码或设备码认领。

## 8. 现有功能对照

| 功能 | 新路径 | 改动 |
| --- | --- | --- |
| 远程控制、任务同步、手机端全部页面 | 原帧经 EdgeHub | 不改 |
| 远程供应商、供应商组、远端 Worker、跨机定时任务、任务迁移、伙伴跨机 | 同上 | 不改 |

## 9. 拓扑界面

已落地（2026-11-06，Desktop「远程连接」页「新版连接」开关后，默认关）：这台电脑在中间，其它设备按怎么连到它分在左右两列，线是曲线，经中转的设备经过中转站，没建链和离线是点线，直段靠图块一端标往返延迟；图块里是单色系统标志，电脑方块、手机竖条，静止时全图灰阶；这台电脑和某台设备真有业务消息时，那条线变成「在用」色，彗星按节拍飞过去、撞上时图块弹一下。点图块看型号、系统、版本、状态、路径、消息、延迟、最后在线与谁在控制本机。颜色登记在 `DESIGN.md` §2，页面规格在 §4，消息流动动效在 §14.4。现在画的是 V1 device-link 的真实数据（本机 IPC `device-link:get-peer-links`），V2 传输接入后换数据源不换页面。

- 不画没有的数据：流量只画「最近几秒有没有、往哪边」，不画大小；丢包、第三方链路和 30 天记录等 V2 传输提供后再加。
- Desktop 用 SVG 线 + HTML 图块，不加新依赖；Mobile 尚未实现，届时用同一份数据竖向布局。

**已裁决（2026-11-06）：** 交互稿默认的立体盘面与缓慢自转不做。同日用户看过后要求在操作某台机器时线上要有消息流动、要有颜色和节奏，于是只为真实流量登记了一个动效例外（`DESIGN.md` §14.4「Remote connection message packets」），并改为灰阶 + 系统图标、组内按名字排。

## 10. 分阶段

每个阶段单独审批。

传输层的步骤见 §0。下面的阶段划分写于 iroh 路线，其中的产品内容不变，凡提到 iroh 的传输细节以 §0 为准。

**第 0 阶段：验证（已完成）。** 见 §2。

**第 1 阶段：局域网 + 全程加密，默认关闭（第一个可用版本）**

- 新建 `packages/agent-net-protocol`、`packages/agent-net`（EdgeHub、路径状态、加密封装），传输用 `packages/agent-net-core`。
- Desktop 把网络核心放进 `utilityProcess`，崩溃不影响主进程。Mobile 新增原生模块 `cindy-agent-net`，加本地网络权限声明，**这是冷更**。
- 节点公钥经现有已认证的中转交换并固定，**这一阶段不改服务端**。自建模式直接用主人证书。
- 处理离线建连：Desktop `getToken` 在 refresh 失败时会跳过建连，要让 EdgeHub 绕过。
- 设置里加实验开关，关闭时 `createWebSocket` 完全走原路径。
- 拓扑页第一版：本机视角的真实数据。
- 这一阶段公网流量仍走 WSS，已经加密，但还不会更快。

**第 2 阶段：公网直连与更快的传输**

- 部署官方中继（国内、海外），自建中转同步上线 `agent-net-relay-v1`，含“只用我的中继”。
- 按类别分流（控制 / 交互 / 批量）；文件换 QUIC 字节流，原生层直接读写磁盘；OSS 兜底改为客户端加密。
- 对新版对端停用 `direct-link-v1`，去掉重复的可靠层。

**第 3 阶段：正式身份（需要改服务端）。** 证书签发、名册、撤销，把四套设备密钥收拢到这里；手机推送隐私模式。

**第 4 阶段：全硬件接入。** 能力清单、节点分级、硬件服务（摄像头、麦克风、显示、算力、传感器）、同机发现、Agent 工具、各语言 SDK 和一致性测试。
Agent 工具按 `product-rules/agent-user-parity.md` 执行；摄像头、麦克风默认关闭，逐项开启。

**第 5 阶段：网络分享（需要改服务端）。** 能力授权：谁、哪些节点、哪些服务、配额、期限。一次性邀请 + 双方确认，沿用 30 分钟离线授权上限，分享者随时可撤销。
授权由被调用的节点执行，跨账号流量也改为端到端加密；受邀者可经分享者的自建中继接入。现有供应商分享和共享任务迁移为预设。

**第 6 阶段：转为默认。** 灰度后默认开启。v1 中转长期保留给旧版客户端，不删除。

## 11. 第 1 阶段的进入条件

开工第 1 阶段前要先拿到下面的实测，全部需要真机：

1. 两台真实设备之间的局域网建连、吞吐，并和现有文件通道对比。
2. 真实断外网时局域网互通。
3. iOS / Android 真机：本地网络权限、发现、前后台。
4. 手机待机耗电不明显差于现有 WSS。
5. 国内三大运营商和海外的 UDP 可达、打洞成功率、回退耗时。需要先部署至少一个测试中继。

## 12. 不变的安全边界

- 被控端继续逐条检查远控开关、撤权名单和通道白名单。消息来源取自已认证的连接，不信任帧内字段。
- 私钥只存系统安全存储，地址和凭证不进日志。
- 单个对端的故障只影响它自己；上游中转断开不影响已建立的直连。

## 13. 验证方法

- 让现有 `scripts/device-link/interop.test.ts`、`reconnect.test.ts` 和 `pnpm --filter @cindy/device-link-relay run interop` 同时跑在 EdgeHub 上，用同一套断言证明功能没丢。
- 加密断言：在测试中转上记录所有经过的帧，断言新版节点之间看不到任何业务明文。
- 自建中转：新客户端配旧版中转、移除设备后失去中继权限、多台中继切换、“只用我的中继”时官方中继零流量。
- 故障半径：至少两个控制端共享一台被控端，其中一个静默，另一个不受影响。
- 混版本矩阵：新对新、新对旧、旧对新；只更新手机时必须可用。
- 故障注入：丢包、UDP 全封、中转宕机、断外网。
- 实机矩阵：macOS / Windows / iOS / Android，蜂窝与 Wi-Fi 切换，AP 隔离，国内三大运营商。
- 用数字对比 v1：建连时间、往返延迟 p50/p95、文件吞吐、恢复时间。没测到的项目如实标注，模拟通过不算实机通过。
- 传输核心三层验证，缺一不可：确定性模拟器（种子矩阵、变异检验）、回环 UDP 加真实时钟（`netperf local`）、真实公网（`netperf`）。
  公网对比必须让各协议轮流跑，尾部延迟至少 30 轮才能下结论。2026-10-30 的公网测试推翻过一次模拟器的模型：
  云主机的带宽上限是令牌桶，模拟器原来没有这种链路，导致发送量是送达量的 4 倍。

## 14. 主要风险与已知限制

- **最大的工程风险**：EdgeHub 会遮住客户端对真实连接的判断（心跳、重连、网络变化通知），这些语义要逐条保留，第 1 阶段重点测这里。第 0 阶段的原型还没有合并上游 WSS，混合场景尚未验证。
- **“不靠服务器”的边界**：首次登录、手机推送唤醒都仍需要服务器。iOS 进入后台后连接会被挂起，手机端的离线互通只在前台成立。
- **局域网发现受网络限制**：访客 Wi-Fi、AP 隔离、部分企业网会挡组播。
- **会出现系统弹窗**：iOS 本地网络权限、macOS / Windows 防火墙。
- **打洞成功率**：完全自研，国内网络的实际数字要到第 7 步才知道。云安全组默认挡入站 UDP，2026-10-30 的公网测试是靠服务器先发包打通的，同账号的两端都要能配合。
- **自研的长期成本**：拥塞控制、打洞、加密握手没有上游替我们修 bug，线上问题都要自己排查。
- **Rust 流水线**：要为 macOS、Windows、Linux、iOS、Android 产出预编译包，这是现有仓库没有的工程投入。
