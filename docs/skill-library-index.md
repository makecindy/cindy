# 本地技能库：索引、按任务发现与语义检索

这项能力解决技能逐渐积累之后的发现成本：Agent 开始工作时知道去哪里找方法，
但不必先接收整库名称和简介。一个共享目录可以服务多个任务、伙伴及引擎；技能作者仍维护原始文件。

实现位于 [`packages/skill-index`](../packages/skill-index/README.md)。该包提供索引基础设施和可直接使用的 CLI，
通过生成的标准 Skill 接入 Cindy。安装、向量配置与使用命令统一见该包 README。

## 方法：存放、发现、检索、读取分开

1. **一份正文。** Skill、脚本、素材、参考文档保留在原目录。索引引用来源，不复制另一份正文。
2. **一个轻入口。** 自动发现目录中只放库的导航 Skill。目录与检索数据位于本地索引，库规模增长不扩张这个入口。
3. **按问题查找。** 以用户当前目标搜索；名称、别名和标签保留精确命中，向量补充同义表达及跨领域方法联想。
4. **选中才读取。** 查询返回少量候选。Agent 读完整 SKILL.md 后按任务展开相关 references，并以原始资源目录执行方法。
5. **更新在使用之外。** `sync` 更新目录与变化的向量。任务搜索读取已有索引，不重扫库、不启动全量嵌入。

例如，“覆盖顺序场”技能可能源自游戏图形学，却也能用于视频中的受潮显字。
其用途描述可以同时表达这些场景；检索按问题选择方法，目录分类不构成检索过滤条件。

## 数据流与模块

```text
原始技能目录 ── discovery ── 元数据目录 + 内容 hash
                                  │
                        可选 embedding adapter
                                  │
                             本地向量缓存
                                  │
任务描述 ── 关键词 + 向量排名融合 ── 少量候选
                                  │
                             按 id 读取原文
                                  │
                        原目录 references/scripts/assets
```

| 模块 | 职责 |
| --- | --- |
| `src/index.ts` | 描述符同步、向量增量构建、查询、快照与按 id 定位 |
| `src/ranking.ts` | Unicode 规范化、中英文词项、名称/别名优先、余弦相似度与排名融合 |
| `src/embedding.ts` | 兼容 API 配置、顺序分批、query/document 共用的普通 embedding 请求 |
| `src/library.ts` | 显式登记目录的发现、原文读取、JSON 快照、固定大小的发现 Skill |
| `src/cli.ts` / `src/bin.ts` | 用户命令与可独立运行的自包含 Node 入口 |

索引核心接收 `SkillEntry[]`，不认识账号、会话或 Electron。Cindy 宿主可以把现有扫描器的
可用目录投影为这些条目；CLI 则以用户明确登记的目录作为来源。每个消费者决定自己的来源范围。

## 检索与增量维护

关键词排名使用名称、说明、别名与标签，精确名称/别名优先。中文采用词项与双字片段，
英文按词边界匹配。语义搜索使用余弦相似度，随后以 reciprocal rank fusion 合并两个候选序列。
分数用于候选排序，Agent 根据候选用途选择实际技能。

检索文本由名称、简介、别名与标签组成。路径和来源标识不进入 embedding 语料，正文保留在原处。
每条记录的检索文本 hash 决定是否需要重新嵌入：新增项生成、变化项更新、相同项复用、删除项移出索引。
API endpoint、model、dimensions 和请求协议共同标识一代向量；改变它们后重新构建该代索引。
快照还保存 API 返回的实际模型名，增量构建和查询核对该型号；服务端别名切换型号后，使用
`sync --rebuild` 全量重建。每次构建发布核对内存代次，防止交错完成的模型构建混合向量。
`SkillEmbeddingAdapter.embed()` 返回 `{ vectors, modelUsed }`；跨批次的实际型号也必须一致。

CLI 的配置读改写与索引发布共用每库写锁，两个进程同时更新时，后进入者收到明确忙碌错误。
查询继续读取已发布的索引。供应商 API 前缀按原路径使用，既可连接 `/v1`，也可直接连接智谱的 `/api/paas/v4`。

当前存储是单个本地 JSON 快照，适合个人与团队技能目录。`SkillIndex` 不绑定存储实现，
宿主可用自己的持久层保存 `snapshot()`，并从中恢复；向量请求也通过可注入接口提供。
这使目录来源、API 服务和运行引擎可以分别演进。

## 在 Cindy 中使用

生成的发现 Skill 通过 Cindy 现有共享 Skill 目录被发现，指向构建后的 Node CLI 与库数据位置。
用户新建任务时，入口要求先以本次目标检索，收到候选后读取所需原文；任务转入另一工序时再查询。
显式点名某项技能时也可以直接以名称搜索，精确命中会排在前面。

这次交付的是独立索引区块和标准 Skill 消费者。它没有修改 maker-core 全局 system prompt、
引擎默认扫描策略、已有 Skill 的启用状态或市场搜索语义。库正文应存放在自动扫描根之外，
只安装发现入口；该入口不会替用户移动已有目录或禁用已有技能。

普通任务、项目与伙伴均可使用这个发现 Skill。SSH 或另一台电脑执行任务时，在执行端准备
对应库与可执行文件；库中的路径属于执行端。该版本不通过 device-link 自动复制或查询另一台机器的索引。

## 后续宿主接入位置

宿主直接消费同一索引时，可以继续沿现有机制接入：

- `skillhub/skillListProjection.ts` 已提供来源身份和跨引擎去重，可作为 `SkillEntry` 来源。
- `maker-ipc/botSkillRuntimeProjection.ts` 已有伙伴大库的单入口投影，可复用同一索引服务进行检索。
- `EmbeddingService` 可适配 `SkillEmbeddingAdapter`，由宿主已有供应商设置提供 endpoint、模型与凭据。
- 首轮召回结果应进入当前轮资料；固定系统前缀只保留稳定发现入口，不拼入完整目录或每轮变化的检索结果。

本包无需替换这些消费者。它提供一个共同的实现入口，使后续宿主接入可以共享排名、增量维护和按需读取，
而不是给每个引擎、每个伙伴另建一套索引。

## 观察效果

使用同一套任务表达比较关键词与混合检索，记录命中的技能和排名；特别包含未直接出现技能名称的同义句。
另比较不同库规模下生成的发现入口：入口只含固定说明、CLI 路径及库位置，条目内容不进入该文件。
本包的行为测试覆盖这两个机制及原文资源使用，真实模型的技能选择效果可在实际任务中进一步评估。
