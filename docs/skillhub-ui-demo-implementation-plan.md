# SkillHub：将现有页面改成 HTML Demo 样式的执行方案

编写日期：2026-10-13。适用仓库：Cindy 客户端；当前分支 cindy/epic-archimedes。

## 1. 目标与结论

以 artifacts/skillhub/SkillHub-副标题上移原型.html 为视觉参考，调整正式 SkillHub 页面；正式页面继续消费现有接口和本地扫描结果。HTML 的示例 Skill、作者、下载量、安装状态、分类和模拟左栏不导入生产代码。

可以直接实施展示层改版，不必修改服务端、数据结构或本地文件。这里的“不改数据”包括不改请求参数、筛选关系、分页顺序、安装状态计算及操作回调，而不只是“不写数据库”。不能承诺零风险；以下通过限定文件范围、固定输入比对和交互回归把风险收敛。

用户所指的 tab 是截图中的分类按钮：全部、集成、自动化、研究、开发、效率、沟通、创意、知识、智能体、运维、安全、金融、生活方式。这是截图标签记录，不是本次接口实测清单；实现必须使用当前接口下发的名称、slug 和顺序，不能照抄这串文字硬编码。

## 2. 接口到底下发多少条

**当前实时总数尚未取得，不应填写估计值。** 本轮核对了客户端代码和宿主工具能力；可用 search_skills 要求非空 query，没有无筛选目录或分类统计入口。没有为了取数读取账号凭证，也没有使用关键词结果冒充全量。

| 数字/字段 | 含义 | 能否当作总数 |
| --- | --- | --- |
| 旧快照公开 28 条、团队 23 条 | q=skill 的历史搜索结果 | 不能 |
| 旧快照本地 15 个 SKILL.md | 部分用户目录文件扫描 | 不能代表云端或完整本地目录 |
| 默认 pageSize=24 | marketService 的默认单次分页大小；实际请求可通过 limit 指定 | 不能 |
| 原始列表响应 total | 当前身份、scope、搜索和分类条件下的服务端匹配总数 | 可以，但必须记录条件和时间 |
| items.length | 单次响应条数 | 不能 |
| 分类 skillCount | 分类接口统计值 | 不能直接相加当作唯一 Skill 总数 |

源码依据：[marketService.ts](../apps/desktop/src/main/skillhub/marketService.ts) 的 listMarket/listCategories。

- 列表 GET /api/skills-hub/skills；参数包含 scope、q、category、sort、order、page、pageSize。服务端返回 items 与 total。
- main 用 total 计算 nextCursor，向 renderer 返回 items/nextCursor，当前这层没有直接透传 total。不要为 UI 换皮顺手增加这个字段。
- 分类 GET /api/skills-hub/categories?scope=market 或 scope=team；返回 slug/name/skillCount/mySkillCount/children 等。
- listCategories 中 totalCount 是分类 count 的求和，不能据此证明去重总数；源码还提示旧服务端分类计数可能存在 scope 差异。
- 本地列表来自现有 scan，与云端目录数量是不同口径。

### 实时数量的核验步骤（只读，不阻塞视觉实现）

1. 在运行 Cindy 的相同账号/身份下打开目标目录，记录版本、scope、时间，清空搜索并选“全部”。通过现有调试链路查看原始列表响应，不拷贝令牌、Cookie 或账号授权文件。Electron 主进程请求不一定出现在 renderer 的 Network 面板，不能把“面板没请求”当作接口不存在。
2. 记录第一份原始响应的 total、items.length、page/pageSize；依照现有 nextCursor 加载到结束。以现有 catalog 身份键去重核对，不能仅按展示名称去重。若原始 total 不可观察，报告完整分页去重数，并说明不是直接读取 total。
3. 同一 scope 读取实际分类名称与 slug，逐类走现有分类筛选/分页，登记“分类 tab → slug → 匹配数 → Skill 身份清单”。不能靠标题猜分类，也不能只在已加载首页里做本地过滤。
4. “全部”不发送 category；分类点击发送原 slug。类别之间允许重复出现同一个 Skill，不要求互斥；以服务端筛选结果作为成员对应关系。
5. 团队目录单独核验，不能与公开相加当作当前页面总数。数据若在采集期间变化，标记时间漂移，重新核对受影响范围。
6. 若当前环境仍无获准的全量读取入口，保留“待实测”，不新增后端接口、不修改认证链路来完成此项。

记录模板：

| 采集时间/身份范围 | scope | tab 名称 | category slug | q/sort | 响应 total | 分页终止/去重数 | Skill 身份清单 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 待实测 | market | 全部 | 不传 | 空搜索/现有排序 | 待实测 | 待实测 | 待实测 |

## 3. 改动边界

现有工作区已经包含未提交的布局、下载量语义、排序恢复和测试改动。以执行开始时工作区为基线，保留这些改动；不能以 HEAD 直接覆盖文件，也不能把之前的逻辑修复算作本轮纯样式改动。

| 范围 | 本轮允许的变化 |
| --- | --- |
| components/HomeMarketCard.tsx | JSX 展示顺序、局部布局 class、文字截断和对齐；原 props 和事件不变 |
| SkillhubHomeView.tsx | 仅目标卡片容器和骨架的局部样式；优先沿用当前栅格 |
| components/SkillTagList.tsx | 必要时调整灰色标签样式；先确认共享调用方，优先用已有 className 限定首页 |
| components/SkillIcon.tsx | 仅必要的外观适配；优先卡片外层控制尺寸，不改图标解析优先级 |
| components/SkillCategoryFilterBar.tsx、SkillSortMenu.tsx | 仅在 Demo 存在明确差异时改局部样式，保留现有控件与键盘行为 |
| 对应 renderer 测试 | 增补或调整展示/行为回归；保留原断言覆盖 |

表中 components 路径均相对于 apps/desktop/src/renderer/features/skillhub/。

**本轮不改：** main/skillhub、preload、vite-env.d.ts、hooks/useMarketList.ts、hooks/useSkillhub.ts、hooks/useSkillhubHomeNavigation.ts、分类解析、安装关联、路由状态、共享协议、数据库、服务端、扫描根目录、依赖/锁文件及用户 SKILL.md。

**不扩大页面范围：** 先完成首页目标卡片；更多/管理页 MarketCard、本地 LocalGroup、详情、发布管理和全局侧栏维持现有行为。若共享组件影响这些页面，隔离本轮样式，不能靠删按钮或统一数据模型迁就 Demo。

## 4. 页面与数据逐项对应

| Demo 中的模块 | 生产来源 | 本轮展示规则 |
| --- | --- | --- |
| 分类 tab | useCategoryList → listCategories，slug/name | 沿用实际接口列表和选中回调；按 2026-10-14 确认方案移除溢出箭头，保留横向滚动 |
| 分类下的卡片 | useMarketList 当前返回结果 | 不重新分组、过滤、排序，不裁成 Demo 的 8 条 |
| 标题 | displayName，缺失回退 name | 头像右侧，长标题截断但可查看完整名称 |
| 副标题 | description | 标题下方，最多两行；无内容隐藏 |
| 灰色标签 | 现有 tags 投影 | 放卡片底部；不把当前选中 tab 强行写成卡片 tag |
| 作者/发布者 | skillPublisherLabel | 底部标签旁，长内容截断，不编造作者 |
| 下载量 | downloads + 现有 hasDownloadCount | 右下，与标签垂直居中对齐；真实 0 保留，缺失隐藏 |
| 已安装/更新 | MarketInstallStatus，installedLocally/updateAvailable | 右侧下载量上方；保留状态优先级和更新行为 |
| 头像 | SkillIcon 当前 url/categories/tags/frontmatter 解析 | 48px 容器、24px 占位图形作为 Demo 对齐目标；不根据示例标题赋分类 |
| 排序 | 当前 sort 与 SkillSortMenu | 保留下载量/更新时间的真实排序回调和导航恢复 |
| 加载更多/空态/错误 | 当前 loading/hasMore/error 等 | 全部保留；只调整骨架几何匹配 |
| 左侧导航 | Cindy 现有页面外壳 | 继续真实侧栏，不嵌入 HTML 模拟任务列表 |

头像优先保留有效 icon URL，默认图/加载失败沿用当前分类图标回退，无可识别分类沿用 Package。生产已使用 lucide-react；不复制 Demo 的按标题 MutationObserver 替换脚本，也不把服务端分类改成 Demo 的五类。若希望全部强制改成 Lucide 占位图，属于另一个明确的视觉规则变更，本轮不隐含实施。

## 5. 收敛执行步骤

### 第一步：固定开始时状态与视觉基准

- 记录 git status --short 与当前 diff，保留原有未提交内容；记录所选 Demo 的文件哈希、浏览器视口和截图。
- 对照当前 HomeMarketCard，列出尚未达到 Demo 的具体间距/排列差异；已完成的“描述上移、底部标签、右下下载”不重写。
- 阅读 DESIGN.md 的 §2/§3/§5/§10，以及 electron-security-and-process-boundaries.md；启动 Desktop 前读 desktop-development.md。
- 产出：短差异清单。没有视觉差异的文件不动。

### 第二步：只调整单卡的展示结构

- 保留传入 skill 对象和原有事件处理；仅移动显示节点或修改布局 class。
- 头像左置；内容区标题、副标题、底部标签/作者自上而下；下载量底部靠右，安装状态位于其上方。
- 用 flex/grid 的同一底行保证标签与下载对齐；不用固定屏幕坐标。描述为空、标签为空、超长作者时也保持稳定。
- 保留详情点击、更新按钮阻止冒泡、loading/disabled、键盘焦点和可访问名称。
- 产出：可在真实 props 下渲染的首页卡片，不改任何数据模型。

### 第三步：校准栅格、工具栏和主题

- 优先复用 lib/cardLayout.ts 已引用的插件卡片栅格；保持宽屏紧凑双列和现有窄窗适配，不修改插件页面全局样式。
- 卡片采用内容自适应高度，避免固定高度裁掉描述或按钮；骨架匹配最终卡片尺寸。
- 分类与排序控件只改外观，保留同一组件实例、值、选项、回调及作用域。
- 使用现有 surface/text/border/focus 语义 token；遵循 DESIGN.md 的字号、圆角及 Light/Dark 要求，不从 Demo 拷贝硬编码颜色。
- 产出：同一真实页面内的完整视觉效果。

### 第四步：证明数据与交互没变

- 同一冻结接口响应/本地输入，改动前后比对列表身份键与顺序完全一致。
- 对每个实际分类，确认点击提交原 slug；“全部”不传 category。分类不能变成前端硬编码数组。
- 搜索、两种排序、加载更多仍走原回调和参数；不同 scope 的同名 Skill 不混淆。
- 详情返回、浏览器 Back/Forward、Settings 嵌入返回保留原搜索/分类/排序。
- 已安装、可更新、更新中、缺下载量、有效 0、无标签、超长文本、图标失败均检查；更新点击不得触发详情。
- 产出：通过项、失败项和未验证项分开的记录。有失败先修本轮展示层；若根因需要改禁改范围，单独记录逻辑缺陷，停止扩大本轮补丁。

### 第五步：交付并停止扩展

- 输出最终局部 diff 与 Light/Dark 截图，标明是实际客户端或组件预览；未目检的模式如实注明。
- HTML 如需再次交付，基于相同展示组件生成预览，并标注真实快照/测试数据来源；它不能成为正式数据源。
- 若共享成员不能打开本地文件，使用当前任务支持的附件交付；附件入口不可用时明确告知，不能将本地链接称为共享链接。
- 达到下方验收条件即结束，不顺带重构 hooks、修复历史业务问题、提交或推送。
