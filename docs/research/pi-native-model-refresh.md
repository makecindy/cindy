# Pi 原生模型刷新与会话连续性

## 问题与采用的方向

已有任务跨来源选模型被拒绝，源于 Cindy 外层将来源变化一律判成进程替换，
而窗口检查又禁止这类替换。只删除拒绝条件会恢复换模型，但仍会丢掉 Pi 进程内状态。
此外，过去通过 `switch_session` 重读压缩配置，即使不退出进程，也会重建会话和扩展。

本次沿用 Pi 原生模型选择、provider 注册和压缩机制：普通切模保留当前会话，
目录下发与凭据变化先进入 Pi，再选择目标模型；容量不足走 Cindy 已有的目标窗口
保护和上下文接续。不能把重新打开 Pi 会话当作普通配置刷新。

对应报告：[跨来源选择被拒绝](https://github.com/makecindy/cindy/issues/4486)。
其建议中的关闭后懒创建不是本次采用的默认方案。

## Pi 配套改动与发布依赖

[配套补丁](pi-native-model-refresh.patch) 基于 Pi
`1b347794e2a630e4359f2584f4eea388145d0ddf`，新增两个小范围原生 RPC：

- `refresh_models`：离线重读模型配置，不替换当前模型描述、扩展实例或排队输入。
  返回的 `aborted` 和 provider `errors` 必须同时检查；成功后显式 `set_model`
  才应用目标描述，包括 provider/model ID 没变的情况。
- `set_compaction_reserve_tokens`：调整当前会话的压缩保留量，所有既有压缩入口
  读取同一有效值；`null` 恢复配置值。不会落盘或触发会话重载。

该补丁是供评审与上游提交使用的源码制品，**不被 Cindy 构建自动应用**。
`tools/pi/latest.json` 仍为 v0.85.1，没有改 pin、下载或替换托管 runtime。
因此本分支不代表现有安装版本已具备新增接口，也不能单独作为完整修复发布。
配套 Pi 版本发布、托管 runtime 更新和实际平台验收须分别完成。

旧 Pi 可以直接完成的选择继续使用原生 `set_model`；需要新接口时，先探测其支持，
在改变目录、凭据或模型前报错，保留原会话。不能用 `switch_session`、`/reload`
或自动关闭来掩盖接口缺失。

2026-09-30 查询时，上游贡献规则要求维护者先给予 `lgtm`，当前提交账号未在批准
名册中；配套改动已本地实现并验证，尚未向上游提交 PR。规则见
[Pi CONTRIBUTING.md](https://github.com/earendil-works/pi/blob/1b347794e2a630e4359f2584f4eea388145d0ddf/CONTRIBUTING.md)。

## 哪些动作需要替换状态

| 情况 | 本次处理 | 是否重开 Pi |
| --- | --- | --- |
| 已加载的模型或供应商之间切换 | 原生选择，核实实际模型与窗口 | 否 |
| Cindy 新增模型、同名模型资料变化 | 刷新当前目录，重新应用目标模型 | 否，需配套接口 |
| 新增供应商或凭据更新 | 私有交接，更新 Cindy 管理的 provider 注册 | 否，需配套接口 |
| 压缩预算变化 | 修改当前会话保留量 | 否，需配套接口 |
| 内容已接近目标小窗口上限 | Cindy 既有目标窗口保护与有交接内容的接续 | 可能；这是容量接续，不是选来源的固定步骤 |
| 回合正在执行 | 等既有安全边界，再运行同一选择事务 | 不为选择中断回合 |
| Pi 已退出、可执行版本或不可热更的启动条件变化 | 按既有生命周期恢复或显式更新 | 需要新进程；不属于普通模型切换 |
| 发生部分应用且无法确认实际路由 | 明确失败并停止不确定的运行实例，禁止错误来源继续接收内容 | 故障处理，不能假报无损切换 |

同一任务保存的聊天记录、Pi 原生会话及扩展内存是不同层次。保留聊天记录不等于
重开 Pi 没有损失。本机 Gateway 代理每次请求读取当前 key；启动占位 key 不是
必须重启的理由。SSH 则需另外维护远端凭据和按需代理转发。

## 实现边界

模型权威仍为 Cindy 统一目录。运行中的 Pi 使用最新可选清单枚举新增 ID，再按来源
取得具体描述；不能只更新选择器，或从启动时模型数组推断实时可用模型。
私有模型文件与设置文件需要回滚时，恢复原字节，不用已经变化的新目录重新生成旧状态。

凭据不放进 prompt、历史或日志。宿主仅对当前实例及本次随机 nonce 返回受限的
凭据快照，收到对应完成回执才继续。只替换 Cindy 自己管理的原生适配器；用户其它扩展
不被卸载。新启动子任务同步已应用的目录、能力与独立来源授权；已运行子任务保持自身身份。

桌面本机、device-link 远控、手机、IM 和定时任务的选择必须走同一宿主容量事务。定时任务
在捕获运行实例、等待结果和拼接交接内容前完成容量准备；排队派发也经过同一发送锁。
延后选择在
回合结束后仍经过该事务；旧选择的迟到回执不能覆盖新选择或新账号。失败通知独立于成功
通知，使用固定原因码，不把原始错误或凭据传给控制端。

## 验证证据与限制

Pi 补丁的 3 个定向测试文件共 22 个用例通过，覆盖真实 JSONL RPC handler、
RPC client、运行中的压缩触发阈值、参数校验、同 ID 模型重新选择及队列/扩展保留。
定向类型检查与改动文件格式检查通过。没有运行 Pi 整仓构建或全量测试。

另将 Cindy 实际生成的原生适配器和私有命令载入真实 Pi 测试 harness，用隔离临时目录、
假模型和假凭据验证新增供应商、同 ID 更新、nonce 回执及扩展实例/排队内容保留，1 个整合
用例通过。没有调用付费模型或读取个人授权。这不是正在运行的 Cindy 产品验收。

Cindy 核心模型路由与压缩预算的两个定向文件共 144 个用例通过，新增私有桥接的
3 个用例通过。宿主与既有容量事务的 6 个文件 323 例通过，收尾后相关 4 个文件
156 例通过（两组有重叠，不相加）；调度直发/排队的 2 个文件 156 例通过，包含冷 Pi
历史恢复、跨来源热切、准备失败停止发送及结果监听顺序。各消费入口的定向验证见本 PR 的验证记录。未启动 Desktop DEV、模拟器或现有
Pi 任务；未完成 Windows、SSH 主机或桌面/手机双设备实机验收。源码与隔离验证通过，
不能替代配套 runtime 发布后各端的实际选择与容量接续验收。
