01定位与范围

同一个「官方飞书」入口背后可以是两种飞书应用，对成员来说用法完全一样，区别只在于应用由谁提供。

第一期组织应用
  • 企业在自己的飞书里建一个企业自建应用（如「Cindy」），由组织所有者或管理员在 Cindy 组织后台填入
  • 该组织的成员在 Cindy 设置里看到「飞书 · 组织名」入口
  • 机器人名字、头像、可用范围、是否对外共享，都由企业在飞书后台自己决定
  • 第一个用户就是我们自己公司：先在公司的飞书企业里配置
审批通过后Cindy 全局应用
  • Cindy 自己申请的飞书应用，由 Cindy 平台统一配置
  • 没有配置组织应用的组织、个人账号都可以使用
  • 已有组织应用的企业，管理员可在后台一键改用全局应用（见第 04 节）
  • 上线前个人账号看不到飞书入口

关于你问的「对外共享」资质：飞书要求应用所在的企业完成飞书认证（法人认证、公章授权认证、团队认证任选其一）； 企业未认证时，应用创建者也可以用个人实名认证（人脸或银行卡，仅中国大陆）开启。开启后还需要该企业的飞书管理员审批应用版本。 已认证的企业通常可以直接开。对外共享由企业在自己的飞书应用里决定，Cindy 这边只要保证：外部用户拿不到飞书网页授权，自动改走关联码。

02企业管理员配置（组织后台）

组织后台侧栏新增「集成 → IM 机器人」入口，里面是「飞书机器人」卡片；样式沿用现有的飞书接入向导。 它和「插件 → 三方应用集成」里的「飞书应用」（插件授权用）是两套独立配置，互不影响。

为什么要给机器人单独建一个应用

在飞书里，「机器人」不是独立的东西，而是某个应用（在飞书开放平台创建、有自己的 App ID / App Secret）打开的一项能力。 很多企业为了接入 Cindy 已经建过应用，比如通讯录同步用的、飞书登录用的。「单独建」是指：给 Cindy 机器人再新建一个专用应用（比如就叫「Cindy」），而不是在已有的那个应用上顺手打开机器人能力。原因有三个：

  • 事件接收方式会冲突：一个应用只能选一种接收方式（推送到某个网址，或长连接）。通讯录实时同步已经让飞书把通讯录变更推到 Cindy 的另一个服务；机器人要用长连接收消息，两者不能共存。
  • 群里显示的是应用的名字和头像：复用「通讯录同步」应用，群里看到的机器人就叫那个名字。
  • 权限和停用互不影响：机器人需要收发消息、读群消息等权限，单独一个应用更容易让飞书管理员审批，也可以单独停用、换凭证，不影响登录和通讯录。

对管理员来说只是在飞书开放平台多点一次「创建应用」，向导会带着做完。

  1. 选平台、建应用。先选「飞书」或「Lark」，向导给出对应开放平台的直达链接和截图：创建企业自建应用，开启「机器人」能力，设置名称和头像（如「Cindy」）。
  2. 一次性配好权限和事件。向导列出所需权限（可一键复制批量导入），事件接收方式选「长连接」，并列出要订阅的事件；安全设置里加入 Cindy 提供的重定向地址（点击复制）。需要群聊上下文时，权限里会包含需要企业管理员审批的「获取群组中所有消息」。
  3. 填写 App ID / App Secret。Cindy 立即检查：凭证是否正确、机器人能力是否开启、长连接能否连上、缺哪些权限，逐项给出结果和修复指引。
  4. 发布版本。提醒在飞书后台发布版本并等飞书管理员审批；可选开启对外共享、配置私聊菜单。
  5. 启用。检查全部通过后打开「对组织成员启用」，成员的 Cindy 里随即出现飞书入口。

场景 5–7

离线、换电脑、命令与菜单

电脑离线 / 断网 / 重启

与官方 Telegram 相同：离线时排队 30 分钟并告知；断网后结果补发；重启后继续且先核对已做的操作；30 分钟无进度才自动停止。

换电脑、解除关联

在新电脑上关联时，机器人在私聊里请本人确认改绑；旧电脑卡片显示「已关联到另一台设备」。解绑：Cindy 卡片「解绑飞书」，或私聊发 /unlink。

命令与私聊菜单

文字命令与官方 Telegram 同一套（/new /stop /project /ctr /model /status /unlink）。管理员可按向导给私聊加底部菜单：新任务、停止、选择项目、设置、帮助。

04切换到 Cindy 全局应用

「方便替换」的含义：Cindy 把飞书应用当作配置，换应用不需要发版；但飞书里换应用就是换了一个机器人，这一点对成员可见。

  1. Cindy 平台配置好全局应用后，组织后台的飞书机器人卡片出现选项「使用 Cindy 官方飞书应用」。
  2. 管理员切换并确认。确认框说明影响：成员需要重新关联一次、群里需要添加新的 Cindy 机器人。
  3. Cindy成员的飞书卡片显示「机器人已更换，请重新关联」，一键走授权页即可。工作目录映射、偏好设置保留。
  4. 飞书旧机器人停止响应。切换后 7 天内，旧机器人对 @ 和私聊回复一句「已更换为新的 Cindy 机器人」并附添加方式（前提是组织保留旧应用凭证）。
  5. 需要时可切回组织应用，旧的关联记录仍然有效，不必再关联。
为什么不能无感切换
  • 飞书用户 ID（open_id）按应用区分，换应用后同一个人的 ID 会变，必须重新确认身份。
  • 群里的机器人是按应用添加的，新应用需要群成员重新添加。
  • Cindy 能做的是把这两步做到最短：一键重新关联、群里给出明确提示。

06第一期不做

后续Cindy 全局应用上线

第一期把「多应用」和「组织切换」的能力做好，全局应用审批通过后只需在 Cindy 平台配置凭证并开放。

后续免关联

组织已用同一个飞书应用做登录或通讯录时，可直接认出成员身份、省掉关联这一步；第一期先用授权页一键关联。

后续Agent 操作飞书文档、日历

第一期机器人只负责聊天和派活。

07请你确认

下面是这一版新增的默认做法。没有异议我就按这份方案出实现计划。

  • 机器人单独建一个应用管理员在飞书 / Lark 开放平台给 Cindy 机器人新建一个专用应用，不在通讯录同步或登录用的应用上开机器人（原因见第 02 节）。
  • 组织应用优先组织配置了就用组织应用；全局应用上线后，由管理员决定是否切换。
  • 组织所有者和管理员可配置入口在组织后台「集成 → IM 机器人」，App Secret 只写不读。
  • 组织没配置时给提示组织成员看到「管理员还没有配置飞书机器人」；个人账号在全局应用上线前看不到入口。
  • 换应用 = 换机器人成员一键重新关联，群里重新添加；旧机器人在 7 天内回复更换提示。
  • 飞书和 Lark 一起做管理员配置时选平台；全局应用上线放到后续。
