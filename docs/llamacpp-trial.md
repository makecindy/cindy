## 如何试验

在包含此改动的 Cindy 中打开「设置 → 模型供应商 → 添加 → llama.cpp」。
点击后立即添加供应商并进入详情，不等待运行环境安装或服务启动。
安装和模型下载在详情中进行，安装后不启动服务，也不展示手动启动按钮。模型下载完成后自动加入模型列表；服务已运行时，需手动重启才能使用新增模型，已停止时首次使用自动启动并应用最新配置。
下载期间可以取消，分片由 Cindy 自动补齐。「手动下载」位于模型清单下方，停止／重启位于
「管理服务」。已有外部服务可通过「自定义端点」添加。
只按用户点击下载，不自动下载这张清单里的所有模型。

## 与 Ollama 交互逐项核对（2026-09-26）

| 场景 | llama.cpp 行为 |
| --- | --- |
| 点供应商 | 立即添加，再到详情安装/连接 |
| 推荐 | 同一目录/硬件筛选，主推与轻量备选明确区分 |
| 已安装 | 默认下载列表隐藏；搜索可找到并标为已在本机 |
| 下载中、暂停、失败 | 只出现一张卡片；搜索或离开页面后返回仍保留进行中的下载 |
| 完成 | 自动同步到供应商，移出下载区，不需要再点应用 |
| 搜索、其他候选、无结果 | 共用列表分组规则，避免空的其他候选区 |
| 下载操作 | 共用暂停/继续/取消控件；继续使用已下载字节 |
| 手动下载 | 仓库与 GGUF 文件选择是运行时必需差异；分片显示总大小 |
| 服务 | 自有进程按启动就绪与退出事件显示状态；停止/重启入口，退出 Cindy 停止自有进程 |

仍有运行时差异：一次一个托管操作；退出应用会取消下载，不能像 Ollama 一样跨进程继续。
这些限制不应被「共用界面」掩盖，也不算已经实现完全等价。

托管服务固定使用本机 `127.0.0.1:11435`，本次多实例共享仅限同一 userData。
Global、CN 或不同 `--isolated=@worktree` profile 可以并行运行 Cindy，但不能同时启动
各自独立的托管 llama.cpp 服务：启动前已发现端口占用时返回 `PORT_CONFLICT`。
2026-09-30 用户确认将不同 profile 同时启动的端口竞态作为已知限制，不增加启动身份校验：
两个实例同时通过端口探测时，失败方可能将另一方的健康响应误认作自己的启动成功，
后续请求可能到达另一 profile 的模型服务；当前实现不保证此时返回 `PORT_CONFLICT`。
这不是已修复场景，也不代表支持跨 profile 共用配置或模型目录。
试验时需由用户停止先前 profile 的服务后再切换，避免同时启动；需要并行独立服务时，
自行运行不同端口的外部服务并通过「自定义端点」接入。本 PR 不提供跨 profile 端口分配、
服务租约或模型目录共享，也不将应用多开支持表述为托管模型服务可多开。

共享 userData 的多个实例各自持有独立暂存目录，操作结束只清理自己的目录。安装、下载、启动与删除共用既有 profile 锁；另一个实例正在操作时，安装、下载和删除返回忙碌，不删除另一实例的文件。删除检查到其他实例拥有存活服务时保留连接，需先在拥有方停止服务；不会跨窗口中断生成。安装使用独立版本目录和暂存清单。为避免误删仍在下载的文件，不自动扫描清理其他暂存目录；强制退出或崩溃遗留的暂存文件目前不会自动回收。

已安装清单信任 Cindy 成功校验、发布时写入的模型记录；它不是持续的文件完整性扫描。
本次不覆盖安装后手工删改分片、杀毒隔离或不完整备份恢复后的自动损坏检测及修复。
若模型记录仍在而 GGUF 缺失或截断，模型可能仍显示已安装，加载会失败；重复下载会因已安装记录而跳过。
恢复时先由拥有方停止托管服务，备份并移出该模型在 userData/llamacpp-runtime/models 下的整个
对应 model-ID 目录（包括 model.json 和分片），再在 Cindy 刷新清单并重新下载。不要只删除供应商连接：
删除连接会保留模型文件。不要在生成、下载或其他实例仍使用该服务时移动目录。
这项边界不放宽首次下载完整 SHA-256 校验，也不新增分片清单持久化或后台修复机制。

配置操作统一由服务拥有方执行：其他实例仍可使用当前服务，但不能安装运行时、下载模型或修改上下文。界面说明限制，后台在既有 profile 锁内检查同一拥有方判据；身份未知时也拒绝修改。拥有方停止服务后，其他实例可以配置并按需启动，不新增跨窗口刷新或取消协议。

删除连接沿用通用供应商删除事务，不提供跨账号切换的原子回滚。等待服务停止或删除队列时
切换账号会在清理前拒绝；但已清理凭证及偏好、正在等待数据库删除时切换账号，若删除失败，
原账号的连接可能仍在而凭证、可见性或价格偏好已丢失。此窗口同样存在于主干的通用删除流程，
本 PR 未修复，也不扩展跨账号恢复机制。删除期间请等待操作结束再切换账号；若遇到该情况，
切回原账号核对连接及模型偏好，按需重新设置。删除不会移除已下载的模型文件。

上下文保存与启动 preset 共用上限检查：目前仅指定 Flash-Next 包装允许扩展到 1,000,000；其他托管 GGUF 最高 32,768，未验证的扩展会拒绝，不静默分配超大 KV 缓存。这是当前托管运行配置边界，不代表上游模型的理论最大窗口。

2026-09-26 用户确认支持多实例共享托管服务。启动复用现有跨进程锁与进程实例存活探测：同一 userData、存活身份匹配且健康检查通过时，第二个 Cindy 直接使用已启动的服务，不生成第二份进程。共享方停止或退出不终止拥有方；拥有方仍需保持运行，正常退出后服务会停止，下次使用重新按需启动。待生效配置不同不阻止继续使用当前服务；身份无法确认时拒绝借用，借用方不能重启拥有方服务。已打开任务在每次发送前也会检查服务状态：手动停止后，下次发送重新按需启动；服务仍运行时不通过这条检查重载配置。该入口覆盖本地聊天、IM、Goal 与 Scheduler，SSH 会话跳过本机服务（实现与回归见 `sessionTurnObserver.ts`、`sessionEventPipeline.test.ts` 和 `preflight.test.ts`）。一次性辅助模型请求同样走按需启动；正常退出等待当前安装／下载取消及其暂存清理完成。多实例服务尚未做正式版与开发版同时运行的实机验收。

POSIX 启动通过固定 shell 包装持有整组进程，Cindy 独占管道写端；拥有方崩溃或被 SIGKILL 后，管道 EOF 触发组内自清理，回收 router 及模型子进程，不读取历史 PID 查杀。参数作为独立 argv 传递。Windows 保持非 detached 子进程方式。macOS 已用真实进程和回环端口验证拥有方被强制结束时，模拟服务与后代端口一起释放；这不等于所有平台真实模型崩溃恢复均已验收。

Windows 的非 detached 并不保证 Cindy 崩溃或被强制结束时自动回收子进程；正常停止／退出会等待现有进程树清理，异常退出仍可能遗留占用内存和 11435 端口的 router／模型进程。此时重新打开 Cindy 可能返回 `PORT_CONFLICT`，无法从新实例接管或停止旧服务。本次不增加 Windows Job Object 或异常退出守护机制。恢复时需在任务管理器中核对遗留进程的可执行文件路径属于该 profile 的 `llamacpp-runtime`，确认相关生成已不再需要后手动结束对应进程树，或重启电脑，再重新按需启动；不要结束其他 profile 或用户自行运行的模型服务。

自有托管进程的运行状态依据启动就绪与进程退出事件，不是持续健康监测。进程仍存活但
服务卡死、健康接口超时或返回失败时，仍可能显示运行中，复用和发送前检查不会自动重启，
后续请求可能持续失败。本次按需启动不包含失去响应后的自动恢复，也不根据一次健康探测
失败停止可能仍在生成的进程。恢复时由拥有方在「管理服务」手动重启，或停止后再次使用；
若返回 `STOP_TIMEOUT`，停止尚未确认完成，不能据此认定旧进程已回收或让其他实例接管。
Windows 树杀失败后即使 router 已退出，也保留拥有方证明并阻止删除；需按上述方式核对并
清理遗留进程树后重启拥有方 Cindy，不自动解除这一保护。
外部拥有方的存活及健康检查仍用于确认可否借用，不赋予借用方恢复或重启权限。
