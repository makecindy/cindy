# 功能介绍：带小动画的一页引导

> `DESIGN.md` 专题，规范效力相同。文中未注明文档的 `§N` 均指 [DESIGN.md](./DESIGN.md)。
> 动效参数只在 §14.4「Get-started guide entrance」登记，本文不重复数值。

用户第一次用到某个功能时，弹出一页介绍：一个标识、一句标题、一句话说明、三张各带一段小动画的
卡片，和一个开始按钮。它来自新装 Cindy 的开始引导欢迎页（2026-11-11 定稿），2026-11-18 用户
要求把这种方式作为 Cindy 的功能引导方式，以后各处都可以考虑使用。第一个功能介绍是任务收件箱。

## 什么时候用

适合：

- 一个功能改变了用户已经熟悉的东西，或者引入了新的概念，第一眼不容易看懂。例如收件箱把任务
  重新分成四个区，「完成」和「稍后处理」是新的动作。
- 能用三件事讲清楚：用户看完就知道这个功能怎么用、和以前有什么不同。
- 只介绍给需要的人：已经在用这个功能的人不必再看（项目的介绍只对还没有项目的人出现）。

不适合：

- 一个按钮或一个选项就能说明白的改动。用悬停提示、空状态说明或设置页说明就够了。
- 需要用户填写、选择或完成配置的流程。那是向导，按 §4 的多步弹窗做；功能介绍只介绍、不收集。
- 版本更新说明、营销推广。功能介绍只在用户自己走进这个功能时出现。

## 什么时候出现

- **由用户自己的动作触发**：在用户第一次打开、切换到或用到这个功能的那一刻出现（收件箱是第一次用
  开关进入收件箱）。不在启动时、登录后或后台事件里弹，也不和其他弹窗同时出现。
- **每台电脑只出现一次**：在决定显示时就记下（本机存储，键名 `featureIntro.<功能>.seen`），关掉或
  看完都不再出现。不同电脑各出现一次，不跨设备同步。
- **用户已经在用这个功能时**（例如升级前就开着收件箱）不主动补弹；下次通过入口重新进入时出现。
- 手机端暂不提供；需要时按手机的原生弹层另行设计，不直接搬这页。

## 页面结构

在 `components/feature-intro/` 里复用，不另画一套：

- `FeatureIntroDialog`：弹窗本身。宽 640px（窄窗口时留 16px 边距），高度随内容、最多 88% 窗口高，
  超出时在窗口内滚动。共用 `.modal-scrim` / `.modal-panel`。
- `GuideCover`：页面内容，开始引导的欢迎页也用它。从上到下：
  1. **标识**：56px 中性底色方块里放这个功能自己的图标（与入口按钮相同的图标）。品牌标识只属于
     开始引导，功能介绍不用。
  2. **标题**（28px）：一句话，说这是什么，例如「认识收件箱」。
  3. **说明**（15px）：用一两句话说清这个功能对用户有什么用。
  4. **三张卡片**：每张上方是一段小动画，下面是卡片标题（14px）和一句说明（13px）。三张卡片讲三件
     用户需要知道的事，通常是「会看到什么」和「能做什么」。
  5. **开始按钮**：居中，点击关闭弹窗、留在这个功能里。
  6. **一行小字**（12px）：告诉用户怎么关掉或切回，例如「随时可以用侧边栏顶部的按钮切回任务列表」。
- 关闭：开始按钮、右上角 × 和 Esc 都能关；点弹窗外面不关，避免没看就被误关。

## 小动画怎么做

小动画是功能介绍的重点。它用界面自身的元素拼成，让用户一眼看到「这个功能会怎么动」。

- **用产品自己的元素**：任务行用细横条，状态点用真实的颜色（新结果 `--card-status-done`、等待回复
  `--card-status-awaiting`），动作用它在界面里的同一个图标（完成是对勾、稍后处理是时钟）。不画插画，
  不用通用图标代替场景，不加装饰色。
- **每段只讲一个动作**：例如「任务带着绿点、蓝点一条条到来」「顶上一行打勾离开，下面的上移补位」
  「任务挂上时钟，过一会儿带着绿点回来」。
- **只用登记过的几种动作**（`globals.css` 的 `.first-run-*`，参数见 §14.4）：
  - `pop`：弹出（淡入并从小放大），用于点、图标、整块出现。
  - `draw`：从左画出，用于文字横条。
  - `leave`：淡出，用于被替换或离开的元素。
  - `shift`：从原位置上移，用于上一行离开后下面的行补位（`--shift` 为移动距离）。
- **时间**：每段动画在它所在卡片到场后开始（`GuideCover` 把开始时间作为 `start` 传给场景），场景内
  每个元素用 `at(毫秒)` 指定开始时刻。相邻步骤一般间隔 90–180ms，整段在一秒左右播完。只播一次、
  不循环，悬停、重绘和数据刷新都不会重播。
- **终态要能看懂**：系统开启「减弱动态效果」时直接显示最后一帧，所以最后一帧本身要能说明这件事
  （例如对勾已打上、任务已回来）。
- 动作放在 HTML 外层元素上，不直接动 SVG 图标；只动 `transform` 和 `opacity`。
- 小动画只是示意，不能拿来显示真实任务、供应商或设备的状态。

需要新的动作类型（例如旋转、路径动画）时，先按[设计治理](design-governance.md)登记到 §14.4，
不要在单个介绍里自行加关键帧。

## 文案

- 用用户看得懂的话，说「会发生什么」和「你要做什么」，不讲实现。
- 卡片讲的是界面上的分区或按钮时（收件箱的「待处理」「完成」），标题沿用界面上的名字；讲的是这个
  功能带来的好处时（项目的「不用重新交代」），标题直接说好处。说明里提到的界面词与界面一致，并查
  [术语表](../../i18n/GLOSSARY.md)。
- 先讲这个功能对用户有什么用，再讲怎么用；不用篇幅去讲「什么时候不需要它」。
- 「任务 / 对话 / 消息」按[命名规则](../product-rules/task-and-conversation-naming.md)使用。
- 所有语言同时提供。

## 新增一个功能介绍

1. 确认适合用功能介绍（见上文），并在该功能的产品规则里写明出现时机与只出现一次。
2. 在功能目录里新建 `<功能>Intro.tsx`：准备标识、标题、说明、三段场景和文案，渲染
   `FeatureIntroDialog`；提供一个「领取」函数，第一次返回 true 并同时记下已显示。
3. 在用户进入功能的那个动作里调用它（参考 `TaskListModeToggle.tsx`）。
   一个功能有几个入口、都打开同一个界面时，由这个界面自己判断，不在每个入口各接一次：读取是否
   显示过放在首次渲染里，记下已显示放在显示之后（参考 `ProjectIntro.tsx` 的 `useProjectIntro`）。
   介绍后面要接另一个弹窗（例如表单）时，先介绍、关闭后再出现那个弹窗，两者不叠在一起。
4. 在该功能的界面检查页（`pnpm ui:check`）加一个 1040×760 的用例：触发后弹出、内容不需滚动、关闭后
   再次进入不再弹出；Light / Dark 都看一遍截图。截图检查固定开启减弱动态效果，只能看到终态；实际
   节奏用 `ui:preview --motion` 或真机查看。
5. 在本文末尾的列表里登记。
