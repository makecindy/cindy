# Codex 对话跟进方式

> 日期：2026-09-30。状态：已实现，Windows 打包预览经用户验证；远程连接与双主题目检待验收。
> 分支：`codex-steer`；2026-10-02 同步主干，并基于主干迁移链重新生成 0123。

## 用户界面

- 设置 → 通用 → 输入，在发送快捷键下增加 Codex 跟进消息设置。
- 默认排队，可选引导；恢复默认删除本地覆盖。
- Desktop 普通 Codex 任务的底部，在 context 用量信息左侧增加紧凑下拉框。
- 下拉框前显示「对话跟进方式」；标题与控件的提示均为「对话过程中的后续消息加入排队，或引导当前对话」。
- 任务可选「跟随全局：实际方式」「排队」「引导」。保存失败保持已确认值并提示。
- 窄窗口允许底栏换行，不挤压用量信息。控件复用 Select、Tip 与语义色，支持 Light / Dark。
- 不增加发送菜单入口，不增加队列「引导」按钮。已有「插话」继续保持同轮注入语义。
- Mobile 不新增设置入口；普通消息使用执行电脑上的有效偏好。

## 设置归属

全局覆盖使用执行电脑 userData 下的 `codex-follow-up-settings.json`，复用原子覆盖文件与跨进程锁。
每个任务的 `sessions.codex_follow_up_mode` 可为 null / queue / steer；null 表示继承。
通过新增 Drizzle migration 0123 添加 nullable 列，不改历史 migration。
新任务默认继承，fork 复制显式覆盖。读取最终值为「任务覆盖优先，否则全局，默认 queue」。
切换方式只影响后续普通发送，不自动迁移已排队消息。

## 投递行为

仅普通 Desktop 来源的 Codex 任务、显式普通输入适用。Claude Code、Pi、Orca、Review、伙伴、IM、自动续跑与合成消息不受影响。
普通发送通过 enqueue 的可选 `composerDelivery: auto` 表达意图，由 Main 按实际任务和引擎解析。
没有可引导的活动轮次或输入边界被锁定时仍入原队列，不中断执行、不新建并行轮次。
引导复用现有 coordinator 和 Codex 原生 turn/steer；显式排队/插话与快捷键语义不变。

引导前先将原消息以稳定 clientId 持久化到原队列，再持久化 host-owned 尝试标记，之后跨内容 RPC 边界。
投递结果不确定时保留消息、暂停队列，后续普通消息不解锁、不重发；重启恢复同样暂停。
用户可使用现有继续发送或删除入口明确处理，不静默重复注入。
附件、引用、清空边界与 generation 检查复用原路径；客户端不能伪造尝试标记。

## 远程与兼容

SSH 继续使用原 Codex 引导通路。device-link 新增任务级读取/写入通道；全局写入仅本地。
任务偏好属于执行端，控制端不覆盖本机全局偏好；多控制端通过现有 projection 推送同步。
共享访客无新设置写权限，Review 外部输入边界拒绝任务设置写入。
projection 可选 `composerAutoDelivery: true` 声明支持能力。
新版 Desktop 连接旧主机时隐藏任务控件；Mobile 仅主机声明能力后将 auto 意图写入持久发件箱。
已准备的旧发件箱记录在重试时保持原语义，不追加新意图；旧主机继续原排队行为。
不修改服务端、relay 协议、原生 Mobile 配置或权限边界。
