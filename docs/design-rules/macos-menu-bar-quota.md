### macOS menu bar quota panel (owner-approved v6 prototype, 2026-10-11)

Windows 托盘面板（2026-11-18）沿用这里的内容顺序、默认任务数量、管理／账号详情／用量详情、
品牌资产与数字字体。鼠标在 Windows 托盘图标上连续悬停 100 毫秒后展示预热窗口，移入卡片后可以继续操作。
卡片只由悬停触发：左键单击保持原有行为，收起卡片并直接打开主窗口；右键收起卡片并弹出托盘菜单。
卡片收起时不展示额度，因此不算额度读取的使用者：只在卡片可见期间读取；开启「低额度提醒」时提醒需要后台读数，
才在收起后继续读取。启动时读取一次作为首帧，收起后保留最后一帧供下次展开直接显示，换账号立即清空。
鼠标停在图标上就会展开，所以展开不能决定请求频率：展开触发的全量刷新最多每 60 秒一次，其间再次展开只复用已有读数；
收起后继续持有读数 3 分钟且不发起新的读取，鼠标来回划过图标不会重新采集。
动效与 Mac 面板同曲线同时长（Swift 的 `Motion`），调整时两端同步：液柱液面与 `TubeView`／`LiquidSurface` 同形同参
（展开时升起并左右晃动后静止，与管壁以圆角相接，有任务在用的账号保持细波纹，鼠标移入时轻晃），额度与月度金额从零滚动到位，
额度列悬停上抬、按下回弹，翻页时离开的页面滑出后才移除，详情圆环逐环绘出，「打开 Cindy」的品牌箭头滑入，
刷新图标转一圈，运行中任务的图标向外扩散一圈细线。波纹与扩散线是仅有的两处循环动效，只在卡片可见时运行；
开启「减少动态效果」时全部静止。液面与数值滚动在 `src/renderer/quota-tray-tube.tsx`，其余在 `styles/quota-tray.css`。
首页和详情按内容测量高度，仅超过屏幕可用高度的 86% 才滚动。所有页面复用
`QuotaPanelController` 的取数、隐私处理、设置持久化和操作派发。
额度列的间距、管宽与数值排版跟随 Swift 的 `Cells`／`CellView`：超过 6 个额度时列间距从 8px 收为 4px；管子最宽 40px，
列更窄时随列收窄，液面按管子实际宽度绘制；管子上方的数值固定占一行 22px 高（额度 18px、余额 16px、
% 号 11px；credits 为 14px 数额叠 10px 单位，守 10px 字号下限，比 Swift 的 15pt／8pt 略高出数值行），
所有管子顶端对齐。数值放不下时整体缩小到列宽，不换行也不压到相邻列；Swift 的 `minimumScaleFactor`
缩到 75% 后截断，Windows 继续缩小以完整显示金额（2026-11-22，九个额度时「100」与「%」分成两行、
「¥90.20」压到相邻列）。推荐账号的描边画在管壁内侧，管子尺寸不变。重置时间仍是 11px 单行，放不下时省略。

两端的尺寸、短屏密度和语义色正本在 `src/shared/quotaPanelDesign.ts`（相对 Desktop）；
controller 随视图发送，Swift 的 `PanelDesign`／`Palette` 与 Windows 的 CSS 变量共同消费。
Swift 内的旧值只供旧预览数据缺字段时兼容，调整设计时改共享正本。平台渲染器仍各自维护页面
结构和原生交互，新增控件须同时适配；Mac 的系统模糊材质与 Windows 的背景合成各自由平台负责。
Windows 回归入口为 `pnpm ui:check --page quota-tray --case all --theme all --locale all`，
覆盖首页任务裁剪、管理、账号详情、用量详情与品牌按钮，以及九个额度并排时的对齐（`crowded`）；
Mac 仍须运行原生 helper 验证。

### Menu bar quota fill motion

**macOS menu bar quota fill (owner request, 2026-10-11; liquid and ripple 2026-10-16).** The native menu bar panel (`apps/desktop/native/menubar/`) fills its detail rings from empty over 0.5s with `timingCurve(0.22, 1, 0.36, 1)` (no overshoot) each time the panel opens or a page loads; page switches use the same curve and duration.
Usage tube liquid rises on the same curve over 0.9s, staggered 60ms per tube; while it rises the surface rocks only slightly (about 1pt, a quick 0.34s rock that swells mid-climb and is level again on arrival) and it sloshes properly once it stops — inertia tips the surface from side to side (first mode, up to about 5pt at the edges for a nearly full tube, ~0.95s period) with a smaller faster second mode, decaying over about 4.5s.
How hard a tube sloshes follows how high its liquid climbed (momentum grows with level^1.5, so a low tube barely moves), and every opening draws a fresh profile — first lean direction, strength, period, decay, the second mode and the instant of arrival — so the tubes never repeat themselves. The slosh then decays to the gentle ripple on a source in use and to a still surface everywhere else.
The task total reads "3M token · $66.46": tokens first, so the amount ends flush with the task amounts below; without tokens the amount alone sits at the right. Plain numbers (tube values, task amounts and total, the month total, the detail ring value) count up from zero on the same 0.9s curve each time the panel opens, with the final text reserving its width so nothing shifts; strings that mix in words stay static.
Today's task total (19pt) reads larger than each task's amount (14pt). After the opening settles, continuous motion carries one meaning only — **tokens are being spent right now**: the liquid surface of a source that a running task on this computer is drawing on ripples gently (about 1.5pt, a 3.6s period; main marks it `active` from the running session's provider, with Cindy-managed providers marking the Cindy balance), and a running task's share bar carries a travelling highlight.
Two "running" markers in the task lists share that meaning: a running task's icon tile has an outline ring that expands and fades on a 2.2s ease-out loop (scale 0.92 → 1.12, opacity 0.7 → 0; In progress rows and Today's usage task rows), and a breathing dot pulses opacity 1 ↔ 0.2 on a 0.8s ease-in-out reversing loop (before "Running 00:12" in a task row, and as the harness-colored dot of a running task in the usage page list).
Under Reduce Motion the ring is not drawn and the dot stays still — in the usage page list a static ring around the dot marks it as running instead. When the task stops, the ripple eases to a flat, still surface over 1.4s; every other tube and the warning glow stay still. Feedback: moving the pointer onto a tube gives its liquid a small nudge (about a third of the opening slosh, scaled by its level, random first direction) that dies down within about a second, and sweeping across the row does not restart a nudge that just began; a pressed tube squeezes to 95% and springs back; the "Open Cindy" `>` slides in once as the panel opens, leans 2pt forward on hover and pushes 4pt on press.
These are SwiftUI motions, not Web duration tiers: the Web tokens do not apply inside the native helper. Reduced motion shows the final values without animation and keeps every surface still. The usage card in Mobile’s drawer repeats the opening only, once each time the drawer opens — the 0.9s rise staggered 60ms per tube, the rock and slosh with their lengths scaled to its narrower well, and the count-up of the tube values and of today’s total (0.2s later, like the month total).
The drawer card has no in-use ripple, pointer nudge or press squeeze, and its liquid is drawn on the UI thread by Reanimated (`apps/mobile/src/widgets/usageOpeningMotion.tsx`), not with the Mobile duration tiers. Beyond that card, this exception does not apply to any other Mobile or Web surface.
