# 插件刷新范围与 mock 性能验收（2026-11-04）

已实施订阅发现索引、安装／项目策略／展示刷新拆分。Windows 独立 mock 中，
12 次任务切换产生的全量扫描调用由 756 次降至 24–25 次；12 次项目开关由 36 次降至 0 次。
项目开关中位耗时由 154.22 ms 降至约 5.3 ms。**任务切换首帧时间没有改善证据，仍有长任务；
不能将扫描减少等同于整页卡顿消失。**

基线提交：`ae8a72e00900e59eda33f306f3777f3bf7533072`。最终版为本工作区修改。
测量环境：Windows、Node v24.14.1、Global、免登录 `--mock`，独立沙箱
`plugin-refresh-bench`。使用同一份 30 插件合成数据：29 个无订阅能力，1 个声明 session topic；
分别测量该订阅者停用、启用两种状态。没有真实账号、凭证或用户内容。

## 改动范围

- `GhostNotificationIndex` 保存当前 owner 的订阅候选。安装事务及安装事实广播主动失效，
  目录、批准记录与停用标记的外部变化通过监听失效；监听不可用时现扫，60 秒有效期兜底漏报。
  没有订阅者也是有效结果，首次未知状态仍需扫描。
- 事件投递按确切实例键读取当前批准，核对批准版本、启用状态与 topic；保留账号代次校验、
  按需唤醒、队列顺序与现有钩子。运行中的插件和已启用但尚未运行的插件均可收到通知。
- 项目禁用只推送 Host 归一后的目录键与禁用列表。保留 setup 通知和远端插件资源失效；
  输入框、插件页只更新匹配的目录，拒绝旧 owner 推送与迟到读取。
- 语言变化更新展示及插件 App 注册表中的本地化名称和工具说明，仍发插件上下文消息；
  不再触发扩展、未读、Skill 和订阅索引对账。
- mock 发现异步可用插件清单在扫描后仍逐个用裸 ID 重查，导致无账号模式下重复全表扫描。
  已改为直接使用扫描所得实例的 manifest 过滤，与同步清单相同；同名不同 namespace 的实例仍独立判断。
- 未修改 Library 同步、持久批准 schema、插件权限声明或 device-link wire protocol。

## 测量方法

[验收脚本](../../apps/desktop/scripts/benchmark-plugin-refresh.cjs) 连接实际 Electron 主进程
inspector 和 Renderer CDP，核验非打包、mock、本地模式及独立沙箱后才装入合成插件。
通过真实 IPC 启停插件、修改项目开关，通过实际路由切换四个 mock 任务。脚本临时包装
manager 扫描／精确读取及网关发送入口计数，退出时还原，不在生产代码加入计数器。

每种订阅状态先预热四次，再测四个任务循环三轮，共 12 次切换。每次操作后等待主进程
扫描与通知发现结束，再开始下一次。项目开关交替禁用／启用一个无订阅插件，共 12 次。
性能采集期间不运行构建、类型检查或单测。

`list` / `listAsync` 记录整个场景内的调用次数，包含 UI 与 Skill 查询，不是只统计通知。
`scanMs` 是扫描方法累计墙钟耗时，可包含异步等待和嵌套计时，**不是 CPU 时间或用户等待时间**。
切换耗时包含设置路由、等待 URL、两次 animation frame；不覆盖后续全部异步工作。
项目开关耗时包含 IPC 往返。偶数样本中位数取中间两项均值。

全部六轮数据见[原始结果](plugin-refresh-2026-11-04.json)。`before-1`、`before-2`
是未等待扫描完全收尾的探索轮，存在串扰；`after-settled-1` 是尚未去掉裸 ID 重查的中间版。
保留这些结果以说明过程，正式比较仅使用一轮 `before-settled` 和两轮 `after-final-*`。
基线只有一轮，不能据此给出统计显著性或外推真实账号的总体收益。

## 正式结果

下表均为每轮 12 次操作。

| 场景 | 基线 | 最终版第 1 轮 | 最终版第 2 轮 |
| --- | ---: | ---: | ---: |
| 无订阅者：同步／异步全量扫描调用 | 732 / 24 | 12 / 13 | 12 / 12 |
| 有订阅者：同步／异步全量扫描调用 | 732 / 24 | 12 / 12 | 12 / 12 |
| 无订阅者：精确实例读取 | 720 | 0 | 0 |
| 有订阅者：精确实例读取 | 792 | 24 | 24 |
| 有订阅者：通知投递数 | 12 | 12 | 12 |
| 项目开关：全量扫描调用 | 36 | 0 | 0 |
| 项目开关：中位耗时 | 154.22 ms | 5.33 ms | 5.27 ms |
| 项目开关：最大耗时 | 178.95 ms | 6.87 ms | 6.31 ms |

最终两轮项目开关各收到 12 次目录策略推送、0 次全局插件清单推送。
任务切换的累计扫描方法墙钟耗时由约 24 秒降至 0.59–0.64 秒，约降 97%；
仍有 UI／Skill 等入口的清单读取，不能宣称任务切换完全不扫描插件。

| 切换 UI 指标 | 基线 | 最终版第 1 轮 | 最终版第 2 轮 |
| --- | ---: | ---: | ---: |
| 无订阅者：切换中位数／最大值 | 31.21 / 47.34 ms | 33.19 / 73.16 ms | 36.42 / 76.00 ms |
| 有订阅者：切换中位数／最大值 | 33.90 / 48.02 ms | 34.45 / 73.36 ms | 40.22 / 67.23 ms |
| 无订阅者：长任务数／最长 | 12 / 93 ms | 7 / 91 ms | 7 / 84 ms |
| 有订阅者：长任务数／最长 | 12 / 96 ms | 7 / 92 ms | 7 / 82 ms |

首帧样本没有变快，最大值反而升高。长任务减少，但最长仍达 82–92 ms；剩余 UI 开销
需要单独定位。本次目标“减少无关插件刷新”已获得调用计数和项目开关延迟的实测支持。
已查看最终 mock 页面截图，任务内容和输入框正常；未做 Dark、macOS 或正式包验收。

```powershell

pnpm restart:desktop:remote -- --region=global --mock --isolated=plugin-refresh-bench
```

`node -e 'process._debugProcess(PID)'` 开启主进程 inspector，再运行：

```powershell
node apps/desktop/scripts/benchmark-plugin-refresh.cjs label "$env:TEMP/cindy-plugin-refresh-acceptance" 9358 9229
```

不要对日常使用实例运行。合成插件保留在独立沙箱中以便复测；原始截图与临时包放在仓库外。
