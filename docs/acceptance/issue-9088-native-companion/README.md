# #9088 原生伙伴设计：方法与复现

在普通任务或设计师伙伴中，把需求落实为可继续合作的原生伙伴：创建或选择同一对象，调整身份、模型和必要能力，按需应用头像，然后在它原有的聊天中工作并根据反馈完善。

设计方法由 Skill 承担；本 PR 为 Cindy 补充通用的目标配置和受管头像入口。两项方法独立导入，不自动安装，不内置设计师身份，也不会因下载方法包而修改已有伙伴。

| 方法 | 源码 | 导入包 |
| --- | --- | --- |
| 伙伴设计与调整 | [companion-designer](skills/companion-designer/SKILL.md) | [companion-designer-candidate.zip](companion-designer-candidate.zip) |
| 名字与形象 | [companion-fy](skills/companion-fy/SKILL.md) | [companion-fy-candidate.zip](companion-fy-candidate.zip) |

下载 ZIP 时使用 GitHub 的 Download raw file，在 Cindy「技能」页本地导入。方法不要求新插件；相对资源随 Skill 目录分发。包本身不会添加宿主工具。

## 复现完整体验

1. 使用包含本 PR 的 Cindy，从 `cindy_helper.list_tools({category:"bots"})` 核对 `list_teammates`、`create_teammate`、`inspect_teammate_configuration`、`update_teammate_configuration`、`set_target_teammate_avatar`。
2. 导入 companion-designer，在普通任务使用；当前 V2 伙伴使用已核实项目的 `.agents/skills` 和本机资源，不写伙伴个人能力名单，核对下一轮实际可用。只在需要命名或头像时再导入 companion-fy。
3. 提出真实需要，例如“帮我创建一位研究伙伴”。从本机名册选择已有对象或原生创建，保留回执里的稳定 id。新伙伴自行开场；若主任务尚未准备，可读取同一对象并修正模型，能力目录需等待运行准备，不重复创建。
4. 在目标原有聊天交给它一件有代表性的工作。根据真实结果提出调整，例如“表达更自然，保留研究职责”。设计任务先读取完整身份和版本，只修改相关字段；回读确认其余选择保持。
5. 如需换头像，通过当前任务可读的受管图片提交刚读取的版本和旧头像，再核对本机头像显示。生成新图与应用图片是两个环节。
6. 继续在同一聊天工作，核对实际方法读取、工具调用和输出。正常延后等待安全边界；`unconfirmed` 时先查当前保存和同步状态，不自动重放写入。

保存、最新运行快照与特定输出的实际采用分别判断。`runtime.matchesSavedVersion` 不提供每条历史输出的精确配置账本。接口及延后扩展的权威范围见 [伙伴运行规则](../../product-rules/cindy-bots-runtime.md#原生伙伴设计与调整9088)，执行电脑与入口限制见 [宿主适配说明](skills/companion-designer/references/host-adapters.md)。
