# 用自己创建的飞书机器人连接 Cindy

Cindy 有三条接入飞书 / Lark 的路径，本文只讲**个人飞书机器人**：你在飞书开放平台创建一个
企业自建应用，把它变成自己的机器人，再在 Cindy 桌面端的「设置 → IM 机器人 → 个人 →
飞书 / Lark 机器人」里填写 App ID 和 App Secret。

- **个人飞书机器人**（本文）：自己创建自建应用，自己填写 App ID / App Secret，只在你绑定
  它的那台工作电脑上运行。适合个人开发者、小团队，或者希望完全掌控应用权限的人。
- **伙伴飞书机器人**：把同一个机器人交给一位伙伴，在那位伙伴的「消息平台」页连接。适合
  把某个机器人固定给一个伙伴、由伙伴带着走的场景。
- **官方飞书机器人**：Cindy 官方维护的商店应用，在 Cindy 里完成账号关联即可，不需要
  App Secret。适合不想自己建应用的人，步骤见
  [官方商店指南](./feishu-store-guide.zh-CN.md)。

三条路径共用同一套 Cindy 能力（私聊、群 @、通知、卡片等），区别在**谁创建应用**、
**是否需要 App Secret**，以及**机器人跟谁走**。

## 1. 开始之前

- 一台安装并登录了 Cindy 桌面端的电脑，保持在线。机器人绑在这台电脑上，任务也在这台
  电脑上执行。
- 一个飞书或 Lark 账号，并且是准备创建应用的那个企业 / 组织的成员。
- 创建企业自建应用通常需要开发者权限；部分企业要求管理员审核应用和权限。
- 先想好机器人的使用范围：只给自己用，还是给群里的同事用。这决定了后面要开通哪些权限、
  以及应用的可用范围。

## 2. 创建应用

1. 打开对应平台的开放平台：[飞书开放平台](https://open.feishu.cn/) 或
   [Lark 开放平台](https://open.larksuite.com/)。服务选错时，后面填的 App ID 会连不上，
   所以先确认平台。
2. 创建一个**企业自建应用**，填写名称。这个名字就是以后在飞书里搜索到的机器人名字。
3. 在应用的「添加应用能力」中添加**机器人**能力。
4. 打开「凭证与基础信息」，复制 **App ID** 和 **App Secret**。App Secret 等同于应用密码，
   不要发到群里、粘贴到公开 issue，也不要提交到代码仓库。
5. 在「版本管理与发布」里设置**可用范围**。只给自己用时选自己；需要同事使用时再把
   对应成员或部门加进去。可用范围之外的成员看不到、也用不了这个机器人。

## 3. 开通权限

在应用的「权限管理」中搜索下面的权限标识并开通。标识在中文控制台里同样可以搜索。

| 权限标识 | 作用 | 何时需要 |
| --- | --- | --- |
| `im:message.p2p_msg:readonly` | 读取用户发给机器人的单聊消息 | 私聊必填 |
| `im:message:send_as_bot` | 以应用身份发送消息 | 必填，否则机器人无法回复 |
| `im:message.group_at_msg:readonly` | 接收群内 @ 机器人的消息 | 群 @ 必填 |
| `im:message.group_msg` + `im:message.group_msg.include_bot:read` | 读取群历史，以及群内其他机器人发的消息 | 需要群上下文时开通；敏感权限 |
| `im:chat:readonly` | 读取群基本信息 | 可选，用于在任务标题里显示真实群名 |

`im:message.group_msg` 和 `im:message.group_msg.include_bot:read` 属于敏感权限，飞书通常只向
企业自建应用开放，开通后还需要管理员审批。不开启它们时，群里的 @ 仍然能收到，但机器人
拿不到之前的聊天记录，只能就当前这条消息作答。

## 4. 绑定与事件配置

顺序很重要：**先在 Cindy 绑定，再去开放平台保存事件和回调，最后发布版本**。

1. 在 Cindy 的「设置 → IM 机器人 → 个人」中展开「飞书 / Lark 机器人」，选好服务，填入
   App ID 和 App Secret，点击「绑定」。状态变为「已连接」表示长连接已经建立。
2. 绑定后回到开放平台，打开「事件与回调」：
   - **事件配置**：订阅方式选择**使用长连接接收事件**，添加「接收消息」
     （`im.message.receive_v1`）事件。
   - **回调配置**：同样选择使用长连接接收回调，添加「卡片回传交互」
     （`card.action.trigger`）。没有它，Cindy 卡片上的按钮不会有反应。
3. 在「版本管理与发布」中创建并发布新版本。自建应用一般需要管理员审核；审核通过后，
   确认自己的账号在可用范围内。
4. 给机器人发一条私聊消息。第一次私聊的人会成为机器人的主人（Owner）。

之后每次修改权限、事件或回调，都要重新发布版本，变更才会生效。只保存配置而不发版，
是「状态显示已连接、私聊却没有任何反应」最常见的原因。

## 5. 日常使用

**私聊**：直接给机器人发任务。任务在绑定的那台 Cindy 工作电脑上执行，进度、结果和需要
确认的操作会回到私聊。

**群聊**：先把机器人加入目标群（群设置 → 群机器人 → 添加机器人），再 **@ 机器人**发任务。
机器人为回复开一个话题（Thread），主群保持干净；在话题里继续 @ 它时，会接着该话题的
历史回答。在主群 @ 时，它会从最近的消息往前读（最多约 250 条），找到相关上下文就停下。

**命令**：`/new` 开新上下文，`/model` 切换模型，`/permission` 修改权限模式，`/ctr` 接管
桌面会话（`/exctr` 结束接管），`/help` 列出全部命令。发送 `!stop` 停止当前运行并清空
排队消息，任务本身会保留，可以继续。

**通知**：可以在机器人设置里开启上下线通知，以及任务完成或需要回复时的私聊提醒。任务
提醒只在 Cindy 窗口失焦时发送。

**呈现**：回复里的操作步骤可以折叠成一行查看；长回复会拆成多张卡片按顺序送达，代码块和
表格不会被截断；消息里的图片和文件会作为任务附件处理。

## 6. 安全与边界

- **主人制**：第一个给机器人发私聊的人成为主人，之后其他人的私聊会被静默忽略。换人使用
  时先解绑，再由新主人发出第一条私聊。
- **群权限**：群任务默认使用 Auto-review（自动审批）权限模式。群消息可能来自其他成员，
  只有完全信任的群才考虑 Full access（完全访问）。已有的群任务可以用 `/permission` 调整。
- **敏感权限按需开通**：群历史相关的 `im:message.group_msg` 和
  `im:message.group_msg.include_bot:read` 不是跑通私聊和群 @ 的必需项，确认需要群上下文
  再开通。
- **凭据留在本机**：App ID / App Secret 保存在本机的系统安全存储中（Electron safeStorage /
  系统钥匙串），不会明文写进普通配置文件。解绑会删除本机保存的凭证和主人信息。
- **一个机器人只能在一处运行**：同一个 App ID 同时被两台设备绑定时，会提示「已被另一台
  设备使用」，在任意一侧解绑即可。
- **交给伙伴**：可以在伙伴的「消息平台」页把已绑定的机器人交给伙伴。连接会从
  「设置 → IM 机器人」移出，之后的聊天跟着伙伴走。

## 7. 排障

| 现象 | 先检查什么 |
| --- | --- |
| 提示错误码 21001 | 平台策略拦截，不是 Cindy 的设置项能解决的。核对开发者账号、应用和企业状态；都正常时联系飞书客服。 |
| 状态「已连接」，私聊没有反应 | 事件订阅是否为长连接、是否添加了 `im.message.receive_v1`，改完是否重新发版；到开放平台的「运营监控 → 日志检索 → 事件日志检索」确认事件是否送达。 |
| 能收到消息，但回复发不出去 | 应用是否添加了机器人能力、是否开通 `im:message:send_as_bot`；最近是否重置过 App Secret，重置后需要在 Cindy 里重新填写。 |
| 群 @ 有回复但没有上下文 | 是否开通 `im:message.group_msg` 和 `im:message.group_msg.include_bot:read`，开通后是否重新发版。 |
| 「已被另一台设备使用」 | 同一个 App ID 在别处仍连着，在任意一侧解绑。 |
| 飞书里搜不到机器人 | 搜应用里设置的机器人名称，并确认自己在可用范围内；自建应用只在本企业内可见。 |
| 飞书和 Lark 混用 | 应用、Cindy 里选的服务、打开的控制台要属于同一个平台。 |

Cindy 工作电脑上的日志也会记录连接细节，可以搜索 `bot open_id resolved`、
`TOFU: claimed owner`、`fetchBotOpenId failed`、`exceed_conn_limit`，以及
`tenant_access_token` 相关的报错。

## 8. 附录

**Scope、事件与回调速查**

| 类型 | 标识 | 作用 |
| --- | --- | --- |
| 权限 | `im:message.p2p_msg:readonly` | 读取单聊消息 |
| 权限 | `im:message:send_as_bot` | 以应用身份发消息 |
| 权限 | `im:message.group_at_msg:readonly` | 接收群内 @ 消息 |
| 权限 | `im:message.group_msg` / `im:message.group_msg.include_bot:read` | 读取群历史与其他机器人消息（敏感） |
| 权限 | `im:chat:readonly` | 读取群基本信息（可选） |
| 事件 | `im.message.receive_v1` | 接收消息 |
| 回调 | `card.action.trigger` | 卡片按钮回传 |
