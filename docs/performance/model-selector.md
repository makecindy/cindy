# Desktop 模型选择器：测宽与展开性能

2026-11-09，Issue [#9403](https://github.com/makecindy/cindy/issues/9403)，
对照基线 `c35521b378`。

## 改动与范围

统一模型面板切换供应商、引擎或搜索过滤后，会保留一份不可见的全目录来测量宽度，
防止切换视图时弹窗变窄。原实现为这份目录挂载完整模型行，重复创建图标、按钮、
来源详情和来源配额订阅。

测宽行现在复用 `UnifiedModelRow` 的文字、价格和排版，固定尺寸图标及按钮改为等宽
占位，不挂载不参与固有宽度计算的来源详情。可见行、收藏及配置交互保留原实现。
`MorphPopover` 在已经提交起始几何后，只等一帧开始展开；减少动态效果时立即应用终态。
220 ms 的形变曲线、起止尺寸和焦点规则保持不变。

默认「全部」视图本来就不挂载隐藏测宽列表，因此必须分开测量展开和筛选，不能把
隐藏节点的减少归为默认展开的收益。此次没有做虚拟列表，也没有修改任务／伙伴切换。

## 方法

- Windows 11 x64（10.0.26200），Intel Core Ultra 7 265K，约 63 GiB 内存；Electron 42.11.12。
- 仓库 UI harness 分别构建基线和候选的生产组件；实际使用 `ModelSelector`、
  `UnifiedModelPanel`、`UnifiedModelRow`、`MorphPopover`、项目字体与主题。
- 合成 20、200、600 个模型，均分到 OpenAI 与 Anthropic；宿主能力和账号响应使用夹具。
  不读取正式用户数据，不请求真实供应商。
- 每个规模在独立页面先测基线，再测候选。每侧连续打开 14 次，每次打开「全部」、
  切换 OpenAI、关闭；前两次作为预热，后 12 次取中位数。首轮另列，未施加 CPU 节流。
- 展开计时从 DOM click 开始，到 `data-state=open` 后的下一次 rAF；筛选计时到 click
  后的第二次 rAF。它们是组件帧边界指标，不是操作系统输入到屏幕显示的精确延迟。
- 每次操作后再等 280 ms，记录 CDP `Performance.getMetrics` 的 LayoutDuration、
  ScriptDuration、TaskDuration 差值，包含这次操作和动画收尾；没有把等待时间当作 CPU。
- 性能采样不与本轮其他构建或测试并行。单次顺序 A/B 不能排除系统负载、缓存和帧相位
  的影响，结果不作为 CI 时间阈值，也不宣称统计显著性。

## 第一阶段结果（尚未修复首次搜索增宽）

单位 ms，后 12 次的中位数，表内为「基线 → 候选」。

| 模型数 | 展开帧边界 | 供应商筛选帧边界 | 筛选 LayoutDuration | 筛选 ScriptDuration |
| --- | ---: | ---: | ---: | ---: |
| 20 | 43.30 → 25.00 | 12.45 → 23.55 | 3.28 → 2.67 | 13.03 → 8.56 |
| 200 | 146.20 → 134.85 | 76.20 → 40.60 | 24.23 → 17.37 | 89.54 → 50.90 |
| 600 | 419.35 → 408.55 | 212.25 → 109.75 | 76.91 → 47.46 | 254.30 → 143.94 |

200／600 个模型的筛选帧边界耗时降低约 47%／48%，布局耗时降低约 28%／38%。
20 个模型筛选的帧边界指标反而增加约 11 ms，虽然脚本和布局 CPU 都减少；不能称为
所有操作都更快。该指标包含 rAF 排队，低于两帧的场景需结合 CPU 和更多重复采样判断。

| 模型数 | 筛选后的总 DOM 节点 | 隐藏测宽节点 | 隐藏按钮数 | 筛选后面板宽×高（前后相同） |
| --- | ---: | ---: | ---: | --- |
| 20 | 884 → 524 | 566 → 206 | 40 → 0 | 377 × 475 |
| 200 | 8354 → 4754 | 5606 → 2006 | 400 → 0 | 386 × 475 |
| 600 | 24954 → 14154 | 16806 → 6006 | 1200 → 0 | 395 × 475 |

默认「全部」视图的节点数保持 610／5650／16850。打开的总 CPU 并没有对应大幅下降：

| 模型数 | 打开 LayoutDuration | 打开 ScriptDuration | 打开 TaskDuration | 首轮展开（各一个样本） |
| --- | ---: | ---: | ---: | ---: |
| 20 | 7.46 → 7.97 | 45.47 → 45.32 | 92.85 → 91.13 | 71.30 → 55.70 |
| 200 | 29.03 → 30.21 | 174.38 → 187.41 | 334.90 → 351.54 | 214.40 → 193.10 |
| 600 | 51.13 → 57.90 | 242.97 → 247.68 | 530.73 → 579.98 | 511.40 → 504.80 |

展开更早显现主要来自少等一帧；大目录仍然需要完整挂载可见列表，并在 220 ms 形变中
进行布局。当前结果不能称为大目录首次展开的 CPU 优化。后续应结合用户跟踪中的目录
规模与调用栈，再决定是否需要优化完整列表挂载。

测宽后恢复尺寸时的强制布局仍然保留：直接跳过该提交，在试验中会让临时测量尺寸
参与后续过渡，增加布局开销。这项试验未进入最终改动。

## 复现与回归

PowerShell（采样输出放仓库外；每次使用新文件，避免混合多轮结果）：

```powershell
$env:CINDY_MODEL_PERF_OUTPUT = Join-Path $env:TEMP ('model-selector-' + [guid]::NewGuid() + '.jsonl')
pnpm ui:check --page model-selector-performance --case all --theme light --engine electron --compare c35521b378 --timeout 60000
Remove-Item Env:CINDY_MODEL_PERF_OUTPUT
```

每个 case 依次输出基线、候选两条 JSONL，保留首轮、12 个有效样本和 DOM 计数；可用
隐藏按钮数区分当前这两种实现。省略环境变量则每侧只执行一次功能检查，不做性能统计。
截图和 UI 检查摘要由现有 `ui:check` 产出，位于忽略的 `artifacts/ui-check/`。

功能检查覆盖打开、供应商过滤、返回全部后宽度稳定、Escape 关闭、真实 CSS width
过渡及 reduced-motion 直切。单元回归覆盖第一帧显示、关闭打断尚未执行的展开帧，
并复用已有统一模型面板和焦点／键盘测试。性能夹具没有接入常规 CI。

本轮验证：

- `morphPopover.test.tsx` 与 `unifiedModelPanelRendering.test.tsx`：217 项通过；
  MorphPopover 文件测试执行约 1.43 秒。
- Desktop 类型检查、`check:test-hygiene`、`check:dev-docs` 通过。
- 性能夹具三个规模的浅色 A/B 通过，默认规模的浅深色功能检查均通过。
- `pnpm ui:check --changed --theme all --case default --engine electron --timeout 30000`：
  42/46 通过，已查看全部 overview；没有修改或跳过失败检查。
  `im-default-model` 两个主题因缺少 AuthProvider 无法启动，单独浅色 A/B 在基线与
  候选均复现同一错误。`pr-popover` 两个主题在大矩阵中记录 sandbox iframe 脚本被
  禁止的控制台错误，随后单独浅色、深色 A/B 均通过；大矩阵下触发原因未定位，
  不把复跑通过写成该夹具问题已修复。

上述性能数字来自隔离的 Electron 组件验证，未验证 macOS 原生窗口响应、真实账号网络、全应用
长期运行状态或 GPU 实际呈现，不能据此认定 #9403 已修复。已在
[Issue 回复](https://github.com/makecindy/cindy/issues/9403#issuecomment-6731944837)
请求用户使用「性能跟踪」录制展开模型列表及切换任务／伙伴，并提供报告编号、版本及
冷启动／长时间运行条件。包含修改的版本可用后，应按同一操作与条件复录作对照。

## 首次搜索增宽修复与复验

同日继续修复上述 4 px 问题。可见列表使用 `morph-panel-list-scroll` 的 8 px 滚动条，
隐藏测宽列表原先只设置了 `scrollbar-gutter:stable`，因而保留全局 12 px 的槽宽。
测宽列表现在复用相同滚动条样式，不额外增加节点或尺寸读取。
扩展验收还发现空收藏提示的全文会参与 `max-content` 计算，将 373 px 面板撑到 404 px；
空态现在复用跨 Harness 提示的 `w-0 min-w-full` 布局，在模型决定的宽度内换行。
没有修改文案、字号、颜色或弹层动效。

浏览器回归先红后绿：分别复现首次搜索 `373 → 377`、空收藏 `373 → 404`，再验证修复。
检查使用生产 `ModelSelector`，测实际宽度；原有测试只比较过滤之后的视图，错过了第一次增宽。
检查加入现有 UI 夹具，没有增加只检查 CSS 字符串的单测。真实动画的检查从点击发起时就开始观察，
避免大列表挂载后才启动下一条自动化命令而错过已结束的动画；保留运行中的宽度过渡断言。

### 性能复测

以第一阶段优化后的代码为本轮基线，仍使用上述 14 轮、去掉前两轮、剩余 12 轮取中位数的方法。
单位 ms，修复前 → 修复后：

| 模型数 | 展开帧边界 | 筛选帧边界 | 筛选布局 | 筛选脚本 |
| --- | ---: | ---: | ---: | ---: |
| 20 | 27.45 → 28.50 | 16.95 → 16.60 | 2.51 → 0.80 | 8.19 → 3.24 |
| 200 | 132.20 → 133.80 | 38.70 → 36.25 | 16.40 → 4.60 | 50.34 → 18.55 |
| 600 | 411.40 → 444.65 | 110.15 → 113.60 | 49.15 → 16.35 | 146.65 → 59.31 |

首轮顺序 A/B 的 600 模型展开增加约 8%，因此追加同一构建内的 **旧槽宽／修复／修复／旧槽宽**
交替对照。对照仅在测试页面把隐藏测宽列表的滚动条还原为 12 px，确实重现 `391 → 395`；
修复侧保持生产样式。每组 14 轮、各去掉两轮预热，每侧合计 24 个有效样本。完整客户端、构建
和其他测试在这次性能采样期间均已停止。此对照隔离槽宽的影响，不代替完整源码版本 A/B。

| 600 模型，交替对照 | 旧 12 px 槽宽 | 修复后 8 px 槽宽 |
| --- | ---: | ---: |
| 展开帧边界 | 433.45 | 440.80 |
| 展开布局 | 64.30 | 65.03 |
| 展开脚本 | 259.34 | 271.85 |
| 筛选帧边界 | 114.90 | 110.20 |
| 筛选布局 | 52.71 | 15.52 |
| 筛选脚本 | 152.19 | 57.56 |

筛选布局减少约 71%、脚本减少约 62%，符合消除多余宽度变化和重排的预期。展开帧边界相差约
1.7%、展开脚本约 4.8%，不把它写成首次展开提速，也不宣称统计显著性。当前采样未发现明显
性能回退；这仍不是低端硬件、macOS 或长时间运行场景的保证。
