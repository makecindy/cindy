# 自定义端点名称搜索：最小改动技术方案

状态：已在 2026-10-30 主干基线上实施，准备 Draft PR 与独立验收包。

## 1. 目标与范围

只在「添加自定义供应商」新建表单的「显示名称」输入框增加供应商搜索下拉。当前添加供应商入口支持的完整供应商集合都必须可搜索，选择后进入与原入口相同的配置流程。用户可以不选择任何结果，继续创建任意名称的自定义端点。

严格边界：

- 添加供应商页面的布局、搜索行为、排序、分组和配置流程保持不变。
- 编辑已有连接时的名称字段保持原行为，不增加跳转，避免改名改变连接身份。
- URL、API 密钥、协议、模型、请求头、连接测试、获取模型列表、保存与校验全部沿用现有实现。
- 不修改服务端、目录内容、IPC、数据库、凭证存储、授权流程和运行时路由。
- 不新增搜索服务、持久缓存、拼音库、供应商白名单或独立配置表单。
- HTML 是交互示例，里面的 7 家数据不进入生产代码；不据此缩减真实目录。

## 2. 已核对的复用点

源码基准目录：`apps/desktop/src/renderer/components/settings/`。

| 位置 | 当前能力 | 本次使用方式 |
| --- | --- | --- |
| `ProviderConnectionDialog.tsx` | 名称输入、新建/编辑区分、`presets`、`listProviderPresets()`、内置离线预设、Popover 与 `childLayer` | 在现有名称字段接入下拉，沿用加载及浮层管理 |
| `AddProviderWizard.tsx` | `oauthChoices`、`builtinApiKeyChoices`、完整预设及本地服务分支 | 作为候选范围和动作的事实来源 |
| 同上 `WizardEntry` | `{ kind: 'builtin', providerId }`、`{ kind: 'preset', presetId }` | 复用直达配置入口 |
| 同上 `pickPreset` | API 预设、预设 OAuth、LM Studio 特殊处理 | 保留原分流，不在搜索组件复制 |
| 同上 `connectOllama` | Ollama 检测、连接与安装引导 | 保留独立入口，不能误当成通用 API 模板 |
| `ProvidersSection.tsx` | `wizard`、`dialog`、完成后刷新及选中连接 | 负责搜索结果到现有配置入口的切换 |
| `presetDisplayName`、`sortPresetsForRegion`、现有品牌图标 | 名称、区域排序和品牌展示 | 直接复用，不手写名称/图标/默认 URL |

当前 `applyPreset` 是在自定义表单内填值，不能代替本需求的「进入已有配置页面」。原有 `WizardEntry` 尚未覆盖 Ollama / 托管 llama.cpp 专属动作，不能宣称所有目标仅传 `presetId` 就能正确跳转。

## 3. 候选来源与全量覆盖

### 3.1 同源目录

沿用 `listProviderPresets()` 返回的运行期完整预设及 `ProvidersSection` 已持有的 `providers`。不从 HTML、前端常量或仅有已连接账号的列表生成供应商目录。保留现有加载、取消异步响应与离线回退策略，不自行重新合并远端与内置目录。

将向导现有候选资格判断和入口标识提取为 settings 内的小型纯函数，供名称搜索使用；向导采用等价调用，保证提取前后集合、顺序、分组和行为一致。只提取确实需要共享的判断，不重构向导状态机或所有行组件。

候选覆盖以下入口：内置订阅、内置 API key、普通预设、本地连接与高级本地预设、Ollama / 托管 llama.cpp 专属连接入口。推荐区域和普通区域重复出现的同一入口只计一次，不能只收集当前推荐结果。

「全部」指当前执行端、账号与平台条件下，添加供应商入口支持的完整集合，不是固定数量。沿用已有可用性和账号限制，不借搜索绕过限制或新增供应商能力。已有连接的重复添加政策保持原样；搜索供应商品牌不等于搜索和编辑用户已有连接实例。

### 3.2 搜索规则

- 对输入做 `trim().toLowerCase()`，名称用包含匹配。
- 搜索当前显示名称以及目录已有的 `name`、`nameEn`、`nameZhTW`；字段缺失直接跳过。
- 不新增人工别名字典；本期不做拼音、模糊纠错或协议关键字搜索。协议仅作为既有摘要展示，避免搜索 `open` 命中所有 OpenAI 兼容厂商。
- 空输入不展开候选；非空输入在本地内存过滤，不逐次请求接口。
- 不限前 5/10 条；多结果通过有最大高度的可滚动下拉展示，全部可到达。
- 保留现有区域排序，不新增地域过滤。
- 按「入口类型 + 稳定 ID」去重，不按展示名称去重。同品牌不同接入渠道可以分别展示，用原有摘要区分，不能合并后误跳转。

生产覆盖验收以真实候选集合为准，不能用手写几个品牌的测试代替。

## 4. 跳转与状态

搜索结果携带类型化目标，不通过名称、数组下标、URL 或字符串拼接猜目标。

| 结果类型 | 目标 | 复用路径 |
| --- | --- | --- |
| 内置订阅 / 内置 API key | `builtin + providerId` | `WizardEntry` 内置入口，由现有鉴权类型决定表单 |
| 普通 / 本地高级预设 | `preset + presetId` | `WizardEntry` → `pickPreset`，包含原有 OAuth 与 LM Studio 分流 |
| Ollama / 托管 llama.cpp 专属连接 | 新增最小的专属 entry 分支 | 调用既有 `connectOllama` / `connectLlamaCpp`，不复制检测、启动或安装逻辑 |

建议给新建表单增加可选回调 `onSelectProvider(target)`，由 `ProvidersSection` 接收并打开对应向导入口。没有该回调的其他使用方保持现状；不为整个应用引入新路由系统。

选中结果只触发现有入口动作。API key、模型、协议和连接参数由目标页面原有逻辑初始化，不从当前自定义草稿自动复制；输入或悬停不触发授权、连接、测试或保存。

自定义草稿在本次搜索跳转期间保留在内存，目标流程取消后恢复，输入不丢失。优先保留原表单组件实例、临时隐藏其 Dialog 呈现并停用其焦点陷阱；不使用 CSS 隐藏一个仍活动的模态层，不另做持久草稿或复制保存逻辑。成功完成沿用 `onDone` 刷新并选中连接，同时释放该临时草稿。普通取消及非搜索入口保持原语义。

目标解析必须在切换前校验；目录更新使目标失效或加载失败时留在自定义表单，保留输入并显示局部可理解的提示，不静默退回向导首页冒充跳转成功。复用入口如需补充错误/取消回调，只服务此搜索来源，默认行为保持不变。

## 5. 下拉交互与视觉

- 名称输入仍是自由文本，不要求选择目录项才能保存。
- 直接展示结果行，不显示「匹配的供应商」标题。
- 有匹配可点击跳转，无匹配保留自定义填写提示；不制造校验错误。
- 点击外部或 Escape 关闭下拉，保留原值；Escape 优先关闭子层，不关闭整个表单。
- 支持上下方向键移动、Enter 选择、Tab 正常离开；无激活项时 Enter 不隐式选择首项，中文输入法组合期间不触发选择。
- 复用现有 Popover、名称输入、品牌展示和主题 token；接入原 `childLayer` 互斥与焦点归还，避免模型选择层同时打开。
- 使用正确的 combobox/listbox 语义、展开状态和活动项关联，不把按钮嵌套进按钮。
- 长名称换行或省略、多结果滚动、320px 窄屏不横向溢出；Light/Dark 同时实现。
- HTML 仅作为交互参考；尺寸、字体、圆角和颜色以现有生产组件及设计规范为准，不照搬稿内简化样式。

## 6. 最小改动清单

| 文件 | 允许的改动 |
| --- | --- |
| `ProviderConnectionDialog.tsx` | 新建名称字段的搜索下拉、候选输入/选择回调、复用子层管理；必要的临时暂停呈现支持 |
| `ProvidersSection.tsx` | 传入现有 providers、接收目标、协调现有向导与草稿恢复 |
| `AddProviderWizard.tsx` | 候选判断等价提取、缺失的专属直达入口、仅搜索来源所需的失败/取消回传；不改选择页 UI 或业务流程 |
| settings 内一个小型 helper（建议 `providerSearch.ts`） | 候选投影、匹配和稳定目标类型；不搬入跨包通用架构 |
| 对应现有测试及必要的 i18n 文件 | 搜索与跳转回归；优先复用已有文案，仅补确实缺失的字符串 |

「添加供应商页面不改」指用户界面和行为不变；为复用其真实入口允许以上有限内部适配，不能借机重构。当前工作区 `AddProviderWizard.tsx` 已有其他改动，实施前必须核对差异并保留。

## 7. 验收与验证

1. 全量覆盖：对实际候选集合逐项用其完整名称搜索，断言结果包含其稳定目标；对每种已存在的本地化名称重复验证。目录新增条目后自动参与测试，无需扩展手写白名单。
2. 正确路由：逐类断言搜索结果与向导原行点击的目标一致；覆盖 API、订阅、预设 OAuth、内置 API key、Ollama、LM Studio。相同展示名的不同渠道不串路由。
3. 输入：部分匹配、大小写、首尾空格、中文、多结果滚动、空输入和无匹配；自由文本仍通过原保存路径。
4. 生命周期：仅输入不创建连接；取消跳转恢复草稿；完成只刷新一次；目标失效不跳错页面；目录迟到响应和重复点击不覆盖新选择。
5. 不变性：提取前后添加供应商候选、顺序与分组等价；编辑连接、原预设填充、测试连接、模型发现、请求头和保存流程原测试继续通过。
6. 可访问性：键盘、输入法、Escape 层级、焦点恢复、窄屏及双模式；视觉目检记录真实执行情况，不以 token 复用代替截图验证。

## 9. 交付实现

本次交付分支从当前 `origin/main` 独立建立，只带名称搜索相关实现、测试和设计稿；原工作区其它未提交改动保留原位。

- 运行期全量预设与语音接入通过既有 `listProviderPresets()` / `withSpeechApiPresets()` 提供；内置候选资格判断与向导共用。
- 托管 llama.cpp 与目录中连接已有服务的 llama.cpp 保持两个稳定目标，按既有入口分别处理；Ollama 同样复用现有专属动作。
- 主干已经具备统一 Radix Dialog / `useDialogExit`，直接复用其模态和焦点生命周期，不新增平行 FocusScope；仅在异步搜索目标就绪后聚焦原表单。
- 单页验证使用真实生产组件、完整内置目录与模拟宿主接口；匹配、无匹配、跳转三种状态覆盖 Light/Dark 与桌面/窄屏。真实凭证、授权与持久化仍按原功能执行，不以模拟验证冒充实际账号验收。
- PR 包维持 Global 端点，使用独立应用身份、独立用户目录和版本 `0.0.0`；构建隔离设置不进入业务 PR，不覆盖现有 Cindy 或读取其正式数据库。
