# 插件调用统计：客户端实施说明

本功能保留当前电脑、当前账户的个人调用记录，并在插件目录提供授权共享统计时展示下载和使用次数。设计与真实 UI 已由用户确认；服务端独立交付见 [cindy-server PR #887](https://github.com/xindong/cindy-server/pull/887)，此说明不代表生产服务已部署。

## 个人记录

- GhostPipeDispatcher 通过可见性、启用、工具声明、权限及账户检查，且 sendToGhost 接受派发后计一次；已有 callId 去重。派发后的失败、超时或取消只更新 outcome，不增加次数；调试入口不计。
- 账户 SQLite 追加 plugin_usage_subjects 与 plugin_usage_events。0128_demonic_odin 一次创建两张表及待上报部分索引；基于主干既有 0126/0127 由 Drizzle 重新生成。历史 migration 不修改；7 日窗口是滚动 168 小时的查询条件，不是记录保存期限。
- 参数、结果正文和凭证不进入记录。个人明细保留宿主工具名、任务引用、版本/发布身份与结果状态，不作为计费级审计。
- 普通升级/回滚保留连续安装主体；本地卸载重装分开，来源可验证的市场重装延续主体。禁用、卸载及任务删除不删除历史。
- 绑定、派发和查询使用实际实例键；市场账本按真实 namespace 精确查来源。同名根/组织实例不能借用另一份记录或来源。旧无 namespace 安装继续沿既有 helper 的兼容路径工作，不要求重装、重新批准或配置。
- owner/clientEpoch 与 historyGeneration 隔离切号和清除。清除在一个 worker 事务中递增代际并删除明细，迟到结果只 UPDATE；旧句柄不重放。

## 可选共享统计与上报

- 下载来自 downloadStatistics.requestCount：成功取得下载 URL 的次数，包含升级、重装和再次取票，**不是成功安装量**。没有成功安装字段或估算。
- 使用来自 usageStatistics={usageCount,usageCountLast7Days,asOf}；非负十进制字符串按 BigInt 显示，缺失/非法指标独立隐藏，真实 0 显示。schemaVersion 仍为 2，旧服务省略字段不会破坏目录或安装功能。
- public/organization 只消费原有授权目录响应；组织的成员、角色、部门门禁不扩大。local/custom 不因为显示 public 标签而进入共享范围。共享读取缓存 60 秒，不缓存个人查询。
- 仅在当前账户、非 local 模式、允许分析数据且来源账本与安装字节身份验证通过时，为新派发冻结 reportTarget。发送前再次核对 owner、服务根和来源；不跨服务根重试、不借用后来登录账户。
- wire 回执仅发送 eventId、releaseId、occurredAt；不发送工具名、任务 ID、参数/结果正文或凭证。SQLite 原记录保存 pending/sent/rejected 状态，批量 ACK/duplicate 去重、退避重试；不开文件 outbox，不补传未取得合法目标的旧记录。
- 关闭分析数据后暂停发送；切号/退出在数据库关闭前有界收尾。崩溃、磁盘故障或尚未绑定的派发可能漏记，不承诺 exactly-once。
- 旧服务未实现回执端点时退避保留 pending；共享字段缺失时 UI 隐藏。个人清除不撤销已被服务端接收的聚合记录。

## 已确认 UI

- 列表灰字保留范围、作者（存在时）与累计下载，移出版本和机器 ID。
- 已安装和市场详情的版本旁显示累计共享下载与使用；内容区不超过 520px 时 metadata 放到 hero 下一整行。
- 个人卡只展示最近调用、近 7 日调用，没有任务列表、图标、分割线、更多菜单或正常态刷新按钮；清除直接放标题右侧，保留确认与取消，失败态仍可重试。卡片保持打开时每 5 秒查询本地统计，隐藏时暂停、再次可见时读取；同一轮查询不重叠，离开实例或清除后的旧响应不覆盖新读数。
- 使用既有语义 token，双主题实现。标题 14/500/20，时间与次数 14/400/20，标签 12/400/16；padding 16、容器圆角 12、描边 1、间距 12/4/16。卡片跟随父内容宽度、自然高度，字号和行高随既有设置缩放。

真实截图及受测版本边界见 [公开验收摘要](acceptance/plugin-statistics-pr/README.md)。图片为隔离 Electron 中真实页面，不是生成稿或伪造统计。

## 通用调用入口补全

本次补全宿主已有入口的统计，不修改具体插件、交互界面、manifest 或权限声明。

- 工具派发保留旧确认点；新增 `tasks.send` 与 `targets.send`（项目、任务、伙伴）的输入接受事实。
  创建空任务、目标查询、附件处理不另计。独立输入被接受才计一次；入队不等于完成，接受后取消仍保留记录。
- Host 生成调用身份并校验可选 `invocationId`，使工具内部提交与父调用共用一条记录。
  关联绑定账号、数据库实例、安装批准、运行代次及清除代次，最长 10 分钟。
  SDK 类型及插件作者手册同步该字段，preload 继续透传既有请求，不新增计数接口。
  旧插件不传关联仍可调用，但工具与独立输入分别计数，不能宣称已自动识别所有用户操作。
- 新增 `entry_kind` 区分 `tool` / `execution`；Drizzle 0132 仅追加默认 `tool` 的列，保留旧调用事实。
  同次输入沿用既有回执的 Host 身份及 requestKey，重放不重新派发或增量；统计错误不改变业务接受结果。
- `entry_kind` 只保留在本机账本，工具及执行事实复用既有 `usage-events` 接口，仍只发送
  `eventId`、`releaseId`、`occurredAt`。服务端沿用按事件身份去重累加的规则，不新增接口、分类聚合或服务端改动。
- 保留原有来源、登录、分析同意及共享目标冻结规则；不发送正文、图片、参数或路径。
  统计保持尽力记录，业务回执与统计不是跨模块原子事务，崩溃或绑定尚未就绪可能漏记；不承诺计费级 exactly-once。
  未知投递结果不凭请求到达或插件响应猜接受，不重放未知操作来补统计。
- 纯插件内部展示仍没有 Host 可确认的业务事实，本次不覆盖，也不新增桌面展示或其它受管交互能力。
  插件不能自报增量；真实自动化或修改开源客户端的滥用仍不属于完整反作弊保证。
