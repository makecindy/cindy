# API 估价原位编辑：纯 UI 重做方案

## 目标与基线

用户目标只有一个：将模型高级设置中的「编辑 API 估价」弹窗入口，改成在原报价区域直接编辑数字，并提供重置。
本轮从上游 main 的 `9fb822760d` 重新开始；旧 PR #8722 的实现、Main 修复和未提交补丁均不移植。
旧分支和工作区保留，不删除、不改写历史。

## 复用清单

| 能力 | 直接复用的现有实现 | 本轮允许的变化 |
| --- | --- | --- |
| 读取 | `maker.getModelPriceOverride(target)` | 在报价区域挂载时读取，原 target 不变 |
| 表单默认值 | `ModelPriceOverrideDialog.formFromView` | 数值改为原位输入框，未知值显示 — |
| 输入校验 | 原 `parseRequiredPrice / parseOptionalPrice` | 不新增数字协议；原位模式非法输入提示并恢复原值 |
| 保存 | 原 `save` 与 `maker.setModelPriceOverride(target, desired)` | 由按钮触发改为离开报价区触发；相同表单产生相同 target/payload |
| 重置 | 原 `reset` 与 `maker.resetModelPriceOverride(target)` | 按钮搬到报价标题旁；未保存草稿仅本地恢复 |
| 引擎、币种 | 旧表单已有选择与允许币种 | 保留；引擎切换前完成当前表单保存 |
| 参考价、冲突提示 | 原 API 回执与现有展示组件 | 原文复用，复杂价目在参考详情中保留 |
| 目标切换与迟到响应 | 原 mutation epoch、读取取消保护 | 保留，不建立新的同步状态机 |
| 视觉 | 原高级设置行、Button、SegmentedControl、语义 token | 保留原布局、字号、间距和双主题 |

## 交互合同

1. 删除高级设置内的「编辑 API 估价」入口，以原表单组件的 inline 呈现替代数字展示。
2. 读取、聚焦、未修改的离开均不写入；价格输入框之间移动只保留本次草稿，离开报价编辑区时调用一次原保存流程。
3. Enter 不提交；第一次普通 Esc 离开价格字段并按离开编辑区保存，后续 Esc 才关闭外层。组合键、输入法合成与长按重复沿用设计规则。
4. 输入／输出仍必填且不小于零，合法 0 保留；缓存空值沿用原可选含义。原位模式非法或不完整输入离开时提示并恢复原有效表单，不增加关闭拦截或草稿持久化。
5. 重置有持久覆盖时调用原重置接口；只有未保存草稿时恢复当前已读取值，不调用写接口。
6. 保存／重置期间避免重复提交，保留键盘遍历并禁止关闭／切换当前编辑目标；不接管停用、删除等动作自身的异步生命周期。
7. 保存失败保留可重试草稿；读写成功只采用原接口回执，不再补读其他价格来源。
8. XD、组织管理、付费锁定以及媒体报价保持原只读与能力边界。模型别名组及其他高级设置原样保留。
9. 原独立弹窗入口仍存在时继续使用原按钮保存方式，新增的失焦交互只作用于 inline 呈现。

## 明确禁止的改动

- 不修改 Main、preload、IPC handler／参数、shared 契约或服务端。
- 不修改公共价／连接价／订阅价的优先级、稀疏覆盖比较与合并规则。
- 不修改费用公式、用量统计、历史估算、价格目录、权限、持久化格式或已有记录。
- 不新增 getReferenceModelPricing 补读、供应商通知订阅、实时草稿合并、保存前重读或后台重试。
- 不修改图片输入、协议、上下文、模型停用／删除／别名组语义。
- 不因 review 顺带修这些领域；若原接口存在问题，记录复现和影响，作为独立任务讨论。

## 文件边界

预计生产代码只涉及两个原组件：

- `ModelPriceOverrideDialog.tsx`：保留原读写／校验，增加原位呈现和必要失焦适配。
- `ModelAdvancedDrawer.tsx`：替换原弹窗入口，复用只读参考展示和原有准入条件。

必要配套限于这两个组件的已有测试、所属 settings-search 定义、现有语言文件、
model-advanced 单页 fixture，以及本方案。设置搜索只登记报价入口，不登记用户模型数据。
不新增业务状态管理层，不改设计 token、基础组件或测试／CI 规则。

- 对照旧弹窗验证：同 target、同输入、同保存 payload；重置仍调用同一接口。

- 检查原独立弹窗行为、原只读行、模型别名组动作及相邻设置没有变化。

- 最终范围检查必须确认 Main/preload/shared/packages 无差异；不能用“测试通过”替代此项。
