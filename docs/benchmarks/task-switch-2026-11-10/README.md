后续的渲染通知优化及独立前后对比见[第二批报告](renderer-follow-up.md)。

基线为 `70eb974da4d3792cc5feabc8bdc9ee1e1f06233d`，修改版为本工作区的三项修复。
2026-11-10 在同一台 Windows 机器上测试，Node 24.14.1、Electron 42.11.12。
[逐轮原始数据](results.json)包含热点测试与完整客户端的全部采样。
中位数统一取排序后两个中间样本的平均值（偶数样本），P95 使用 nearest rank。
2026-11-10 提交前按此口径重算第一批汇总，原始采样未改动；此前汇总取的是下中位数。

结论：技能列表校验的连续阻塞和插件列表重复读取明显减少；普通模拟任务的切换耗时仅小幅变化，
页面长任务没有减少。数据不能证明原日志中的全部卡顿已经解决，也不是线上发布后的效果。

## 修改与功能边界

- `/pr` 引导使用现有异步工作目录策略 Hook。策略未知时不展示尚未确认的引导项；
  点击时仍读取最新安装与禁用状态，安装/启用入口、返回原任务、保留草稿和回填 `/pr` 均保留。
- 技能列表通过宿主内部回调取得异步校验后的禁用路径，复用到内置技能投影。
  未运行任务的列表不再触发重复的同步全文哈希；正在运行的任务仍使用启动时的技能快照；
  SSH 判定与真实执行入口不变，异步完整性校验的最终检查未删除。
- 插件列表投影按扫描批次读取安装记录。异步扫描结束前重新核对全部记录，发生变化就重试。
  同名不同命名空间、损坏记录与授权读取保持原判据；授权入口仍实时读取，不使用展示快照。
  未改变安装记录、批准记录或用户配置的格式，不要求重新安装或重新授权。

## 主进程热点

手工基准：`apps/desktop/scripts/benchmark-task-switch-stalls.mjs`，不进入常规 CI。
从 Git 基线和当前文件分别打包真实 `Maker`、`BaseAgent`、`GhostManager`、安装账本及技能校验代码，
使用临时目录里的 30 个合成插件、3 个内置技能和额外 120 个技能引用文件。
两版预热后交替先后顺序，各测 12 轮；构建、准备、安装不计时。

技能场景隔离的是 **列表激活与完整性校验**：Agent 自身扫描返回固定空列表，
不包含模型进程、网络或原生 Agent 扫描时间。插件场景调用实际 `GhostManager.listAsync()`。
同步读取次数通过 `fs.readFileSync` 计数；账本计数包含事务恢复记录读取。

| 指标 | 修改前 | 修改后 | 变化 |
| --- | ---: | ---: | ---: |
| 技能列表校验耗时，中位数 | 176.25 ms | 102.87 ms | -41.6% |
| 技能校验每轮最大事件循环间隔的中位数 | 73.49 ms | 4.02 ms | -94.5% |
| 每次技能校验同步读取技能正文 | 191 次 | 0 次 | 消除重复同步读取 |
| 30 插件完整异步扫描，中位数 | 51.57 ms | 20.86 ms | -59.6% |
| 每次插件扫描的账本相关同步文件读取 | 120 次 | 8 次 | -93.3% |

事件循环间隔用 1 ms 定时器观察，是事件循环阻塞代理值，不是操作系统原生输入延迟。
插件扫描读取从逐插件 30 轮变为初始快照与结束核对共 2 轮，保留结束核对的成本。
插件扫描最大事件循环间隔的中位数为 3.01 → 2.96 ms，基本不变；收益主要是总工作量下降。

复测命令（输出路径由调用者提供，推荐仓库外）：

```powershell
node apps/desktop/scripts/benchmark-task-switch-stalls.mjs 70eb974da4d3792cc5feabc8bdc9ee1e1f06233d <output.json>
```

## 完整客户端任务切换

两版均通过正式开发启动器运行独立 `--mock` 沙箱，沿用同一份模拟任务、30 个无订阅的合成插件、
1280 × 800 窗口和浅色主题。插件由实际管理器安装，未使用用户聊天或正式版插件数据。
使用已有 `benchmark-mock-navigation.cjs`：预热 4 个任务后，每轮切换 12 次，各跑 3 轮，共每版 36 次。
每次切换后输入相同测试文本并清空，不发送给模型。计时期间没有并行运行本次的构建或测试。
每版第一轮均开启 renderer CPU profiler，其余两轮关闭。

计时从自动化点击开始到目标路由出现后的两次动画帧，包含自动化调度开销，不等于全部异步资源加载完成。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 切换耗时中位数 | 86.35 ms | 83.93 ms |
| 切换耗时 P95 | 98.13 ms | 92.63 ms |
| 切换与随后输入期间的长任务数（≥50 ms） | 36 | 38 |
| 长任务累计耗时 | 3260 ms | 3520 ms |
| 最长长任务 | 104 ms | 129 ms |

切换中位数下降约 2.8%，样本较少且存在系统调度波动，不能当成稳定的整体性能提升。
长任务统计包含输入过程；本轮没有消除这部分阻塞，应继续定位 renderer 的剩余开销。
两版 profiler 都未采样到 `workdirPrefsSync`，因此不从采样结果推断其调用次数；
渲染期同步 IPC 的消除由真实 Hook 回归测试验证。

该沙箱中的共享内置技能版本高于此基线，日志出现保留较新 bundle 的提示。
因此完整客户端场景不能代替上面的受控技能校验测试，也没有完整重现上传日志的负载。

- `pnpm ui:check --changed --theme all`：52/52 变体通过并查看 overview。
  其自动覆盖入口为设置页依赖图，不等于对真实市场安装流程的端到端验证。
- 完整客户端两版均通过 Windows 原生任务点击验证。修改后另以原生 `SendInput`
  输入 `native input check`，由新的 UIA 状态确认文字进入输入框，未发送。

  首次探测约 10 ms，其余 0.026–0.104 ms。仅作为空闲窗口响应核验，不是压力测试的前后对比。
- 测试沙箱已停止，进程归属检查确认当前工作区无残留开发实例；数据和性能证据保留。
