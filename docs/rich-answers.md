# 流式正文与可组合组件

2026-10-18 用户确认：Cindy 提供流式编辑器和组件库，模型自由编排正文。普通任务与伙伴、外露进展与最终答案共用一套展示能力。不是完整 HTML 文件预览，也不依赖特定模型或 OpenAI 内部协议。

## 输入与展示

文本型 Harness 复用现有累积文本事件，以 `cindy-ui` 围栏承载逐行操作。每一完整操作行即可提交，无需等围栏或回答完成。普通 Markdown 仍用现有正文组件。用户消息、引用内嵌示例与文件预览不启用组件解释。

共享解析器保存稳定节点：create、append、patch、move、remove。节点按 id 更新；输入、勾选和选择值与模型默认值分开。模型的常见笔误就近挽救成可读节点：打到容器上的 append 落入该容器的隐式 markdown 子节点，裸字符串 props 与内联 children 转成正式子节点；无法挽救的内容才计入未能显示。Markdown、图片、视频、公式和 Mermaid 沿用现有文件来源与预览边界。布局仅接受组件属性，不执行模型 HTML、CSS 或 JavaScript。数值表达式只支持有界的算术/选择树；按钮默认修改本地状态，也可声明显式提交一条用户消息。

Desktop 使用原生 React 组件；Mobile 使用原生 View/Text 与既有媒体组件，不新增原生依赖或 runtime fingerprint。浅深主题取各端语义 token，窄屏按可用宽度换行。

### 跨端与双模式

同一份答案会在桌面消息列（约 560–900 px）与手机（约 320–430 px）上阅读，常在一台设备生成、另一台查看，并在生成后随时切换浅深色。公共交付说明直接告诉模型这一点：按 320 px 可读设计，不假设当前设备或模式。

2026-10-18 用户裁决：背景色与文字颜色由 Cindy 限定，避免答案花哨或出现与界面割裂的黑白反差。模型负责布局、层次、字号与间距；颜色只能写角色名：`primary` / `secondary` / `tertiary`（文字层级）和 `success` / `warning` / `danger`（仅表达结果、提醒、问题）。两端把角色映射到各自主题 token（Desktop 用 CSS 变量，Mobile 用当前调色板），切换模式自动跟随。`backgroundColor`、`borderColor`、字面颜色与旧的 `{light, dark}` 颜色对一律忽略；边框固定为 1 px 主题边框色。图表与 SVG 的颜色同样只接受角色（SVG 另可用 `none`）。已保存的旧答案按同一规则显示，不再出现自定义背景。

数值宽度限定不超过可用宽度，最小宽度不超过容器，固定尺寸在窄屏缩小而不横向溢出。

## 恢复与容量

原始操作流作为原消息正文持久保存，重新打开时从原文还原文档。完整累计文本快照天然包含断线前的操作；序号重复不重复执行，缺口保留已提交内容并报告未能显示部分。历史传输超过原有预算时先合并为完整树快照，仍超限则使用可读正文降级并保留原有远程截断标记，不传半截操作 JSON。

用户值在查看端保存，按账号、消息、片段隔离；手机另包含来源设备和任务身份，默认不进入模型上下文；只有用户点击发送时，`send` 表达式中明确引用的值才随可见用户消息提交。缓存最多 256 个片段、总序列化 524288 个字符；未修改控件继续使用模型默认值。异步读取不会覆盖加载期间新输入。当前查看端之间不自动同步控件状态。旧客户端没有组件渲染器，可能显示原始围栏；对不支持组件的渠道可使用普通 Markdown。

## 公共交付入口

统一路径只有：**公共交付说明与已有用户偏好 → 当前模型生成 → Cindy 流式展示**。

`ANSWER_DELIVERY_PROMPT` 在 `packages/maker-shared/src/richAnswerGuide.ts` 定义一次；Desktop Host 通过 runtime config 的 `answerDeliveryPrompt` 提供给三个适配器。Codex 使用现有 developer instructions，Claude Code 使用现有 system append（本地与远端），Pi 使用现有 `--append-system-prompt`。普通任务和伙伴都使用这一段，不因伙伴跳过普通 Cindy 身份说明而丢失交付能力。隔离 Reviewer 不注入这一段。

这是一项明确的宿主提示词改动：直接告诉当前模型可用组件、流式操作格式与交互边界。无需先调用发现工具，也不增加第二次答案优化调用。能力查询仍返回同一份协议，避免两份规则。用户偏好沿用已有 userPrompt、伙伴用户档案与当轮请求，不新增偏好存储，不修改或覆盖 CLI 二进制、原生提示词和模型缓存。

模型自由组合布局；简单回答、代码和显式要求的格式保持简洁。组件仅适用于 Cindy 正文，外部渠道沿用其格式。编辑控件只改变本地查看状态；带 `send` 的按钮或表单在显式点击后提交可见用户消息，不直接执行工具。原有执行、停止、上下文压缩及工作过程折叠流程不变。计算可引用输入与其它计算节点；缺失、循环或非法计算显示局部不可用，不伪造零值。流式尚未到达的引用先等待。

2026-10-27 用户确认将组件改为按需使用：普通交流、解释、进度和简短结果默认直接使用文字或 Markdown；图表、交互、媒体展示或结构化排版明显有助于理解时，以及用户明确要求组件时，才使用 `cindy-ui`。普通文字不为装饰而套进 `text` / `markdown` 组件，混合回答仅把受益的部分做成组件，周围说明保留 Markdown。模型仍可自主选择有用的可视化，用户指定格式优先。

这取代此前“各种题材和答案长度都主动使用组件”的要求；适用判据放在共用 `RICH_ANSWER_GUIDE`，宿主注入与能力查询读同一份说明。协议例子只说明选用组件后的语法，不要求每条回复套用。组件协议、颜色边界和三个 Harness 的注入位置不变，也不增加发现调用或额外模型调用。更新后的静态文本首次使用会使对应提示词缓存前缀变化，后续请求仍保持稳定。

流程图按阅读效果与用户指定格式选择表达方式：`diagram` 是 Mermaid 自动布局的入口，不是所有流程图的必选组件；需要控制几何与连线路径时可以用 `svg`，也可以把小图与文字、分栏、折叠区或页签组合。两种格式都不能保证天然易读。用户要求画图或看样稿时应实际展示图，而不是只描述布局方案。

复杂图应保留判断、分支、汇合和回路，通过路径分组、结果标注及对应清楚的连接点减少交叉线；分段展示时必须交代段间关系并保留完整逻辑。按实际显示宽度检查文字，不把整张 Mermaid 或 SVG 缩小当成可读性方案。`svg` 没有内建缩放、平移或节点点击能力；需要小屏可读时用现有组件分段组织，不虚构渲染器交互。此选择指引复用上述公共入口，不改 Harness 原生指令、组件协议或历史消息渲染。

当前图表外观仍由组件固定，仅支持单系列折线/条形与数据标签。用户已否决其视觉效果；下述数据正确性和展示检查不代表视觉设计通过。2026-10-18 的通用交付说明完成过三 Harness 真实生成复测（见后文），图表设计空间与默认样式仍待优化；这不代表本次按需使用规则已完成三 Harness 复测。

## 网站视频（2026-10-18）

文件视频直接嵌在消息流中，提供播放、暂停和拖动进度；全屏只是可选操作。
Desktop 保留播放器底部的原生全屏按钮，使用 Fullscreen API 将视频铺满屏幕；
退出或按 Esc 返回原位置，保留同一个播放器与播放进度。主进程仅允许 Cindy 自有
顶层页面的全屏请求，嵌入页面、无手势自动全屏与屏幕采集仍按原边界拒绝。
本地视频的右键菜单在全屏时进入独立顶层，保留复制和打开所在目录；关闭菜单、
退出全屏或卸载播放器时清理该层，菜单关闭后焦点回到视频。
媒体加载错误显示「视频不可用」并提供重试；仅凭播放器 error 不判断源文件已经丢失。
Desktop 复用受控媒体协议与浏览器播放控件，`xdt-file:` 同时列入 `media-src`，
本地文件仍由原协议核验路径与类型。Mobile 在点击播放后通过既有远程媒体取件服务
解析源地址，再挂载原生播放器；目录外文件同样只在显式点击后取件，不自动预取。
离开消息/页面或应用进入后台时暂停，回到页面不自动续播；失败可重新取件。
历史消息沿原地址重开，不重写原文件，不公开上传媒体，也不新增原生依赖。
直连取件与 OSS 复用媒体 MIME 映射；旧端返回泛型二进制时，仅在授权元数据的版本与
字节数完全一致时补全音视频类型，不靠消息 URL 猜类型。手机视频取件先验证元数据，
