# 执行端的模型用量账本

桌面执行端为 Claude Code、Codex 和 Pi 记录模型用量。每次有可靠的模型明细时，消息回执保留各模型的普通输入、输出、缓存读取和缓存写入，四项分别与整轮计数对账。价格缺失或订阅费用为零时也保留 token。Codex 的代理响应带有模型名且与原生用量通知唯一匹配时，分项会保留响应中的模型，即使它与任务选择的模型不同。供应商未披露的内部后端仍只能显示执行端可观察到的标识。

个人用量页继续按设备的本地日历记账。同一笔本地模型用量在同一事务内也写入 UTC 日期、接入来源、计费方式、模型四个维度的日汇总。Pi 按原生请求回执去重，后续的价格修订只更新金额。远程会话在控制端显示的副本不写入这张 UTC 表。没有运行这个版本的执行端不会产生新日账。

旧消息仍可正常读取。遇到只有多个模型名和整轮计数的旧消息，可在同范围内改读已经存在的个人模型日账。旧日账的订阅/API 标志只说明计费方式。有历史原生路由凭据时可以另做同范围对账，否则无法从这个标志还原供应商。

## 授权后的本地导出

用仓库根目录下的命令读取指定的账号数据库。输出为 JSON Lines，可以读入区域汇总或单人试点报表。

```sh
python3 scripts/export-token-usage.py --database /path/to/profile.db
```

每行包含 UTC 日期、公开接入来源、计费方式、模型、四类 token 及合计。独立辅助调用从自己的回执取数；供应商未说明的计费方式显示为未记录。公开预设的配置与实际接入匹配时才保留其名称，例如 Magpie。路由或模型没有提供更深一层的信息时，报表只能展示执行端观察到的这一层。

导出默认合并私有来源和私有模型。经授权需要区分它们时，传入 `--private-label-key-file`，该文件须包含至少 32 字节的随机密钥，并限定在一个统计范围内。生成的标签可在同一范围内关联，属于假名化数据。导出仅包含汇总值，不输出账户、会话、设备、端点或私有名字。命令仅读本地数据。执行端快照重导时应覆盖同一范围的旧版本；区域汇总或 TapDB 消费者不能把不同版本直接相加。

## 企业成员用量

企业身份沿用桌面「使用统计」开关。公司是否启用、当前登录成员能否参与，以及远程执行授权，由所在区域的认证服务判断。参与状态只决定资料去向，设置页对所有身份展示相同的文案。已有的员工退出状态继续生效；在企业身份下主动重新开启总开关，才会申请恢复该成员的参与状态。关闭、切换账号和重新开启时不得补传关闭期间的个人或企业活动。

企业后台按成员权限查看每天可归属的非 Gateway 模型与输入、输出、缓存读写计数。Gateway 已有自己的服务端记录。企业批次不包含产品留存代号、设备上的对话、提示词或文件。发布前需在国内和国际正式隐私政策的使用统计说明中披露授权管理员可查看的成员数据范围。

## 参与产品日用量统计

桌面「设置 → 关于 → 使用统计」同时控制活跃与模型用量。已同意隐私政策且旧开关开启的桌面用户，在升级后首次打开对应账号账本时建立起点；保留已有模型统计授权的发送进度。关闭后立即停止新的上报并撤销本机各账号的用量统计授权。再次开启从新的账本快照起算。个人用量页继续使用完整的本地账本。

执行端读取 UTC 日账与独立辅助调用回执。每个来源、计费方式、实际模型的四个累计计数可重复发送，区域服务确认持久化后才在本机记下发送进度。离线补传窗口为最近 90 个 UTC 日。私有名称在端上合并，去重摘要按账号授权与日期限定作用域，跨日无法用该标识关联。公开预设保留其实际配置对应的名称。控制端展示远程任务的用量不增加第二笔。范围为启用了该功能并写入这套账本的桌面执行端；无回执或无上报能力的执行端留在覆盖范围之外。

区域服务在 UTC 日结束后发布达到不同成员数量门槛的增量。TapDB 看板展示总量、模型与接入来源排行、计费方式、四项明细以及参与统计的执行端实例数。迟到回执也适用同样门槛。模型份额的分母为同期已发布的 token，覆盖实例数按日理解。

账号留存使用区域认证服务签发的专用假名。使用统计以 `use1_` 的登录事件去重，充值以 `pay1_` 登记身份，两个命名空间分别使用密钥。两类登录不可合并计算人数。桌面切换时生成新设备标识，并为充值登记使用单独的 SDK 存储空间。旧留存曲线不能直接续接。同一使用假名可在区域内识别回访。旧版区域汇总不带固定账号代号。区域服务从登录凭证识别当前成员，按用量日期生成当日代号，用于核对贡献记录和统计不同成员数。同一成员次日使用不同的代号。达到门槛后传给 TapDB 的是分组总量。

手机在用户已同意隐私政策、已开启使用统计且区域服务已签发代号时，直接使用留存代号和充值代号。缺少某个代号时跳过该用途的账号登记。手机沿用 TapDB 原生 SDK 的设备标识：能够查看旧版统计明细的人可能凭相同的设备标识，将新代号关联到旧版上报的原始账号 ID。「使用统计」开关旁向用户披露这一限制。

## 按留存人群比较模型用量

让分析人员在同一区域内比较留存人群的用量和模型偏好。例如，以首次使用日相同的账号为起点，等完整的第七天结束后，按第七天是否回访分组，比较两组首日的人均 token、使用过各模型的账号占比。图表应给出纳入统计的账号数与用量覆盖范围，缺少回执时标为未观测，不把缺失记成零。按实际回访事件分组，后台任务、离线补报和充值登记均不能算作一次回访。

执行端与区域服务按以下口径记账。

- 账号用量事件为 `cindy_account_model_usage_daily_v1`。区域服务从已验证的登录身份取得与回访相同的区域代号，用作事件的 `user_id`。按使用日、代号、公开模型、接入来源与计费方式汇总四类 token。分析人员可以关联同一代号多天的回访和用量。充值代号独立。上报字段排除原始账号 ID、对话、文件、提示词、会话标识、服务地址和私有名称。
- 模型选择与模型消耗分别计量。用 `cindy_account_model_choice_daily_v1` 中的 `pu_selected_model` 统计采用该模型的不同账号数；自动选择须单列，缺失值记为未知。用执行端回执统计实际模型的 token。一个任务请求 A、实际由 B 执行时，选择记 A，消耗记 B；辅助调用只贡献实际用量。不能从回执推断用户曾手动点击某个模型。私有模型与来源在端上合并。
- 桌面升级沿用「使用统计」原有开关状态，不弹提示，不要求再次开启。只有已同意隐私政策且开关开启的账号参与。首次在新版打开账号账本时，为按账号统计记录新的起点，包括此前已参与区域汇总的账号。区域服务只为明确标有新版统计范围的新增用量生成账号事件。旧版积累的账本和旧客户端迟到的回执不得补成个人历史。撤回和再次开启之间的用量不补传。关闭及换账号时取消待发送请求。
- 桌面「使用统计」开关说明账号与设备使用代号，回访情况和各模型的用量汇总用于改进产品。手机端说明账号代号、设备标识与旧版记录的关联风险。升级时不另外推送这段说明。
- 每次重试沿用相同事件标识；迟到回执按原使用日记增量。同一账号在不同执行端的真实消耗合并，远程控制端不重复记账。账号事件与现有区域汇总使用不同事件名，两套数字不能直接相加。
- 联调用测试账号验证次日及七日回访分组、选择 A 实际使用 B、自动选择、单日多设备、离线重试、账号切换和关闭期间的用量。核对 TapDB 实际接收的字段、事件日期、去重结果及两组的统计分母。

分析时以 UTC 对齐回访事件时间与用量的 `pu_stat_day`。先按代号汇总首日 token，再按第 1 天或第 7 天是否回访分组。每组列出全部符合条件的账号数、有回执的账号数和覆盖率；有回执账号的人均用量须注明分母。各模型的采用率按不同账号数计算，同一账号可以采用多个模型，各模型的占比之和可能超过 100%。原生 SDK 的账号登录登记用于留存，扣费或用量事件不得作为回访。
