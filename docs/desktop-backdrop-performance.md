# 桌面透明与模糊：性能检查（2026-11-08）

保留用户已认可的视觉效果。首轮检查新增可重复的性能样本与测量记录；经用户确认，
随后落实原生状态去重与透明度滑竿本地预览两项优化，结果见下文。

## 测量范围与口径

- 本机：Apple M5 Ultra，36 个逻辑 CPU，256 GiB 内存，macOS 27.3，Electron 42.11.12。
- 独立测试进程、独立临时 profile、1280×800 点的窗口，2× 像素密度，120 Hz 显示器。
- 前窗复用生产背景 hook、侧栏尺寸 hook、主题、全局 CSS、SettingsCard / SettingsRow；100 行合成内容。
  后窗是测试程序自己的条纹画面，可静止或持续平移；原生层直接调用生产 addon 与 backdrop dispatcher。
- 比较 0% 透明、60% 透明且不模糊、60% 透明且模糊 5 / 20。
  静止、滚动、背后动画、30 次/秒缩放各测两轮，第二轮逆序；每段预热 1 秒、测量 4 秒。
  对背后动画另外做了两组每段 10 秒、逆序重复的确认。
- CPU 统计包含测试应用的 main、两个 renderer、GPU 进程和网络进程，不包含 WindowServer；
  统一为单核 100% 口径。Electron 的 `percentCPUUsage` 除过 CPU 数，汇总时乘回 36，
  同时检查累计 CPU 秒数的量级。参见 [Electron 实现](https://github.com/electron/electron/blob/main/shell/browser/api/electron_api_app.cc)。
- GPU 来自 IORegistry 的整机 `Device Utilization %`；WindowServer 也属于整机，其他应用照常运行。
  两者不能直接归因为 Cindy。采样得到的 0 值保留，没有挑选或剔除。
- rAF 间隔衡量 renderer 调度，**不是 GPU presentation FPS**。工作集是进程驻留内存，
  不是独占物理内存或显存；进程复用带来的缓存预热会影响差值。
- 这是合成负载下的渲染路径检查，不是完整客户端、真实长任务、视频解码、电池续航或低配设备结论。

首轮 fixture 的主题参数误用了主题 ID，实际回落到系统主题；后续记录确认是 Cindy Dark，
原生 HUD 外观固定为 Light。因此首轮只用于同一主题内的渲染负载比较，不用于明暗外观比较。
已修正为合法的 `light` 参数，并在明确的 Cindy Light + Light HUD 下复测动态背景。

## 结果

首轮同一环境内，两次测量均值如下。CPU 的小幅反向变化视为噪声，不代表加模糊更快。

| 场景 | 0% 透明 CPU | 60% 透明、模糊 0 CPU | 60% 透明、模糊 20 CPU | rAF P95 |
| --- | ---: | ---: | ---: | --- |
| 静止 | 1.05% | 0.33% | 0.37% | 不主动运行动画采样 |
| 滚动 | 14.87% | 18.47% | 13.29% | 三组均约 9.3 ms |
| 背后动画 | 7.44% | 9.63% | 9.94% | 不测前窗帧回调 |
| 窗口缩放 | 31.98% | 32.89% | 27.13% | 约 9.2–9.3 ms |

滚动/缩放中超过 16.7 ms 的回调约为 0–0.1%，没有观察到与开启模糊一致关联的恶化。
所有稳定测量区间内，原生半径设置、侧栏设置与 `setVibrancy` 的调用增量都是 0。
没有发现静止时不断重设材质的应用侧循环。

明确浅色主题下的动态背景复测（60% 透明，两次各 10 秒）：

| 指标 | 模糊 0 | 模糊 20 |
| --- | ---: | ---: |
| 测试应用 CPU（单核 100%） | 5.46% | 6.39% |
| 测试应用进程工作集合计 | 617.7 MiB | 625.0 MiB |
| 整机 GPU 读数均值 | 21.61% | 19.33% |
| 整机 WindowServer CPU（单核 100%） | 51.89% | 54.19% |

其他两组动态背景测量的 GPU 均值是 16.7% → 25.5%、7.4% → 21.3%，
与浅色复测的方向不一致。**本轮无法给出可归因的 GPU 占用增量或能耗百分比。**
不能把某一组升幅当作产品性能结论，也不能把最后一组下降解释为模糊节省 GPU。
能支持的结论是：这台机器与这组负载中 CPU 增幅小，帧回调稳定；GPU/功耗仍需
在受控背景负载下用系统级图形分析复测。不能外推到 Intel Mac、低配 GPU、Windows 或 Linux。

## 首轮发现的优化机会

1. **按窗口、按变化项应用原生状态。** `applyMacWindowBackdrop` 每次先
   `setVibrancy(null)`，再设置半径，再恢复 HUD 与侧栏遮罩；同一配置也重复执行。
   100 次相同配置实测产生 100 次半径设置、100 次侧栏设置、200 次 vibrancy 设置，
   同步提交约 9–11 ms（不含 WindowServer 后续工作）。
   可缓存成功应用的状态，半径变化只更新半径，几何/外观变化只更新侧栏。
   需覆盖主题/壁纸切换、失败回退、缩放、窗口销毁和圆角恢复，不能仅凭缓存跳过必要恢复。
   预期收益集中在拖动滑竿、主题广播、多窗口切换；不是静止 GPU 开销的大幅下降。
2. **透明度滑竿采用本地预览、提交时保存。** 当前 `onValueChange → setVisibility → patch`
   每个数值都进入持久队列；main 写配置、向所有窗口应用外观、处理 Dock 图标并广播。
   可沿用模糊滑竿已有的 preview/commit 模式：当前窗口即时显示，提交一次持久值；
   如其他窗口仍需实时预览，可独立合并瞬时消息，不能把预览当作持久写入。
   必须保留键盘、取消手势、离开设置与失败回滚的语义。
3. **把同一帧内的重复更新合并。** 在证实某条通知确实重复后，只应用该显示帧的最终值；
   不降低显示刷新率、不降低模糊半径、不降低分辨率。收益须分别测量，不能预先承诺百分比。

已有的低开销设计应继续保留：普通控件只改变底色 alpha，不逐个加 blur；桌面模糊在原生
窗口层；侧栏几何去重且只在变化/动画期间更新；0% 透明暂停整窗模糊，独立左栏材质保留。

原生模糊在动态背景下仍需要图形合成，这是合理的成本来源。上述优化去除重复管理工作，
不意味着可以在保持同样画面、分辨率与刷新率的前提下把模糊的图形成本降为零。

## 已落实的两项优化

1. 原生 dispatcher 按窗口缓存成功应用的背景色、半径、材质与侧栏几何/外观。
   半径变化保留已有侧栏 HUD；材质被替换时重新同步遮罩；失败不缓存成功状态，可再次重试。
   背景色也由 dispatcher 统一设置并去重，避免重复写入透明色覆盖维持 AppKit 圆角的微量 alpha。
   离开桌面模式仍清除半径，并释放旧的局部遮罩后恢复普通主题材质。
2. 透明度滑竿沿用模糊的本地 preview/commit 流程。拖动只更新当前窗口，松手或键盘提交
   才进入原有保存队列并广播；取消、窗口失焦、离开设置撤销预览，保存失败恢复已保存值。
   桌面与壁纸模式共用此行为，不降低模糊半径、分辨率或刷新率。

真实 Electron + 原生 addon 复测：先应用一次目标配置，随后连续重复 100 次，
半径、侧栏和 vibrancy 调用增量均为 **0**，同步耗时约 **0.10 ms**。
首轮未去重时相同配置重复提交产生 100 次半径、100 次侧栏、200 次 vibrancy 调用，
约 9–11 ms；首轮入口可能包含一次合法的半径切换，因此这不是严格逐调用同条件的耗时比。
该结果证明重复提交被消除，**不代表稳定画面下 GPU 或整机能耗按同一比例下降**。

验证包括原生 dispatcher 的切换、失败重试与几何/外观更新；真实 provider + Slider
的提交、取消、远程值到达与失败回滚；Electron 界面中桌面/壁纸模式的深浅色指针和键盘操作。
原生调用检查通过，但测试进程没有屏幕录制权限，本次未用截图重新证明系统模糊的视觉效果。

## 复测

```sh
node apps/desktop/scripts/desktop-blur.perf.mjs
CINDY_BLUR_PERF_FOCUS=behind node apps/desktop/scripts/desktop-blur.perf.mjs artifacts/desktop-blur-perf/confirmation
```

脚本只操作自身的测试窗口，不截屏、不读取或修改用户设置；结束时销毁窗口并清理临时 profile。
原始记录默认写到 `artifacts/desktop-blur-perf/result.json`，本次另外保留了
`behind-confirm/result.json`、`light-confirm/result.json`、`optimized/result.json` 与汇总 `summary.json`。
这些是本地测量产物，不是提交到 Git 的用户数据。
