# macOS 语音输入静音对照实验

2026-09-25，macOS 27.0 (26A428)，Apple Silicon。独立脚本调用真实系统输出设备，
没有启动 Electron，没有访问麦克风、账号或云端。每次静音后都核验已静音，并恢复、
核验原状态。测试前系统输出未静音。

可复现入口：`node scripts/voice-mute-benchmark.mjs --apply`。
不加 `--apply` 时只读状态，不会改变系统输出。脚本在唯一临时目录编译、测试并清理。

## 结果与选择

每组 6 次，按原生 → AppleScript → 预编译 AppleScript → 反向顺序交错，共 18 次。
耗时包括子进程启动、系统读写与退出，不是麦克风启动或首字出现时间。

| 方案               | 静音中位数 |      静音范围 | 恢复中位数 |
| ------------------ | ---------: | ------------: | ---------: |
| 原生 CoreAudio     |     66.9ms |   61.3–79.5ms |     69.7ms |
| 原有 AppleScript   |    149.3ms | 137.0–177.3ms |    154.1ms |
| 预编译 AppleScript |    156.0ms | 139.1–177.0ms |    148.7ms |

预编译组只预编译静音脚本，恢复沿用原有 AppleScript。原生较原方案静音快约 82ms
（55%），恢复快约 84ms。此前一轮两组各 6 次的独立交错测试结果为静音 52.0ms /
144.8ms、恢复 52.6ms / 151.4ms；两轮结论一致，但绝对时间会随系统负载变化。

新编译原生程序第一次只读探测为 345ms（此前一轮 397ms）。这不是清空系统缓存或
重启机器后的冷启动测量，不可承诺所有设备都能复现。因此采用**后台只读预热后才启用
原生路径**：点击时未就绪就立即走 AppleScript，不等待编译或预热。
不新增常驻进程，不缓存输出设备的静音状态；每次录音重新读取实际状态。

## 正确性与边界

- 原生程序在写入前输出原状态；即使后续写入失败或超时，父进程仍保留恢复依据。
- 原生恢复使用采集的设备 ID，并校验 UID，避免默认输出切换后误改其它设备。
- 未就绪、缺少编译器、设备不支持时使用 AppleScript；已取得原状态后的写入失败
  不重新读取并覆盖原状态，交给现有恢复流程处理。
- 静音继续等待提示音完成；麦克风准备和收音不等待本流程。
- Windows 保持原后端，平台分支由单测覆盖，未在 Windows 实机测试。

48 项定向测试通过（静音后端/状态恢复、提示音、录音启动、现有原生依赖打包测试）。
Apple Silicon 原生程序编译并实测通过；错误设备 UID 的原生拒绝路径也已实测，未改变
输出状态。Intel macOS 10.15 目标源码编译通过，但本机链接验证未完成：
本机 Command Line Tools 的 Swift 兼容库仅含 arm64/arm64e，缺少 x86_64；需要完整
工具链或 Intel 构建机验证。未生成、签名或启动完整安装包，未重启当前开发版。

上述收益仅证明静音与恢复更快，不代表识别首字提速。真实云端连接 A/B 不在本实验中。
