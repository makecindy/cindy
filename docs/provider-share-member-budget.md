# 供应商分享：成员模型占比上限

## 数据与口径

- 规则按供应商连接、经过身份核实的受邀成员、单个目录模型分别设置。
- 指标固定为：该成员在此供应商使用该模型的已记录输入＋输出 token，除以同一成员在此供应商全部模型的已记录输入＋输出 token。缓存读取、缓存写入、机主、同账号使用和其他成员均不计入。
- 时间窗口是提供服务的电脑本地时区的今天及之前六个自然日，不是过去 168 小时，也不是订阅周额度窗口。每天零点向前移一天。
- 数据直接来自已有分享用量账本；比例是对已记录数据的计算，不声称覆盖上游全部请求。历史账本缺失的请求及子代理归属不能追溯补造。
- 不再根据账号额度变化或 API 参考价格分摊个人订阅额度。不需要知道 GPT 周额度是多少，也不依赖订阅配额 API。
- 模型与推荐模型来自该供应商的当前目录和授权范围。新增型号可以配置；未配置型号不自动继承其他模型上限。

## 草案与执行

- 成员的「可用模型」面板同时编辑模型授权、单模型占比上限和推荐模型，一次保存。沿用原有成员入口，不另设上限管理页；只修改上限时保留既有模型授权。
- 新建规则默认关闭，明确显示草案；保存草案不改变模型可用性。预览的“达到上限”和真实“正在拦截”分开记录。
- 百分比为 1–100 的整数。目录已有的桥接型号别名按统一模型键合并统计和判定，不能用别名绕过同一条规则。
- 开启后，占比大于或等于上限时暂停该成员对此模型的新请求。100% 表示不限制；其他模型维持原授权。
- 没有记录时显示“暂无用量数据”，比例为未知，不显示 0%。允许首次请求以建立使用记录；其结果可能使下一请求超限。
- 已有记录中某型号没有用量，可以显示它在当前账本中的 0%；不能说它消耗了账号周额度的 0%。
- 无法读取、解析或可靠求和账本时显示不可用。已启用且小于 100% 的受限模型暂停；草案、未受限模型和机主不受影响。 损坏记录的不完整日期边界会持久化；无法定位日期时按发现当日处理。七天窗口移出该边界后恢复，正常写入及重启不会延长暂停。
- 已发出的请求完成后入账，不中断当前输出。并发请求与回执延迟可能跨过阈值，不能承诺严格零超支。
- 该成员使用其他模型或旧记录退出窗口后重新计算；低于上限才恢复。午夜只更新窗口，不保证恢复。不会自动重试或静默换模型。
- 推荐模型也受既有授权及自身上限约束，不推荐已不可用的模型；推荐不是自动切换。
- 规则持久化携带 `basis: member-input-output-7d` 和独立 `enabled` 字段，旧的账号额度估算草稿不能被重新解释成这个指标。

## 适用边界

- 机主、本机、同账号远控和机主子代理在成员规则读取前豁免。分母只属于该成员，不因机主或其他人继续使用而变化。
- 这是模型使用结构控制，不是个人总用量上限，不能保证节省多少订阅额度。账号总额度保护是另一独立指标，不混入本次个人占比设置；该能力尚未交付。
- Codex/Pi 的共享 ChatGPT 代理按真实请求型号记账并检查准入。Claude 保留原生 CLI 登录与直连；启动、换模型、新一轮准入已有检查，CLI 一轮内部逐请求即时拦截仍未完成，不能宣称等价支持。
- 供应商组通过已有的反向模型准入通道检查成员占比；暂停标识回传使用端。暂时达到上限的模型保留在静态授权目录中，实时准入复核负责阻止与恢复，避免比例恢复后仍无法使用。三宿主中转定向测试已覆盖，真实跨账号网络路径尚未验证。
- 旧记录按原有归属保留；新计量不能补齐历史没有记录的明细。真实跨账号、并发、断线、重启和升级路径仍需验收。

## 本轮验证范围

真实账本只读试算使用生产的 `memberTokenSnapshot` 与 `memberBudgetStatus`，结果另存任务私有草案，不写入正式配置。定向测试覆盖草案豁免、机主豁免、个人/供应商/分享隔离、缓存排除、阈值边界、其他模型用量导致恢复、自然日窗口切换和损坏数据。

完整开发版中的设置交互使用隔离测试成员及模拟的管理传输边界核对；设置存储、账本计算与成员准入调用生产实现。该测试不代表真实跨账号认证、外部模型请求或正式部署已经验证。
