# 实验性网页版的后续实施计划

2026-11-10，接续已合并的 PR #9246。目标是让基础功能方便使用，并让桌面与网页版
长期共用同一套业务实现。最初不以完整桌面功能还原为目标；2026-11-10 范围扩展为
所有客户端共用的完整无界面后台，包含没有图形环境的 Linux 服务器。
后续架构、实施顺序与验收以 [完整无界面 Cindy 计划](headless-runtime-plan.md) 为准；
本页保留已完成两批工作的范围与验证记录。

## 保持的边界

- 普通桌面启动保持原有运行方式，只有显式选择才启动或连接 Host。
- 测试继续使用独立 profile，不迁移正式账号，不停止正式 Cindy。
- 不增加另一套任务后端、账号库或插件运行时。共用数据前先解决唯一写入者与生命周期。
- 回归测试、浏览器实测、三平台实测分别记录，不能互相代替。

## 实施顺序与完成条件

| 阶段 | 用户得到的结果 | 架构调整与完成条件 |
| --- | --- | --- |
| 1. 接口与连接可靠性 | 操作结果可信；断线后能找回真实状态 | 网页与显式 Host 桌面客户端共用参数和回包定义；清理写操作假成功；事件连接区分可重放断线和后台重启／历史窗口丢失；恢复不重发用户消息、不刷新整页或丢输入草稿。 |
| 2. 共用业务核心 | 两端修一次即可生效 | 按任务读取、任务执行、账号与设置顺序抽取无 Electron 依赖的服务接口；平台能力经适配器注入；逐步去掉 Host 对 desktop/main 的反向引用。每次迁移验证正常桌面的原行为。 |
| 3. 日常使用入口 | 能方便地开始、查看状态和退出 | 启动、状态、日志、停止由同一个生命周期服务管理；先改善现有预览 CLI，再接入桌面实验设置。发行包不依赖源码工作区或临时 Vite 目录。 |

阶段 2 先抽取有两端实际调用者的小服务，不一次搬空 main、不先设计全能服务框架。
阶段 3 的桌面管理入口和是否允许桌面与 Host 共用正式 profile，需要在生命周期方案明确后
再确定交互。前两批未引入后台常驻、自启动、局域网监听或无窗口 Electron 辅助进程；
后续无图形后台按新计划逐步实现，不以隐藏 Electron 窗口替代服务器支持。

## 第一批：接口正本与失败语义

- 把现有 `hostChannelContract` 接入网页适配层；参数与返回值在 shared 中维护，
  浏览器只保留同步快照、缓存失效、重定向等展示适配。
- 修正权限回答、插话和鉴权刷新等返回形状；错误或拒绝不能转换成成功。
- 已明确未实现的设置、账号切换、维护动作返回明确错误；启动时的只读占位与
  无原生窗口时的展示通知单独保留，避免破坏基础任务启动。
- 将网页 shim 的模块依赖随 Host 编译为同源脚本，继续在 renderer 之前安装；
  不要求正常桌面增加启动步骤。

## 第二批：连接恢复（已在本地实施）

- Host 为一次运行提供事件代次，并给出可重放范围；旧客户端维持旧协议。
- 两种 Host 客户端共用解析、游标和断线恢复规则。
- 重放不完整时由 renderer 重新查询任务列表、已打开任务的历史、输入队列和待确认操作；
  复用现有状态仓库的对账与请求代次机制，避免另造一份聊天状态。
- 只因当前连接恢复补读所需快照，不扫描所有历史、不轮询云端、不自动重试有副作用的操作。

连接层不能只增加一个 reset 事件就称为完成：必须把信号接到真实界面状态消费端，
验证断线中任务结束、后台重启、历史窗口溢出、连续断线及草稿保留。

## 第一批验证记录

第一批已在本地实现：共享请求参数与回包转换、网页同源脚本编译、已审计写操作的明确拒绝。
能力查询失败不再永久缓存 rejected Promise，后续调用可恢复。

- 共享接口 6 项通过（0.34 秒）。另修复主干测试中的重复 import；交互测试 40 项通过

## 第二批实现与验证记录（2026-11-10）

- `/events?protocol=2` 使用每次进程启动的运行标识和单调序号。保留最近 1000 条事件；
  短时断线补收遗漏事件，重复序号不再重复投递。重启、超出历史窗口、非法游标明确要求快照恢复。
- 网页与显式 Host 桌面客户端共用 `hostEventStream`。支持 UTF-8/CRLF 分片、重放完成边界、
  异常帧恢复；15 秒服务端心跳连续 45 秒不可见时重连。未提供 v2 响应头的旧 Host
  每次重连走快照恢复；未请求 v2 的旧客户端保持原 SSE 语义。
- 连接前读取 Host 鉴权状态，交由现有账号边界处理；恢复查询按连接代次与账号代次作废。
  renderer 补读已缓存任务列表、已加载／可见／运行中的本地任务历史、输入队列、待确认操作。
  复用现有聊天状态仓库与合并逻辑，最多同时恢复 4 个任务，不扫描数据库中的所有任务。
- 遗漏结束事件时，根据新鲜的运行状态快照收尾；新事件可否决较早查询。旧连接或旧账号的
  迟到结果不能覆写新状态。初次历史读取失败也可以恢复，读取失败在当前连接内重试。
- 新增非模态连接提示，支持重试。RPC/SSE 401 保留原页面，停止自动尝试，重新配对后通过
  同源通知、回到原标签页或重试继续。原有短期 HttpOnly cookie 和配对规则保持不变；
  不保存账号密钥到网页，不重发输入、不刷新整个页面，现有草稿仓库保持不动。
- 正常桌面不注册 Host 连接处理器，不打开 Host socket；只有显式客户端收到连接提示。

本机 macOS 隔离验证：

- Host 全部 **95 项**通过（4.31 秒），包括真实 HTTP 的新旧 SSE、窗口溢出与进程切换，
  以及实际网页脚本执行中的 401／重新连接／不跳转回归。
- 共享契约与事件传输 **16 项**通过（约 0.30 秒），含半开连接、丢失 ready、重复事件和旧 Host。
- Desktop 相关 **98 项**通过（3.18 秒），包括原有 Device Link 对账和账号边界回归；
  新增 renderer 订阅组件 **3 项**通过（连同任务恢复、任务列表定向复验合计 34 项，3.24 秒）。
- Desktop 整包类型检查、maker-shared 类型检查、开发文档合同 10 项与测试规范检查通过。
- `ui:check --page host-connection --case all --theme all --locale zh-CN` **8/8** 场景通过；
  `ui:check --changed --case host-pairing,host-restoring,host-retry --theme all` **6/6** 通过。
  已查看浅色／深色截图，包含 320 px 配对提示。只实测本次提示场景，不把其他页面的
  依赖扫描当作界面验收。`App.tsx` 和 `vite-env.d.ts` 在该 UI 扫描中为 `UNCOVERED`：
  订阅组件另有挂载测试与类型检查，完整应用启动仍需独立 profile 的集成验收。

本批恢复的是客户端视图与后台真实状态，不会重新启动被 Host 进程退出中断的执行。
当前 Host 输入队列仍主要存于内存，后台重启前尚未派发的排队输入不保证恢复；
队列持久化及执行恢复语义属于下一阶段共用业务核心／生命周期设计，不能由客户端自动重发补救。

当前产物为同一分支上的第一、第二批本地改动，尚未提交、推送或发布。上述传输、重启和
恢复使用受控服务／时钟／接口替身，不代表真实模型或三平台实机验收。下一批按计划进入
共用业务服务抽取，优先任务读取服务，再逐项迁移执行和设置；不提前改变普通桌面的启动方式。

## 第二批真实浏览器复验（2026-11-10）

随后在 macOS 的独立预览 profile 上完成真实模型对话、停止与队列继续、权限允许一次、
事件连接中断后的补收，以及真实 Host 重启后的重新配对／旧页草稿恢复。
过程与人工步骤见 [基础网页版：本地人工验收](basic-web.md#本地人工验收2026-11-10)。
没有操作正式 Cindy 数据或停止正式 app。

实测另发现两处桌面展示通知漏适配，已修复并补回归：网页适配测试 12 项、Host 全部 96 项通过；
不支持的配置写入继续返回错误。实际连接中断用测试页内临时 fetch 故障注入；
不是物理网络故障、手机后台或三平台实机验收。队列持久化、共用业务服务和生命周期入口
仍按原计划推进，本轮没有提前实现。
