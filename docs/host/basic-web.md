# 基础网页版：范围与验收

2026-11-07：首版以现有 PR #9246 为基础，让用户能通过网页完成基础任务，
不再以完整还原桌面功能为交付前提。继续本地验收，未经确认不推送或更新原 PR。

## 实验功能的发布边界

2026-11-08：基础网页版按主动启用的实验功能维护，普通桌面用户的现有使用流程是验收底线。

- 普通桌面启动不自动启动 Host、不开放网页服务，也不因为存在 `host-endpoint.json` 而切换运行方式。
- 测试入口使用独立 profile；已有桌面账号、任务与设置不迁移到实验实例。
- Electron 连接 Host 仍需显式指定 `CINDY_HOST_API`；`dev:host` 是主动选择此模式的开发入口，
  不是普通桌面启动流程。连接失败不能静默切换到另一个运行时。
- 实验功能未启用时，登录、任务执行、插件、自动化及退出行为必须保持原有桌面语义。
  取消自动接管只是其中一项保护；共享模块的改动仍须通过对应桌面回归验证。
- 第一版先验收文本任务全流程。未支持的设置不能假装生效，尤其不能显示已经切换权限或账号。
- 在权限确认、停止、断线恢复和正常桌面回归完成前，只称为本地实验预览，不称为可正式发布。

自动接管边界的现有回归见
[`hostDelegation.test.ts`](../../apps/desktop/src/main/__tests__/hostDelegation.test.ts)；
跨平台验证结果仍按实际执行系统记录。

## 第一版要完成的使用流程

1. 在执行电脑显式启动 Host，通过配对入口在浏览器连接；认证失败有可理解的下一步。
2. 使用 Host 上已配置且可用的账号和模型，新建文本任务、发送消息、查看流式回复。
3. 需要操作确认时能看到请求并回答；执行中能停止，不丢失已经生成的回复。
4. 查看任务列表和历史，重新进入任务继续对话；不把空白的新 Agent 上下文当作恢复成功。
5. 刷新页面后找回任务和真实运行状态；短暂断线不会自动重复提交用户输入。
6. 未支持的功能不显示假成功；保留入口时说明当前不可用，并避免影响基础任务。

以上是验收目标，不是已验证声明。账号初次连接和高级配置可以先在执行电脑完成；
不要求网页承担完整设置管理。浏览器中的任务实际运行在 Host 电脑上。

## 暂不作为首版交付条件

- 完整插件页面、插件管理、MCP Apps、自动化及伙伴功能。
- 远程桌面、语音、系统快捷键、托盘和其它原生窗口体验。
- 浏览器与执行电脑之间完整的文件上传下载、剪贴板和媒体管理。
- 全设置页、多账号管理、运行中跨引擎切换等高级行为。
- 彻底抽离桌面后台，或引入无窗口 Electron 辅助进程。

复用已经实际可用的能力，不为缩小范围删除用户配置或数据。尚未实现的功能不能靠返回
空数据、伪造版本号或成功结果冒充支持。基础版不新增另一套页面和任务后端。

## 仍需保留的交付底线

- 保留配对、身份隔离和授权校验；只监听回环地址，远程使用经安全隧道。
- 暂用独立测试 profile；在桌面与 Host 共用目录的运行协调完成前，不操作正在使用的正式 profile。
- macOS、Windows、Linux 分别记录实际验证结果；单测通过不等于三平台完整可用。
- 上线前用真实模型验证一次完整任务流程；模拟传输测试不能替代这一步。
- 每个仍可点击的未支持入口须明确不可用，不能静默吞掉操作。

## 当前进展与未完成项

### 本机试用（2026-11-07）

在本分支根目录运行 `pnpm preview:host`。已有测试服务时直接打开网页，否则启动服务并打开浏览器。
固定监听 `http://127.0.0.1:3466`，只供本机访问。保持启动终端运行，Ctrl+C 停止本次启动的测试服务。
仅打开入口可用 `pnpm preview:host open`。如果网页构建不存在，先运行 README 中的 renderer 构建命令。

首次使用先运行 `pnpm preview:host login`（Google），或 `pnpm preview:host login --method=apple`。
登录完成后启动服务；已启动时先停止再启动。测试登录态经系统凭证加密保存到独立目录，
不复制正式 Cindy 的账号文件。预览目录固定为平台 appData 下的 `CindyHostPreview/pr-9246`，
启动器不继承正式目录标记或外部指定的 owner。

本机 macOS + Chrome 已完成真实验证：登录、首次创建数据库、获取账号模型连接、
网页新建任务与模型回复、刷新后继续对话、停止并重新启动 Host 后继续原对话。
最后一步已由模型正确复述此前的回复验证，非仅显示历史记录。

启动修复包括新账号从已验证身份创建数据库、ESM 下加载 CommonJS migration companion、
首次登录自动取得模型连接（凭证只留后台内存）、SDK 会话标识恢复，以及网页 `osRelease` 值适配。
Host 回归 88 项通过（约 4.3 秒），数据库迁移回放 26 项通过（约 2.4 秒）。
这不是全平台或全功能验收；当前优先试用文本任务，插件、自动化、文件面板等入口仍有未完成适配。

### Host CI 的触发范围

三平台 Host 回归只在相关输入变化时运行：`apps/host/`、`apps/web/`、
`apps/desktop/`（Host 直接复用其数据库、账号模块和 renderer）、`packages/`、
`apps/*-bin/`、`scripts/`、`patches/`，以及根依赖清单／锁文件／Node 配置与
`.github/workflows/ci.yml`。共享树和脚本保守地整体纳入，避免间接依赖漏测；
纯文档、纯 mobile 代码等改动不分配三平台 Host 测试 runner。

一个不安装依赖的 Linux job 负责选择。PR、合并队列和 main push 都比较各自事件的
base 与实际检出提交，包含删除与重命名的旧路径。手动运行或没有比较基准时全部运行；
Git 比较失败会阻断，不能视为无关。稳定的 `verify` 检查始终运行，只有选择成功且
明确无关时才接受 Host 的 skipped；需要运行时仍要求三平台全部通过。
