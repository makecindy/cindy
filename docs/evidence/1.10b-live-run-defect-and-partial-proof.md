## Defect the run exposed (in 1.10's "cleanly" scope)

**A user Stop surfaced as a turn FAILURE, not a cancellation.**

- UI: "Could not complete the reply" + error banner "Hermes exited with code 130".
- Log 18:24:48.426: `[maker-ipc] provider group: failure decision {sessionId: '7ad6b464…',
  phase: 'run', action: 'switch', cause: 'failed', cool: false}` — the Stop was classified as
  a provider failure and offered to the provider-group switch machinery.

Root cause: real Hermes answers SIGINT by writing a failing terminal `result`
(`exit_code: 130`) to stdout before it dies. The daemon forwards it, then settles
`session/closed reason=killed`. The agent's `turn-complete` handler ran first, saw a non-zero
exit and pushed a terminal error + `done status:'failed'`; the following killed close was
consumed by the awaiting-close epoch without reclassifying. The fake daemon in the agent
tests never reproduced this (its interrupt produced only the killed close), so unit tests
missed it.

**Fix (this session, `unit-tested`):** `packages/maker-core/src/agents/hermes/agent.ts` now
records the user's stop intent per epoch (`userAbortEpoch`, set in `handle.abort()` before the
interrupt RPC). `turn-complete` settling a user-aborted epoch with a non-zero exit emits
`done status:'cancelled'` and **no** error event; genuine failures are untouched. Without the
error event and with `cancelled` status, the desktop's turn-error machinery (error banner,
auto-resume classification, provider-group failure decision) no longer fires on a Stop.
Fake daemon gained an `abort-result` turn mode reproducing the real SIGINT shape. 2 new tests
(cancelled-not-failed; genuine failure still surfaces), mutation-checked: disabling the guard
failed exactly the cancelled test, 29 others passed.
