# 插件市场反馈与作者收件箱提案

> 状态：待评审的功能提案，描述预期行为。

[交互网页预览](design-previews/plugin-market-feedback/index.html) 使用当前页面内的示例数据演示提交、收件和标记已读。

## 用户和作者怎样使用

- 用户在公开市场的插件详情页选择「反馈问题」，填写问题和必要的复现步骤。登录后即可提交，包括尚未安装的插件。表单展示收件方的角色，例如「插件作者」或「官方维护团队」，并允许用户核对随附的插件版本。发送失败时保留输入；服务端确认收件后显示「反馈已提交」。
- 插件页顶部沿用现有作者管理入口，将按钮文案改为「我的插件」。作者管理页并排展示「已发布」和「收到的反馈」，右上保留「发布插件」。作者在「收到的反馈」查看插件名称、反馈时间、正文和相关版本。作者可在收件箱将反馈标记为已读。未读反馈数显示在收件箱内。反馈提交后即进入收件箱，作者离线或换设备时仍可在登录后查看。
- 官方插件使用市场配置的维护入口，由明确授权的维护团队收件。缺少有效收件关系的插件不展示反馈入口。首版覆盖桌面端公开市场，企业、自定义市场和本地插件留待各自的收件规则明确后再接入。首版提供文字反馈和站内收件箱，后续再评估作者回复、附件和桌面系统通知。

## 如何确保反馈交给正确的人

- 收件关系由服务端按可信市场来源和 `pluginId` 解析。社区插件沿用个人首发绑定的账号身份，投稿权限与反馈查看权限分别校验。官方插件使用服务端配置的维护关系。每次提交、读取和标记已读时校验当前会话及对应权限。客户端传入的作者署名和插件自行声明的身份均不能决定去向。
- 反馈仅向有权收件的账号展示。界面不公开社区作者身份，也不向作者展示反馈人的账户标识、邮箱或设备标识。用户自己填写正文，界面提醒勿贴密钥和个人资料。提交只附带插件身份、经来源核对的可选版本和正文，不自动采集日志、路径、插件配置或对话内容。
- 服务端按发送账号限流，校验正文长度，并使用幂等键处理超时重试。反馈和收件记录应原子写入，只有确认入库后才返回提交成功。作者侧按需分页读取，未读状态在服务端保存。市场浏览和收件箱关闭时不轮询，首版在作者打开或主动刷新收件箱时读取未读状态。
- 客户端只在服务端明确表示该插件可收件时展示入口。先部署服务端能力，再启用客户端入口。旧客户端和不支持该能力的服务端应继续正常浏览、安装与更新插件。回滚时关闭新入口，保留已提交的反馈。

## 验收条件

- 分别验收社区插件作者、已配置的官方维护团队和未配置收件关系的官方插件。前两种反馈只能由有权收件的账号读取，第三种详情页不展示反馈入口。
- 用两个账号验收。用户在插件详情页提交反馈，作者登录后能在对应插件的收件箱里看到一条未读记录。标记已读后刷新或换设备，状态一致。
- 另一个账号、同名插件的作者和仅有投稿权限的维护者均无法读取或标记该记录。公开列表、详情和请求日志不暴露反馈正文或作者私人身份。
- 模拟超时后用同一提交重试，作者最终只收到一条反馈。提交失败保留表单，未登录、无法收件和不支持反馈的市场不会显示虚假的成功状态。
- 在旧客户端、旧服务端以及企业或自定义市场并存时，原有的插件列表、详情、安装和更新继续可用。

## 已核对的现状

公开客户端的 [市场详情](../apps/desktop/src/renderer/features/plugin/MarketPluginDetailView.tsx) 和 [我的插件](../apps/desktop/src/renderer/features/plugin/MyPluginsPage.tsx) 提供两个接入位置。现有 [投稿契约](plugin-community-contribution-contract.md) 记录固定作者归属与公开署名隐私。本提案需要独立的市场服务端和客户端共同实现，接口和部署顺序由维护者在实施时确认。
