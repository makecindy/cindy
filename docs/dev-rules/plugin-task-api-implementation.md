# 插件普通任务接口：第一阶段实现

状态：实验接口，尚未发布。入口为插件逻辑页 `cindy.tasks`，声明 `agent.tasks: true` 后由既有插件权限流程确认。存量 `errand` 声明不自动获得此权限。

## 已接入

- `capabilities/create/list/get/send/getRun/listRuns/readMessages/cancel`。
- create 可传 isolatedWorkspace:true，由宿主分配独立空作答目录；返回本任务 workingDir 与 permissionMode，插件不能覆盖权限。
- 创建用户可见的普通本地 Session；工作目录及权限来自用户配置，不接受插件传入绕过权限、任意目录或另一插件身份。普通任务创建前复用 Worker 的目录身份判据：配置路径必须仍为原规范路径，改链、缺失或非目录拒绝；异步解析后复核账号、tasks 批准及配置。缺省/isolatedWorkspace 仍由宿主分配目录，旧 errand 路径不变。旧别名配置没有原目标证据，不自动授权当前目标；这不解决校验后的目录置换窗口。
- 发送走普通输入协调器，使用持久 requestKey 去重和稳定输入 ID；重复请求不会再次启动模型。
- 指定 provider、model、effort、Fast 必须通过当前目录核验；派发前再次核验，不静默 fallback。
- 创建回执写入后、创建 Session 前，按原始请求重新解析路由并与已受理路由比较；默认模型配置变化则拒绝，不静默使用旧值。目录解析及创建器的最终 continuation 同时复核 agentKind/model/provider/effort/Fast、目录和权限。
- 本次创建在 Session INSERT 开始前明确失败（如配置、目录或工作区准备失败）时，沿现有回执队列撤回仍为原版本、且原始 Session 行不存在的新回执；修正原因后可用原 requestKey 显式重试，不自动重派。回执存储固定原账号数据库，撤销或版本变化的回执不删除。
- 新请求的幂等摘要忽略对象键顺序，保留数组顺序；计划及已受理配置共用相同比较。早期开发版创建回执保留原序列化输入的精确重试兼容；这类旧摘要未保存原始键序，不能承诺首次以不同键序重放成功。
- 回执独立落库，区分任务、输入执行及原生执行代次；原生终态按 instanceId + generation 结算，不以 idle 或最后一条 assistant 消息猜测完成。
- send 回执写入后，进入宿主派发前的检查拒绝可确定未发送，结算为 failed；进入派发后的异常仍为 reconciling，明确拒绝仍为 failed，已有原生进展优先。同 requestKey 只读取旧回执，权限恢复后需新 key 显式提交。若账号、归属或存储条件不再允许结算，调用仍拒绝并保留回执，不绕过权限门补写终态。
- 读取限定于本插件创建的任务；返回消息 clientId。list/listRuns 按 (createdAt, id) 排序，现有回执 ID 游标在同插件与目标内解析，不再只按随机 UUID 排序。列表是分页查询，不是增量订阅；刷新应从首页重扫，不能把游标当永久同步水位（同毫秒追加、系统时钟回退或既有回执终态更新均需刷新）。
- 插件持有 create 归属的任务及其 Orca Worker 使用既有 restricted `cindy_helper` 能力面，不提供账号级历史、待发消息或跨任务控制；发现与实际调用共用实时 Host 判据，猜工具名也不放行。整个 `cindy_memory` registry（发现、读取、搜索、写入、删除、合并、复核及 `session_search`）复用账号数据守门，在访问前拒绝，返回前复核账号及输入来源；不伪装为空结果，也不回滚已经接受的写操作。按创建回执和 Worker→Team→Lead 关系判断，不按 `source=plugin` 一刀切，也不因团队结束而放开。旧 errand/workspace 无回执时保持原行为；明确 `ownershipRevoked=true` 后，调用方已无正在执行的输入或已接受新的 Host 真人输入时，保留的用户任务恢复普通 helper 与历史检索能力；仍执行旧插件输入时继续受限。发现、调用和 memory 检索复用 Orca 的只读来源判据，首个异步查询前固定当前来源、返回前复核；真人重试保留 Host 文本及稳定来源，插件重试不变真人。Lead 自动回报可沿当前可见输入追溯，但 Worker 的新 Lead 指令阻断对更早真人的回溯。损坏回执、未知来源或查询失败保持拒绝；这不恢复插件归属、旧 requestKey 或插件控制权，也不承诺停止已接受执行。独立 Orca 工具不受影响。这不是通用执行或文件系统隔离。
- 账号级 `cindy_contacts`、`cindy_scheduler`、`cindy_slack` 的发现与实际调用也复用上述实时来源判据。插件持有的任务及 Worker 在读取管理器、调度器或 Slack 绑定前拒绝，猜工具名不能绕过；Codex/Pi 共用服务按每次调用的实际任务判定，Claude 使用当前服务上下文。读取后再核验账号及来源，不返回过期结果；Slack 的既有结果文件路径解析与目录准备后、写入前再核验。普通任务与明确撤权后的真人接管保持原能力；缺少上下文或核验失败拒绝。这不回滚已经接受的外部写操作，不保证中断已派发原生执行或跨工具授权事务，也不改变独立 UI 的调度与通讯录管理。
- 取消只撤回自己的排队输入或其原生重试别名；停止前在 Session 锁内再次核对执行身份与插件权限。
- 请求跨账号切换后不能继续操作新账号数据库。禁用插件后不能继续发送或停止。
- 用户通过插件页或市场卸载时，在删除插件包前持久撤销其旧任务归属；保留任务、消息、作答文件、成绩和回执。正常更新保留归属；卸载重装后旧任务和旧 requestKey 不再可用，新请求键可创建新任务。撤销写入失败则不删除包；删除包失败时已撤销的归属不回滚。此处不改变内置插件 orphan/audience 自动回收路径。

## 与伙伴的共用和隔离

`sessionExecutionOwnership.ts` 提供执行身份比较、锁内二次核对、按归属撤回排队输入。伙伴委派与插件任务均使用这套函数。

插件继续复用现有普通 Session 创建、输入协调器、停止服务及产品终态边界。没有创建假伙伴，没有另建模型执行器。伙伴的身份、父子委派规则及专有配置仍由伙伴服务管理。

## 当前限制与后续工作

- 仅本插件创建的本地普通任务；不支持选择既有任务、远端任务或 Bot；自有普通任务可通过 startTeam 成为 Orca Lead。
- 尚未开放修改/归档任务、队列暂停、事件订阅、逐输入费用与用量。usage 明确返回 unavailable。
- 回执已经持久化，但完整的重启后终态补账、无输入别名的自动续跑归属尚未闭环。缺少原生证据时返回 reconciling，不重放请求、不报告成功；目前不应作为无人值守正式评测的完成依据。
- 一旦 Session INSERT 已开始、创建进程中断或回执撤回失败，结果仍可能不明：保留回执，重放只读取已存在任务，不补建，可能返回 TASK_NOT_FOUND。旧孤立回执没有本次失败证据，不自动修复；已删除任务不复活、已撤销任务及旧 key 不接管。此限制与创建前明确失败后的显式重试不同。
- 无推理档位的模型暂不支持；不支持的 route 明确拒绝。
- cancel 的 requestKey 当前不建立独立账本；同一 run 的终态保持幂等，进行中的重复取消仍可能再次请求原生停止。
- 评测插件已接入此接口；实际 UI 联调结果另记，未自动启动付费模型。

服务、执行归属、权限入口、清单兼容、Worker 创建与释放均有定向回归。数据库迁移使用隔离临时数据库验证，不触碰真实用户数据库。完整 UI、真实 provider 执行和重启后的长期恢复仍需发布前验收；不能把模块测试通过解释为无人值守评测已完成。

## 首次修改授权

插件新增的 tasks 能力首次使用时复用宿主权限确认。拒绝、超时或确认失败后，同一账号代际和安装修订在当前宿主进程内不再自动弹窗；插件重载或重复调用不能清除该状态。用户可在本机插件详情权限区点击“确认任务权限”重新进入原确认流程，点击不等于批准；在途确认不并发，账号、安装修订或发起窗口改变时旧结果无效。旧插件的既有功能、启用态、凭证与设置不变。此显式入口不向插件页面或 device-link 暴露；重启宿主后可重新首次询问。

逻辑页可调用 cindy.tasks.requestWriteAccess({taskId, mode?})。省略 mode 保留旧行为（acceptEdits，仅限未开始执行的任务）；mode: auto 请求宿主原生确认，为空闲自有任务及插件后续任务启用 Auto。插件不能替用户确认，不能请求 Full access。拒绝不改状态；账号、配置、任务版本在确认期间改变则拒绝写入。Auto 插件主任务的 Worker 固定使用 Auto，不继承或改写全局 Worker 偏好；授权撤销后拒绝新建。Host 读取该次权限时一并保留账号与插件来源，在团队查询、Worker 准备/启动、落盘后以及首条输入的 accepted 回调中复核；在途卸载、重装、归属消失或降权不能将本次创建降为普通 Orca。调用开始前已明确撤销的旧用户任务仍可新发起普通 Orca。首条输入（任务或就绪消息）真正接收时沿现有回调再次复核；任务接收生命周期的异步更新前后均检查，失败回滚本次临时运行态并取消派发。直发拒绝后，在派发调用退出后才沿原生命周期清理新 Worker；排队后迟到的拒绝仅取消该输入并回滚本次临时状态，保留 Worker 和用户数据。既有内存回调不构成跨重启的授权事务，也不保证中断已接收执行。失败沿原生命周期尽力清理，不保证跨账号数据库补偿或跨进程事务。独立目录不是沙箱。返回 granted 与更新后的 task/revision，插件应继续原批次。

### 主任务协调评测

插件拥有的主任务通过公共 `start_team` 显式请求 Worker Full access 时，Host 在原确认入口前复用当前插件归属与 Auto 判据，直接返回 PERMISSION_DENIED，不弹确认、不更新全局偏好或创建团队。Auto／省略参数和普通用户任务的 Full access 确认保持原流程；已撤权任务仍按当前接受输入的来源判定，旧插件执行不会变成普通用户调用。

Worker 创建后至首条输入真正接受，继续核对实际解析的目录与模型路由；落盘、创建预留释放、Lead 激活和排队接收不会结束这次校验。异步来源/计划读取后同步复核当前目录授权，配置目录被取消或 picker 记录淘汰不能借旧检查放行。复用原创建失败补偿；排队后迟到拒绝只取消该输入，不删除已创建的 Worker。回调仅在 Host 内传递，不进入任务回执或 IPC 返回值。

模型调用的暂停 Worker、归档、结束团队与切换焦点，也复用当前输入来源和插件权限检查；关闭、归档及既有目录锁等待后的写入前复核。原有延后完成确认保存同次调用的核验回调，消费一次后不重登记；独立用户确认不继承模型限制。用户 UI/远程控制的停止清理及内部失败补偿保持原入口。多步清理途中拒绝可能已有局部效果，不构成跨工具授权事务，也不保证停止已接受的原生执行。

已运行的插件 Lead 继续派发或替换 Worker 输入时，复用创建入口的当前归属/批准、Auto/Plan 与账号核验；更新、取消、合并排队输入同样复核。来源取当前输入及既有 send 回执，原生发送回执尚未返回、人工 steering 尚未接受时也不丢失插件来源。撤权后的运行中任务遇到自动回报（含绕过输入队列的原生直发）时，复用现有可见消息中最近的插件输入或 Host 保护的真人输入证据；自动消息本身不构成接管，缺少证据拒绝；来源不明的普通输入阻断回溯，不能跳过它借用更早的真人授权。重试沿既有 retrySource 继续原输入，不恢复已撤销的插件控制权；用户在保留任务中新发送且已接受的消息仍可发起普通 Orca。调用内核验覆盖查询/恢复与真正接收，interrupt 在队列恢复后、插队和停止前复核；队列修改同步核对所读条目仍是同一对象，不以相同 ID 覆盖后来的用户消息。以上不停止已经接收的原生执行，也不改变用户独立停止/清理入口。

任务写权限请求在当前宿主进程中按账号代际、安装修订和任务记忆拒绝或失败，插件 reload 和更换请求模式不能恢复自动弹窗。用户可在本机任务权限菜单点击“重新确认插件写权限”，复用原请求模式和原生确认；在途请求不能并发。此专用 IPC 拒绝 device-link，并校验真实顶层窗口、账号与安装修订。已有效授予的权限直接复用，未改变普通权限切换行为或旧 errand。重启宿主后可再次首次询问。

插件授权确认后的提交、本地/远程任务权限切换及 IM 权限命令，共用按任务排列的内存提交队列，覆盖运行态变更、数据库保存和失败回滚；较早操作不能在较晚用户选择完成后再回滚覆盖它。确认弹窗在队列外。普通权限切换不占发送/重启锁，原生群轮次的临时权限恢复和续跑仍可完成；插件提交仍保留原来的空闲检查与发送保护。界面与远程转发不再追加第二次权限保存。等待后及异步边界核对原账号实例，失败不延迟重试，不承诺跨账号补偿或跨重启事务。

首次协同计划检查落盘 user 消息与任务开始/结束时间；清空或回退对话不会抹除执行事实。目录核验到保存复用普通发送锁，同计划重放仍保持幂等。

`tasks.startTeam({taskId})` 为本插件拥有的普通任务启用 Orca Lead，复用现有协同入口及 Worker 权限确认。插件不能指定 Worker 权限绕过确认。确认返回后检查原修订；团队查询、创建和 Lead 激活后复用同一准入回调，核对原账号、插件归属/批准、当前 Auto/Plan、任务路由与目录以及插件配置目录。正常成为 Lead 会改变包含角色的修订，原生阶段改比这些准入事实，不把本次角色变化误判为用户变更。`tasks.getTeam({taskId})` 只投影所属团队的 Worker 身份、实际模型配置、目录、队列和终态；不会将 Lead 一轮完成解释为整个团队完成。

协同启动要求任务仍为 active；创建或激活中的归档、撤权、降权及配置变化会拒绝本次调用。新建团队沿原 lifecycle 补偿标为 failed，清理 Lead 角色及运行态选项，不删除任务或成果；复用已有团队时只拒绝本次调用，不结束原团队。检查与尽力补偿均处于原生操作的 drain 跟踪内；存储补偿失败仍返回失败，不保证跨账号数据库补偿，也不宣称最终复核与后续跨进程归档形成事务。

插件可读取自己任务在权限变化后的状态与执行停止，但新发送拒绝超出插件策略的 full access 任务。任务快照同时返回独立的 planModeEnabled 与原 permissionMode；独立 Plan Mode 开启时拒绝新发送、排队接受、写权限请求及 Worker/团队启动，不以原 Auto/AcceptEdits 作为执行授权。普通 permissionMode 为 plan 的既有流程保持不变。既有普通任务的所有权收据在成为 Lead 后继续有效；Worker 不是插件直接控制的普通任务。

评测客户端每批仅创建一个 Lead，答案目录逐份隔离，由 Lead 使用原生 Orca 调度。插件根据 Worker 成员、配置、目录、done 且无活动/队列的状态独立验收。该投影不是逐轮执行账本，不作为精确费用证据。重试先核对既有 Worker；未知归属不得重派或算零分。停止须确认 Lead 停止处理完成和团队不再活动。

getTeam 的 completedAt 可由宿主落盘的 turnCompleted 终态恢复：仅接受当前轮最终顶层 assistant、启动/结束边界吻合、无后续用户输入、无活动/排队/暂停工作，并须有未清空/回退的真实顶层任务输入。初始化就绪确认及仅有自动续跑输入不能充当题目；续跑可关联原始真实输入。同毫秒消息按 SQLite rowid 插入顺序确定最后一条，不按随机消息 ID 排序；releaseWorker 共用该读取。没有交卷证据的原生 done 仅在插件投影中显示 idle，不改原生状态；lastTurnEndedAt 仍是诊断时间而非交卷凭据。空闲状态或 Worker 报告正文自身不是交卷凭据。投影同时返回实际 permissionMode，供插件诊断。

### 已登记协同计划与释放

`setTeamPlan({taskId,plan:{concurrency,items}})` 在本插件自己的创建收据中冻结计划。首次登记必须早于输入派发和 Worker 创建（包括创建预留）；同一计划的幂等重放不受此限制。每项含唯一 label、workingDir 和精确 route；重复设置必须一致。未登记计划的存量插件沿用原行为。Worker 创建复用原子 reservation，预留后再次核对计划，计划上限只可收窄宿主硬上限。已结算 label 持久保留，不因归档再次变成可派发项。

计划保存目录准入返回的 canonical 路径，后续别名改链不会把冻结计划改成新目标；这不构成 OS 目录对象隔离。首版仅用于可信本地工作区，不防御同权限进程在最后校验后、harness 使用 cwd 前恶意替换目录对象；路径复核或 JS 锁不能消除该窗口，不把另建 OS 隔离后端列为本接口的发布前提。插件归属、显式撤权、用户降权与任务范围的检查仍须成立。`getTeam` 先恢复 Lead 的持久输入队列，恢复失败或未确认时拒绝返回空闲；最终读取实时 Lead 状态，不以启动后的空内存队列报告批次完成。

`releaseWorker({taskId,workerId,completedAt})` 仅释放本插件 Lead 内、结束时间仍匹配、无活动/排队输入的 Worker。它与 getTeam 共用宿主成功终态判据，不能以 Worker 更新时间或失败轮结束时间替代交卷凭据。调用方应先保存交卷快照和评分。复用 Orca 的归档路径、transition 锁和发送锁；持锁后再次核对 completedAt 与归属。有计划时必须在归档前确认标签归属；无计划的兼容调用不写标签结算。已有发送锁时直接拒绝释放，不等待而形成锁反转；只有归档成功才结算 label。拒绝正在发送或运行的 Worker，保留任务历史与作答文件。

`getTeam` 增加包含创建预留的 capacity 快照（advisory；准入仍由创建事务裁决）、逐 Worker 的等待确认状态、首条输入/首条执行消息时间、最近轮结束时间，以及 Worker/Lead 分列的 session-total 用量。`host-message-window` 是可观测作答窗口，不是精确模型计算时长。无确切 USD 金额时返回 null，不把订阅估值或其他币种直接当美元。

写权限确认前及最终提交前，在原 session/send 锁下恢复持久输入队列；恢复未确认或仍有排队输入时拒绝提权，不把冷任务的空内存队列当作空闲。任务能力批准在收据临时文件准备完成后紧邻原子发布复核账号时效，该受保护替换不跨事件循环；普通收据写入保持原路径。

Plan Mode 的本地及 device-link 切换与插件确认复用同一内存权限提交队列，由 Host 完成 runtime、落库与失败恢复；renderer 不再另写 DB 或发第二次回滚。原生 Plan 事件只异步登记镜像，不阻塞事件消费和 turn 收尾；落库前核对原账号、绑定 Session 及当前 armed 值，忽略迟到的旧事件。插件授权另同步核对现有稳定 Plan 状态（含未知/切换中），不等同于仅看数据库镜像。普通新输入 IPC 在 send/restart fence 外等已有权限提交完成后才进入发送；内部续跑、steering 与独立停止不等待该队列。上述复用不新增 Plan 代次、持久字段或后台重试，也不承诺跨工具事务。
