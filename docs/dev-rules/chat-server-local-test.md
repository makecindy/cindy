# Chat Server 本地接入测试

正式客户端统一通过端点清单的 `chatApiBaseUrl` 连接聊天服务器，WebSocket 从同一地址派生。国内与国际清单连接同一生产聊天数据源，支持跨区邀请；不再按打包形态选择本地群聊。下文的 loopback 配置仅供显式隔离测试，正式安装包不会读取。

已有账号的本地群先按稳定来源 ID 建立服务器群，按原消息顺序导入作者、时间、正文和附件。服务端保存导入水位；断线或重启从已提交位置继续，已提交记录不重复，导入不触发 Agent。成功后的群 ID/水位回执保存在账号目录 `chat-upgrades/<端点及账号摘要>/`，以后退出或转让群不再重新导入。旧本地数据保留为迁移源和 Agent 元数据，不作为另一套可发言群。单群导入失败时保留源数据和服务端水位，后台按群续传，界面提示尚有旧记录待上传；不阻塞云端群列表、其他群和建群。附件独立加载，失败不会阻断文字历史。

上线顺序：先部署服务端和持久数据库/对象存储，验证 `https://chat.cindy.app/ready`、两区登录与 WebSocket，再把两个区域的 CDN `endpoint.json` 发布为本仓清单，最后发布客户端。仅修改随包 JSON 不等于在线 CDN 已发布。服务端部署登记与操作说明见 cindy-server 的 `docs/chat-server-production.md`。

## 两个 DEV 接入同一聊天服务

在 cindy-server 的 `chat-server` 目录运行：

```sh
NODE_USE_ENV_PROXY=0 HTTP_PROXY= HTTPS_PROXY= ALL_PROXY= pnpm dev:local --cindy-auth
```

需要本机 PostgreSQL 的 `pg_config`、`initdb`、`pg_ctl`。真实账号模式使用仓库外 `~/.cindy/chat-server-dev/db` 持久数据库，正常重启直接复用记录；不读取业务数据库配置，仅开放私有 Unix socket，API 只监听 `127.0.0.1:3018`。本模式同时使用真实 `https://auth.cindy.app` 和 `https://auth.cindy.com.cn` 的 RS256/JWKS、成员状态校验，不启动虚拟身份服务。

在两个隔离 profile 的 `chat-server-dev.json` 写入以下配置（不含凭证，不放入源码目录）：

```json
{"baseUrl":"http://127.0.0.1:3018","auth":"cindy"}
```

从两个独立 worktree 启动相同代码，各用独立命名 profile 和调试端口：

```sh
XDT_CDP_PORT=9238 pnpm restart:desktop:remote --region=global -- --isolated=chat-server --wait-ready
XDT_CDP_PORT=9239 pnpm restart:desktop:remote --region=global -- --isolated=chat-server-peer --wait-ready
```

每条命令须在对应 worktree 执行，成功须返回 `DESKTOP_DEV_VERDICT=ready`。数据目录分别是 `CindyGlobal-dev2-chat-server` 和 `CindyGlobal-dev2-chat-server-peer`。启动遵守当次用户授权；不从正式 profile 复制账户、数据库或模型凭证。

由用户通过正常界面登录两个不同账号。国内外、个人与企业账号均可互相邀请，不要求同一区域或同一组织。每个账号由自己的认证服务验证；服务端身份包含 issuer，防止不同认证域编号碰撞。两个独立 profile 拥有不同设备身份，但不能据此宣称已验证两台物理设备或手机直连。

## 操作路径

1. 伙伴侧栏 → 加号 → 新建群聊。可以选择零到六位本机伙伴，建群后再邀请人。
2. 群顶栏邀请按钮 → 生成邀请链接 → 复制。链接 24 小时有效、一次使用；群主或管理员可以创建。
3. 另一账号：伙伴侧栏标题旁的加入按钮 → 粘贴链接 → 查看邀请 → 接受并加入。预览只展示群名和邀请者，不开放历史；加入后按群的历史策略读取。
4. 每条消息下面可打开回复面板、添加/取消表情回应。消息显示回复数和回应人数，自己的回应有选中状态。伙伴回复 Thread 消息时，结果写回同一 Thread。
5. 两个窗口分别发消息、回复和回应；检查实时刷新、不同作者名字及本人标记。退出其中一个 DEV 后，另一个仍能读取历史；重开 DEV 重新从服务器读取。

## 数据与执行边界

现有群界面 → 受信 IPC → Main `chatServer.ts` → 清单配置的 HTTPS/WSS → PostgreSQL。账号令牌仅由 Main 从正常登录服务读取；不透传给 renderer，不写入测试配置。切换账号会废弃旧请求、连接及执行租约上下文，并重新注册当前账号的伙伴。

人和 Bot 使用同一成员、消息、回复、回应及邀请合同。Bot 通过稳定本地 ID 注册；服务器分发执行请求，Main 复用现有群专线、权限同步、输入队列和终态回传。成员资格不授予另一账号的电脑或工具权限。

本地数据库只保存执行所需的群成员元数据及 Agent 上下文，群时间线始终读服务器，不镜像写入 `bot_group_messages`。WebSocket 推动刷新；测试适配器不持久化客户端游标，重连后重新读取。执行每两秒领取，租约每十五秒续期。

终态回传遇到网络或临时服务错误时，当前进程保留同一份结果，每十五秒使用相同操作 ID 补交，不重新运行 Agent。收到成功收据或明确的过期/撤权等拒绝后结束；账号切换或退出会清理该账号的待发送结果。这是运行期重试，不是跨应用重启的持久 outbox。每次续租使用独立操作 ID，避免服务端幂等缓存导致租约无法延长；恢复只作用于该次执行，不重启共享远控连接。

## 群资料、成员与伙伴授权（2026-10-03）

点击群标题打开群设置。可以查看群主、管理员与每位伙伴的主人；群主/管理员修改名称、主题、简介和接话方式，管理成员、归档/取消归档。群主可转让给人或伙伴；群主是自己的伙伴时，主人可以代其执行管理操作，后台仍用该伙伴的角色鉴权。最后一位群主退出前须转让。

每人可修改自己的群昵称，留空使用账号显示名。「修改昵称与头像」复用 Cindy 既有账号资料编辑器，写入当前区域的账号服务，Chat Server 仅刷新经过认证的资料投影。头像使用现有公开 OSS 上传路径；伙伴本地媒体头像先通过统一媒体仓读取并上传，不能把本机路径发给另一台设备。名字/头像变化通过群事件刷新当前消息作者和成员列表。

其他成员使用伙伴有三档，由伙伴主人按群选择：仅主人、仅群内交流（默认）、工具与资料。群主/管理员不能替别人的伙伴授权；授权工具与资料前有明确确认，沿用伙伴原有操作审批。

- 服务端从消息请求者和伙伴的真实所有者计算执行权限，领取时写入租约，客户端不能自报授权。非主人请求要求执行器声明 `accessPolicyVersion: 1`，旧执行器不能领取；客户端遇到缺失或未知授权字段也拒绝启动。
- 默认交流使用独立群上下文，不装配主人的 SOUL、用户资料、私人记忆、Bot Home、已学 Skill、工具集及私人 MCP；保留公开名字与简介。每轮通过现有三种引擎的 `toolsDisabled` 执行门禁关闭全部工具。
- 主人自己发起、获准工具的外部成员、只交流的外部成员分别使用独立专线。授权版本变化不复用旧版私人上下文。
- 撤回授权会取消旧执行、递增租约版本并通知客户端停止；服务器拒绝过期结果。已经完成的外部操作不可撤销。
- 人退出或被移除时，他带来的伙伴同时退出，清空群授权并停止相关执行。重新加入恢复默认角色和默认伙伴授权；重新订阅长连接，不能沿用被撤销的旧订阅。

定向验证覆盖群资料/角色/昵称、不能代授权、执行中撤回、过期结果拒绝、主人离群后的伙伴退出，以及三个引擎的工具禁用。两个真实 DEV 已验证群昵称推送、跨区域头像、个人资料入口、成员/管理员操作、群主在人与伙伴间转让，以及未授权读取测试文件失败、授权后真实 Read 工具成功、执行中撤回后无结果发布。资料编辑入口已实际打开；未为验收修改用户的真实账号名字或头像。

## 入群系统提示的兼容接线

Desktop 将服务端持久消息 `origin: "system"` 中的
`card(namespace: "cindy.membership", schemaRevision: 1)`、
`data: { type: "member.joined", actorId, displayName }` 映射为 `member-joined` 系统提示。
只有服务端 origin 可信；用户、伙伴或导入内容里同名 card 仍是普通消息。
使用入群时保存的显示名，不根据当前成员列表反推加入，也不因成员改名或退群改写历史。
未知系统事件版本保留普通系统文本回退，不猜测事件含义。

主消息流与侧栏摘要使用阅读者的界面语言（五种语言）。手机复用现有 Remote Resource
投影，`noticeCode` 是新增可选摘要字段；旧手机忽略它，时间线可读消息 fallback，
不支持群聊原语的旧手机保留 Markdown 回退。WebSocket 收到
`message.system.created` 时沿现有群 scope 刷新并重新读取相同的持久消息 ID，
客户端不插入临时消息或触发伙伴回复；“继续讨论”也不以入群事件作为来源。
入群提示不算他人回复，不推动 `lastReplyAt` 或未读摘要回退；已有待读回复仍保留，读位不变。

客户端可先发布，旧服务端不产生事件时保持现状。服务端对应修复负责真实加入事务、
事件去重、历史可见下界与系统记录保护；只发布本客户端不会补出入群记录。
建议先客户端后服务端，新服务端先发布时旧客户端仍可读取 card fallback，但会沿旧式
作者气泡呈现，不等于已获得本地化系统样式。旧加入历史不从成员现状补造。

本次客户端回归使用离线 HTTP/WebSocket fixture、桌面与手机组件测试；不代表安装版、
线上服务或真实双账号已经验收。普通项目任务与伙伴私聊不经过本次群提示投影。
