# ZCode 团队 Coding Plan 接入

## 运行边界

ZCode 是独立引擎，持久化种类为 `zcode`，模型来源为本机 `zcode-native`。它沿用 ZCode 已选择的团队账号、组织和项目，不经过 Cindy 的 HTTP 模型代理，也不使用公共模型目录推测套餐型号。

本次按官方源码 `zai-org/ZCode` 的 `3c5b227649371507ddc4eb46ac5133afe6db1cab` 实现，并验证本机 CLI 0.17.0。使用 `app-server --stdio` 的原生会话协议，模型清单、默认推理参数和窗口来自运行时。每条消息必须携带完整 `modelSelection` 和唯一 `inputId`；仅在创建时选择模型不足以形成有效的原生输入。

支持本机文本任务、流式正文与思考、原生工具、权限确认、用户提问、停止、切模型、原生会话恢复，以及手机控制该桌面任务。SSH、引擎与工作目录分置两台电脑、Orca、伙伴身份、插件宿主会话、复核、附件、附加目录、Plan/Auto、自定义宿主提示词和推理／窗口覆盖尚未适配，界面不提供这些操作，运行端仍会拒绝不支持的请求。原生 ZCode 自己加载的项目说明和原生工具保持其自身语义。

## 账号与存储

- 首次探测只检查程序路径。用户在设置中选择「连接 ZCode」后，才把本机账号的使用许可绑定到当前 Cindy 数据所有者，并读取原生账号与模型。
- 连接操作携带界面显示时的所有者和代次。切换 Cindy 账号、撤销授权和迟到回包均受所有者及授权代次检查约束。
- 使用许可有独立的供应商代次；普通刷新和其他供应商的更新不会使现有 ZCode 任务失效。断开再连接会生成新代次，旧回包不能继续使用。
- 「断开」撤销 Cindy 的使用许可并结束当前引擎进程，保留 ZCode 自己的登录、配置和历史。后续连接仍需用户明确发起。
- 原生设置和加密凭据只读，不修复、不迁移、不写回。只解析当前团队账号所需的凭据字段，不解密其他来源。
- 按当前账号校验组织、项目及有效团队成员权益，使用现有团队 Key 签发短期令牌。令牌仅在主进程与 ZCode 子进程的私有通道中使用，不进入界面、聊天记录和日志。缺少原生团队 Key 时明确报错，不自动创建永久 Key。
- 请求前后校验原生账号、组织、项目和登录范围。订阅接口里的产品编号与本地选择键不是同一字段域，不进行跨域等值比较；本地选择变化仍会使旧会话失效。
- Cindy 会话使用按区域及数据所有者隔离的运行目录，同时设置 `ZCODE_DATA_BASE_DIR`、`ZCODE_STORAGE_DIR`、`ZCODE_SESSION_DB_PATH`、`ZCODE_LOG_DIR`。只设置第一个变量无法隔离原生 SQLite 历史。
- 每条原生记录另存稳定身份摘要，恢复前核对原账号与团队项目；摘要不含登录令牌，正常续期仍可恢复。缺少归属记录、记录损坏或切换了团队项目时拒绝恢复，不把旧历史交给新项目。
- 认证仅访问已核验的官方业务域名，不接受子进程提供的认证 URL，不跟随 HTTP 重定向。异常仅投影固定错误码和安全文案。

## 实现入口

- `packages/maker-core/src/agents/zcode/`：协议客户端、事件转换和原生会话生命周期。
- `apps/desktop/src/main/maker-host/zcode-host.ts`：安装探测、原生模型发现和每会话认证钩子。
- `apps/desktop/src/main/maker-host/zcode-native-auth.ts`：只读团队授权、短期令牌与范围校验。
- `nativeProviderAuthBinding.ts`：Cindy 所有者的使用许可，复用现有持久授权机制。
- `shared/appDefaultModelSelection.ts`：普通任务默认模型可包含 ZCode；伙伴模型链继续保持自身的支持集合。

程序发现支持标准安装目录，以及高级环境覆盖 `CINDY_ZCODE_CLI_PATH`、`CINDY_ZCODE_NODE_PATH`、`CINDY_ZCODE_BUILTIN_CONFIG_PATH`。这些覆盖用于程序与公开内置配置定位，不保存账号凭据。宿主必须提供能够运行该版 CLI 的 Node；不自动替换系统 Node 或修改 ZCode 安装。

模型参数在 ZCode 中管理；Cindy 仅控制模型在选择器中的可见性，不提供尚未接入的模型高级修改入口。用量按原生请求的代次、模型和累计 token 快照求增量，重复帧不重复记账；未知金额不推测，token 事实进入模型、任务和首页历史。

## 验证要求

协议升级应验证创建、订阅、发送完整模型选择、权限批准与拒绝、停止、关闭、持久记录跨进程恢复、原生子会话的认证与确认，以及进程退出。原生空会话可能尚未持久化，不能用它证明跨进程恢复失败。

认证测试使用假加密凭据与内存 HTTP 响应，覆盖组织／项目撤权、登录切换、迟到换证、到期、401 指纹、缺少 Key 和固定错误投影。真实检查只输出通过状态和数量，不能把账号、组织、项目、令牌或原生配置写成测试材料。

本次真实验证完成团队账号与模型发现、固定短回复生成、关闭进程后的同一原生会话恢复。固定提示词要求不使用工具，权限申请均拒绝；这不等于系统层禁用了原生免确认工具。Windows、Linux、原生附件和其他套餐不据此宣称已验证。
