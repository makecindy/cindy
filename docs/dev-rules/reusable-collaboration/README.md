# 可复用协作 Playbook

> 本文是项目无关的组织经验模板，不是 Cindy 仓库的新增强制规则。它把 Agent 指引、
> 分支交付、review 分层、UI 约束和自动化门禁整理成可迁移的基线。新项目可以直接
> 复制结构，再按团队规模和风险替换具体命令与工具。

## 使用方式

- 先落地「最小可用基线」，不要一次引入全部实践。
- 把本文中的占位项替换成项目的默认分支、测试命令、类型检查和签名机制。
- 通用方法论以正文为准；本仓实现只作为末尾参考，不应原样复制到其他项目。
- 团队重复纠正同一类问题时，优先把它升级为规则、模板或自动化守卫。
- 需要直接复制成套文件时，使用
  [docs/templates/collaboration-experience-kit](../../templates/collaboration-experience-kit/README.md)；
  本文只保存方法论和取舍依据。

## 核心模型

协作体系围绕四个闭环组织：

1. **按风险路由规则**：入口文档只列触发条件和必读规则，避免所有约束堆在一处。
2. **把确定性交给机器**：格式、签名、依赖、测试、类型和文案结构用脚本与 CI 固定。
3. **把判断交给 review**：安全边界、产品语义、数据迁移、兼容性和体验质量由人工或
   AI reviewer 分层判断。
4. **用 PR 收集证据**：改动范围、验证结果、未验证原因、风险和回滚方式留在 PR 正文，
   不依赖聊天记录。

## 最小可用基线

| 能力 | 最小标准 |
| --- | --- |
| 仓库边界 | 说明哪些目录属于本项目，哪些服务或仓库不能顺手修改。 |
| Agent 入口 | 提供一个共用指引文件，列出仓库地图、规则索引、工作流程和安全底线。 |
| 风险路由 | 高风险目录绑定专项文档；改动前按路径选择必读规则。 |
| 变更隔离 | 默认从最新主干创建短生命周期分支；复杂任务可用 worktree 或等价机制。 |
| 本地门禁 | 至少包含相关测试、受影响包的类型检查和格式检查。 |
| 授权记录 | 每个 commit 带来源授权声明，例如 DCO 签名或团队认可的等效机制。 |
| PR 证据 | 说明改了什么、不包含什么、如何验证、未验证原因、风险和回滚。 |
| Review 口径 | 统一 P0/P1/P2 严重度，区分阻塞项、本次必修项和非阻塞偏好。 |
| 安全底线 | 凭证、用户数据、权限提升和不可恢复操作必须显式确认。 |

## 占位项

迁移到新项目时先替换这些名称：

| 占位项 | 含义 |
| --- | --- |
| `<DEFAULT_BRANCH>` | 主干分支，例如 `main`。 |
| `<CHANGE_BRANCH_PREFIX>` | 短生命周期分支前缀，例如 `task/`、`fix/` 或日期前缀。 |
| `<RELATED_TEST_GATE>` | 只跑本次改动会影响到的测试的命令。 |
| `<TYPECHECK_GATE>` | 受影响包或工程的类型检查命令。 |
| `<FORMAT_GATE>` | 格式或空白检查命令。 |
| `<SIGNOFF_MECHANISM>` | commit 来源授权机制，例如 DCO、提交声明或内部审批记录。 |

## 工作流程

### 1. Agent 与人类共用入口

- 共用入口只保留仓库边界、规则索引、通用流程和安全底线。
- 模块专属规则放在模块内；跨模块专题放在集中文档，并在入口索引。
- 每条规则写清读取时机、必须做什么、禁止做什么、验证方法和例外条件。
- 文档之间只保留一个权威正本；其他位置用链接引用，避免双份规则漂移。

### 2. 分支、commit 与 PR

1. 同步 `<DEFAULT_BRANCH>`，创建 `<CHANGE_BRANCH_PREFIX>` 下的短生命周期分支。
2. 保持一个 PR 只解决一个清晰问题；发现无关问题另开任务。
3. 提交前运行 `<RELATED_TEST_GATE>`、`<TYPECHECK_GATE>` 和 `<FORMAT_GATE>`。
4. 使用 `<SIGNOFF_MECHANISM>` 记录贡献授权；Agent 自动提交遵守同一规则。
5. PR 标题使用约定式格式，例如 `type(scope): description`。
6. 正文至少覆盖摘要、范围、用户可见变化、验证证据、未验证原因、风险和回滚方式。

直推主干只在维护者明确允许时使用，并追加独立对抗性 review。活跃 worktree 必须有明确
所有者；自动回收不得删除仍被会话使用的目录。

### 3. Review 分层

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| P0 | 红线、崩溃、数据丢失、安全、跨平台失效、兼容性破坏 | 不改不能合 |
| P1 | 明显 bug、规范违反、影响面未处理 | 本次必修 |
| P2 | 可选优化或风格偏好 | 不上报，或单独跟踪 |

AI review 只补充机器查不到的风险：安全边界、迁移正确性、协议兼容、存量数据迁移、
模型行为漂移、双主题 UI、可访问性、跨端一致性和测试弱化。它的结论映射到统一严重度，
并且不替代 CI 和人工 review。

### 4. UI、UX 与文案

- 设计规范集中在一个权威正本；入口文件只做导航。
- 新增或修改 UI 必须覆盖全部支持的主题模式；颜色、间距、字体、圆角和动效走统一 token。
- 交互规范覆盖焦点管理、键盘与输入法、加载时序、动画性能、危险操作确认和可访问性。
- 用户可见文案进入 i18n；术语表是唯一裁决来源。机器检查结构和术语，人工 review 检查语境。

### 5. 自动化分层

1. **快速失败**：文档契约、命名、文案 key、端点、依赖锁定和轻量 guard。
2. **类型与 schema**：各端 typecheck、migration 校验和接口契约检查。
3. **完整单测**：按平台或 workspace 分片，分片并集必须等于全量。
4. **专项集成**：数据库、Git、协议、真实设备、模拟器或其他高风险运行时 smoke。

能由脚本稳定判断的规则不要只写在文档里；至少提供 lint、test、CI check 或 PR 字段校验。

## 新项目落地清单

```text
- [ ] 写明仓库边界和不属于本仓的服务。
- [ ] 建立 Agent 与人类共用的入口文档。
- [ ] 建立顶层仓库地图和模块职责表。
- [ ] 为高风险模块绑定专项规则和读取时机。
- [ ] 定义默认分支、变更分支、本地门禁和签名机制。
- [ ] 设计 PR 模板，强制记录范围、验证、风险和回滚。
- [ ] 定义 P0/P1/P2 review 口径。
- [ ] 把重复纠正沉淀为脚本、CI guard 或模板字段。
- [ ] 定期清理过期规则，保持入口索引可导航。
```
