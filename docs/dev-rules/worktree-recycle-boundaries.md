# 本机 worktree 回收的执行边界

归档只产生回收意图，不授权绕过活引用、物理目录身份、Git 身份或恢复证据检查。回收失败保留原目录和已经生成的恢复证据。

## 等待与失败

- 活引用、运行期仍在使用、内容发生变化：进入 waiting，不消耗故障预算，不安排定时重试。运行期释放资源的既有事件可重新唤醒；启动时只复查一次，补偿应用关闭期间已释放的资源，也可手动重试。
- 用户要求保留：进入 kept，不被后台事件自动恢复。池复用同样不能重置这个目录。
- 校验失败、磁盘空间/权限错误、目录身份异常：进入 paused，停止自动尝试。用户排除原因后手动重试。
- 其它临时故障：退避重试；同一 generation 最多 3 次失败，失败处理累计达到 30 分钟也暂停。预算是内部常量，不增加高级数值配置。

`retryPolicy` 作为 version 1 journal 的可选字段记录状态、失败次数与失败处理耗时，正常重启不重置。历史记录没有新字段时，用 reason 区分等待和失败：旧的活引用等待不能被历史 attempts 判为失败；已反复失败的记录则先暂停。

如果失败发生在核心写 journal 之前（例如资源锁/卷不可用），维护器另有每进程最多 3 次的轻量兜底，避免无法写入预算时仍不断轮询；能读取状态时同样展示暂停。它不能冒充已经持久化的预算，应用重启后允许重新检测不可用的存储。

## 用户入口

设置 → 存储空间 → worktree 回收：显示原目录、状态和归类原因，提供刷新、重试回收、保留目录。

手动动作携带资源 ID 与 generation，主进程查自己的 journal 并在资源锁内复查；不接受调用者传入任意路径。重试只重置这一 generation 的预算并唤醒既有队列，不直接删除；保留只改变回收策略，不丢弃备份或 Git 快照。已经完成恢复/删除或被新 generation 占用的旧操作无效。

此入口管理当前桌面设备的本地持久回收 journal，与本地磁盘存储设置相同。SSH 的远端 worktree 不在此 journal 中；本机 IPC 不列入 device-link 白名单，手机/另一台设备不获得这个本机存储管理入口。没有 device-link 重连行为改动。

## 与单次归档超时的关系

有限重试治理不依赖归档实现的 worker 拆分，可独立合入。ASAR 物理读取与 worker 生命周期修复负责单次执行的终止请求；本策略负责执行失败后是否还应继续。只合前者仍可能反复重试，只有后者不能修复底层 ASAR 校验或终止阻塞 I/O；两者合入才能覆盖这两类故障，不要求合并顺序。

本策略不清理旧 archive/history/recovery ref，也不把恢复证据当作可丢弃缓存；恢复副本容量与保留期限需要独立数据保留策略。
