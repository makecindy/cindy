# Model Access 静默切换引擎

> 通用规则见[跨端协议兼容](../protocol-compatibility.md)。

Pi 和 Codex 运行时准备就绪后，桌面在 V5 目录请求的 `X-Cindy-Model-Capabilities` 中声明 `silent_switch`。如果冷启动先拿到兼容目录，引擎就绪时复用现有同步补拉一次。Model Access 只为声明该能力的组织成员读取成员覆盖。旧服务端返回原有目录，新客户端接受没有 `silentSwitch` 的响应。

桌面只采用权威目录（同步成功的最新响应）里以 `silentSwitch: true` 提供唯一可用引擎的 Cindy AI 模型条目；目标引擎还须在本机可用并通过路由校验。字段缺失、关闭或目标不唯一时使用原有选择逻辑，其它模型不会因此默认到 Codex。

- 新任务：解析 Cindy AI 默认组合时，所选模型（如 `auto`）带该标记就直接用目录指定的引擎，模型 id 不变。草稿记着原引擎加该模型（如 Pi + `auto`，含用户自选）时，本机草稿同样换到目录指定的引擎再创建任务，不再因原引擎没有该模型而拦下；原引擎的记忆槽位保留。
- 已有任务：每次发送都在发送锁内按最新权威目录重新判定，不按任务记录“已判定”。任务当前内置引擎不在该条目的引擎中时，先完整交接（保留历史）再发送，模型 id 不变。目录尚未权威（同步在途或失败）或任务忙（回合进行中、待回答交互、已登记手动切换）时本次跳过，下一次发送再判定。交接期间目录刷新只要该条目仍指向同一目标就继续；切换失败记日志、保留用户输入并在原引擎发送，下一次发送重试；取消的发送照常抛出。
- 切换不分方向：目录把引擎从 Pi 指定为 Codex 时切到 Codex，再指定回 Pi 时同样切回，模型 id 始终不变。只撤掉 `silentSwitch` 而引擎列表不变时不换引擎，任务留在当前引擎，按原有逻辑处理。
- 服务端配置约定：成员退出试点后要自动切回，组织默认条目必须同样带 `silentSwitch: true` 并只给原引擎（如 XD 的 `auto` 组织默认为 `allowedAgents: ["pi"]`、`silentSwitch: true`，试点成员只覆盖为 `["codex"]`）。删除成员覆盖后，成员继承带标记的组织默认，下一次发送即切回。
- 不在目录刷新时后台切换空闲任务，切换只发生在下一次发送（新任务在创建时）。
- 目录里没有任何带标记的条目时直接返回，不读会话行。非 Cindy AI 来源、SSH、跨设备、协同、伙伴、定时与共享任务的发送，以及插件引擎任务，沿用各自的发送路径。
