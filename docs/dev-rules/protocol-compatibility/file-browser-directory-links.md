# 文件浏览器目录链接

`file-browser-core.listDir` 的展示结果支持工作目录内的目录软链接，返回逻辑 `relPath`
和 `type: directory`。完整枚举（无 matcher / `includeIgnored: true`）及全局递归文件
清单仍不跟随链接。越界、失效及文件链接不作为可浏览目录。

普通展开与文档探测均过滤指向当前逻辑路径任一真实祖先（及其上级）的回链，
并按不区分大小写的完整路径段过滤真实目标中的 `.git`（含 `.GIT`、`.Git`），与内置忽略
规则一致，不误伤 `.github`；展开时重新检查目标。文档探测继承展开路径的
祖先集合，不能用已隐藏回链中的文档决定目录可见性。单次 `listDir` 每批最多处理
64 个条目；每个文档探测顺序深入，不在递归层级重新扇出并发。此预算按单次调用，
不是跨调用的全局限流；别名的逻辑过滤规则及在途目录读取共享保持独立。

目录链接条目追加可选 `symlinkTarget?: string`：目标相对真实工作目录的 POSIX 路径，
根目录为 `''`，不传宿主绝对路径。Desktop 用它把 watcher 的目标路径事件映射回已缓存的
链接目录，合并后只刷新受影响目录，并让正文预览及其缓存失效共用这些别名映射；
映射随现有树缓存回收。访问权限仍由每次文件操作的 realpath 检查决定。
Mobile 现有 watcher 对工作目录事件去抖后刷新当前目录，无需消费此字段。

本地 IPC、SSH file-service 和 `file-browser:remote-op` 透传同一条目。旧控制端忽略
新增字段；Device Link 新控制端连接旧执行端时字段缺省，保留原刷新行为及手动刷新入口。
SSH file-service 按既有严格版本策略将 schema 升至 4、bundle 升至 0.2.9；Desktop 首次
连接探测到旧版本后自动重推 bundle，再完成握手，避免已有主机沿用旧扫描器与保存行为。
daemon 随 SSH channel 退出，无持久数据迁移。不新增 channel、能力位或服务端校验。
Device Link 的加密业务 payload 与自建中转
保持原样透明传输，无需中转升级；不改变握手、签名、路由或恢复行为。

回归入口：`completeDirectory.test.ts`、`scanner.test.ts`、remote-file-service 的
`rpc.test.ts` 和 Desktop `useFileTree.test.tsx`。分别覆盖目标相对路径、边界/循环、
链接本身的重命名删除、RPC 字段透传，以及目标事件合并和旧字段缺省行为。

目录条目结构比较包含 `symlinkTarget`；改指向时丢弃并补读已展开的后代目录，
通知当前正文和后代 LRU 失效。手动刷新发现目标变化也走同一通知，不依赖 watcher
一定送达；旧的在途正文读取不能覆盖新代次的结果。正文事件按微任务合并，单个预览
同一时刻最多一个事件重读，期间的新变化只保留一次补读。
当前正文已打开时，后台重读遇到远程截断文本仍保留原编辑器及草稿，不切入大文件
下载占位；用户复制草稿并重新打开后才取回完整文件。初次加载、已有下载与占位预览
仍可重新取回，保存沿用原正文目标校验。

编辑防误覆盖：`readFile` 增量返回可选 `resolvedPath`（相对真实工作目录的 POSIX
文件目标），编辑器把它随正文基线保存，脏草稿不采用后台重读的新目标。`writeFile`
接受可选 `expectedResolvedPath`，在执行端解析及原子发布前校验；不符返回既有保存
失败通道，错误含 `FILE_TARGET_CHANGED`，保留草稿。成功返回目标供下一次保存使用。
本地、SSH RPC、设备互联（包括 gzip 和 SSH 二跳）透传字段，服务端及自建中转仍只
转发既有业务 payload，不需部署、握手或 relay 适配。

字段缺省兼容旧端：旧控制端不携带保护条件，新控制端从旧执行端读不到目标时仍走
旧保存行为，不宣称具有目标变更保护；这项保护要求实际读写执行端支持新增字段。
校验针对解析后的文件路径变化，不是跨进程文件锁或一般内容冲突检测。
新增读取成本仅为读写时的根 realpath；写入带条件时在发布前再核对目标，无轮询或
服务器新请求。回归补充见 `fileBodySelectionQuote.test.ts`（真实编辑器保留草稿目标）、
`deviceOp.test.ts`（压缩写入及 SSH 二跳）与上述 scanner/RPC/hooks 测试。
