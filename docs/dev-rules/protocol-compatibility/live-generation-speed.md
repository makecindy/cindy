# 实时生成速度

> 通用规则与 Review 清单见[跨端协议兼容](../protocol-compatibility.md)；本文件只记录这一项能力的协议约定。

既有 maker status 可选携带 `tokenSpeed`（`rate`、`average`、`tokens`、`elapsedMs`、
`streaming`），由主机计算。Claude Code、Codex、Pi 共用同一口径：**从每个请求的首字节起算的
生成速度**，等待首字节、工具执行与审批不计入。流式内容用于实时读数，请求结束时供应商报告的
真实输出（含思考／推理 token 数）替换估算并校准后续估算：

- 正文与工具参数按文字估算（Claude Code 按字符，Codex 与 Pi 按词），比例随真实用量学习；
- 思考按摘要文字或供应商给出的 token 估计折算到真实思考量；完全不流出的思考（Codex 推理）
  按已完成请求测得的思考节奏以时间计；
- 首字节之前已生成的内容（首包、整条到达的工具调用、报告了却从未流出的推理）不进入任何
  速度，其生成时间按已测得的速度补回 `elapsedMs`，且不超过该请求等待首字节的时长；本轮尚未
  测得速度时先以等待时长计，测得后替换。

`rate` 是最近 5 秒（思考摘要为 30 秒）的速度，至少 1 秒的请求结束时取该请求的真实速度；
100 毫秒内到达 200 个以上估算 token 的文字是被压住后一次放出的积压（Codex 在推理摘要写完前
压住正文，摘要结束时几百个词在 100 毫秒内拆成大量小增量到达），不进入任何窗口；
工具执行或等待首字节期间 `streaming` 为 false。任意时刻 `tokens / elapsedMs` 等于 `average`，
自行相除的旧端读到同一数值。支持 `tokenSpeed.measurement` 的端使用以下口径：

- `latest.kind = stream` 为最近有效窗口的估算。可见正文、工具参数、原样输出的推理文本、按 token 计数的推理流可采样。压缩摘要的字数与真实推理量没有稳定比例，只用于暂估累计输出。
- `latest.kind = request` 为时长至少 1 秒、可配对请求的结算均速（有供应商计时的请求不限时长，见下），供界面标为「上次请求均速」。首个有效样本前 `latest` 为 null。状态栏和浮窗使用同一读数：状态栏只在采样后 60 秒内把它当作实时速度显示（只显示数值，不加「最近」字样）；浮窗一直显示本轮最后一次读数，新的一轮开始才清空。
  `measurement.sampleAgeMs` 可选，由宿主计算，发送远程状态时计入宿主离线队列和微批等待的时间。查看端在接收时换算成自己的时间，连接两端无需对时。重复读数只缩短有效期，暂停与重新打开视图不续期。`measuredAt` 仍标识宿主采样，未带样本年龄的旧宿主沿用原时间戳逻辑。自建中转透传既有状态事件，帧、鉴权和重投规则保持原样。
- `measurement.average` 按所有满足计量条件的已结算请求汇总：可配对输出 token 之和除以对应生成秒数。分子排除首包积压与未流出的推理，分母排除补估生成时间、工具执行和等待。首次结算前为 null。Pi 缺用量的请求保留累计输出估算，单独结束计时。ACP 的用量通知只有上下文与可选费用，不据此计算速度。
- `trace.requestRateTimes` 标记宿主曲线上来自请求结算的位置。新端首次在暂停期间收到状态也可还原已有曲线。以上字段均可选，兼容旧端；不增加请求、订阅或持久化操作。
口径来自真实录制的流：改动计数、窗口或校准前后，用 `pnpm exec tsx scripts/token-speed-replay.ts`
回放（不带参数时回放测试用的 Claude Code 与 Codex 录制，也可传入 `scripts/token-speed-capture.ts`
新录的一轮），对照运行中显示值与真实用量之比。回放同时报告「有自己读数的请求数」：只看准不准、
不看测不测得到，是此前几次修复后最近速度仍常显示「—」的原因（Codex 工具循环的录制里 6 次请求
只测到 1 次，报告却全部正常）。带供应商计时的 Codex 录制另报读数与供应商速度之比；加
`--no-server-timing` 回放客户端自己能测到的部分。Codex 录制格式在 `t/b/e/d/u/r` 之外有 `z`
（推理摘要增量）、`x`（响应结束）与 `s`（供应商计时）；同一毫秒的多个增量逐条保留，合并会掩盖
积压放出。Pi 的供应商凭证只在应用内注入，无法在应用外
录制，目前以会话记录回测计数，流式节奏尚未实测。
仅用于显示，不参与费用、缓存或上下文计数。新客户端校验数值，非法即丢弃；旧主机省略时
沿用原 usage 计数路径，旧客户端忽略新增字段。主机检测到挂起或时钟异常时，本轮后续帧不再携带该字段并标记
`generationReliable: false`，客户端据此丢弃已保留的速度。无需服务端更新、新通道、权限或
数据库 migration。

Codex 的工具调用整块到达、不逐字流出，现在多数请求（代码模式下一次请求只输出一个工具调用）
在客户端看不到生成过程，首字前的服务端排队与预处理又有 1–3 秒波动，客户端无法扣除。Cindy 为本机
app-server 打开 `RUST_LOG` 中的 `codex_api::responses_websocket_timing=trace`（保留其余默认输出），
从每次响应一行的计时 trace 读取供应商报告的采样 token 累计与 `sampling_and_stream_total_ms`，
按到达顺序与该响应自己的 token 数对上具体响应（供应商的累计值中途可能从头再计，实测出现过）：
先到则随用量结算，后到则替换刚结算的读数；结算出读数时立即推送一次状态，不等下一次请求；读数、
本轮平均与曲线位置都以它为准。该行只用于显示，不写入 Cindy 日志（带线程与响应 id）。字段未公开，
部分版本为空（openai/codex#56481），取不到时回到客户端测量；SSH 远端主机不打开。Codex 会把
自身环境传给它运行的命令，所以每个本机线程配置 `shell_environment_policy`：用户原有 `RUST_LOG`
原样还给命令，没有时追加到用户现有的 `exclude` 列表；读不到现有列表就不改（替换未读到的列表
可能放出用户屏蔽的变量）。响应结束取 `turn/moderationMetadata`（每次响应一条，在它调用的工具
运行前到达；原始事件只对新建线程生效，不能用于恢复的任务）；收到过一次后，时钟从首字节一直走到
响应结束，不再在最后一个流式条目结束时停下。没有供应商计时、也没流出任何内容的请求仍测不到，
浮窗沿用本轮上一次读数，整轮都测不到时显示「—」。

Codex 的速度累计独立于计费桶：同一产品轮次中的原生接续保留已测得的输出与时长，
用户新消息同时清零。工具占用轮次期间到达的输出（code mode、后台工具）没有自己的模型时长，
不进入速度分子或分母。已有配对读数时继续发布暂停的快照，本轮平均和峰值可见；尚无配对读数或时钟失真时省略速度。费用仍完整记账。
有未配对的输出时，快照另带可选的 `tokenSpeed.totalOutputTokens` 供累计输出显示，兼容字段 `average` 仍以 `tokens / elapsedMs` 计算。旧客户端忽略新字段，新客户端在旧主机上沿用 `tokens`。
Codex 流出的思考摘要从文字估算、按真实推理用量校准；同一思考块的原文和摘要只取一路，逐段快照和增量重复到达只计一次。首次有效流速立即发布，后续流式刷新至少间隔 500 毫秒；工具执行期间收到的输出结算立即发布。
旧客户端使用的 `outputTokens` / `generationDurationMs` 与速度快照同源，不能用计费桶
补速度分子。若某个原生 turn 丢失过配对区间，其结束用量不附完整输出的生成时长。
`tokenSpeed.peak` 是新增可选字段，保存产品轮次内已测最近速度的峰值；新端跨重连读取，
曲线裁剪不再丢峰值。旧主机没有它时使用客户端已观察到的峰值，旧客户端忽略此字段。


`tokenSpeed.trace` 为可选的有界本轮轨迹，随既有状态快照发送。客户端的速度图和下方统计（本轮平均、累计输出、峰值、推理占比）同属当前一轮：新的一轮开始时图从空白重画，不接着画上一轮的曲线与推理笔画。新客户端用其请求标记与
累计输出恢复整轮推理占比，切换任务或首次打开运行中任务后也能恢复。旧客户端忽略该字段，
新客户端连旧宿主时继续按观察到的 `request` 累计。轨迹的速度读数、请求标记各最多 48 项，
不会随轮次长度无限增长。长轮次合并覆盖时间范围最小的相邻标记，位置为请求数加权中心，
保留总推理量与请求数，图中位置属于限长采样近似。无服务端协议或中转适配变化。
