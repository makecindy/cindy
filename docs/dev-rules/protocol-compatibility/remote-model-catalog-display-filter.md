# 远程模型目录按显示设置过滤

> 通用规则与 Review 清单见[跨端协议兼容](../protocol-compatibility.md)；本文件只记录这一项能力的协议约定。

`maker:provider:list` 在执行主机完成既有授权和账号快照读取后，先按同一快照中的
`modelVisibilityOverrides` 与模型 `defaultEnabled` 过滤，再通过原有响应格式传输。
判定复用共享 `isModelVisible`：用户显式开关优先，否则跟随目录默认；不限制已开启模型的
数量、不修改用户偏好。聊天模型按 agent/provider/model 区分，媒体模型沿用主机的显示设置键。
未开启模型的详情不再传给控制端；供应商结构、连接状态、顺序及开启模型的能力配置保留。
投影中的既有 `modelVisibilityOverrides` 补齐有效开关布尔值（含默认关闭项），不回写偏好。
Mobile 据此区分已关闭与已删除的旧选择：保留任务或草稿原模型身份，发送前提示重选，
不自动替换模型、不清空草稿，也不为旧选择重新传输关闭模型的详情。

这是执行主机的投影修复，旧 Mobile 和远控 Desktop 无需新增能力协商即可接收。
不增加分页、客户端重组或重试，不提高传输大小上限；本机 Desktop 设置仍读取完整目录。
“关闭后必须重选”的提示与发送前检查随 Mobile 更新；旧版控制端仍沿用各自既有选择处理。

同账号手机在每次 `maker:provider:list` 的 `capabilities` 中声明 `provider-picker-v1`。
桌面端在构建视图、检查凭证之前排除整家停用的供应商，并以 `deferredProviderIds` 返回其标识。
Cindy AI 和组织来源保留用于识别 Auto 迁移的来源身份与 Auto 归属，不读其连接状态。
若已有任务绑定其中一家，手机可用同一通道附带 `retainedModel: {agent, providerId, modelId}`，
只读取该任务的停用来源及匹配的聊天模型。已登记跨引擎切换时，当前和待切换的模型各在自己的执行电脑补读。
两者相同只读一次。历史记录的 `providerId: null` 按原有默认来源和主机顺序解析。
普通目录已能确定来源时直接使用，只有停用来源仍可能优先时才补读。任务在另一台同账号电脑执行时，手机只用那台电脑已开放远程调用的供应商和型号判断来源。补读结果仍与该电脑的原目录快照匹配。
补读时主机先刷新支持该 agent 的候选订阅池，再判断其中哪些提供当前模型。候选包括内置池、自建订阅池和已登记到池中的旧 Codex 连接。
补读沿用主机可见性和授权投影，结果仅用于该任务。瞬时故障只重试当前模型，每轮最多重试两次。
手机进入后台时暂停重试，原设备恢复后可重新补读。目录或任务路由变更、组件卸载会取消旧重试。
手机发送前按下一条消息实际选择的电脑、来源和模型检查可见性。补读与当前目录快照、模型路由都匹配时，
已隐藏的模型会触发重选并保留草稿。主机发现目录里已经没有该模型时，精确补读仍会返回该模型已有的显式偏好。
待发送目标需要补读而结果尚未确认时也保留草稿，离线时同样不会将其加入发件箱。发送检查只读已有快照。
旧主机忽略能力并返回完整目录，旧手机、本机设置与访客沿用原有读取。自建中转透传既有 invoke 帧。

组织供应商的可选 `customIcon` 是成员目录 v2 中已清洗的 BYOK SVG，仅向同账号控制端投影。

用户添加的连接可以通过现有 `logoKind` 指定个人、工作或内置品牌（`mark-*`）图标，也可以通过
`customIcon` 显示本机重新编码的 48×48 PNG 缩略图（data URL 上限 16 KiB）。两者仅在同账号且
控制端支持完整品牌图标时传输。共享任务访客使用品牌推断，供应商分享目录剥离自选图标和图片。
旧控制端对未知图标或无法解码的图片沿用原有回退，中转透传原有 invoke 响应。
