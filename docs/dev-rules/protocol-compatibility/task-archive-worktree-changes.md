# 单任务归档时丢弃 worktree 未提交更改

桌面归档预检沿用 `worktree:removal-preview`。被控端返回可选的
`canDiscardChanges: true` 时，控制端才会在脏 worktree 的单任务归档确认中展示
「丢弃未提交的更改」。同账号远程控制沿用原有 `local-db:sessions:patch-meta`，
其中 `discardWorktreeChanges: true` 仅能与 `status: 'archived'` 一起提交，
且只作用于该任务自己登记的托管 worktree。

缺少能力标记、预检失败或用户未勾选时，继续按原有规则保存快照。旧控制端忽略
预检新增字段。旧被控端会拒绝带未知字段的状态写入，控制端不会重试成另一个用户意图。
新增字段在原有设备隧道内传输，自建中转和云端中转继续只转发加密数据，无需升级。

被控端先完成归档的状态写入，才在已有的持久回收记录上登记丢弃意图和内容快照。
目录成功回收后从恢复记录移除该快照，并释放其 Git 引用。目录回收仍受任务归属、
运行时、目录身份及其他活跃引用的保护。如果回收前检出内容有变化，则保存新内容供恢复。
