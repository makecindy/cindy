# 远程模型显式窗口（#9501）

> 通用规则与 Review 清单见[跨端协议兼容](../protocol-compatibility.md)；本文件只记录这一项能力的协议约定。

`maker:provider:list` 的模型行可选增加 `contextWindowOverride`，仅表示来源电脑的显式工作预算。
原 `contextWindow` 与 `contextWindowMax` 的默认／容量含义不变；远程 Agent 选择共用投影合入
有效窗口，设置页保留默认及恢复默认语义。旧提供端缺字段时沿用原值，旧使用端忽略字段；
提供端和使用端均升级后生效。分享备用执行目录在发布时将有效预算写进原 `contextWindow`，
不增加服务端字段。运行时仍在实际执行电脑读取本机窗口与压缩比例。

无新帧、channel、allowlist、权限、订阅或请求；官方及自建中转透传原 invoke JSON，无需升级。
回归通过供应商服务、隧道序列化、远程选择与备用目录发布生产入口验证；不改变连接恢复机制。

## 同账号远控的小窗口选择（2026-11-18 用户裁决）

`maker:get-capabilities` 对支持整理的 Harness 增量返回可选布尔字段
`supportsRemoteModelWindowRebuild`。控制端只用它决定是否以短提示代替已知缩窗拒绝。
选模继续调用原来的 `maker:set-model` / `maker:switch-session-agent`，只登记意图。
Device Link 继续拒绝 `confirmedContextWindow`，授权只来自宿主验证的同账号 owner 调用。
宿主在派发时读最新的精确窗口、使用量及任务预算；Pi 需要实际运行时的最终窗口。
无法核实时保留当前路线。Codex 继续原生压缩，SSH、任务访客、供应商分享和外部应用
均沿用现有权限。

| 控制端 | 宿主 | 已知缩窗时 |
| --- | --- | --- |
| 新版 | 新版 | 允许选模并展示短提示；宿主在发送时核实并整理 |
| 新版 | 旧版 | 缺能力位时显示原提示，保留原拒绝 |
| 旧版 | 新版 | 宿主收到原有选模请求即可在发送时自动整理；旧界面在本地已拦掉的选择仍不会发出请求 |
| 旧版 | 旧版 | 保留原行为 |

能力位与 intent 复用原请求、回复和任务变更推送。官方与自建中转都按原有信封
透传，不新增 relay 帧、确认往返、重试或订阅。Agent 在第三台同账号电脑时，Desktop
只在应用有变化的待选路线时，复用一次已有的授权目录查询核实窗口，普通发送不会轮询。
无法核实或准备失败时只阻止该任务的本次派发，原路线和原生记录仍可使用，
共享链路和其他任务继续运行。
