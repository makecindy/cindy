# Agent-Net 官方中转多副本（2026-11-13）

> 通用规则见[跨端协议兼容](../protocol-compatibility.md)；产品规则见
> [Agent 网络](../../product-rules/agent-net.md)。

## 背景

内核原本只能单进程运行：设备连接表、防重放记录在进程内存里，状态是一份整体重写的 JSON 文件。
同一账号的两台设备连到不同副本时，数据包在找不到对方的副本上被静默丢弃；两个副本共用状态文件
会互相覆盖。官方服务因此既不能扩容，也不能用两个副本轮流更新。

## 做法

`startAgentNetRelay({ mode: 'official', cluster })` 以副本身份运行，实现在
`packages/agent-net-relay/src/cluster.ts`、`clusterStore.ts`、`memoryCluster.ts`。

- **按账号网络固定副本。** 每个网络由一个副本负责，用活跃副本名单做 rendezvous 哈希选出；
  副本加入或离开时，只有它得到或失去的网络会换副本。
- **原样转交。** 请求和 WebSocket 升级由 `Authorization`（`AgentNet` / `AgentNetGuest` /
  `AgentNetIdentity`）里的 networkId 选副本。这个值只用于选副本、不作信任依据，负责副本仍完整鉴权。
  不负责该网络的副本把字节原样转给负责副本，签名、路径与帧都不变；副本间的转交带共享密钥，
  被转交的请求一律就地处理，不会二次转交。没有网络标识的请求（加入、官方登记、健康检查、`/info`）
  由收到的副本直接处理。
  转交的连接建立最多 10 秒，HTTP 正文发送完成后等待响应头最多 10 秒，字节流另有 30 秒空闲期限；
  持续正常上传不受 10 秒总时长限制。WebSocket 握手独立限时 10 秒，升级成功后
  取消转交期限，不影响长期连接。鉴权等待期间归属改变或开始下线时，不再在旧副本登记新会话。
  转交 WebSocket 的副本间连接开启 `TCP_NODELAY` 与 15 秒 TCP keepalive，及时发现无声消失的负责副本。
  `createClusterRouter` 可选传入 `source(req)`，为不是副本转交来的请求解析限流用的客户端地址。
- **共享状态。** 每个网络和每个全局文档（分享、委托申请等）各是一个带版本的键。事务只提交改动过的键，
  并核对读过的每个键的版本；被别的副本抢先时，用最新值重跑。重跑前等待逐次加倍、带随机抖动的间隔
  （约 2 ms 起，上限约 100 ms，最多 16 次尝试）：刚提交成功的副本总比落败方早一个往返开始下一次提交，
  立即重试或固定间隔会让落败方在对方持续写入时一直落败。每个副本在内存里保留完整副本，
  鉴权、登记和加入等控制入口用空写入的条件提交核对所需键的最新版本，不依赖通知先于请求到达；
  核对与 nonce 申领失败返回 503，实际无效／撤权凭证仍返回 401。逐包授权不等待后端。
- **后端不可用。** 条件提交抛错、重试用尽、或附件锁在开始工作前就失败时，内核抛出
  `RelayStateUnavailableError`（`STATE_UNAVAILABLE` / `STATE_CONTENDED`，从包入口导出）。HTTP 请求据此返回
  可重试的 `503 CLUSTER_STATE_UNAVAILABLE`，不返回 500，也不当作鉴权失败；同类告警每 10 秒最多记一条。
  附件锁内工作本身的错误（偏移校验、文件 I/O）照常返回。
- **变更传播。** 其他副本提交的变更到达负责副本后，它关闭已不被允许的会话（4410／4408），
  再重新下发目录。分享状态变化按受影响资源所绑定的主机网络传播。
- **全集群防重放。** 签名请求的 nonce 向后端申领成功后再在本机记录；一次性约束跨副本成立。
- **主机在线状态。** 提供商分享的 `hostOnline` 通过副本内部 `/_agent-net-cluster/host-status`
  查询负责副本；收到分享的列表在查询前按网络过滤，单次读取内复用同一网络、设备的状态请求。
  该路径没有共享密钥时返回 404；响应超过 16 KiB 时按无效处理。
- **副本离开。** `close()` 先退出名单，再以 WebSocket `1012` 关闭本副本的会话，等关闭帧送达；
  在 `drainMs` 内仍把迟到的请求转给新的负责副本。客户端遇到 4410／4401／4403 以外的关闭码本来就会
  重连，所以不需要客户端改动。
- **过期清理。** 每个副本只清理自己负责的网络；每个含过期加入请求、加入码或授权的网络各提交一次
  小事务，不再用一笔覆盖全部网络的事务——那会与其他副本对任一网络的写入冲突。多副本只用于官方模式，
  不存在租户邀请与申请；单进程模式保持原来的一次清理（含租户邀请与申请）。
- **就绪探针。** `GET /ready` 平时返回 `200 {"status":"ready"}`，副本开始离开后返回
  `503 {"status":"draining"}`，供负载均衡停止派发新连接；`/health` 仍只表示进程存活。
- **附件。** 附件存储必须为各副本共享：共享目录 `mediaDir`，或实现 `RelayMediaStorage` 的 `mediaStorage`
  （对象存储，可让客户端直传，见[附件存储接口与客户端直传](./agent-net-media-direct.md)）；附件元数据在共享状态里。
  每次读写、删除与过期清理都通过后端 `withMediaLock` 跨副本串行执行，锁内先应用最新网络状态，
  再校验进度与操作文件；归属变更也不能让新旧副本同时操作同一附件。
- 自建中转仍是单进程：`cluster` 只能与 `mode: 'official'` 同时使用。

## 后端合同

`RelayClusterBackend` 需要提供：

- 每键版本递增、多键全有或全无的条件提交，以及按提交顺序送达所有副本的变更通知；
- `commit({ expected, writes: [] })` 也必须原子核对每个指定键，冲突时返回已变化键的最新值及版本；
  空写入不改变版本，也不发出变更通知，用作控制入口的定向新鲜度屏障；
- 只能申领一次的 nonce 集合；
- `withMediaLock(networkKey, mediaId, work)`：按附件互斥，取得锁后向 `work` 提供该网络的最新版本
  （包括删除记录），一直覆盖文件操作与状态提交，直到回调结束。不能只依赖本机队列或过期租约；
  若使用租约，必须先隔离／停止旧持有者的文件操作，才能让后继者取得锁，不能仅凭到期放行。
- 快照保留删除记录及其版本，避免重启后把已删除键误当作从未存在；
- 活跃副本名单。副本异常退出时，名单要在短超时内把它移除，否则发往它的转交会失败直到超时。
  副本无法再续约自身存活时，后端应把它从它自己看到的名单里移除（自我隔离）。副本加入后，名单里找不到负责者的网络
  一律不承载：现有会话以 `1012` 关闭，该网络的 HTTP 请求回 `503 REPLICA_UNAVAILABLE`，WebSocket 升级回 503；
  名单为空即不承载任何网络，不回退为单进程行为；
  名单 URL 可用导出的 `checkMemberUrl` 预先校验，无法解析时抛 `INVALID_CLUSTER_URL`；
- 只接纳与存活副本 `RELAY_CLUSTER_COMPAT` 相同的副本加入，不同时拒绝启动，不能混跑；
- `commit` 与 `withMediaLock` 在后端不可达时抛错即可，内核把它转成上面的 503，不要返回伪造的冲突结果。

`createMemoryRelayCluster` 是同进程参考实现，只用于测试和本机试用；部署方用自己的数据库实现同一合同。

## 混版本与发布

| 场景 | 结果 |
| --- | --- |
| 旧客户端连多副本官方服务 | wire 协议不变；遇到 1012 按现有逻辑重连，被转交到负责副本 |
| 不传 `cluster` 的官方或自建中转 | 行为不变（JSON 文件存储、本机 nonce、单进程） |
| 已部署的自建中转 | 不受影响；多副本只对官方模式开放，不提升 `RELAY_VERSION` |
| 新旧构建的 `RELAY_CLUSTER_COMPAT` 相同 | 可以滚动更新：先起新副本，再让旧副本离开 |
| 新旧构建的 `RELAY_CLUSTER_COMPAT` 不同 | 后端拒绝新副本加入；先停全部旧副本再发布 |

服务端仓需要把本次内核改动同步到其本地同名 relay package，并实现数据库版
`RelayClusterBackend`，再给 agent-net-server 配置 `replicaId`、内部 `url`、`secret` 与共享附件存储（`mediaDir` 或 `mediaStorage`）。
副本间转交不做跨版本协商，因此由 `RELAY_CLUSTER_COMPAT` 表示集群合同：共享状态文档的形状、副本间
请求头与 `/_agent-net-cluster/*`、网络归属函数。改动其中任一项的构建必须在同一改动里提升该值。

2026-11-14 补充：重试退避、`RelayStateUnavailableError` 与 503、按网络的小事务清理、`GET /ready`、
`RELAY_CLUSTER_COMPAT`、副本间连接 keepalive、查询响应上限与 `checkMemberUrl` 先在服务端仓同步 PR
实现并经数据库后端验证，现回合到本仓内核。服务端仓另有的分享文档全局清理
（由固定伪网络的负责副本执行）只针对它本地内核的分享清理逻辑；本仓内核的过期清理不涉及分享文档，
因此不回合。

同日另回合两项服务端评审发现：已加入的副本在名单里找不到负责者时不再承载网络（原回退在后端自我隔离、
名单为空时会让该副本与新负责副本同时承载同一网络）；集群模式必须显式配置共享 `mediaDir`
（`CLUSTER_MEDIA_DIR_REQUIRED`），不再默认落到各副本自己的数据目录。同日起也可改传 `mediaStorage`。

  目录与状态、两个副本同时写入同一网络、副本加入与离开时的交接（1012、状态、附件、离开后的重放），

  写入仍能提交（去掉退避或抖动即失败）；已加入副本在名单里没有负责者时关闭会话并对该网络回 503
  （改回原回退即失败），未配置共享附件目录时拒绝启动，以及从包入口调用 `checkMemberUrl` 的合法／非法地址。
