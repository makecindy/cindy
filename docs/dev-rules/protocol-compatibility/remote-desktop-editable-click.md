# 远程桌面点击输入框唤起手机键盘

> 通用规则与 Review 清单见[跨端协议兼容](../protocol-compatibility.md)；本文件记录本次能力的字段、降级和自建中转验证。

## 能力与请求

被控 Mac 以可选能力 `editableClick: true` 声明输入框命中检测。手机仅在能力为真、
当前会话可控制且仍在前台时，针对已发送的单击请求
`{ op: "editableClick", lease, sequence }`，返回 `{ editable: boolean }`。
查询不携带输入内容，也不读取文本值、占位文字或密码。

`lease` 必须属于当前调用方；`sequence` 是该次已发送输入批次的非负安全整数。
主机保存这批最后一个左键释放的位置，每次单击最多消费一次检测。查询等待已有输入队列的
原生完成确认，随后复核会话、控制权、输入序号、控制代次和显示器。检测期间发生新输入、
切屏、撤权或会话结束时，迟到结果不会唤起键盘。无对应单击或输入未完成成功时返回 false。
手机的短延迟只合并连续点击，不作为原生输入已经送达的依据。

主机辅助程序只判断命中的控件是否可编辑、可用且已获得焦点。macOS 锁屏、
辅助功能不可用或旧原生辅助程序不支持检测时降级为手动键盘按钮。
窗口代输入与插件实时画面不声明此能力，也不开放该请求。

## 新旧端和发布顺序

- 新手机连接缺少能力位的旧主机时，继续使用手动键盘按钮，不发送新 op。
- 旧手机连接新主机时，忽略新增可选能力，原有输入和键盘入口继续工作。
- 新手机连接支持能力的 Mac 时，主机 JavaScript 和随桌面分发的原生辅助程序都需要支持检测。
  辅助程序过旧时返回 false，手动入口仍可用。
- 手机与桌面端可独立升级；中转可保持已部署版本，不要求协调停机窗口。

## 中转与媒体通道

请求沿用 `device-link:remote-desktop:v1` 的业务 invoke 隧道。
共享客户端负责业务参数和能力协商；自建中转 `packages/device-link-relay/src/hub.ts` 的
`route` 只验证既有路由头与设备访问边界，原样转发 `payload` 和设备签名，
不枚举其中的业务 op。回复沿用 `invoke-result`，因此自建中转、官方服务端及
`RELAY_VERSION` 均无需同步修改。

`editableClick` 同时列入 `REMOTE_DESKTOP_CHANNEL_OPS`。已有 `channelRequests` 能力、
媒体播放和有效 lease 条件满足时，手机可通过 `input-v1` 发送同一请求，
主机执行与业务隧道相同的授权、lease、输入序号检查。缺少通道支持或尚未发出时沿用
业务隧道；已发出的请求沿用既有失败与超时处理，不重复消费单击。

2026-11-22，在 PR #11855 分支实际运行：

- `pnpm --filter @cindy/device-link test`，60 个文件、1347 项通过。
- `pnpm --filter @cindy/device-link-relay test`，5 个文件、61 项通过。
  真实 WebSocket 路由测试覆盖该 op 的 payload 与布尔回复透传。
- `pnpm --filter @cindy/device-link-relay run interop`，2 项通过。
  该命令启动独立的真实自建中转，执行加入、设备签名通信和生产客户端重连。
  互通场景验证传输兼容，Mac 的 AX 命中及手机键盘行为由控制器、原生输入与手机测试另行覆盖。

本次未修改连接恢复、relay 帧格式、设备签名语义或中转媒体接口。已部署旧中转
可依据同一通用隧道继续转发本业务请求；上述互通结果不代表对所有历史中转版本逐一实测。
