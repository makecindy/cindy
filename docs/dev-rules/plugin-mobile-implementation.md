# 移动插件接入

手机通过设备互联使用执行电脑上的已装插件。插件业务逻辑、Library 和任务仍在电脑上；
手机提供入口、隔离页面及原生交互，不复制插件安装或另造任务类型。

## 入口与页面

- 主菜单提供插件入口和聚合未读点；目录按电脑展示，支持搜索、最近使用、详情和启停。
  宽屏目录与内容并列，样式使用 Light/Dark 语义 token，文案覆盖现有五种语言。
- iOS 已装目录使用现有 `@expo/ui` 的 SwiftUI List、Menu 和 Picker；搜索复用现有导航栈的
  UIKit UISearchController / UISearchBar，置于标题下并常驻。电脑范围和标题行是普通列表内容，
  随页面滚出；All/Unread 筛选暂不展示，保留内容通知提示点。未读不表示可用更新。
  两页使用平面 List；详情启用 Toggle 放在插件名称右侧，iOS 可视目标 48×24pt，保留 56×44pt 操作区域。
  Use it in 标题下仅保留新建/已有任务原生 secondary 按钮，不附加说明。
  panel/mainView 合并为一个打开插件入口；Tools、Permissions 与 Details 使用真实 Host 只读数据，
  Tools 使用弱底色胶囊与工具图标，随容器宽度自然换行，默认最多两行，标题保留总数；溢出时提供 Show all / Show less，始终隐藏描述；权限复用 PC 声明摘要（排除 tool）。
  分组之间不画线，仅 Details 条目之间使用系统 Divider，避免重复 padding；身份首行顶部 inset 8pt。
  Details 按 PC 顺序展示版本、作者、来源与签名、标识、包含能力、面板和只读安装目录，
  内容与信任标签复用 PC 共享规则。旧 Host 缺字段时仅显示已有真实版本/标识；可选字段为空则隐藏，
  Tools/Permissions 无数据则整组隐藏，不展示未提供数据或缺描述的占位提示。
  不推断为无权限、不补造事实或面板停靠状态。配置和任务偏好不内联，提示到电脑插件详情设置。异常时显示必要提示和单个解决动作；
  导航容器负责容器安全区，Host 保留键盘避让。图标与专用任务设置继续复用 RN 内容。Android
  保留平台列表与搜索，控件同样随内容滚动，详情使用平台原生 Switch。
- Installed 固定按最近使用排序，不展示添加时间/最近使用的筛选交互，不重复展示 Recent 分组。
  最近使用以手机 MRU 优先、Host MRU 补充；不得用没有真实来源的安装时间替代。
  只记录实际成功打开页面/使用入口，查看详情不记。列表可选 pluginOrder 只下发
  addedAt/recentIndex：addedAt 来源于成功首装记录，不取更新/通知/首次手机发现时间；
  老 Host 或历史缺失时间保持未知，排在已知添加时间之后并稳定原序。手机 MRU 优先，
  Host MRU 补充，同排名保持稳定。不同电脑的插件用资源 key 区分，配置与凭证不参与排序。
- 启停开关等待电脑操作回执并重新读取插件状态，操作期间禁止重复点击，成功后保留详情。
  离线时不可操作；失败不自动重发，账号或详情已切换时旧响应不覆盖当前页面。

### 插件市场与安装（提案实现，待维护者确认）

2026-11-25 提案实现：插件页搜索框下加「已安装 | 插件市场」分段（默认已安装，搜索时收起，
先列已安装再列市场），让手机给某一台电脑安装它还没装的插件。这是新增界面行为，是否接受由维护者确认。

- 市场是「某一台电脑能装什么」：顶部「安装到 <电脑>」，多台电脑时可切换，不含「所有电脑」。
  顺序：本次打开插件页期间在市场里手动选的（在已安装与市场分段之间来回切换也保留，退出插件页后失效）＞
  已安装分段选的具体电脑（这两种即使离线也保留，显示未连接）＞
  本机记住的上次市场电脑（在线时）＞ 任一台在线电脑 ＞ 都不在线时用记住的或第一台。自动选择不改写
  「记住的那台」，并在每次进入市场分段时定下（本机偏好读完、且已知有电脑在线后；偏好没读完前市场显示加载、
  不向任何电脑发读取），浏览期间电脑上下线不会让列表跳到别的电脑，下次进入再重新选。
  安装进行中市场固定在正在安装的那台。
  来源筛选全部 / 官方 / 社区 / 团队共享 / 自定义，默认官方；团队共享与自定义只在有对应内容时出现；
  官方与社区是公开页按 `publisherKind` 在本地筛出的子集，与电脑端远程页一致。
- 读取只用目标 Host 的 `management:snapshot {read:'capabilities'}` 与 `{read:'catalog',query}`：
  列表页 `excludeInstalled:true, counts:false`，计数另读一次 `scope:'all', limit:1, counts:true`；
  同一电脑、查询、来源 30 秒内复用（最多 6 份），下拉刷新强制重读；只看市场时（不在搜索），下拉刷新与「重试」
  同时重新查找电脑，读取电脑列表失败后不用切分段也能恢复。切到别的电脑或连接代次后才返回、被丢弃的
  读取会把那份缓存的读取中状态放开，回到原电脑时重新读取而不是一直加载。官方 / 社区整页无匹配时的自动续读
  只在插件页仍挂载、市场仍可见、页面有焦点、还是同一份列表，且当前实际的来源筛选与输入中（未去抖）的搜索词
  都没变时继续（官方与社区共用公开列表，切换筛选或去抖期间不按旧条件续页）；搜索按「全部来源」判断是否有匹配。
  装好后只从安装目标那台电脑的缓存里移除该插件、重读那台的计数，其他电脑的列表不动；同时作废那台电脑在安装前
  发出、还没返回的列表读取（含下拉刷新），它们的回包不再落地，回到市场时重读一次那台电脑的当前列表。已装详情里的
  管理操作成功（卸载、升级等），以及那台电脑发来的 `plugins` 变更通知，同样作废那台电脑的列表与计数（`invalidateComputer`）：
  屏幕上的列表与计数立即重读一次，其它缓存的列表下次进入时重读；通知按 500 ms 合并，一阵通知只重读一次，其它电脑不受影响。旧 Host 回 `INVALID_PARAMS`
  或没有管理能力时显示「先更新那台电脑」，不回退一次读全量；普通读取失败只给重试，重读失败但保留上次条目时
  附一句「未能读取插件市场」。市场详情读取失败时（现有行为）：顶部「读取失败 · 重试」，下面仍是市场列表已读到的资料（名称、
  说明、来源、安装按钮），工具清单只来自详情读取，读到前不显示；「重试」重新读那份详情，成功后横幅消失、
  工具清单出现；列表的「重试」同样恢复。探测通过后某次分页读取回 `INVALID_PARAMS`，同一电脑与连接代次内最多重新探测一次。Host 抛出的错误经
  dispatch 到手机是不带 code 的 `Error("[CODE] …")`，管理 client 按 `deviceProvidersCache` 的做法解出 `CODE`。
  页面按白名单字段做有界解析，`publisherKind`、`organizationAccessError`、`counts`、`nextCursor`
  缺失即降级；图标只接受未过期的 HTTPS 链接，自定义市场项不显示图标。
- 详情读 `management:market-detail`（列表项 + manifest，无 README），工具名来自 manifest；
  权限只在电脑下载并检查真实安装包后的确认回执中出现。安装沿用现有管理 controller 与确认面板：
  点「安装」→ 等待确认 → 允许并继续 → 正在安装 → 这一行结束、市场留在原处，结果列在顶部提示里，用户点「查看」→
  「打开插件」进入该插件的已装详情（页面不因结果自己换页，见下文「成功之后只有一个读取方」）。每次安装单独
  挂一个 controller；这条路径的 controller 读 `{read:'installed'}`（安装前已确认 Host 支持分页），
  一次安装 5 次轻量读，不读全量（结果之前 3 次，是 controller 对任何操作都有的读取；结果之后 2 次：记录自己的那一次
  已装读取，结论只看它；以及 controller 在任何操作结束后照例读的一次，市场行这时已经结束，这次回包没有别的用处）；之后打开的已装详情仍沿用原 controller 的全量管理快照（既有行为）。
  同一时间只允许一个安装；安装中市场固定在那台电脑（已安装分段改电脑要等安装结束才生效），
  也不能同时从已装详情发起升级或卸载；反过来，已装详情的升级从读市场详情起就占用这一位置（宽屏下市场仍在旁边），
  读完前市场不能开始安装。管理位置按账号与目标电脑各一个（提案，待维护者确认；维护者 15:37 复审后改为结构性的同步占用，
18:45 复审后按电脑区分并与待核实记录分开）：
  - 它是一个按账号存在的同步对象（`pluginManagementSlot.ts`），不属于任何组件：页面、详情、表单、市场卸载或重新挂载都不
    释放、不重置；换账号得到新的占用。每台电脑一个位置，一台电脑上的操作不挡另一台电脑。
  - 六个入口只通过它抢占：按下的那一刻 `tryAcquire`（按 `who.deviceId` 取那台电脑的位置），拿到独有的凭据才做事；拿不到
    （别的入口持有、同一次渲染的第二个回调、旧渲染交付的按下、重新挂载的表单、同一插件有待核实记录）什么都不发。只有持有
    该凭据的调用能 `release`，晚到的另一条释放路径放不掉别人此后拿到的占用。
  - 持有者此后每一步（预检回包、确认面板的允许 / 拒绝、每次写出）先核实自己仍是持有者：controller 操作收到
    `pluginOperationHold`，begin、answer、cancel 的写出前校验都包含它。
  - 按钮的「不可用」只是投影（`slot.available(who)`：那台电脑有人持有，或同一插件有待核实记录），不用渲染态决定能不能发。
  - 管理 controller 的视图走开（换到别的插件详情、打开 README 再返回、离开页面）而操作还没结束时，controller 由
    `usePluginManagement` 留着（同一视图回来时接回）。走开后下一步只由 `nextDetachedStep`（纯函数，状态每次变化都重新判定，
    所以不会重入）决定：有写入在途就等；确认还没答复就取消一次；其余情况只要 begin 已写出就作为待核实记录留着，只在没有
    写出任何东西（预检中失败）时放开。

  账号的一条记录，与目录、筛选、分页、市场列表和占用都无关。

    不循环）；路由里只有一个插件页，正常使用走不到。

    实例却没有它的记录时，待核实的一行写明「电脑上有这个插件，但读不到它的安装记录，还不能确认结果」，「核实结果」

    回执被查出已过期时若还有这笔操作的写入在途（begin 或「允许」的回包没回来），先不下结论，等那次写入结束：
    回包到达且不比已显示的进度旧，就按回包处理（它是这笔操作的回执；取消的回包同理）；begin 确知没写出是普通失败；其余情形（回包
    丢失、回包到达但比已显示的进度旧、「允许」确知没写出）按那份事实收口，不需要用户再点一次。「不再跟踪」在写入
    结束后可点。
    确认只在它还在屏幕上的期间算「本机展示过」（controller 的 `shownConsent`）：结果一旦不再是这个确认（已答复、
    有了最终结果，或只是暂时未知：那台电脑掉线、App 进后台、自动查询停了），面板不再显示它，这个标记随即清掉。
    此后视图走开（市场行自己结束成待核实、用户按返回、换开另一条的「查看并决定」）都不算离开一个确认，同一个确认
    再被查到时不会被取消：视图还挂着并且正显示它的由那个视图重新显示（重新计为展示过），否则在记录面板里只读
    等待「查看并决定」。「电脑正在等你确认 / 查看并决定」按「此刻没有任何面板在显示这个确认」判断，不按「有没有视图
    挂着」：已装详情的确认面板只在那个详情开着时显示，重新查到确认时用户正在插件自己的页面的，确认仍能从记录面板
    打开（确认正在屏幕上时直接从详情进同一个插件自己的页面是另一回事：真机上确认面板是模态的，挡住了这条路；
    绕过它时沿用主干的行为，标记留着，离开这个插件时才取消）；答复过一次
    之后电脑要的第二个确认，用户离开它时不取消（已写过答复），同样回到记录面板等「查看并决定」；离开时的取消
    没能写出去的（被链路拒绝，或那台电脑的位置正被另一项操作占着），再查到同一个确认时也一样。同一个确认只由
    一个面板显示（已装详情自己的面板在显示时，「查看并决定」的面板让位）。
    「离开即取消」因此只剩它本来的含义：确认正在屏幕上、未答复，用户离开了它。以上只适用于插件页保留为待核实记录
    的操作；别处发起的操作（聊天里的页面批准提示）视图走开后没有任何地方能再答复，沿用原规则：离开它展示过的确认
    仍然取消，包括结果暂时未知期间离开、随后查到同一个确认的情形。
  - **市场行**：最终结果一到这一行就结束（不等读取），这一页可以开始下一笔；成功的结局不写在行上，也不提示，统一由
    顶部提示与记录面板呈现。一笔成功一旦得知（不论读取结果），那台电脑的市场列表立刻重读，已装好的插件不会还显示
    「安装」；这时开着的若正是这个插件的市场详情，详情当场改显示「已安装」并重读一次，重读还没回来或失败时也不再给
    「安装」。行内的说明只用于没有成功的结局（失败、回执过期后未能确认）。待核实的记录再查到电脑在等确认时，这一行
    写「等待确认…」，与记录面板的「电脑正在等你确认」一致（不写「正在安装」）。一次安装尝试在市场正在屏幕上的时候结束
    （市场列表在显示，或市场详情还开着：宽屏上开在另一个列表旁边，或别的页面暂时盖在前面；不论结局），市场留在它所在的那台电脑上（安装期间被固定在那里）：那台电脑成为这一次市场访问的自动选择，不在
    结束那一刻跳到另一台。这不是用户的显式选择：用户自己选了电脑（市场里选，或已安装分段选了具体某台）时照旧以
    用户的选择为准。尝试结束时市场列表不在显示、也没有市场详情开着的不固定；离开市场再回来是新的一次访问，重新
    自动选择（例如那台电脑已离线时选在线的一台）。市场详情开着时固定的这一次，到详情关掉且列表不在显示为止：
    其间那台电脑离线，市场显示「未连接」而不是自己换到另一台（详情属于那台电脑，换电脑会把它丢掉）。
  - **已装详情**：任何操作之后，详情自己的显示仍按 controller 在结果之后发布的快照（`finalReadback`）刷新或关闭（卸载），
    每笔操作一次，这只是这个详情的显示，不产生「打开」。结果之后的那次读取按当前的连接代次发出，不沿用带回结果
    的那个请求的代次：操作期间 App 进过后台或电脑断开过，结果由写入自己的回包带回时，这次读取照样落地。刷新只在这个详情正显示着的时候做：用户已经回到插件自己的
    页面时不把详情盖回去，之后点详情按钮会读它。那次快照没读回来时，详情停在操作之前的内容，直到它被再读一次
    （重连、下拉刷新、电脑的变更通知、重新打开），这与主干相同；结果这时列在顶部提示里（见「是否已经看过」）。
    页面不另外记账「哪个详情反映了哪笔结果」，也不为此追加读取。回执过期后由事实核实出的更新（详情自己的「核实
    结果」）没有成功回执，详情不会自己刷新：结果列在顶部，从记录面板「打开插件」会读这个详情。已装列表在每笔操作
    得出结论时重读一次。`finalReadback` 的事件排列仍由 `pluginManagementReadback.test.ts` 检查（「查询说进行中、随后写入自己的回包带回
    结果」这种跨连接变化的顺序不在排列里，由同文件末尾的定向用例和页面层用例覆盖）。

  写出与否的判据（调度要求 N-1；`pluginManagementClient.ts` 的 `call`）：失败的请求按证据分三种。
  - 已写出：收到回包，或传输层调用了 `onRequestWritten`（本次请求自己的帧首次写出；握手帧不算）。
  - 确定没写出（正向证据，可直接报失败、可重试）：本 client 自己的写前检查（`preSend`）拒绝；或 `DeviceLinkContext.invoke`
    调用 `onNotSent`。它只在一处判定（调度要求 O-3；`invokeSendEvidence.ts`）：调用失败、本次请求的写出回执没有来过、也没有哪条
    传输还拿着这次请求。Device Link 与 Agent-Net 都只在自己写出（或会话收下）这次请求时给回执、调用结束后不再给，所以「传输
    调用结束了却没有回执」就是该传输自己的「没写出」证据；还没交给传输就退出的分支也都在这一处被覆盖。`onNotSent` 与
    `onRequestWritten` 互斥、各至多一次。看的是失败的来源，不是错误码字面。
  - 两种证据都没有（传输层不报告写出、失败来源无法判断）：按「可能已写出」处理。写操作进入「结果待确认」并按原操作号核实，
    不显示「失败，请重试」，再点也不会发第二条 begin。

    | 已答复的确认仍在（答复已写出、回包丢失） | 1、2、4、8、16 秒…… | 30 秒 | 按 30 秒持续查询，不再答复，可「核实结果」 | 同上 |
    | 查询失败（超时、离线、链路断开等可重试错误） | 1、2、4、8 秒 | 连续 4 次 | 停止自动查询，可手动「核实结果」 | 同上 |

    | 原回执已不在（NOT_FOUND） | 不再自动查询 | — | 读一次电脑事实收口 | — |

    每 30 秒一次）。进行中的封顶更低，是因为结果多半很快到，用户正看着进度。查询失败不读安装快照，只有 NOT_FOUND 之后才读一次
    快照用于核实。故障半径三问：① 证据是什么——这一个操作的查询结果（失败或没有新信息），不是链路或电脑的状态；② 影响范围——

    回到前台或用户点「核实结果」立即按 1 秒重新开始，最慢多等一个封顶间隔。本机已写出答复而回包丢失时，

### 与桌面的差异及理由（提案，待维护者确认）

主干 5fd5f542c0 重做了桌面插件管理与市场。手机随之对齐的部分：
- 插件更新一律叫「更新」，按钮用桌面同一条「更新到 v{{version}}」（各语言照搬桌面 `settings.ghosts.page.updateTo`）；
  同一句里既有更新 Cindy 又有更新插件时写明宾语；
- 市场详情资料：版本带 v、显示作者（规则同桌面 `pluginPresentationAuthor`，公开社区作者不显示）、来源写「公开市场」或「组织」；
- 名称下只放作者，不再重复徽标与版本；
- 公开的社区作者插件显示桌面同一句社区声明（安全提示，手机不比电脑少）。

手机确认面板一直展示全部权限说明（可滚动，高风险在前），与主干 428bbdd035 之后的桌面一致。

其余差异保留：

| 差异 | 理由 |
| --- | --- |
| 「已安装 / 插件市场」分段不带数量 | 窄屏，原生分段控件 |
| 安装、更新、卸载收在右上角原生菜单 | 两端平台习惯；桌面也把卸载收进「更多」 |
| 「安装到 · 设备名」与安全说明措辞不同 | 手机是遥控另一台电脑安装，要说清装到哪台 |
| 已装的市场行用「这台电脑已经安装了这个插件。」替代描述 | 点明是哪台电脑 |
| 自定义市场的来源显示市场名，不写「自定义」 | 信息更多 |
| 没有今日推荐、排序、使用量、近期更新、包大小 | 手机不读这些字段，也控制 device-link 请求量 |
| 市场详情不提前列权限（桌面有「权限 · N 项」）；可另行跟进 | 手机在确认面板里展示 Host 生成的权限事实，允许前一定看得到；提前列要在手机上从 manifest 自己推导，有与 Host 口径分叉的风险 |
| 市场详情里可更新的插件不给更新按钮 | 更新只走已装详情的管理流程，管理位置与来源核对都绑在那条路径上 |

## 配置与授权

手机原生表单负责密钥、设备码和可远程完成的浏览器授权；PKCE/电脑 loopback 场景明确返回电脑操作。
加密复用 v3 Host 授权协议，使用 X25519、Ed25519、HKDF 与 Expo AES。
执行电脑身份固定在 SecureStore，换钥拒绝；来源变化或未知提交结果不静默重试。
凭证不进入插件页面或普通桥接；表单关闭清空临时输入。

## 兼容、冷更与回退

现有插件不需要重装、重新批准或重配凭证；mobile 为可选扩展，新增远程集合由能力协商发现。
插件批准格式、安装布局、旧任务偏好文件和 Library 数据未迁移。插件基座改动合并前需白名单明确批准。

历史移动插件接入新增纯 JavaScript `@noble/curves@1.9.7`，复用现有 Expo 随机数与 AES，
未新增原生模块，但当时依赖变更改变了 runtime fingerprint，需要冷更与指定把关人明确批准。
iOS 指纹从 `d8cd3b87cb7dcf418004eeb36b0ff1b8f29a44c7` 变为
`25a5a753aaf7740670f9588e976b4770b0817999`；Android 从
`c2eb49bea3303f89edf8de95af3a0cf45179faca` 变为 `d1d89bd866a64c681f3ded59075536abccb84c9a`。
这些指纹记录属于历史接入，不能作为后续页面调整的冷更判据。已装插件页面调整 PR #5730
未修改原生配置、依赖或 runtime fingerprint 输入；本地重建用于匹配现有基线，不代表新增冷更。
发布仍按实际构建与目标 runtime 核对兼容性，不向不匹配的旧 runtime 投送 OTA。
回退客户端代码即可撤销移动入口；不删除插件数据。
