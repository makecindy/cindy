# 功能下线与插件迁移

## 产品行为

下线必须删除旧功能的运行实现、Agent 工具、权限项、控制接口、设置、构建依赖和打包资源。Core 只保留通用下线通知机制与识别旧安装所必需的兼容字段，不用保留旧实现来展示通知。

当前迁移：原内置 iOS 模拟器下线，替代插件为 Baguette。未安装原插件的用户不新增卡片、不提醒、不推荐。已安装但原先停用的用户只在原插件位置看到下线状态，不展示迁移推荐。原先已安装且启用的用户，在插件入口及原卡片看到一次未读提示，打开详情即标记已读；「暂不迁移」保留详情入口，不反复提醒。

“正在使用”的确定性依据是首次升级扫描时实际安装目录及有效安装凭据中的启用状态，兼容旧 `.disabled` 标记；不把默认权限开关、历史工具调用或残留凭据当作安装证据。跨版本升级先复用已有安装凭据迁移，再识别下线状态。

替代插件未安装时，点击安装复用现有市场详情、下载和安装流程及其授权规则；不自动下载。已装且启用时打开替代插件，已装但停用时可启用。安装失败沿用市场错误与重试入口。

原侧栏页签投影为下线说明，独立侧栏窗口中的详情按钮也跳回主窗口。没有受影响安装时隐藏旧页签。用户可关闭旧页签或通过原卸载流程移除旧插件。

## 实现边界

- `shared/featureRetirements.ts`：离线目录，保存稳定的下线 ID、旧插件 ID / 兼容字段 / 旧页签类型、翻译键及替代插件市场 ID。无需在线下发即可识别，条目跨版本保留。
- `FeatureRetirementStore`：在现有账号与设备范围内的安装状态根下保存首次启用事实及已读时间，原子写入。失败不消耗首次识别机会，不修改原批准凭据；重启后重试。
- `GhostManager.list()`：先记录旧启用事实，再投影为不可运行；不给旧插件挂载 Skill。新装或重新启用已下线插件被拒绝。Agent 名册不包含旧插件，历史调用得到明确下线结果。
- `RetiredFeatureDetail`：宿主渲染，不挂载旧插件代码或 WebView；沿用现有明暗主题和安装流程。新下线功能复用该视图与状态存储。
- 移动端不再产生旧模拟器跳转。旧电脑发来的 `simulator` 消息仅保留协议读取兼容，使用通用不支持提示，不打开远程控制。
- `iosSimulator` / v2 `ios-simulator` 清单字段仅供旧凭据解析与序列化往返，防止修改旧授权摘要；不展示为能力，不授予权限，无控制入口。
- 伙伴旧工具名单按目录中的 `builtinToolsetIds` 清理：本机/远程设置、能力发现、运行时和后续保存都不再列出已下线内置工具；不修改历史档案版本，不改变其他选择或权限档，也不把旧工具选择当作已安装证据。
- 输入框恢复旧草稿时移除已退役的 Host 能力芯片，保留正文、附件和其他引用；不再保存旧能力交接字段或生成路由。已发送消息的能力标记只保留历史显示。

本次不删除用户的模拟器设备、App 或登录数据。Baguette 安装不等于设备迁移，也不自动接管旧设备。旧客户端回滚仍能读取原安装凭据。

## 后续迁移

新增插件下线时，在目录注册识别条件、说明和可选替代插件即可。智能通讯录等内置功能未来迁出时，需要先从其真实启用状态接入同一观察接口，再删除旧实现；不能伪造插件安装记录或给所有用户制造下线提醒。数据迁移应由对应功能独立实现并说明范围，不能借用安装成功状态冒充数据已迁移。

## 验证范围

定向用例覆盖首次扫描、跨版本升级、停用与未安装、重复启动、账号隔离、写入失败、拒绝旧能力执行、三种 Agent 的插件发现、历史页签、迁移详情和通用插件回归。保留既有设备数据，不通过启动模拟器做验证。
