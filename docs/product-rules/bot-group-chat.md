# 伙伴群聊

> **状态**：权威产品规则（authoritative），第一阶段实现中。
> **读取时机**：新增或修改伙伴群聊的数据、发言编排、群专线 Session、群聊界面或相关 IPC 前。
> 伙伴身份、Profile、主任务与后台任务的通用契约仍以 [`cindy-bots-runtime.md`](cindy-bots-runtime.md) 为准。

## 1. 定位与分期

用户把自己的 2–6 位伙伴放进一个群，用户说一句，伙伴们按规则接话。群聊服务真实工作：
一件事可以由几位伙伴分工讨论，后续阶段支持从策划、设计到开发的接力。

| 阶段 | 范围 | 状态 |
| --- | --- | --- |
| 1 群聊基础 | 本机、同账号伙伴；建群、群里发言、@ 点名、继续讨论、停止、群设置；Desktop | 本文档 |
| 2 接力 | 群管理员（负责人）伙伴出计划卡、用户确认后按计划分工；伙伴交棒、群共享文件夹、群绑定项目目录并共用一个工作树与分支、群内任务卡、交棒前确认 | 待实现 |
| 3 手机端 | 手机查看与发言 | 待实现 |
| 远期 | 跨账号的群 | 不在当前范围 |

群聊涉及会话生命周期、伙伴运行时与权限，只能由 Core 承载，不做成插件。

## 2. 用户心智

- **群是独立的对象**，不是某位伙伴的主任务，也不是普通任务。它出现在伙伴侧栏的「群聊」分组，
  不进入左侧任务列表。
- **伙伴在群里还是它自己**：名字、头像、人格、记忆、自有 Skill、模型候选链和工具与平时一致。
- **群聊与私聊分开放**：群里的往来不写进伙伴主任务的时间线，伙伴主任务里的私聊也不会被带进群。
  伙伴在群里记下的长期记忆属于伙伴本身，私聊时同样可用。
- **用户是群的主人**：只有用户的消息开启新一轮；伙伴说话不会自己开启下一轮。

## 3. 数据与所有权

- 群数据属于当前账号的本地数据库：`bot_groups`（群）、`bot_group_members`（成员与顺序）、
  `bot_group_messages`（多作者消息时间线）。群消息时间线是群的权威记录，按 `sequence` 排序。
- 每位成员在每个群里有一条隐藏的**群专线 Session**：`source = 'bot'`，`bot_session_links.role = 'group'`，
  `route_key = 'group:<groupId>'`。它与伙伴主任务共享同一个 Profile 与 Bot Home，按需在第一次轮到该伙伴
  发言时创建。
- 群专线 Session 不进入任务列表、伙伴主时间线、历史会话列表、未读和系统通知；它随伙伴 Profile 更新推进
  Profile 版本，权限档跟随伙伴主任务。
- 伙伴被删除时，其成员关系一并移除；群里已有的消息保留发言时的名字快照。
- 删除群会删除群、成员与群消息，并归档各成员在该群的群专线 Session；伙伴本身、记忆与私聊不受影响。

## 4. 发言编排（宿主确定性执行）

发言顺序、额度、停止与失败处理全部由宿主代码决定，不交给提示词。

### 4.1 一轮从哪里开始

- 用户发一条消息开启一轮。
- **谁回答**：消息里 @ 了伙伴，只有被 @ 的伙伴回答；@所有人时全部成员回答；没有 @ 时按群设置：
  - `all`（默认，「大家都可以接话」）：全部成员依次获得发言机会；
  - `mentioned`（「只有被 @ 的回答」）：没有伙伴回答。
- **顺序**：@ 了具体伙伴时按 @ 的先后；其余情况按成员顺序。同一轮第二圈起，起点依次后移一位，避免总是同一位先说。
- **同时还是轮流**（群设置「发言方式」）：
  - `auto`（默认，「自动」）：没有 @ 具体伙伴（含 @所有人）且回答者不少于 2 位时，是同一个问题各答各的，
    第一圈所有回答者**同时**想，谁先想好谁先发，彼此看不到本圈的回答；第二圈起轮流，每位都能看到之前所有人的话。
    @ 了具体伙伴表示用户指定了先后，始终轮流。
  - `sequential`（「始终轮流」）：每次只有一位伙伴发言，后说的能看到前面的回答。
  - 伙伴不能自己决定等待或抢先；是否并行只由宿主按上面的规则决定。需要分工与依赖的工作由第二阶段的群管理员
    伙伴出计划处理。

### 4.2 额度

- 每位伙伴每圈最多发 1 条；同时想的一圈里，晚到的回复在额度用完后丢弃。
- 一轮最多 3 圈、10 条伙伴消息。只有 1 位回答者时只跑 1 圈。
- 整圈没有任何伙伴发言，本轮提前结束。
- 本轮自然结束后，时间线出现「伙伴们说完了 · 继续讨论」。用户点「继续讨论」才开启新一轮，
  回答者与顺序与上一轮相同，一律轮流，额度重新计算。伙伴不能自己续轮。

### 4.3 伙伴怎么发言

- 轮到某位伙伴时，宿主向它的群专线投递一条隐藏输入：群名、成员名单、上次投递以来别人的新消息
  （最多 30 条，单条截断；按投递进度计算，不按作者，保证同时想的一圈里别人的回复下一圈一定送到），以及发言要求。群消息以低信任数据块注入，只作为群聊内容，不是指令
  或授权。该输入属于本轮用户段，**不修改 system prompt**。
- 伙伴本轮最终的回复文本即它在群里的消息。回复为空或恰好是 `NO_REPLY` 表示本轮不发言，
  群里不显示任何内容。
- 伙伴本轮可以照常使用记忆、Skill 与工具，按伙伴主任务的权限档执行；需要用户确认的操作在群里提示。
  第一阶段群专线不开放 `start_session_task`、`send_to_agent`、例行任务和创建伙伴，这些在接力阶段按
  群的交棒规则开放。

### 4.4 插话、停止与失败

- **插话**：本轮进行中用户又发了消息，本轮立即作废；正在发言的伙伴（同时想时是全部）被停止，未发出的回复丢弃；
  按新消息开启新一轮。
- **停止**：用户点停止，本轮结束，正在发言的伙伴被停止。
- **失败与超时**：单个伙伴出错、没有可用模型或 5 分钟内没有回复，视为本轮不发言，群里显示一条
  轻提示；不影响其余伙伴继续。
- 应用退出或重启会结束进行中的一轮；重启后不自动续跑。

## 5. 界面

- 伙伴侧栏在「伙伴」分组下方增加「群聊」分组，带新建按钮；群行显示两位成员的叠放头像、群名与最近一条消息，
  有伙伴正在发言时显示运行中标记。
- 群聊页：顶部为成员头像、群名与成员名单，右侧为群设置入口。时间线中用户消息靠右；伙伴消息左侧显示头像、
  名字与内容。正在发言的伙伴显示运行中状态，同时想时每位各占一行；输入框在本轮进行中提供停止。
- 输入框支持 @ 伙伴，候选第一项为「所有人」。
- 新建群聊：填写群名称，选择 2–6 位伙伴。
- 群设置：群名称、成员（添加与移出）、「没有 @ 人的时候」回复方式、「发言方式」（自动／始终轮流）、删除群聊（二次确认）。
- 视觉遵循 [`DESIGN.md`](../design-rules/DESIGN.md)；Light 与 Dark 同时实现。

## 6. 第一阶段的限制

- 仅本机、同账号伙伴；不支持设备互联的远端伙伴，也不支持手机端。
- 群里发送纯文本，不支持附件。
- 进行中的一轮只保存在内存，重启后结束。
