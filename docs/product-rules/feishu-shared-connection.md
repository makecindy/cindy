# 飞书共享连接与伙伴切换

## 使用方式

本功能复用伙伴设置中已经配置好的飞书 / Lark 机器人，不复制凭证、不新增连接实例。
在该机器人的**主人私聊主聊天**中操作：

1. `/share on`：明确允许本 Cindy 账号的普通任务、自动化和伙伴通过此连接通知主人，
   并把私聊默认落点设为 Cindy（`cindy-default` 的长期主任务）。
2. `/bot`：查看可用伙伴及完整 ID。
3. `/bot 五条`、`/bot 真人` 或 `/bot <完整 ID>`：切换后续私聊消息的伙伴。完整 ID 和全名
   优先匹配；短称只取名称中 `@`、`＠`、`|`、`｜` 前的完整部分。例如
   `五条@韩服|对账|公告` 可用 `/bot 五条`，`真人@wiki` 可用 `/bot 真人`。
   短称或全名多重命中时拒绝切换并列出完整名称及 ID；不会选第一位。未知或非 active
   伙伴不切换。完整名称也可直接使用，如 `/bot 五条@韩服|对账|公告`。
4. `/bot cindy`：回到 Cindy 的长期主任务。
5. `/share off`：关闭共享并恢复该连接原有伙伴归属，不清除凭证、主人绑定或伙伴历史。

`/help` 包含上述入口。命令只能在主人私聊主聊天里使用；引用回复、附件消息、群与访客
不能修改共享或选择。正在选择接管任务时，先完成或退出选择。切换伙伴会结束该私聊原有
的 `/ctr` 接管；之后仍可以显式使用原有接管功能。

目前共享入口针对**伙伴设置中的现有连接**；设置页个人机器人仍保留原有专属行为，
如需共享，可先使用现有「移给伙伴」入口，再在其主人私聊开启共享。

## 归属与兼容

- 老记录不包含 `sharedFeishu`，升级后保持原有专属连接行为，不自动迁移凭证。
- 共享是账号级显式 override，每个账号只允许一条共享连接。记录位于现有账号隔离的
  `bot-im-connections.json`；只新增 AppID、该 App 的主人 open_id、当前伙伴选择三个非凭证字段。
- 原 `botId` 不变，仍用于群、话题和访客专线。共享选择只影响主人的私聊。
- Cindy 和伙伴各用自己的 canonical Session；切换、断线重连与重启沿用原历史。
  当前选择持久化；`selectedBotId: null` 表示 Cindy，不表示创建新的普通任务。
- 占用 AppID 的排他建连检查保持不变。共享解析仅返回原有在线实例，不新建客户端。
- 群策略、工具权限、逐轮作用域、伙伴工具白名单及通知开关保持原有判据。共享不授予
  原生群 API 的新权限，也不会把群收件人当作主人。

共享连接属于运行它的 Desktop 实例；当前实现不跨其他电脑或隔离实例转发收发。
Cindy 和所选伙伴仍遵守原有主力电脑归属：选择成功不代表取得执行权，也不会自动接管。
若主力电脑在别处，不能把 `/bot cindy` 的确认文字视为 Cindy 已在此实例成功接待；
应在具备相应执行权的实例验证实际回复。

## 发送与失败行为

普通任务、独立调度任务及伙伴主任务的主人通知共用 `createFeishuTransportResolver`。
共享开启后选择共享连接；无共享时沿用个人 / 伙伴专属连接。消息来源由宿主依据 Session
与伙伴关联生成；流式回复的来源在创建轮次时冻结，不能跟随之后的伙伴切换改名。
文件发送前单独标明来源。来源不是模型填写的字段。

共享开启后，Cindy 与伙伴的主人主任务、话题及例行任务均挂载飞书通知工具，即使伙伴本身
没有专属飞书连接。挂载清单来自当前账号的连接记录；关闭共享后恢复原专属清单。
工具可发现不代表连接在线或获得原生 API 权限，实际调用仍逐次核验传输与轮次作用域。
共享渠道与实际挂载清单参与伙伴运行时变更判断；已打开的主任务、话题和例行任务在下一轮
发送前沿既有刷新流程更新工具，关闭共享会清除旧渠道标记。不中断正在运行的轮次。

共享连接必须在线，AppID 与主人 open_id 必须和开启共享时一致。断开、授权失效、连接被
删除、账号边界切换或无法确认唯一连接时拒绝发送，不转借其他连接的收件人。
伙伴暂停、缺失或无法解析时，共享入站拒绝回落成另一个身份；通知回复也检查原伙伴是否
仍 active。未开启共享的老专属连接保留原有不可用回退策略。

飞书平台撤销权限的实际生效时刻由平台决定。连接在线不代表发送权限仍有效；发送被平台
拒绝时应保留真实错误，不改用其他 App。仅关闭开放平台中的权限并发布，不能据此声称
现有凭证已立即失效；需以真实 API 拒绝回执验证。2026-10-28 测试应用关闭 `im:message`
并发布后约五分钟内仍能发送，此现场未证明即时撤权，不应写为已通过。

完成通知保留原任务收据。回复该通知时，继续原任务，不因主聊天当前选择另一位伙伴而改道。
伙伴通知回复保留原任务的伙伴归属，发送前同样检查伙伴状态并刷新模型、权限和工具；
伙伴归属缺失或原任务属于群／访客专线时拒绝将它作为主人私聊继续。
调度通知仍只在 `notify.feishu=true` 时发送；本功能不修改已有调度、补发或重跑历史业务。

## 实现与验证入口

- 命令、主人校验和来源：`apps/desktop/src/main/im/feishu/sharedConnection.ts`
- 存储与在线实例：`im/shared/botImConnectionStore.ts`、`botImConnectionRuntime.ts`
- 主人通知路由：`mcp-integrations/feishuTransportRouting.ts`
- 入站：`im/shared/turnRunner.ts`；通知回复：`im/feishu/notificationOrigin.ts`
- 调度：`scheduler-host/notifier.ts` 与 `scheduler-host/index.ts`
- 定向测试覆盖命令、旧绑定、共享实例唯一性、来源冻结、两位伙伴、独立调度、跨 App
  收件人拒绝、断线重连、暂停、换账号、群和访客边界。

源码开发版需在当前 worktree 执行：

```powershell
pnpm.cmd restart:desktop:remote -- --region=global --isolated=@worktree
```

只有返回 `DESKTOP_DEV_VERDICT=ready` 才表示启动完成。隔离版没有正式版的 Cindy 账号和
飞书凭证，不能通过复制正式数据来验证，也不能让同一 AppID 的测试实例与正式版抢连接。
先以单测验证路由；真实联调使用独立测试机器人及本人测试账号。源码改动不会影响当前安装版。
