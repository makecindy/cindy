# 同机移动与跨电脑复制任务

任务菜单保留同机「移动任务」的项目、选择文件夹及移到对话行为；「复制到其他电脑」在目标
创建独立副本。选定电脑及位置后，确认框只简短说明自动任务和消息渠道不随副本复制，不强调原任务保留。自动任务、飞书路由、共享或 Goal 绑定不阻止复制，也不转交给副本。
源任务不会归档、变成只读或失去执行权；不删除源项目及 fork 共用目录。

离线电脑不显示。明确不支持复制协议时才提示更新；连接失败不推断为版本过旧。
远程任务的同机项目切换仍发送到任务所属电脑，复用已有 `moveSession` 宿主业务路径，
不开放远程原始 DB patch。同机移动不会传输文件，其既有绑定及运行状态校验保持不变。

## 复制内容与流程

1. 复制普通 Desktop、共享来源或飞书来源的任务，以及从主任务发起的整组 Orca 任务。
   SSH、Review、其它消息渠道和伙伴任务不在当前范围。不能单独复制 Worker；整组包含已归档成员。
   准备时检查成员、排队输入及运行状态，等待已有消息落盘。自动运行的绑定本身不构成阻止条件。
   导出与目录快照完成后复核成员、运行／排队状态和任务更新时间；发生变化则留在准备阶段重试，
   不发布这次副本。该检查不冻结输入，也不承诺外部编辑器与数据库的跨进程原子快照。
   复制是一次快照，不持续同步；源任务后续变化不会更新副本。快照遇到文件变化会失败并允许重试。
   Git 项目以 HEAD、分支与暂存区内容判定变化；其它任务的 `git status` 等只刷新 index 缓存、不改内容，不算变化。
2. 复用任务分享导出、原生上下文恢复及 worktree 快照。包含未提交、未跟踪和忽略文件；
   仓库已登记、位于 `.cindy-worktrees`（旧名 `.xdt-worktrees`）下的其它任务 worktree 不随副本复制，
   也不计入统计；在这些 worktree 里运行的任务不阻止复制。这些文件夹里的其它内容、非 Git 目录照常复制。
   Git 保留 HEAD、暂存区和工作文件差别，不复制本机 Git 配置、hooks 或凭证。
   目标始终创建独立目录，不覆盖已有项目。整组共享物理目录只复制一份，独立目录分别创建。
   保存位置可选目标电脑的已有项目；不选项目时按任务类型只给一个选项：对话任务显示「对话」，
   副本放进目标的对话工作区、仍归在「对话」；项目任务显示「新建项目」，按源项目相对用户目录的
   路径在目标用户目录下新建（如 `~/Code/app`），同名已存在时依次加「 2」「 3」，并登记为最近项目。
   任务在 `.cindy-worktrees` 等 worktree 中时，按侧栏归属的主项目路径计算。
   源项目不在用户目录下或路径在目标系统无法创建时，只用项目文件夹名放在用户目录下。
   Worker 的独立目录在未选项目时放在 Cindy 管理的 `task-copies/projects` 下，不进用户目录。
   旧版源端不提供任务类型、或文件夹名本身无法创建时，目标仍放在 `task-copies/projects` 下。
   目标以 `mkdir` 直接占用文件夹（并发复制不会选到同一个），任一位置创建失败都依次尝试下一个。
   未选项目时，复制前的预检不估算落点所在磁盘，接收端在解包前按实际落点检查空间。
3. 复用 peer 直传及 OSS 回退、冷却。按实时磁盘和可用内存预算准备、发送、接收及解包，
   不设任务总大小上限；大文件按现有单对象传输容量分段，校验大小及 SHA-256 后解包。
   目标声明 `externalTranscripts` 时，32 MiB 以上的原生会话记录（Codex rollout、Claude、Pi，含 Worker）
   不进内存里的任务包，流式暂存、单独发送，目标逐行改写会话 ID 后原子落位，内存只随其中最长的一行增长（单行接近字符串上限属已知边界）；
   能力在每次准备时询问，旧目标仍随包携带。Cindy 消息与附件仍整体在内存中处理。
4. 目标以复制 ID 幂等导入，整组沿用已有团队事务。导入成功即可使用目标任务，
   不等待源端让出执行权，也不自动开始模型回合。任务使用目标模型设置，权限回到需要确认的模式。
5. 确认页使用接收电脑名称或“本机”，展示项目文件数量与复制前估算大小（含隐藏／忽略文件，整组共享目录去重）。
   Git 历史、任务对话与附件另行复制，不计入项目文件统计；统计完成前不能开始复制。
   `copyEstimate` 能力存在时才调用 `estimate`；旧源端无法统计时明确提示连接／版本检查，不开始复制。
   源端以明确原因拒绝统计（如任务有排队中的消息 `MIGRATION_TASK_QUEUED`）时显示该原因，不提示连接／版本；
   没有专门文案的错误码仍提示连接／版本并附错误码。
   统计在任务所在电脑上按 3 分钟截止（本机任务同样适用；文件系统调用本身卡住时无法中断，属已知边界），超时时提示项目文件过多，不提示连接／版本；项目文件超过 50 万个时提前停止统计，
   提示改为复制文件更少的项目，不开始复制。该上限只是确认页的准入检查，复制本身仍不设总量上限。
6. 复制进行中的弹窗可通过「后台继续」或 Esc 关闭，关闭不中断复制，之后从原任务顶部的复制状态重新查看进度
   （2026-10-01 用户要求，替代此前“全程保留弹窗、不提供隐藏到后台入口”的口径）。准备阶段显示 Spinner 与空进度条，
   发送阶段显示“已传输 X / Y · 平均 Z/s”（2026-10-02 用户确认：不写“上传”、去掉“尚未完成接收”的括注；
   状态行已写明正在传输并校验文件，接收、校验与创建任务另有阶段显示，见下文）。
   源端声明 `cancellable` 时提供「取消复制」：在目标开始接收前立即中止，正在发送的文件（直连或 OSS 中转）
   与大文件分段复制都当场停止、不等发完（含仍在建立的直连与等待中的块确认）；直连已送达的部分通知目标丢弃，
   取消不计入直连失败冷却。随后
   清理已上传的 OSS 对象及本地暂存并记为已取消，弹窗显示 `cancelling` 直到停稳后关闭；目标开始接收后拒绝取消
   （`MIGRATION_CANNOT_CANCEL`），不回滚目标；重试中的复制在回执确认目标没有这次复制的接收记录前同样不可取消。旧源端不声明 `cancellable`，只提供后台继续。
   OSS 进度计 HTTP 请求体已提交字节（可能仍在缓冲），peer 计分段确认字节，不作为接收完成凭据。
   文件发送结束后显示目标端接收、校验与创建任务阶段，只有目标完成且源端清理结束后才显示“复制成功”。
   成功页只提供关闭和“打开新复制的任务”；有未复制的条目时，成功页逐条列出项目内相对路径与原因
   （最多 100 条，其余只计数），原任务顶部的状态按钮显示「复制成功，N 项未复制」并可打开该页。失败页只提供关闭，关闭会复用完成路径清理已上传的 OSS 对象及本地暂存，结束本次源端复制；目标端可能已提交的副本不会回滚。
   失败页优先显示对应原因；没有专门文案的错误显示通用提示并附错误码。目标端拒收文件名不可移植、
   仅大小写不同或链接指向目录外的条目时（如旧版目标），同时显示出问题的项目内相对路径。源端把原始报错写入日志，
   关闭后复制记录仍保留错误码，直到再次发起复制，便于事后排查。
   任务历史超出内存上限时说明是历史过大（不提示释放内存），源端判定时附「需要约 X，上限约 Y」，
   日志记录预算各组成；目标版本旧、需随包携带原生会话记录而超限，且拆出 32 MiB 以上的会话记录后即可装下时，提示更新两台电脑；
   拆出后仍超限则照常报历史过大。
   再次复制从任务菜单发起。宿主异常退出后的既有幂等恢复协议保留，不自动重试。

源端仅记录 `preparing → transferring → complete`（运行中在目标接收前、或停止运行后可结束为 `cancelled`）；目标记录接收与完成。
开始、取消和后台复制复用同一个源任务标识的既有跨进程锁，防止多实例覆盖同一进度。
进度日志不用于限制源任务的输入、改名、标签、Goal、共享或团队操作，不扫描其它任务日志。
旧交接日志不会让任务只读。新副本不复制调度、渠道和共享授权绑定；原绑定继续使用原任务。

准备中断后先清理本次旧暂存再重建；传输重试先清理本次旧分段再检查容量。
目标提交结果未知时保留恢复目录，重试按固定任务 ID 和目录核实。失败目录不会自动删除，
避免丢掉用户已经打开或编辑的文件；路径保存在当前账号 `task-copies/receipts/<复制 ID>.json`
的 `retainedWorkingDirs`。确认不需要后可手工清理旧目录，勿删除当前任务及 Worker 的工作目录。

## 边界与兼容

- 本机到远端、远端到本机及远端到另一台电脑均通过同账号 Desktop 设备互联。Mobile 没有新增入口。
- 新通道 `maker:task-copy` 与旧交接协议隔离，避免新客户端误调用旧主机的移动语义。
  `task-copy:request` 仅供受信 Desktop Renderer，不能提交接收或回执请求；共享访客不可调用。
  接收绑定源设备、源任务和复制 ID，持续复核账号代次、DB 实例及远控授权。
- 不转移 Cindy 登录或供应商凭证。项目内 `.env` 等忽略文件属于用户项目快照。
- 原生上下文必须完整，为 CC、Codex、Pi 分配独立标识；不降级为只有可见消息的副本。
- Git 目录须为仓库根；暂不支持子模块、嵌套 Git 元数据、无首个提交仓库。空间或内存不足时提示并保留源文件。
- 复制允许有瑕疵（2026-10-02 用户要求）：单个条目无法复制时不阻止整次复制，源端打包时跳过并在成功页告知。
  跳过的只有：解析后指向目录外部或 `.git`（含绝对路径、循环链接）的链接、其他系统无法表示的文件名、
  仅大小写不同的同名条目（保留先遇到的一个），以及套接字、管道等特殊文件；被跳过的目录连同其内容一起跳过、只列目录本身。
  项目内的链接链（如 CocoaPods 与 `.framework` 的 `Versions/Current`）和指向项目内暂不存在位置的断开链接原样复制。
  目标端仍严格校验收到的清单，并在解包时最后按清单创建链接、按源端权限恢复文件与目录模式，不受本机 umask 收窄。
  旧版目标仍会拒收链接链，报 `MIGRATION_EXTERNAL_LINK`，此时需更新目标电脑。
  跳过按目录自上而下判定，被跳过目录的内容不参与大小写冲突与链接判断；链接解析按不区分大小写比对，偏保守。
  已知边界：被跳过的子树仍计入复制前的文件数估算与源端暂存空间核算，只在该子树极大时才会影响结果，暂不单独剪枝。
- 失败仅影响本次复制，不重启 relay、不关闭其它设备链路、不重放无关请求。接收预算 30 分钟，
  文件统计 3 分钟，其它请求 30 秒；写请求没有通用自动重试。没有服务端或数据库 schema 变更。

两台真实电脑端到端、Windows 实机与 Light/Dark 实际目检尚未完成；单元测试不替代这些验证。
