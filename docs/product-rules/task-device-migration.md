# 跨电脑移动任务

任务菜单统一为「移动任务」，位于「共享任务」和「导出任务」同组。二级菜单先列任务所在电脑的项目，
随后列「其他电脑」；电脑子菜单提供默认位置与已有项目，选定后直接确认，不重复选择目标。离线电脑不显示。
目标电脑明确不支持迁移能力时，提示更新该电脑上的 Cindy；普通连接或加载错误保留重试，不推断为版本过旧。

同机项目切换保留已有的项目、选择文件夹及移到对话行为。设备互联远程任务也支持：项目列表与文件夹
浏览均来自任务所属电脑，移动请求发回该电脑，复用已有 `moveSession` 宿主校验和 `updateSessionInDb`
业务路径，不放开远程原始 DB patch。写入前复核运行状态、工作目录、伙伴／IM 绑定、账号与远控授权；
同机切换不会执行跨电脑文件传输。SSH 任务仍不支持。

跨电脑移动复制任务对话、原生上下文、附件和工作目录快照，再交接执行权。
源任务保留为只读迁移记录，**不归档、不删除源项目目录，也不触发 worktree 回收**。
fork 任务共用目录时，仅迁移选中的任务；其它任务和源文件继续保留。
目标始终新建独立目录，不覆盖已有项目。界面可选择目标电脑的项目作为新目录的父目录。

## 数据与执行顺序

1. 源端持久化 `preparing`，停止该任务接收新输入。共享目录的任务正在运行时拒绝准备；
   准备期间拒绝新的共享目录写入任务。外部编辑造成文件清单变化时快照失败。
   迁移启动与最终输入受理共用宿主 send/route 锁，并复用已有跨进程资源锁保护输入落盘和
   `preparing` 发布；整组迁移同时取得全部成员的资源锁。回合收尾、在途输入与未持久化队列仍算忙。
   导出前等待已有消息持久化队列结清。清空上下文在相同输入受理边界内执行；Goal 的恢复、
   状态和消息写入复用同一跨进程边界，手动及自动入口均复核只读状态。
   团队创建、结束、成员变更、焦点和归档也在该边界内等待数据库提交；不允许只检查可写后
   就释放保护。Worker 创建 reservation 的申请同样参与互斥，续租与释放保留既有清理语义。
   消息删除与 Rewind 在各自提交锁内复核同一迁移只读判据。
2. 复用任务分享导出和 worktree 恢复归档，包含未提交、未跟踪和被忽略的文件。
   Git worktree 在目标重建 Git 元数据，保留 HEAD、暂存区与工作文件的区别；不复制 `.git` 的
   本机配置、hooks 或凭证。Git 分支的上游配置需在目标重新设置。
3. 源端写入 `transferring`，复用设备互联 peer 附件直传；直传不可用时复用 OSS 回退及冷却。
   文件均校验大小与 SHA-256，归档认证完成后才解包。
4. 目标以迁移 ID 幂等导入任务，持久化 `ready`，此时仍禁止执行。
5. 源端持久化并同步 `moved` 后才发送激活请求；目标写入 `active` 后可以继续执行。
   源端收到确认后先清理本次传输临时文件，再写入 `complete`；清理中断保持 `moved`，
   沿用原有重试入口恢复，不重复导入。OSS 删除复用现有尽力清理及服务端生命周期兜底。
   目标不会自动开始一个模型回合。

源端状态和目标接收回执分开存储，支持已迁入任务再移动到第三台电脑。重启后从同一任务菜单
读取日志、重试同一次操作；回执丢失不新建第二个目标任务。最终 DB 提交结果未知时保留恢复目录，
重试用持久化的目标目录和任务 ID 核实。曾失败的目标目录保留，不自动删除用户可能已打开的文件。
接收回执的 `retainedWorkingDirs` 保留此前所有尝试的目录，成功后也不丢弃。恢复或清理时，
在目标电脑当前账号的 `task-migrations/receipts/<迁移 ID>.json` 中读取这些路径，用文件管理器
检查并取回文件；确认不再需要后手工删除对应旧目录，不删除当前 `workingDir` 或修改交接状态。

仅在 `preparing` 且后台操作已停止时允许取消。进入传输阶段后，无法仅凭超时判断远端是否已提交，
因此只能重试恢复同一次交接，不能自动恢复源任务执行。任务头部显示交接状态和目标任务入口。

## 当前范围

- 同账号 Desktop 设备互联：本机到远端、远端到本机、远端到另一台远端电脑。
  控制端请求发给任务所属机器，项目列表取自目标机器。旧主机不支持新通道时提示升级，不退回本机执行。
- 普通、已停止的任务，以及从主任务发起的整组 Orca 任务。整组包含当前团队全部 Worker，
  包括已归档成员（在目标仍保持归档）。不能单独移走 Worker；任一成员正在运行、创建中、
  有排队输入或不满足迁移条件时整组拒绝，不能只搬主任务。SSH、Review、伙伴绑定、共享、
  调度绑定、未完成目标不迁移。
  Mobile 沿用原有远控能力，本次未新增迁移入口。
- 整组复用同一交接记录，主任务与 Worker 一起冻结、导入和激活。目标通过已有团队导入事务
  一次提交全部成员及关系；原生上下文标识、模型路由、权限和各自工作目录按成员恢复。
  共用物理目录只复制一份，独立目录分别新建；源目录均保留。目标需明确声明整组迁移能力，
  旧版只支持普通迁移时提示更新，不尝试部分导入。
- 不设置项目、Git bundle、对话包的固定大小上限。准备完成和发送前查询目标实时资源，
  接收及解包前再次检查；同一磁盘上的传输暂存、分段重组、项目解包、Git 导入和上下文副本合并估算，
  保留相对余量。空间变化导致写入失败时保留源文件，不激活不完整的目标任务。
- 大文件按既有 peer／OSS 单对象容量分段，逐段沿用直传、回退、校验，流式重组；
  这属于传输粒度，不是任务总量上限。源端临时分段大小也受当前磁盘空间约束。
- 任务分享仍复用现有 JSZip 导入导出；迁移按当前可用内存和 V8 堆余量设置预算，
  导入前检查压缩包声明的解压总量。内存不足会明确提示释放资源后重试，不退化为丢弃历史。
- Git 工作目录须位于仓库根；暂不支持子模块、嵌套 Git 元数据、未产生首个提交的仓库，
  以及无法跨平台表示的文件名、大小写冲突、目录外链接和链接链。失败时保留源文件。
- 目标复用现有导入逻辑，为迁移副本分配独立的原生上下文标识或目录，支持再移回源电脑，
  不覆盖已有原生会话。标识在同次重试中稳定；原生上下文不完整时不降级成只有可见消息的任务。
- 不转移 Cindy 登录信息或供应商凭证；项目内文件（包括 `.env` 等忽略文件）属于快照。
  目标通过既有模型路由解析器选择该引擎可用的本机模型，重置为需要确认的权限模式。

## 协议与故障范围

`maker:task-migration` 是同账号受控端业务通道；共享访客不可调用。
`task-migration:request` 仅对受信 Desktop Renderer 开放，不能直接提交 `receive`、`receipt`、`activate`。
源／目标始终复核账号代次、DB 实例和远程授权。接收回执绑定迁移 ID、源设备和源任务。
状态文件在 owner 私有目录下，用已有原子写文件机制和同步落盘保存。

迁移失败只影响这次任务交接，不重启 relay、不关闭其它设备链路、不重放无关请求。
接收操作单独使用 30 分钟预算，其余请求为 30 秒；写请求不加入自动重试或读取合并白名单。
文件传输错误沿用 peer／OSS 的既有隔离与回退。没有服务端或数据库 schema 变更。
