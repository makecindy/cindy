# 账号用量上限：等重置后自动继续

2026-10-07 裁决。订阅账号撞上 5 小时 / 周用量上限时，任务不该需要用户守着手动续跑。

## 行为

- **普通任务**：照常报错暂停，用户可以随时自己处理（重试、换模型或来源、发新消息、收下错误）。
  同时默认等待额度重置：错误横幅显示「将于 X 自动继续 · 取消」，到点时用户仍未处理就自动继续
  这个任务。有产出的 turn 发续跑指令，零产出的 turn 重发原文，与人工「重试」同一条路径。
- **目标模式**：沿用 `usageLimited` 状态到点自动续跑（见 `goal-host`），与普通任务共用同一套
  「按会话所用账号求重置时刻」的逻辑，两者不会重复续跑。
- **定时任务**（2026-10-22）：真实 Schedule run 的账号限额失败同样保留手动重试并等待重置。
  本次运行内自动继续沿用同一个 run；等待期间复用调度器的纯等待状态，不占执行名额，也不按无进展判卡死。
  到点重新检查执行名额，暂时无空位时复用限额等待计时器每分钟再检查，不请求模型、不消耗续跑次数。
  用户手动重试或取消等待时结束原 run 的等待，保留普通任务的手动恢复入口；手动续跑不继承已结束
  run 的执行上下文。暂停／删除定时任务也撤销其等待和尚未派发的自动续跑。
- 自动继续按自动动作呈现：隐藏续跑指令气泡，消息流里显示「用量已恢复，已自动继续」活动行，
  不计为用户发送。

## 重置时刻从哪来

按顺序取第一个可用的：

1. 限额错误自带的结构化时刻（Claude 订阅：SDK `rate_limit_event`）。
2. 会话实际使用的订阅账号用量窗口，且窗口已用满。本机按既有 reader 刷新；远程 Agent
   经已有 device-link 余量通道读执行电脑，独立账号必须核对回包的 providerId。
   Claude 查询等待既有 CLI `get_usage` 刷新完成，保留节流和失败退避，不新增登录或凭证读取。
   多个相关窗口同时受限时，等它们全部恢复；不拿其它模型或本机另一个账号的额度推断。
3. 报错原文里写明的时刻（ChatGPT 订阅 `resets_at` / `try again at 3:05 PM` / Pi 的
   `Try again in ~N min`，Claude 的 `resets 1:20am (TZ)`）。
   订阅家族由 provider 的 `auth.native` 决定，与跑在哪个 Harness 上无关。

以上来源也只对订阅账号生效：Coding Plan、Copilot、API key、Cindy 网关个人额度等即使报错原文带了
重试时刻也不等（那多半是按分钟的请求速率限制），**不等待、也不定时试探**，只报错交给用户。

快照只看会话模型实际受限的那一格：Codex 按模型取对应的用量桶（如 Spark 单独计），Claude 订阅
除 5 小时 / 周窗口外只计该模型的分模型窗口，其它模型用满不影响本会话。SSH 远程会话与远程 Agent 任务（Agent 在
另一台电脑、含分享来的供应商，2026-10-09 起）都用那台机器的登录，不读本机快照（目标模式同样只用远端报错里的时刻），且不采用远端报错里不带时区的钟点
（如 Codex `try again at 3:05 PM` 用的是那台机器的本地时间）；相对时长与带时区的时刻照常。判定见
`apps/desktop/src/main/usage/accountUsageLimit.ts` 的 `sessionUsesOtherMachineAccount`。
普通任务在本机目录认不出远程独立账号时读取执行电脑的目录。SSH 没有余量查询通道，仍只采信
远端报错中的可靠时刻；目标模式的远端查询边界沿用既有行为。
快照不可靠时同样不等：用满的窗口没有重置时刻（不拿别的窗口的时刻顶替）、窗口已过重置点（快照
在翻篇前取的）、SuperGrok 缓存快照超过有效期。目标模式同样只对订阅账号采信报错原文里的时刻，快照也须显示已用满才采纳其时刻。只认具体窗口显示用满，不认快照级「已触顶」标记（说不清来源，且混有需要充值的余额耗尽）。

## 边界

- 普通任务与定时任务的等待按 Cindy 账号保存到本机 `usage-limit-waits.json`，复用原子文件存储。
  保存原错误、恢复项、模型路线、截止时刻及次数；重启登录后自动恢复，已过点的留一分钟启动缓冲。
  取消、手动接手、清空、改路线、归档/删除会使保存项失效；换账号只停内存计时，原账号下次激活再恢复。
  正常退出先冻结等待再停 scheduler/Maker，等待写入完成。派发前原子消费保存项，多个实例只能一个续跑；
  消费后发生崩溃不重放结果未知的发送，保留既有中断后的手动恢复流程。
  重启后旧 schedule run 按既有规则收口，恢复的是该任务的续跑，不复活旧 FireContext；等待时仍阻止
  同 schedule 再排一份输入（包括每次新建任务的 schedule），并核对 schedule 未暂停/删除。
  自动续跑只放行已确认的限额恢复输入；重启恢复的其它排队消息保持原顺序与暂停，用户明确暂停仍有效。
  目标模式沿用已有的持久状态。
- 已收到上游终态错误后，远程运行消失等收尾错误不得覆盖原始原因和重置时刻；下一次发送仍独立报告
  新错误。额度等待期间 Agent 自行退出只清运行时，保留任务的恢复意图；用户明确关闭任务仍撤销等待。
- 普通任务里用户动手换模型或来源即视为接手，开始切换时就撤销等待（新选择可能有额度；切换失败时错误
  与手动重试仍在，不恢复等待）。目标模式的
  `usageLimited` 排期沿用既有行为，由目标自身的暂停 / 恢复控制，不在本规则内。
- 重置后再等约 1 分钟并错开几十秒，避免同账号多个任务同时涌入。
- 同一任务两次实质产出之间最多自动继续 3 次，防止重置时刻算早时反复撞上限。
- 不覆盖：复用 scheduler 来源、但没有真实 runId 的 Slack / X / Telegram Hook 消息（由各自 runner 收尾）、Orca worker（失败已交给 Lead；归在供应商组里的 Worker 仍会先自动换电脑接着跑，见 [供应商组](provider-groups.md) §6.1）、伙伴会话（走候选链）、
  目标模式在管的任务、执行已暂停的任务、共享任务访客发起或插话的回合（授权可能在等待期间被撤销，
  由房主手动处理）。
- **共享中的任务撞上限额不自动等待**（Dash 2026-10-08）：普通任务与目标模式都一样——报错照常，
  不排自动继续 / 自动恢复，由房主手动处理；等待期间开始共享的，到点也不自动继续。判断的是此刻
  任务是否处于共享中，访客可能已影响过本任务，撤权后到点替其续跑不安全。目标模式过载的短窗口
  重试不受影响。
- 自动继续在真正发给模型前被丢弃（任务关闭、准备失败等）时，恢复原错误与手动重试入口，不再自动等待。
- 等待由被控电脑持有；手机与另一台电脑只显示等待并可取消。

供应商组在首次分配或应用待生效的模型／电脑切换时，若确认所选模型的可用账号额度耗尽，
同样显示限额原因并接入上述等待。组所在电脑只汇总在线、未暂停、支持该模型的成员，
取已知的最早恢复时间；单个账号仍须等它所有耗尽窗口恢复及既有冷却结束。没有可信时刻就不自动等待。
此时保存的任务路线可能还是切换前的账号，不得借用原账号的用量或展示原账号的重置卡，
也不因原账号重置而提前续跑。
尚未发给模型的消息保留原队列项和 clientId，到点重新分配后发送一次；取消或改选仍作废等待。
原用户气泡保留，随原消息保存恢复活动，桌面与手机均显示「用量已恢复，已自动继续」。

## Codex 重置卡的自动使用

手动使用由用户决定：有效重置卡不因剩余额度大于零而禁用。界面确认具体卡和账号，
服务端仍可返回无需重置、无卡等结果，不能把“按钮可点”说成服务端保证接受。

自动入口是重置卡旁的开关与小下拉，默认关闭。编辑规则不自动打开开关；取消最后一个
条件同时关闭自动使用。两项条件独立，以“或”组合，合并触发只用最早到期的一张：

- 普通 Codex 周窗口剩余低于 1%；可限定距自然配额重置至少 3 / 2 / 1 天，或不限、
  自填整数天数（0–365）。默认 3 天。其它模型专属窗口耗尽不触发这项条件。
- 卡即将过期；可提前 30 分钟 / 1 小时 / 6 小时 / 24 小时使用，默认 1 小时。

所有已知有效窗口均未使用时自动跳过；未知或失效用量不授权兑换。这些自动条件不限制
手动使用。配额重置时刻与卡到期时刻分别来自额度窗口和卡，不能混用。

设置属于执行电脑、当前 Cindy 数据所有者、供应商连接和确切 ChatGPT 账号。仅保存
用户改动的覆盖值，恢复默认清除覆盖；换 ChatGPT 账号不继承自动授权。手机通过已有
同账号远控权限修改执行电脑上的设置；旧主机无 `autoUse` 字段时隐藏入口。共享任务
访客、供应商分享访客不能通过新通道授权扣卡。

电脑上的 Cindy 运行时，在用量变化、唤醒及每分钟检查规则；手机不用保持连接。
睡眠、离线或退出 Cindy 时不承诺能赶在到期前执行。自动与手动共用兑换锁和幂等键，
自动检查在发出上游请求前复核授权；结果不明只重试自身同一个请求，不接管用户的
未决手动请求。成功后重新读取权威配额，再通过已有普通任务和目标模式的等待机制
提前恢复符合条件的任务；保留用户停止、取消、共享任务和执行电脑边界，不缩短过载等待。
