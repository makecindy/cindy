## 1. 定位

用户有多台电脑都登录了同一个供应商（例如多份 Anthropic 订阅），希望把它们合成一个入口：
不用自己挑电脑，哪台忙、离线或撞到用量上限时自动换一台，并且能把这个入口分享给别人。

做法是在某台电脑（下称**组所在电脑**）的某个供应商下建一个**供应商组**，把其他电脑上的同一个
供应商加进来。之后这个供应商在组所在电脑上的所有使用都按**组策略**选一台**组内电脑**运行：

- 组所在电脑自己的任务；
- 同账号的其他电脑把组所在电脑的这个供应商当远程供应商使用（组所在电脑选电脑，那台电脑直接连过去）；
- 别人通过分享使用组所在电脑分享出去的这个供应商（组所在电脑选电脑并转发）。

这样一台现成的 Cindy 就是网关，不需要另外部署服务；登录、界面、分享链接与审批全部复用。

**Agent 始终在被选中的组内电脑上运行**，用那台电脑的 Agent 程序、登录、供应商与网络；
任务的文件与命令仍在发起任务的电脑上执行。组所在电脑只负责选电脑，对分享的人还负责转发。

## 2. 术语

- **供应商组（组）**：某台电脑上某个供应商的一组运行位置。界面用「供应商组」，不单用「分组」，
  避免与模型列表、设置页的模型分组混淆。
- **组内电脑**：组里能运行这个供应商的电脑，来源见 §3。
- **组策略**：新任务选哪台组内电脑的规则，见 §5。
- **组所在电脑**：建了这个组的电脑。
- **使用方**：经这个供应商发起任务的一方：组所在电脑本身、同账号的其他电脑、分享的人。

术语表登记见 `i18n/glossary.json`（`provider-group`、`group-strategy`，均为 `proposed`）。

## 3. 组的组成

- 每个供应商最多一个组。组跟着供应商连接（连接 ID）走：删除这个供应商连接即删除组。
- **组内电脑就是这台电脑已经能用的同一个供应商**，与模型列表里远程供应商区域是同一个来源。自己的电脑和
  别人的电脑走同一套规则，与现有「自己用和被分享走同一套」一致（供应商分享 §3、§5）：
  1. **本机**：默认在组里，可以关掉。关掉后组所在电脑只负责选电脑与转发，不在本机运行这个供应商的 Agent。
  2. **已经能用的远程供应商**：同账号电脑上已打开「允许被远程调用」的，和别人分享给这个账号的，在同一个列表里
     勾选加入，不需要再申请。
  3. **还不能用的别人的电脑**：粘贴对方的分享链接，流程与加入分享相同：预览 → 发送申请 → 双方核对配对码
     → 对方同意，同意后直接加入组。自己账号的电脑不需要链接（服务端也拒绝申请自己账号的分享，`PROVIDER_SHARE_SELF`）。
     首版：「分享链接」一页打开现有的输入分享链接与申请流程，对方同意后回到「已经能用的」勾选加入；
     申请前按组核对供应商、同意后直接加入组放到 P2。
- **必须是同一个供应商**，不一致时不发送申请，提示「这个链接分享的是 {对方供应商}，不是 {本供应商}，
  不能加入这个供应商组」；可勾选的列表只列同一个供应商。「同一个」按下面的口径判断，不直接比较供应商 ID：
  - **官方供应商与订阅账号**（Anthropic、OpenAI、xAI 及其登录预设）：同一品牌即可。内置的默认连接 ID 固定
    （如 `anthropic`），但在设置里再添加的订阅账号，ID 是品牌加随机后缀（如 `anthropic-1a2b3c4d`），
    两台电脑上一定不同；多个订阅账号正是供应商组的主要用法，按 ID 比较会把它们全部拒掉。
  - **自定义供应商**：名称相同即可（忽略大小写与首尾空格），首版就支持。供应商 ID 相同也算同一个。
    ID 不由用户填写，是添加时按名称自动生成的，但添加后改名不改 ID、本机已有同名时会带 `-2` 之类后缀，
    所以按名称比较，不只比 ID。名称不同时提示「这个链接分享的是 {对方供应商}，不是 {本供应商}」，
    把两台电脑上的名称改成一样即可。
  - 判断所需的品牌信息取远端供应商目录里已有的去敏字段，不新增协议字段。
- 组内电脑必须与组所在电脑在同一区域（跨区域分享默认关闭，见供应商分享 §8）。
- 分享关系属于账号：组所在电脑账号收到的分享，这个账号的其他电脑也能直接用。被组所在电脑加进组之后，
  这个账号的其他电脑上不再单独列出它，只列组那一项（与同账号电脑被收进组同一条规则，§10）；组所在电脑离线时
  它重新单独出现。组设置本身仍只存在组所在电脑本机。
- 组内电脑数量不设上限；每台的并发上限见 §5。
- 协同任务的 Lead 与 Worker 与普通任务一样归供应商组分配、出问题时自动换电脑（2026-10-10 用户裁决：远程与本机
  供应商对协同是同一套逻辑与体验），细则见 §6.1「协同任务」。审查任务的设置固定跟随源任务，不归供应商组分配。
- 组里至少保留一台组内电脑；移除最后一台即删除组。
- **组只是这台电脑上这个供应商的一项设置，不新增账号级的概念。** 同账号的几台电脑可以各自建组、成员也可以重叠，
  组与组之间互不感知：每个组只管经它发起的任务；被收进组的电脑在其他电脑的列表里只在组所在电脑离线时单独出现，
  这时直接选它仍是在那台直接运行，与现在一致。
  重叠不会出错——组内电脑被别的组或别人直接用满、撞到用量上限时，经本组的任务会失败，按 §6.1 直接换下一台，
  最多多一次换电脑。界面建议在一台常开的电脑上建组，其他电脑选这个组的入口，但不强制。

## 4. 哪些使用走组

- 判断依据是任务实际使用的供应商连接，不看发起方：§1 列出的三种使用走同一套组策略与绑定规则。
- 组内电脑是本机时，Agent 直接在本机运行，与现在一致。
- **组所在电脑自己的任务**：组内电脑是其他电脑时，组所在电脑作为控制端连过去：对「我的其他电脑」是同账号远程 Agent；
  对分享来的电脑，组所在电脑的账号是那台电脑的受邀者。
- **同账号其他电脑（直连，2026-10-10）**：任务所在的电脑先问组所在电脑「该用哪台」（`provider-group:remote` 通道，只给
  同账号），再**自己直接连到选中的组内电脑**：选中组所在电脑本身就连组所在电脑，选中任务所在的这台就在本机运行，
  选中分享来的电脑就用这个账号收到的那个分享（分享属于账号，§3）。少一次中转；组所在电脑关机不影响已经在跑的任务。
  组所在电脑看不到这些任务的内容，任务所在的电脑把正在跑的经组任务报告给它（只用于统计负载），组内电脑出问题时把
  需要冷却的电脑报告给它（§5、§6.1）。
- **分享的人（中转）**：连不到组内其他电脑，由组所在电脑选电脑并中转（P2b）：
  - 受邀者的**新任务**按组策略选一台：选到组所在电脑就在本机运行；选到别的电脑就由组所在电脑中转，事件、反向请求、
    WebSocket 帧原样转发，消息与附件不解码、不落盘（§8「只在内存中转」）。受邀者带来的「已分配」「中转」字段一律
    当作普通受邀者任务处理，组所在电脑不让受邀者自己决定去哪台。
  - 只选能接受受邀者的电脑：组所在电脑自己；分享来的电脑（那台本来就把组所在电脑当受邀者隔离）；同账号电脑要声明
    能按受邀者隔离（`guestRelay`），不声明的旧版本一阵子（10 分钟）不再给它受邀者的任务，但不冷却它，组所在电脑
    自己的任务照常分过去。
  - 被中转过来的任务，组内电脑一律按受邀者隔离运行（即使来自同账号的组所在电脑）：受邀者目录、会话索引与运行数按
    （组所在电脑, 受邀者）分开，受邀者在那台的身份是组所在电脑为它取的不透明键，任务 id 也按受邀者派生，两个受邀者
    用同一个任务 id 不会撞车。组所在电脑在同一台组内电脑上按受邀者各算 16 个任务、合计不超过 64 个。
  - **续接**只回到当初运行这个会话的那台（组所在电脑记着「哪个会话在哪台」，那台被移出组后也回到那台），不在别处重试；
    受邀者不能凭 id 接回别的受邀者的会话。
  - **启动阶段**（新任务还没开始运行）那台接不下时直接换组里下一台，受邀者无感，旧版本受邀者也享受；每台最多试一次，
    组里能接的都试过才报错（组的电脑数不设上限）。每次尝试的 WebSocket 连接编号不同，换台时关掉上一次尝试的连接；
    打开的结果不明（超时、断链）时，先请那台关掉同一个任务再换下一台（关不到时那台没人拉取的任务也会在空闲超时后结束）。
  - 删除受邀者（分享删除）时，组所在电脑请接过它任务的组内电脑清掉它留下的会话记录与目录（`forget`）；组内电脑只清
    调用方自己的那个受邀者。「接过任务」从发出打开那一刻算起，启动失败、还没有会话的那台也会通知。当时没通知到的
    （离线等）记在组所在电脑上，之后自动再通知（约每 10 分钟一次，重启后继续），通知到才划掉。
- **防转圈**：经组分配到组内电脑的任务，在那台电脑上直接运行，不再进入那台电脑自己的供应商组。
  打开任务时带一个可选标记 `groupAssigned` 说明「已由供应商组分配」；旧版本不认识这个标记，也是直接运行。
  登记见 `docs/dev-rules/protocol-compatibility.md`「供应商组」。

## 5. 组策略

- **选择方式**：最少占用（默认，选正在运行任务最少的那台）、轮询、按顺序（排在前面的优先，前面的不可用才用后面的）、
  按权重。
- **并发上限**：每台组内电脑单独设置，默认 4，最多 16（远程 Agent 对每个控制端的上限）；只统计经本组分到这台的任务，
  包括同账号其他电脑经本组直连过去的任务：它们由任务所在的电脑在每一轮开始、结束时报告，运行期间每分钟再报一次，
  组所在电脑 150 秒收不到就不再计入；刚选中、还没报告的任务先按占用记 30 秒，同时开的几个任务不会全落到同一台。
  - **分享来的电脑**（2026-10-10）：分享者电脑在给组所在电脑的供应商目录里报告**本账号**（组所在电脑这个账号的每台电脑）
    此刻在这个分享上正在运行一轮的任务数，包括不经组、直接选那台用的任务；不含分享者本人和其他受邀者的任务。
    这台的运行数取它与上面经本组的计数中较大的（经组分过去的都在其中，刚选中还没开始跑的仍按经组计数占着）。
    设置页显示与分配用同一个数。目录短时缓存 15 秒，设置页每 15 秒刷新，最多晚约半分钟。分享者是旧版本时不报，
    照旧只算经本组的。
  - **本机与同账号电脑**（2026-10-10）：按那台电脑上这个供应商**实际正在运行一轮的任务总数**统计：那台自己的任务
    (Agent 在那台运行的，不论是否经组)，加上它替其他电脑运行的远程 Agent 任务(本账号其他电脑的、分享的人的)。
    Agent 在别处运行的任务算在别处，转给组内另一台的任务算在那一台，不重复计。本机现算；同账号电脑在给本账号电脑的
    供应商目录里报告(`runningTurns`)，只报允许被远程调用的供应商，分享出去的目录里去掉，受邀者看不到。取值方式、
    刷新时间与分享来的电脑相同；那台是旧版本时不报，照旧只算经本组的。因为算的是全部任务，那台的主人自己在用时
    也会占它的并发上限。
- **只分给可用的电脑**：在线；对方仍允许远程控制，且仍对这个供应商允许被远程调用；分享未暂停、未删除；
  不在冷却中；提供所选模型；未被设为「暂停分配」。优先分给未达到并发上限的；都满了时分给相对最空的一台，
  并发上限只用来分摊，不因满载拒绝消息。
- **冷却**：组内电脑上的任务报用量上限时，这台电脑进入冷却，不再接新任务。重置时刻按
  [用量上限自动继续](usage-limit-auto-continue.md) 的口径取（不采用不带时区的钟点）；取不到时默认冷却 30 分钟。
  冷却不主动迁移这台电脑上正在运行的其他任务；它们自己撞到上限时再按 §6.1 换电脑。
  同账号其他电脑直连时撞到用量上限、登录失效或服务繁忙，也报告给组所在电脑冷却那台（报来的重置时刻最多信 8 天）；
  连不上只由发现它的那台电脑自己在这一轮避开，不替全组判断——可能只是那台电脑自己连不过去。
- 组内电脑的在线状态、分享状态与模型目录定时核对；不可用的电脑在组里标出原因。
- 组里所有电脑都失败才报错，见 §6 自动换电脑。

## 6. 任务与组内电脑的绑定

- 任务第一次在组里运行时选定一台组内电脑，之后固定在这台：对话记录保存在那台电脑上。只有正常运行时才保持
  固定；那台电脑出问题时按下面的规则**自动换电脑**，不需要用户操作。
- 正在正常运行的任务不会因为组策略变化或其他电脑空闲而迁移。
- 只给从没运行过的任务按策略选电脑。已经运行过、正用着组那一项的任务不按策略挪走：留在原处并纳入组，之后出问题时
  照常自动换电脑（2026-10-10 用户要求：老任务也要生效）。包括：
  - 建组前就在用这个供应商的任务、回退或清空后原生会话被清掉的任务；
  - 运行过之后才在模型选择里换到组那一项的任务；
  - 同账号其他电脑上的老任务：用着另一台电脑上建了组的那个供应商（在组所在电脑本身运行），由任务所在的电脑问组所在电脑
    确认它在组里。
  - 纳入的时机：启动 Agent 时（问组所在电脑最多等 3 秒，问不到就照常启动）；当时没纳入的（一直开着没重新启动、
    或启动时问不到）在因 §6.1 的原因失败时先纳入，再照常换电脑，所以已经开着的老任务点重试也会换。
  - 不纳入：直接选组里某台电脑或分享来的供应商的任务（用的不是组那一项，§4）；因组内电脑被移出、或组被删除而解除过
    这个组的任务（§9.4，任务所在的电脑按组记下，之后同一台重新加入、或重建同一个组也不纳入）。
- 用户在模型选择里把任务挪到组外的电脑或换成别的供应商，任务即退出组：之后不再自动换电脑，也不把那台的失败
  记到组内电脑头上。挪到组里另一台时绑定跟着更新；之后再挪回组那一项时按上一条重新纳入。

### 6.1 自动换电脑

供应商组的目的就是多个账号一起用、出问题自动换，所以**因电脑本身的原因失败时，自动换到组里下一台可用的电脑
继续，组里所有电脑都失败了才报错**。

- **会触发换电脑的失败**（问题出在那台电脑或它的账号上）：
  - 撞到用量上限、额度或余额用完、请求频率限制；
  - 那台电脑的供应商登录失效、被拒绝或被停用；
  - 那台电脑离线、不可达、关闭了远程控制或远程调用、分享被暂停或删除，或已被移出组、暂停分配；
  - 那台电脑上 Agent 启动失败；
  - 供应商服务报错、过载或超时（同一台连续失败才算，偶发一次先按现有重试处理）。
- **不换电脑的失败**（换到哪台都一样）：用户停止、权限确认被拒绝、上下文超出模型上限、请求本身无效、
  内容被模型拒绝、工具执行出错。这些照现有方式报错。
- **怎么换**：
  - **还没开始运行**（打开任务、Agent 启动阶段）失败：直接换下一台，没有可感知的中断。
  - **运行中失败**：把这台标为不可用（用量上限进入冷却，§5），复用现有的跨电脑交接，把任务交接到组策略选出的
    下一台：新建会话并带上交接上下文，然后继续这一轮——这一轮还没有产出就重发原消息，已经有产出就发续跑指令，
    与 [用量上限自动继续](usage-limit-auto-continue.md) 的续跑口径一致。消息流里显示一行活动记录
    「{原电脑} {原因}，已换到 {新电脑} 继续」（受邀者那边写「已自动换一台电脑继续」，§8），不计为用户发送。
  - **连不上先等它恢复**（2026-10-11）：那台是连不上（离线、断线）时先不换：现读一次那台的状态，确实连不上才等，
    按退避（约 3、6、12、20、20 秒，与中断自愈相同）最多重试 5 次，每次现读。恢复了就留在原电脑继续这一轮（不交接、
    不冷却，活动记录写「已重新连上 {电脑}，继续运行」，读不到名称时写「原来的电脑」）；5 次都不行才按上面的方式换到下一台。
    等的期间错误同样先不呈现，消息流与输入框状态显示「重新连接中 n/5」，开始换电脑时改为「正在换一台电脑继续」。
    - 只是连接断了（断线、远程 Cindy 重启后会话没了）而现读第一次就已连得上：断线刚好已恢复，也算一次重试、留在原电脑
      继续；同一轮次数照算，那台反复断也只这 5 次，用完就换。
    - 不等、直接换的情况：现读连得上但问题不在连接（如那台 Agent 起不来）；那台本身不能用（供应商关掉、关闭了远程控制或
      远程调用、分享暂停或删除等）；本机这台；用量上限、登录失效、过载等不是连不上的原因。
    - 次数按一轮、按电脑计，自动续跑与运行中失败共用；用户亲自发消息、重试、换模型即开始新的一轮，重新计。
    - 发送前：已归组的任务所在那台显示离线、或这次发送要重新打开那台上的会话（会话没开着或不在运行态）时，现读一次那台的
      状态；离线就同样先等（消息还没发出，进行中行显示「重新连接中 n/5」），恢复了照常发到原电脑，等不到再换到下一台
      再发。用户停止这次发送时立刻停下：不再等、不再换，也不再去打开那台上的会话。
    - 别的电脑上的组读不到（常见是任务就跑在组所在电脑上、它自己断了）：换不了电脑，但仍按任务记录里的位置先等那台恢复，
      恢复了在原电脑继续（活动记录写「原来的电脑」），等不到照原有方式报错；发送前同理。
    - 已经发出却在那台上没确认收到的消息（如请求超时）不自动重发：可能已经在跑，重发会让同一条消息执行两次，照原有方式报错。
    - 下面「换电脑久久没有结局（3 分钟）先把错误放出来」的计时不吃掉等它恢复的时间：每次重试、开始换电脑时重新计时。
  - **换电脑期间不报错**（2026-10-10）：这次失败会先试着换电脑时（已归组、自动换电脑开着、组里还有别的电脑；
    受邀者那边是收到了「需要换一台」凭证），失败那一刻就不呈现：没有红色横幅、不写错误卡、不亮红点、Agent Island 不提醒，
    消息流末尾只有一行「正在换一台电脑继续」，输入框上方的状态同样这样写。换成了，历史里只留上面那行换电脑的活动记录
    （原因在展开详情里）；没换成（组里都不能用、交接失败、自动换电脑关着等），这时才补上错误卡与横幅，交回原有的报错与
    额度重置后自动继续。换电脑途中用户亲自接手时，错误卡照常补进历史（按出错的时刻排在用户新消息之前），但不再弹横幅。
    换电脑久久没有结局（3 分钟）时先把错误放出来，之后换成了照常续跑。出错时才纳入组的老任务（§6）判断不到，仍会先报错再换。
    少见的时序例外：错误早于这一轮的用户消息落库完成到达时，错误卡与红点在判断之前已经出现，换电脑期间只是不再挂横幅。
  - 换过去之后任务固定在新电脑上，原电脑恢复后也不换回去（每换一次都要重新交接）。
  - **协同任务**（2026-10-10）：Lead 与 Worker 都按上面的规则分配和换电脑，引擎与模型不变、只换 Agent 所在电脑；
    用户仍不能中途给协同任务换模型或换位置（`docs/dev-rules/orca-team-architecture.md`）。
    - 新建的 Worker 跟普通新任务一样按组策略选电脑。Worker 跟着 Lead（没另选位置，或选的就是 Lead 现在所在那台）
      而 Lead 用的是组那一项时，Worker 跟的是这个组，不是 Lead 这次落到的那台；组那一项不提供所选模型时照旧跟 Lead
      所在那台。Lead 的 `list_available_models` 不指定位置时同样列组那一项所在电脑的模型。
    - Worker 换电脑期间这一轮还没有结局，不把「异常终止」回报给 Lead：换成了，续跑那一轮结束时照常把结果回报给 Lead；
      没换成（组里都不能用、交接失败、久久没有结局、中途有人接手）才把这次异常终止回报给 Lead，与没有供应商组时一致。
    - Worker 换电脑后不做「等额度恢复后自动继续」：组里都不能用时失败照常交给 Lead 重新安排
      （[用量上限自动继续](usage-limit-auto-continue.md) 不覆盖 Worker 的口径不变）。
    - 换电脑途中 Lead 给 Worker 发来消息、或 Worker 的回报到达正在换电脑的 Lead，按亲自接手处理：这一趟换电脑停下，
      那条消息开始新的一轮（发送前发现原电脑在冷却时照常先换电脑）。
    - 换过去的会话照常带着协同身份、提示词与协同工具；唤醒空闲 Worker 与换电脑互斥，不会在换电脑的空档里按旧位置
      把它拉起来。
- **何时停止**：同一轮里每台组内电脑最多试一次；全部试过仍失败才报错，并提供换模型。
  其中有电脑是撞到用量上限的，按 [用量上限自动继续](usage-limit-auto-continue.md) 等恢复后自动继续
  （错误横幅显示「将于 X 自动继续 · 取消」）。
  - 首版：交回现有的报错与额度重置后自动继续，等的是任务当前所在那台的重置时刻；错误里逐台列出原因、
    按全组最早恢复的一台等，放到 P3。新任务分配时组里没有能用的电脑，报「供应商组里的电脑现在都不能运行这个任务」。
  - 一轮的边界：用户亲自接手(发消息、重试、换模型)即开始新的一轮；距上一次换电脑超过 30 分钟也算新的一轮。
  - 首版运行中的换电脑只在不同电脑之间进行：同一台电脑上的不同账号(例如一台电脑登录了两个订阅)可以接新任务，
    但不会在运行中互相替换，后续支持。
  - 交接会关闭旧会话；交接前先登记这次错误的重试入口，交接完成后凭它重新挂上续跑。用户在换电脑途中亲自接手
    (发消息、重试、换模型)或那次错误已被新的一轮接管时，后续每一步都停下：不再交接、不冷却任何电脑、不续跑，
    也不再交回原有处理。
  - 交接失败只有在问题出在目标电脑本身(连不上、分享暂停、Agent 起不来、登录失效等)时才把那台记为试过并冷却，
    换下一台再试；任务正在运行、已被删除等与目标无关的失败直接结束本次换电脑。都不行时交回原有的报错与额度重置后
    自动继续。
- **代价与告知**：每换一次电脑都是一次交接——原会话的提示缓存失效，新会话按交接上下文继续，细节可能比原会话少，
  也会多消耗一些 token。自动换电脑默认开启，组设置里可以关掉；关掉后照现有方式报错，用户可以在模型选择里
  手动换到另一台电脑。
- **实现**：运行中的换电脑复用「已建任务换 Agent 所在电脑」(`performSessionAgentSwitch`，全量交接 + 全新原生会话)，
  续跑复用额度重置后自动继续的同一条路径(`continueAfterUsageLimitReset`)，活动记录在这条续跑记录上带
  `agentSwitch`(原电脑、新电脑、原因)；旧版本手机与桌面不认识该字段，显示成「用量已恢复，已自动继续」。
  Agent 还没开始运行就失败(打开任务阶段)时，在启动入口直接换下一台。代码在 `apps/desktop/src/main/provider-group/`。
- **谁来执行换电脑**：交接要用到任务的对话记录，所以由任务所在的电脑执行。
  - 组所在电脑自己的任务：组所在电脑直接换。
  - 同账号其他电脑（直连）：任务所在的电脑直接看到组内电脑的报错，自己换：把需要冷却的电脑报告给组所在电脑，
    再问它下一台（带上这一轮试过的），交接与续跑与组所在电脑自己的任务同一套。组所在电脑读不到时（离线、断线）
    不换电脑、绑定不动，交回原有的报错；确认组已删除或这台已不在组里时才解除绑定，任务成为普通的远程 Agent 任务。
  - 分享的人（P2c，2026-10-10）：组所在电脑告诉任务所在的电脑「需要换一台」，那边自动交接后重新打开，
    组所在电脑再为它选新电脑。任务所在的电脑需要更新到支持这个功能的版本；旧版本只会看到原有的报错，
    可以手动换模型。具体做法：
    - 任务所在的电脑打开任务时声明支持（可选字段 `acceptsGroupSwitch`）。组内电脑（包括组所在电脑本机）上的任务因 §6.1 列出的原因
      失败（终态错误，或一轮进行中那台的任务意外结束）时，组所在电脑先按组的口径冷却那台，再看组里还有没有能接的
      电脑（这一轮已经换下来的不算）；有就在事件流里先发一张一次性凭证，再转出原来的错误。旧版本、没有能接的
      电脑、或换到哪台都一样的失败，只转出原来的错误。
    - 任务所在的电脑只在持有这张凭证时才换：分享被暂停、删除、撤权是分享本身的问题，没有凭证，不会触发换电脑。
      凭证只用于紧随其后的那次错误(2 分钟内)；用户亲自接手(发消息、重试、换模型)即作废。
    - 换法与组所在电脑自己的任务相同：任务的位置仍是同一个分享，强制交接(全量交接 + 全新原生会话，分隔条写
      「Agent 已改到另一台电脑上运行」，不写电脑名称)，重新打开时带回凭证，组所在电脑据此避开这一轮换下来的
      电脑；然后按额度重置后自动继续的路径续跑这一轮，活动记录写「已自动换一台电脑继续」。交接没成时交回原有的
      报错与额度重置后自动继续。
    - 凭证只认发给的那个受邀者的那个任务，用过、过期(10 分钟)即作废；组内电脑转来的同名状态一律丢弃，组内电脑
      不能替组所在电脑发凭证。同一轮每台组内电脑最多试一次；那台上一轮正常结束，或距上次换电脑超过 30 分钟，
      算新的一轮。
- **不续接的打开**（第一次运行、交接后的新会话）优先回到原电脑；原电脑不可用或满载时换一台，绑定改到新电脑，
  旧电脑上的会话不能再续接。
- **模型**：组对外提供组内电脑模型的并集；新任务只分给提供所选模型的电脑。任务中途换模型时在当前组内电脑上核对，
  它不提供该模型时提示换模型，不自动换电脑。
  已知差异（P2a）：同账号其他电脑的模型列表里，组那一项列的是组所在电脑本机这个供应商的模型，还不是并集。
- 任务详情与任务头部显示实际运行的电脑：「在 {电脑} 上运行 · 由供应商组分配」；受邀者那边不显示（§8）。

## 7. 用量

- **记账位置**：组所在电脑。经这个供应商运行或转发的任务都记账，包括本机、同账号其他电脑与分享的人；
  组所在电脑选电脑，知道每个任务实际在哪台运行。同账号其他电脑直连时组所在电脑不经手内容，用量要由任务所在的
  电脑报告给它（P3 定口径）。
- **两个维度**：
  - 按使用方：本机、我的其他电脑（按电脑分开）、分享的人（按人分开）；
  - 按组内电脑：每台实际运行的用量。
- 指标：轮次、输入 token、输出 token、估算金额；时间段近 7 天、本月、全部；展开按模型列出。
  订阅类供应商按本地单价估算并标注「估算」，不代表供应商实际账单（与供应商分享 §7.4 一致）。
- 没有组的供应商也显示「按使用方」：列出我的其他电脑与分享的人经这台电脑使用这个供应商的用量。
- 组内电脑的主人在自己的分享管理页里看到的是组所在电脑账号的合计用量，看不到最终使用者。

## 8. 告知与隐私

- **组对受邀者透明，不打扰。** 分享者建组、加减组内电脑都是分享者的运维操作，受邀者不收到弹窗或提示，
  使用体验与没有组时一致。为此告知前移到申请时：
  - 受邀者申请弹窗**不论有没有组**都写「Agent 在 {分享者} 的电脑或 {分享者} 安排的其他电脑上运行」，隐私说明写
    「对话内容和 Agent 读取的文件内容会经过 {分享者} 的电脑，并保存在实际运行任务的那台电脑上」。
    之后建组不改变受邀者同意过的内容，所以不需要再提醒。
  - 「分享给我的供应商」详情里的说明与申请弹窗同一句话，受邀者想了解时可以查看。
  - 受邀者那边不显示组内电脑的名称：模型列表标题写「{供应商} · 来自 {分享者} 的分享 · 供应商组 · N 台电脑」
    (2026-10-10 用户裁决：受邀者只知道背后是个组、有几台)；任务头部不显示实际运行的电脑；
    自动换电脑的活动记录写「已自动换一台电脑继续」。组内电脑的名称属于分享者和组内电脑主人，不透给受邀者；
    分享者的电脑名同样不给受邀者(供应商分享 §6)。
  - 分享者这边也不弹确认：「远程与分享」页的供应商组一块写明「分享的人的任务也按组分配」。
- 已知差异（2026-10-09 确认接受）：这条规则上线前加入的受邀者，以及仍在用旧版本申请的受邀者，看到的是
  「Agent 在 {分享者} 的电脑上运行」。不补提醒，只更新「分享给我的供应商」详情里的说明。
- 分享来的组内电脑上，组所在电脑作为受邀者照常受到受邀者隔离（供应商分享 §9）；它的主人只看到组所在电脑账号的昵称与头像。
- 组所在电脑能看到经它转发的对话与文件内容，与分享者电脑一致；转发内容只在内存中转，不写入日志。
- 组内电脑报出的、会透露它是谁或它与组所在电脑关系的错误(那台对组所在电脑的分享暂停、没开远程调用、连不上等)，
  转给受邀者时统一成「暂时不可用」。已知差异(P2b)：Agent 输出与工具路径里可能出现组内电脑上的会话目录路径(含那台的
  系统用户名)，与受邀者直接用分享者电脑时看到分享者电脑的路径同一程度。

## 9. 安全不变量

1. **Agent 只在被选中的组内电脑上运行。** 组所在电脑不代替组内电脑调用模型，不取得组内电脑的任何凭证。
2. **组不扩大受邀者的能力。** 经组的受邀者仍只能使用远程 Agent 与只读查询（供应商分享 §9.1），其他能力一律拒绝。
3. **使用方之间互相隔离。** 分享来的组内电脑把组所在电脑当作同一个受邀者，所以组所在电脑必须按使用方隔离
   转发的任务、会话续接与上传：一个使用方不能读到、续接或关闭另一个使用方的任务。
4. **撤权立即生效。** 组所在电脑对某人的分享被关闭或删除时，此人经组运行在任何组内电脑上的任务立即停止，
   不触发自动换电脑；对方暂停或删除分享、对方关闭远程调用时，分配到它的任务下一次发送即失败，按 §6.1 换到组里
   其他电脑。组内电脑被移出组只影响之后的分配：已经在它上面的任务留在那台，成为普通的远程 Agent 任务，
   不再自动换电脑；之后同一台电脑重新加入、或重建同一个组，这些任务也不会恢复自动换电脑。
5. **防转圈**（§4）。
6. 同账号的组内电脑沿用同账号远程 Agent 的信任等级，组不改变它；但组所在电脑替受邀者中转过去的任务，组内电脑一律按
   受邀者隔离运行，受邀者不会因为经过同账号的组所在电脑而拿到主人级权限。
7. **组内电脑的名单只给同账号电脑。** `provider-group:remote` 通道与目录里的组摘要都只给同账号电脑：受邀者与共享任务
   访客调用通道一律拒绝，分享出去的目录里去掉组摘要（分享者电脑、受邀者电脑与手机各去一遍），只带组里有几台
   （`groupSize`，2026-10-10）。组摘要里分享来的组员也不带名字（旧快照可能是那位分享者的电脑名）。

## 10. 界面

- **入口**（2026-10-11 用户反馈供应商详情多出一行太长，改为不单独占行）：「允许被远程调用」一行开关左侧的入口按钮
  有组时写「供应商组 · {N} 台电脑」，没有组时写「远程与分享」，点击进入该供应商的「远程与分享」页（供应商分享 §7.1）；
  组策略只在那一页显示。有组时这一行的说明改写「由供应商组选一台电脑运行 Agent」，不再说 Agent 在这台电脑上运行。
  供应商组不依赖「允许被远程调用」：入口始终可点，只给本机用时也可以建组。
  - **不闪状态**：入口按钮读本机组设置（全窗口共用的快照），不等组内电脑的实时状态；第一次读完之前整行不出现，
    不先显示「没有组」再跳成组。「远程与分享」页再次打开时先显示上次读到的组，没读过就按本机组设置先排出组内电脑、
    状态写「检查中」，再在后台刷新。
- **「远程与分享」页**（原「分享 {供应商}」管理页扩展）分三块：
  1. **供应商组**：组内电脑列表（来源、状态、正在运行的任务数、冷却到何时）、并发上限、添加电脑、组策略；
  2. **用量**（P3）：按使用方 / 按组内电脑切换，时间段切换，展开按模型；
  3. **分享**：生成分享链接、待处理、已分享的人（与现在一致；P3 起按人用量移到「用量」块，首版仍在已分享的人里）。
     未开启「允许被远程调用」时，这一块置灰并说明先开启哪一级（供应商分享 §3）。
- **组内电脑一行的结构对所有来源一致**，右侧才能真正成列：设备图标 → 名称与来源 → 状态行 →
  并发上限（按权重时多一个权重）→ 参与分配开关 → 行内 `···` 菜单。三条由此固定：
  - **参与分配只有一种控件。** `paused` 是同一个布尔值，本机与远程都用开关表达，不按来源分叉成
    「开关 / 暂停分配按钮」两套；暂停后的含义由状态行文字说明，不另弹 toast。
  - **运行数是状态，上限是设置。** 运行数只出现在状态行，上限只出现在下拉里，同一个数字不在一行里说两遍。
    **能用时状态词本身报负载**：跑 0 个说「空闲」，跑了就说「{N} 个任务运行中」，不写「可用」——
    否则组里都空着时整列没有数字，看不出每台在跑几个。「已满」等于跑满上限，不再重复报数。
  - **「移出组」收进 `···` 菜单**（与供应商详情头的供应商级菜单同模式）。本机不能移出（§3），
    该位置留等宽占位以保持列宽。
  - **点名称一侧展开这台的剩余配额**（2026-10-10 用户要求）：名称旁一个箭头，展开后在这一行下方显示这台电脑上
    这个账号的订阅配额（5 小时 / 每周剩余等），与供应商详情页底部的用量卡、任务底部的用量条同一份数据；
    紧贴在这一行下方、与电脑名左对齐，不再出卡片的「Claude · 套餐」标题行（行本身已说明是哪台电脑）。
    本机读本机账号，我的其他电脑经设备互联读那台的账号；别人分享来的电脑不读（分享者的配额不对受邀者开放），
    只写「别人分享的电脑不显示配额」；不在线的电脑不去读。只在展开时读，收起的行不读任何电脑。
    另一台电脑上的组的只读列表同样可以展开。这是剩余配额，不是 §7 的经组运行的用量统计（P3）。
- **添加电脑**：弹窗分「已经能用的」与「分享链接」两页：前者把你的其他电脑和别人分享给你的放在同一个列表里勾选；分享链接沿用申请与配对码流程，
  供应商不一致（§3 口径）、链接属于自己账号、链接失效时给出对应提示。
- **模型列表**：组那一项的分组标题与左栏悬停提示写同一句，只写组里有几台，不写是哪几台，也不另起一行
  （2026-10-10 用户要求）。台数与设置页左栏的「供应商组 · N 台电脑」同一写法：
  - 同账号其他电脑上的组：「{供应商} · {组所在电脑} · 供应商组 · 3 台电脑」；
  - 本机建的组：「{供应商} · 供应商组 · 2 台电脑」，每行模型右侧的来源名仍只写供应商名；
  - 受邀者：「{供应商} · 来自 {分享者} 的分享 · 供应商组 · 3 台电脑」（§8）。
- 设置页组内电脑一行与「添加电脑」弹窗里，分享来的电脑写「{分享者} 的电脑」，不写分享者的电脑名（供应商分享 §6）。
- **只显示组**（2026-10-10）：同账号其他电脑的模型列表与设置页左栏里，被其他在线电脑的组收进去的远程供应商与
  分享不再单独列出，只列组所在电脑那一项；不在任何组里的照常单独显示。规则：
  - 只看此刻在线、列表里有的电脑的目录：组所在电脑离线时组那一项不在，组员自动重新单独出现；
  - 本身带组的项不收起（两个组互相包含时两个组都还在）；本机自己的供应商照常显示；
  - 当前任务正在用的那一项不收起，已直接用某台组员跑过的任务不会丢了来源；
  - 设置页里组那一项行内写「供应商组 · {N} 台电脑」，详情只读列出组内电脑与状态（问组所在电脑，每 15 秒重读），
    说明组设置要到组所在电脑上改。
  - 手机端本期不收起（手机只显示任务实际运行的电脑）。
- Light 与 Dark 两种模式都要实现。

## 11. 与现有规则的关系

- [供应商分享](provider-sharing.md)：§4.1 第 3 步的告知不论有没有组都改用 §8 的说法；§1「Agent 在分享者电脑上运行」、
  §7.2 管理页、§7.4 用量、§9 安全不变量在有组时按本文调整；实现时同步修订该文。
- 远程 Agent 协议：新增 §4 的「已由供应商组分配」可选标记(`groupAssigned`)；同账号直连新增同账号通道
  `provider-group:remote` 与目录里的组摘要；分享的人经组所在电脑中转(P2b)新增 `relay`、`guestRelay` 与 `forget`；
  分享的人的「需要换一台」(P2c)：任务所在电脑打开任务时声明支持（可选字段 `acceptsGroupSwitch`），组所在电脑只对
  声明了的电脑在事件流里发出凭证状态(`providerGroupSwitch`)，重新打开时带回(`groupSwitchToken`)。其余沿用现有协议，不改服务端。兼容做法见 §14，登记见
  `docs/dev-rules/protocol-compatibility.md`「供应商组」。
- [跨电脑复制任务](task-device-migration.md) 与已建任务换 Agent 所在电脑：§6.1 的自动换电脑与手动「换一台继续」
  都复用现有交接，不新增交接机制。
- [用量上限自动继续](usage-limit-auto-continue.md)：冷却的重置时刻口径与之一致；有组时先换电脑，组里所有电脑都失败且其中有
  撞上限的，才按该文等最早恢复的一台；组内电脑冷却期间，自动继续不会分到这台。
- 手机端：首版只显示任务实际运行的电脑，供应商组的设置与用量只在电脑上。

## 13. 验收

1. 链接的供应商与组不是同一个（§3 口径）、链接属于自己账号、链接失效时不发送申请，并给出对应提示。
2. 组所在电脑、同账号其他电脑、分享的人三种使用都按组策略分配，组内电脑离线、冷却、暂停分配、满载或不提供所选模型时不会被选中。
3. 正常运行的任务固定在原电脑；原电脑因 §6.1 列出的原因失败时，自动交接到组内另一台继续这一轮，消息流显示换电脑的
   活动记录；同一轮每台最多试一次，全部失败才报错并逐台列出原因；其中有撞上限的，等最早恢复的一台自动继续。
4. 用户停止、权限被拒、上下文超限、请求无效、内容被拒、工具出错时不换电脑。
5. 经组转发到组内电脑的任务不会再进入那台电脑的供应商组。
6. 两个使用方用相同的任务或会话标识也不能读到、续接或关闭对方的任务。
7. 关闭或删除对某人的分享后，此人的任务立即停止且不换电脑；移出组内电脑后不再给它分新任务，已在它上面的任务留在那台。
8. 「用量」按使用方与按组内电脑两个维度的合计一致，订阅类标注估算。
9. 受邀者申请弹窗不论有没有组都说明 Agent 可能在分享者安排的其他电脑上运行；建组、加减组内电脑后受邀者不收到任何弹窗或提示，
   也看不到组内电脑的名称。
10. 第二个订阅账号（ID 带随机后缀）能加入同品牌的组；自定义供应商名称相同时能加入（含改过名、ID 带后缀的），名称不同时给出提示。
11. 没有建组的供应商，在新版本里的行为与现在完全一致。
12. §14 列出的旧版本组合都能照常使用：旧版本只是没有组，不报新的错误、不出现看不懂的提示。
13. Light 与 Dark 两种模式都已实现。

## 14. 版本兼容

原则：**没有更新的用户只是没有组，其他功能与现在一致**；新版本里没有建组的供应商，行为与现在完全一致。
新增的协议内容都是可选的，旧版本不认识就忽略：远程 Agent 解码只保留认识的字段（`apps/desktop/src/main/remote-agent/wire.ts`），
不认识的错误码会显示成通用错误，所以新错误码只发给声明了支持的电脑。

| 角色 | 是旧版本时 |
|---|---|
| 组所在电脑 | 组只在新版本里存在。降级到旧版本后组不生效，这个供应商回到只在本机运行；经组分到其他电脑的任务在旧版本里不能续接，需要换模型或新开任务。同账号其他电脑问它时得到 `CHANNEL_NOT_ALLOWED`、目录里也没有组摘要，当作没有组照常直接连它；已经经它的组分到别处的任务留在原处，成为普通的远程 Agent 任务 |
| 组内电脑 | 照常作为普通的同账号远程供应商或分享来的供应商接任务。「已由供应商组分配」标记对它是不认识的字段，解码时丢弃；它本来没有组，也不会转圈。旧版同账号组内电脑不声明 `guestRelay`，组所在电脑不给它分受邀者的任务(它不会按受邀者隔离)；旧版分享来的组内电脑本来就把组所在电脑当受邀者，照常接，只是不按受邀者再细分作用域(组所在电脑自己按受邀者隔离) |
| 同账号其他电脑 | 直连由任务所在的电脑执行，旧版本不认识组：选组所在电脑的这个供应商时直接在组所在电脑上运行(没有组)，模型列表里组内电脑照常单独显示、没有供应商组的标注 |
| 分享的人 | 照常使用，中转对它透明(协议不变)。打开任务阶段的换电脑由组所在电脑完成，旧版本同样享受；运行中失败时它没有声明支持「需要换一台」，组所在电脑照旧返回原来的错误（如用量上限），用户像现在一样换模型或稍后重试。新版本声明支持，运行中失败时自动换一台（§6.1）。旧版本申请弹窗仍是「Agent 在 {分享者} 的电脑上运行」（§8 已知差异） |
| 受邀者申请 | 申请弹窗由受邀者自己的 Cindy 显示，旧版本仍是原来的说法（§8 已知差异） |

- 本地数据：供应商组设置只新增存储，不改已有的供应商、远程调用与分享数据；涉及数据库时按
  `docs/dev-rules/database-and-migrations.md` 只做新增。
- 测试要覆盖上表每一行：新组所在电脑配旧组内电脑、旧同账号电脑、旧受邀者，以及降级后的组所在电脑。
