# 共享任务：远程连接的多人版本

> 产品裁决更新：2026-09-20。实现与验证进度见文末；本文不代表已上线。
> 产品、代码、协议与存储统一使用“共享任务 / SharedTask”，开发期旧协议不保留兼容别名。

## 定位

房主分享一个现有任务，其他已登录用户通过邀请进入同一个远程任务页面，共享完整历史、上下文和 Agent。复用现有远程连接、输入队列、附件、语音输入和断线恢复，不做独立会议产品或普通讨论频道。

用户明确要求减少复杂度：访客与房主触发的 Agent 调用使用相同任务权限。加入方式选择最简单方案，采用邀请即授权。

## 用户流程

1. 房主在任务内点击“共享任务”，开启共享并复制邀请。
2. 访客在菜单“加入共享任务”粘贴邀请，登录后直接加入，无申请或批准步骤。
3. 双方进入现有任务页面，查看全部历史、工具结果、上下文和附件，向同一个 Agent 发消息。
4. 房主可复制新邀请、移除访客、停止共享；访客可退出。

不增加申请记录、审批通知、在线人数、正在输入、编辑标记或独立会议页面。成员列表和消息作者只用于识别参与者。

## 权限与顺序

- 任务由原桌面运行，模型费用沿用房主连接；同账号远控行为不变。
- 访客可发消息、使用附件和语音输入、修改 Agent/模型/推理设置、停止 Agent。
- Agent 工具、shell、已有插件/MCP 沿用任务现有权限，Full Access 语义不变；已有需审批操作仍由房主处理。不添加访客专属沙箱、per-turn 权限或工具审批。邀请意味着房主信任访客使用该任务的 Agent 能力。
- 房主保留共享管理、归档/删除/导出/分支、权限模式、工作目录、插件/MCP 配置和后台/定时任务管理权限。
- 访客通过客户端接口只能直接访问共享任务及其资源，不能调用全局凭证、其他任务或任意主机文件接口。Agent 原生工具不承诺工作目录硬隔离。
- 消息按主机现有输入队列顺序处理，保留 clientId 幂等。访客仅编辑/撤回自己未处理消息，房主可处理全部未处理消息；直接更新内容，不显示“已编辑”。
- 发言者身份来自经过验证的账号和成员关系，不能信任消息正文或客户端自报的身份。

## 邀请、成员和生命周期

- 每个账号同时最多开启 5 个共享任务、最多加入 5 个共享任务；两个角色独立计数，可以同时开启 5 个并加入另外 5 个。各自跨设备统计，加入名额跨房主统计。开启与加入的名额均由服务端判定，客户端不维护固定数量。
- 邀请可转发，持有邀请的登录用户即可加入；每个任务最多 2 位访客（加房主共 3 人），按账号计数。服务端在事务内强制校验，超额分别提示开启、加入或访客人数已满。
- 已存在的超额共享及成员关系不自动关闭或踢出；只拒绝新增开启／加入，退出、移除、关闭或房主离线关闭后释放对应名额。访客临时断线不释放加入名额。
- 同一账号重复加入幂等，多个设备不重复占用名额。邀请令牌只存摘要，不进入日志。
- 移除或退出立即撤权；原邀请不可重入，房主生成新邀请后才能再次加入。
- 停止共享、归档、房主登出使旧邀请和成员关系失效。重新共享产生新的共享 ID。
- 归档后恢复为活动任务，可以显式重新开启共享；须先完成旧共享关闭，旧代次的请求仍然失效。
- 房主设备的 relay 连接确认离线后有 60 秒重连宽限，期间重连保留共享、邀请与成员关系；持续离线超过宽限后由下一轮服务端扫描关闭（正常情况下确认离线后 60–90 秒）。关闭后重新上线不会恢复旧共享，需显式重新开启并发送新邀请。主动关闭与登出的显式关闭请求不等待宽限。已由新连接接管的旧连接退出不算离线；TTL 内短暂网络抖动不承诺立即判定。
- 服务端是成员关系权威；主机保存恢复与关闭记录。迟到响应、旧快照、缓存和重连不能恢复已撤销访问。
- 访客断线保留成员关系，重连后可继续访问仍有效的共享；不能影响其他访客或同账号远控。
- 正常断开触发关闭；relay 崩溃、路由过期或关闭落库失败由服务端每 30 秒扫描补偿。访客当前通过约 5 秒轮询更新界面；服务端授权在关闭提交后立即失效。
- 不承诺撤回访客已经看到或下载的内容。

## 实现约束

- 复用 packages/device-link；新增跨账号的单任务授权，禁止降级为旧版全设备远控。
- 长标题不阻止开启共享（2026-09-22 用户确认）：只在创建共享的请求边界，将去除首尾空白后的标题截短到服务端现有的 128 个 UTF-16 码元上限，避免截断代理对；共享列表／管理页可显示该短标题，原任务标题和历史不变。昵称与服务端响应仍沿用严格校验，不放宽服务端协议。
- 同时校验 invoke、push、历史、附件、嵌套引用、离线补发与结果缓存的任务及成员归属。
- 共享附件使用 `cindy/device-link/shared-task/<sharedTaskId>/<uploaderAccountId>/<uuid.ext>`，复用既有中转前缀的 OSS 授权与生命周期；共享路径仍按任务和当前成员校验，不回退为同账号对象权限。客户端与服务端同步升级，不保留未发布开发版顶层 `cindy/shared-task/` 路径别名；普通远控附件路径不变。
- Desktop 与 Mobile 复用现有任务页面；房主在手机上通过既有同账号远控管理共享。网页端和匿名访客不在范围内。
- 新协议以能力协商开放；缺少能力提示升级。两区域独立，不默认跨区域加入。
- 关闭记录必须落入原 profile 的 journal 后才能释放数据库；本地同步撤权，服务端失败下次恢复重试。
- 同一 profile 的非 relay 持有实例归档／删除任务，也必须写入该 profile 的共享关闭记录，并以操作开始时捕获的账号凭证尝试关闭服务端共享。Host 在既有 5 秒刷新周期先消化本地关闭记录、使现有授权捕获失效，再查询服务端；relay 离线或服务端读取失败不能跳过本地撤权。此机制只关闭对应共享，不重启 relay 或影响其他任务。
- 覆盖式任务文件导入属于旧任务的终态变更：被替换的旧任务图及其共享关闭记录在同一数据库事务提交，失败一起回滚；成功后再通知本机共享运行时撤权。即使成功回执丢失或进程切换，持有 relay 的实例仍可从持久记录完成关闭，新导入任务不继承旧共享。
- 登出时等待已发出的创建请求收尾，迟到的创建 ID 也必须先落关闭记录；在线关闭仅使用退出账号的固定凭证与端点，不刷新或影响新账号。
- 移除请求未获确认前暂停该成员访问；网络失败须以服务端状态恢复。临时暂停或同账号新增设备造成的旧授权失效返回可重试错误，只有确认撤权才从访客端移除任务。
- 本仓只改客户端；服务端实现位于独立 cindy-server 的本任务 worktree。两仓协议需一致。

## 开发期命名与发布顺序

2026-09-18 用户确认：功能仍在开发，不维护旧共享协议和存储命名兼容层。客户端和服务端各自维护本仓协议包并同步更新；独立 cindy-protocol 仓不再被当前 workspace 消费。

- 类型与函数统一为 SharedTask / sharedTask，能力为 shared-task-v2，REST 为 /api/device-link/shared-tasks，标识字段为 sharedTaskId，IPC 为 maker:shared-task / shared-task:account。共享是原任务的状态与授权关系，原 sessionId 不变。
- relay 的 src/dst 始终为真实设备 ID；可选 sharedTask 字段独立携带共享 ID 与目标角色/成员，来源角色/成员由服务端按已验证账号与设备重写。不带范围的帧沿用同账号远控，包括 ID 恰好带 shared-task~ 前缀的真实设备；非法范围直接拒绝，不能降级。
- 客户端仅在 relay 声明 v2 后发送共享帧，服务端还检查双方能力、任务状态、成员与真实目标设备绑定。先升级全部 relay 再发布客户端；不兼容未发布的共享 v1 开发版，已发布普通远控协议不变。
- 客户端缓存/IPC 使用包含共享范围的本地连接索引，长度大于物理设备 ID 的 128 字符上限，避免同设备普通连接与多个共享连接碰撞；索引不会进入 wire 的设备地址字段。请求、结果、ACK、重连与错误都按各自连接范围隔离，不扩大到其他任务或设备。实现与回归见 packages/device-link/src/sharedTaskEnvelope.ts、sharedTaskPeer.ts 及其测试。
- SQLite 使用 shared_task_events / shared_task_id；Prisma 使用 SharedTask、SharedTaskGuest、SharedTaskInvitation。初版直接使用最终命名建表，不保留旧开发版搬迁脚本、旧接口、双写或别名。
- 不支持新旧共享开发版本混用，也不自动转换旧开发数据库。旧开发沙箱保留原库，使用新的隔离数据库和沙箱验证新版，不修改现有验收数据。
- 旧开发分支 migration 0108、0110 未进入 main，已与新主干编号冲突。基于 2026-09-20 的主干 0113 重新生成 0114_shared_task_events。旧分支沙箱保留原库备份，使用新的独立沙箱验收，禁止改写 schema_version 或强行打开不匹配库。0114 只新增最终命名的共享记录表，不读取或改写旧开发版记录、消息作者与队列作者。

- 尚未部署共享功能的环境先执行服务端增量 migration，再升级全部 relay，最后发布客户端。运行旧开发版的隔离环境按上面的新库方案验收，不原地套用新迁移链。服务端不改写既有同账号设备关系；不能把缺少共享能力的 relay 当作已支持。
- 新客户端连接旧 relay 时，普通同账号远控继续使用原协议；共享入口提示升级，Mobile 不轮询旧 relay 的共享 API。新 relay 连接旧房主时，房主缺少共享 channel 的错误也提示升级，不能降级为全设备访问。
- 错误处理只把明确的能力缺失或版本不兼容映射为升级提示，断网或超时错误仍提示重试。Mobile 连接未建立时将能力视为未知，显示重试；重新连接后重新读取能力，升级后可恢复共享。
- Desktop 的本地 SQLite migration 0114 为增量建表，但“可从旧版升级”不等于“可用旧版打开新库”。既有 migration manifest / schema 校验会拒绝旧程序打开已升级数据库；本功能不放宽该保护。
- 发布前保留升级前数据库备份。需要回退时优先修复新版；如必须恢复旧程序，应使用升级前的对应备份，并明确接受备份之后的数据不会随之保留。不得通过降低 schema 版本、删表或改历史 migration 强行回退。服务端回退时保留增量表，不执行破坏性 down migration。
- 新旧版本真实混合部署尚未端到端实测；能力协商与错误提示的自动化回归不能替代该发布验收。

## UI review 与全部关闭（2026-09-18）

单文件交互原型仅保存在本地 `artifacts/shared-task-design/index.html`，不随仓库提交；仓库内的实现依据为本文记录的已确认方案。原型展示三种入口：A 任务顶部小面板与账号菜单；B 一个共享窗口，分当前任务与我发起的共享；C 侧栏入口与右侧管理面板。原型是设计展示，不是实际客户端或验收截图。Light/Dark、小屏及开启、加入、邀请、移除、全部关闭、离线结束一起评审。

已选定方案 B：“共享任务 → 我发起的 → 关闭全部共享”。范围为当前账号、当前区域内由我发起的共享（含其他主机），不退出加入别人的任务、不停止 Agent、不删除任务、不影响同账号远控。确认面板列出任务与主机，默认取消；失败保留未关闭项供重试。

实现状态（2026-09-20）：已按方案 B 在 Desktop 落地统一共享任务窗口（`SharedTaskButton.tsx`），含「当前任务 / 我发起的」页签、确认面板（移除 / 退出 / 关闭当前 / 关闭全部，默认取消）与房主离线结束态；账号级 `owned` / `close` IPC（`shared-task:account`）支持跨主机关闭，失败保留未关闭项供重试。Mobile 仍沿用任务菜单内的共享入口。

## 验收

### 桌面共享任务入口修订（2026-09-20，用户确认）

- 任务顶部不单独显示共享图标；「共享任务」收进标题旁的「…」菜单，打开原有共享管理窗口。移除菜单前的弹性空白，恢复「标题 → 标签 → … → Git/PR 信息」顺序。访客菜单仅保留共享管理入口，不开放房主的改名、归档、删除等操作（2026-09-23，用户确认）。
- 标题旁、左侧文字版与列表版共用菜单内容与顺序：置顶／重命名／移动／标签；复制链接／共享任务／导出；新窗口；归档（已归档时为取消归档）／删除。仍按任务状态隐藏不适用项；移除任务分支菜单入口，访客侧栏继续仅导航，不增加右键菜单（2026-09-23，用户确认统一两处菜单）。
- 采用单一「共享任务」列表内分组：房主与访客任务按最近活动时间混排，不使用 Tab 或角色子分组。仅房主任务在 Agent 图标与标题之间显示金色皇冠（Desktop `--warning-fg` / Mobile `warningFg`，Light / Dark 均为 `#F3A115`）；访客任务不渲染身份槽，标题起点与普通任务一致。皇冠不占用右侧时间、状态、PR、工作区或悬停操作槽。Desktop 共享分组只跟随主列表的文字版／列表版，不适配仅向置顶区开放的三态展示；Mobile 使用同一身份语义。分组不显示计数，且不受下方设备筛选影响（2026-09-22，用户确认；同日由中性色调整为金色）。
- 共享不是常用功能：未开启且未加入共享任务时，整个分组隐藏，不保留空状态、加入按钮或分隔线；首次开启或加入后出现，最后一个共享关闭或退出后自动隐藏。首次加入继续使用原有菜单入口。
- 设备菜单仅保留真实设备，不显示共享任务或内部 peer 标识。访客任务不再重复混入下方普通项目／任务列表。房主任务仍保留原项目归属，共享分组作为快捷入口。
- 共享任务行沿用普通任务的 Agent 身份图标，按任务的 Agent 类型显示；不得因共享状态替换为人群图标。
- 已加入任务直接打开既有任务页面，重复点击当前任务不重新连接、不清空页面。访客撤权继续使用现有结束提示与清理路径，不缓存已失效的可访问内容。
- 「共享任务」分组标题和访客任务行不提供右键菜单，也不触发侧栏空白处的整理菜单；房主任务行复用普通任务的右键菜单与归档快捷操作，归档或删除前先停止共享。左键折叠／展开与进入任务保持不变，共享管理仍使用任务内已有入口（2026-09-22，用户确认）。侧栏其他区域的右键行为不变。
- 当前任务管理页底部的“关闭此任务的共享”与“我发起的共享”页底部的“关闭全部共享”使用同一底部居中、全宽危险操作布局，避免同类关闭操作出现左对齐差异。
- 共享只是新增分组：任务行复用普通主列表的文字／列表显示模式、标题、最近消息预览、Agent 图标及状态信息，不使用“这台电脑／其他电脑／共享任务”替代预览。访客任务保留仅导航交互；房主任务沿用普通任务右键行为，但归档／删除必须先停止共享。尚未取得跨设备任务镜像时只显示已知标题和房主皇冠，仍可点击进入，不伪造预览、时间或 Agent 身份（2026-09-22，用户确认）。
- 加入弹窗采用 C 方案：标题说明下显示「我发起的共享 / N 个进行中」，右侧灰阶「关闭全部共享」，与底部加入按钮分离。无共享时禁用，获取失败可重试，不把未知状态当成零个。
- 关闭确认在同一个窗口内替换表单内容，不叠加第二个弹窗；列出确认时的任务及所在电脑类别，默认聚焦取消。取消保留邀请与昵称。只关闭确认清单中的我发起的共享，失败保留未关闭项重试；不退出我加入的任务、不停止 Agent、不删除记录。账号变化或窗口退出后，旧请求不得继续操作下一项。
- 本轮设计稿面向 Desktop；Mobile 仍遵循上文全屏主页面和平台确认控件规则。

## 本地联调

最小组合是一套测试服务、一个房主 Desktop 和一个访客客户端。验证多人并发时增加第二个访客，使用三个不同 Cindy 账号；同账号的两个实例走既有远控，不能用于验收跨账号共享。

1. 在独立测试数据库和 Redis 上启动本任务版本的 device-link-server，并执行该服务的 Prisma migration。登录需使用同一测试区域的 auth-server；附件上传下载还需要可用的测试对象存储配置。不要把测试指向生产数据库。
2. 两个 Desktop 使用不同 checkout、不同命名沙箱和独立端口。分别从各自 checkout 使用仓库根安全启动入口：

       pnpm restart:desktop:local --region=global --isolated=sharing-host
       pnpm restart:desktop:local --region=global --isolated=sharing-guest

   启动参数、端点与端口以 [Desktop 开发规则](../dev-rules/desktop-development.md) 为准；包装脚本会停止当前 checkout 的旧开发实例，因此不要在同一个 checkout 连续执行两次来模拟双客户端。也可用 Desktop 房主加 Mobile 访客；手机端点必须是手机可达的测试服务地址。
3. 房主打开已有任务，开启共享并复制邀请。访客从菜单加入，确认无需审批即可进入普通任务页，能够查看加入前的消息、工具结果和附件。
4. 同时发送不同内容，确认两个客户端看到同一 Agent 输出及正确作者。Agent 忙时编辑或撤回自己的待发送消息；修改其他成员的待发送消息应失败。编辑带图片的消息，保留旧附件并增加新附件，确认发送后和重载后都可打开。
5. 分别验证切换 Agent、模型和推理设置、停止 Agent、普通权限与 Full Access。已有审批由房主处理，访客能查看请求并继续排队发消息。
6. 访客断网后重连，确认有效共享与历史恢复。房主断线后 60 秒内重连保留共享；持续离线超过宽限后共享关闭、旧邀请失效，上线后需重新开启。房主主动关闭或退出账号立即关闭共享。单个访客断线时，另一个访客及同账号远控继续工作。
7. 验证移除、退出、停止共享、归档和登出。旧邀请不能恢复已退出或移除的身份，新邀请可以重新加入；未共享任务与主机全局设置不可经访客客户端访问。
8. 验证本地工作区及 SSH 工作区的图片、音频、视频，检查 Light/Dark 和小屏。旧服务端或旧客户端应提示升级，不得退化成全设备控制。
