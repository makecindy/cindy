# 隐私屏：用遮罩代替锁屏，让 AI 在你不在时继续用电脑

> **读取时机**：新增或修改隐私屏（离开时遮住屏幕、远程控制时的遮罩、远程结束后的保护）、物理输入转锁屏、锁屏失败处理、
> 屏幕常亮策略，或「离开电脑时」设置与遥控端「安全」面板里的相关开关之前
> **适用路径**：`apps/desktop/src/main/remote-desktop/**/{privacy,awayGuard,controlledOverlay,displayDemand,linuxPrivacy,linuxSessionLock,linuxLock,windowsLockScreenSetup}*`、
> `apps/desktop/native/remote-desktop/hyprland-privacy/**`、
> `apps/desktop/native/remote-desktop/windows-input/src/privacy.rs`、
> `apps/desktop/native/remote-desktop/macos-input.swift`、
> `apps/desktop/src/main/device-link/**/{power-blocker,powerBlocker}*`、
> `apps/desktop/src/main/remote-desktop-viewer/**/safety*`、`apps/desktop/src/shared/awayGuard.ts`、
> `apps/desktop/src/renderer/components/settings/AwayFromComputerSection*`、
> `apps/desktop/src/renderer/hooks/use{AwayGuard,KeepAwake}Setting.ts`、
> `apps/mobile/src/remote-desktop/{RemoteDesktopSecuritySettings,useRemoteDesktopSafety}*`

2026-11-14，用户裁决：把「离开时继续工作」的黑色遮罩和远程桌面的「电脑防窥」合并成同一个东西，
统一叫**隐私屏**。画面、有人碰电脑时的处理、锁不上时的处理、对屏幕的保护和设置位置，都按本文
统一。原 PR #9899（远程结束后保留遮罩）已关闭，其原生能力和锁屏修复并入本文的实现。

给用户的一句话：**你不在电脑前时，Cindy 用隐私屏代替锁屏：旁人看不到屏幕内容，一碰电脑就真锁屏，
AI 在后面照常工作。**

隐私屏不是系统的身份认证边界。它负责挡住旁人的视线，把“有人碰电脑”变成系统真锁屏；解锁永远由
系统完成（Touch ID、密码或 Windows 登录），隐私屏不解锁、不改系统的锁屏和授权设置、不保存密码。

## 三种场景，同一个隐私屏

| 场景 | 怎么出现 | 有人碰电脑时 |
| --- | --- | --- |
| 你离开一段时间 | 本机开启「用隐私屏代替锁屏」后，键盘鼠标没人碰达到设定时间自动出现 | 直接锁屏 |
| 远程结束（遥控端退出、断线、心跳超时、无人操作达到离开时长） | 遥控端开着「退出后保护电脑」时自动出现 | 直接锁屏 |
| 远程控制中 | 遥控端开着「连接时打开隐私屏」时出现 | 先弹「断开远程桌面连接？」；选「断开连接」才结束，并按退出后保护处理 |

远程控制中保留确认框（用户决定）：遥控端可能正在使用，碰一下不应直接掐断连接。其余两种场景碰一下
就锁屏。

远程结束后盖隐私屏还是真锁屏，**只由被控电脑本机的设置决定**：本机开了「用隐私屏代替锁屏」就盖
隐私屏；没开就真锁屏（这是 #9899 之前的行为，也是默认）。#9899 里“远程结束一律盖遮罩、不看本机
设置”的做法作废。

以下情况始终真锁屏，不走隐私屏：Cindy 退出（helper 断开也会锁）、隐私屏建立失败、平台不支持。

## 有人碰电脑

- 只有“有意的操作”才算有人：按键、鼠标按下、按下修饰键、一秒内滚动 30 点以上。鼠标漂移、松开按键、
  Caps Lock、零星滚动不算，因为无线接收器和闲置鼠标会自己发出这些事件。
- 隐私屏盖着时，物理输入不会传到后面的应用；AI 注入的输入照常放行。
- 只是移动鼠标时，隐私屏上的说明文字恢复正常亮度几秒（见“画面”），不锁屏。

## 锁屏与锁不上时

- macOS 先调用系统的立即锁屏，1.5 秒内没确认再模拟 Control-Command-Q（需要辅助功能权限）。旧做法只靠
  快捷键，最前面的应用卡住、全屏游戏、吞键的虚拟机或远程客户端会让锁屏失败。Windows 用系统锁屏并按
  当前会话状态确认；Hyprland 用合成器确认的锁屏。成功只认系统报告的锁定状态。
- **锁不上时，三种场景一律继续盖着，但主人总能出来**（2026-11-14 用户决定）：
  1. 隐私屏显示「Cindy 没能锁住这台电脑」，同时放开屏幕常亮，让系统自己熄屏锁屏；系统锁屏或解锁后隐私屏撤下
     （#10665：错过锁屏通知、或锁屏失败的结果比系统解锁晚到，都不再把隐私屏放回来）。
  2. 立即弹出系统自己的身份验证（macOS 用 Touch ID 或登录密码，Windows 用 Windows Hello 或 PIN）。验证窗口
     由系统提供，Cindy 不接触任何密码，只拿到“通过／没通过”。验证通过就撤下隐私屏，回到桌面。
  3. 取消或验证不了时继续盖着；之后每次有人碰电脑，先自动再试一次锁屏，还锁不上再弹出验证。
  4. 原生输入助手无法重新启动时，隐私屏自身接住的本机点击仍会重试锁屏和系统身份验证。
     这期间点击由隐私屏接住，不会穿过去落到看不见的应用上；验证窗口打开时隐私屏暂时让位，让它显示在最上面。
  5. 提示里写上其他锁屏方法：macOS 合上屏幕或按电源键，Windows 按 Windows 徽标键 + L。

  任何情况下都不露出一个没锁的桌面，也不会把主人挡在外面。此前锁不上时，点击会穿过遮罩，主人只能等系统
  自己锁屏或强制退出 Cindy。Hyprland 暂时没有对应的系统验证，只能每次有人碰电脑时重试锁屏，需另行补齐。
- 远程控制中在电脑前选「断开连接」而真锁屏失败时，同样转成上面这种状态（2026-11-14 用户决定；此前会
  直接撤掉遮罩）。
- 锁不上的原因写进日志，只记固定的原因词（不是本人会话、调用方校验失败、没有权限、超时），不记屏幕或
  输入内容。

## 画面

三种场景用同一种画面：**黑色背景加 Cindy 插画和说明文字**（用户选定，保留品牌插画）。

- 插画用适合深色背景的版本，标志用深色模式版。不随浅色／深色主题变化：黑底本身是为了让屏幕看起来像
  关着。
- 说明文字按场景变化：「Cindy 正在工作」「正在通过 Cindy 被远程控制」「Cindy 没能锁住这台电脑」，
  第二行写有人碰电脑会发生什么。
- 刚出现和有人移动鼠标时，以正常亮度显示约 10 秒；之后整体降到约三成亮度，仍能认出是 Cindy 的隐私屏。
- 插画和文字作为一个整体，每隔一到两分钟在屏幕中部区域缓慢平移一小段（动画过渡，不跳动），同一位置的
  像素不会长时间亮着。系统开启「减弱动态效果」时不做平移动画，改为淡出后在新位置淡入。
- 「没能锁住」的提示同样降亮度并漂移，不再固定不动。
- 鼠标指针隐藏。
- 遮罩略微透光（99% 不透明），后面的应用会认为自己仍然可见、继续绘制，AI 截图拿到的是实时画面。
  完全不透明的全屏窗口会让 macOS 判定后面的窗口被遮挡，Electron 类应用就停止绘制（2026-11-06 的实测
  问题）。远程画面和 AI 截图都不包含隐私屏本身。

## 爱护屏幕：只在需要时常亮

- 黑色在 OLED 屏上等于像素不发光，在分区背光屏上对应区域背光关闭；风险只在插画和文字这些亮的部分，
  由上面的降亮度和漂移处理。普通液晶屏（含多数外接显示器）显示纯黑时背光仍然亮着，所以关键是**不无谓
  地一直亮**。
- 隐私屏只在需要时让屏幕保持常亮（用户选定）：有 AI 任务在运行、有远程连接，或定时任务即将执行（3 分钟内）。
  长时间没有这些，就放开常亮，系统按自己的设置熄屏、锁屏；隐私屏随系统锁屏撤下。此前“开着就一直
  常亮”的做法作废。
- 锁不上而等待系统自己锁屏时，同样放开常亮。

## 设置

**分工：被控电脑本机决定怎么保护；遥控端只决定这一次连接什么时候保护。** 同一个开关不出现在两处。

### 本机：设置 → 通用 → 离开电脑时

新分组，放在「应用行为」之后。相关设置从「应用行为」移出，「应用行为」只保留登录后自动启动、
菜单栏余量、关闭主窗口时、后台窗口首次点击。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 保持电脑唤醒 | 关 | 电脑不休眠，后台的 AI 任务和定时任务能继续运行；屏幕照常熄屏、锁屏。全平台。 |
| 用隐私屏代替锁屏 | 关 | AI 需要用屏幕时，电脑不熄屏、不锁屏，隐私屏遮住屏幕，AI 在后面继续工作；有人碰电脑就立即锁屏。没有任务时照常熄屏锁屏。远程控制结束后也用隐私屏保护这台电脑。 |
| 离开多久后打开隐私屏 | 跟随系统 | 只在上一项打开时出现：30 秒、1 分钟、2 分钟、5 分钟、跟随系统（系统熄屏或屏保时间中较早的一个，都未设置时 10 分钟）。 |
| 立即试一下 | — | 3 秒后盖上隐私屏；碰一下锁屏，两分钟没人碰自动撤下且不锁屏。缺权限时在这里提示去授权。 |

- 两个开关保留（用户选定），不合成三选一。打开「用隐私屏代替锁屏」时，「保持电脑唤醒」显示为已打开且
  不可关，说明改为「已包含在隐私屏中」：隐私屏要让 AI 随时能用这台电脑，电脑本身不能休眠。关掉隐私屏
  后，「保持电脑唤醒」恢复成用户自己原来的选择。
- 「离开多久后打开隐私屏」保留 Cindy 自己的选项加「跟随系统」（2026-11-14 用户决定）。讨论过“只跟随系统、
  点按钮去系统设置改”和“在这里直接写入系统熄屏时间”两种做法，均不采用；Cindy 不修改系统的熄屏、屏保或
  锁屏设置。
- 不支持隐私屏的平台只显示「保持电脑唤醒」。
- 总开关默认关（用户选定），靠引导开启（见下）。
- 升级兼容：旧的「离开时继续工作」开启状态和离开时长原样沿用为新设置，用户不需要重新设置。
- 仅本机生效，不随账号同步，不进入跨电脑的设置迁移默认项（与原「离开时继续工作」一致）。

### 遥控端：远程桌面窗口 → 安全

手机和电脑上的遥控窗口一致，按“这台遥控设备 × 那台被控电脑”分别记住。

| 现在 | 改为 | 默认 | 说明 |
| --- | --- | --- | --- |
| 电脑防窥 | 连接时打开隐私屏 | 开 | 远程控制时遮住这台电脑的屏幕；有人在电脑前点按或按键会先询问是否断开。 |
| 退出后锁定电脑 | 退出后保护电脑 | 开 | 说明按被控电脑的设置显示：「退出后盖上隐私屏，AI 可以继续工作」或「退出后锁屏」。 |
| 无操作后断开并锁屏 | **去掉** | — | 改为跟随被控电脑自己的离开时长，见下文「远程连接中没人操作」。 |
| 自动解锁电脑 | 不变 | 关 | — |

协议字段 `lockOnExit`、`privacyScreen`、`idleTimeoutMinutes` 保持名称和兼容性；被控端需要向遥控端
声明本机采用隐私屏还是真锁屏，供说明文字显示。旧被控端不声明时按“退出后锁屏”显示。新遥控端连接
仍依赖 `idleTimeoutMinutes` 的旧被控端时，继续发送原默认值 5 分钟，旧被控端行为不变；新被控端忽略
这个字段，改用本机离开时长。

## 远程连接中没人操作

2026-11-14 用户决定：远程连接不再单独设置「无操作后断开」，和本机用同一条规则、同一个离开时长
（「离开多久后打开隐私屏」，默认跟随系统；系统没设熄屏时间时按 10 分钟）。

- 遥控端的点按、打字算“有人在用电脑”，重新开始计时，和本机有人操作一样。只看不操作、AI 的操作都不算。
- 离开时长到了：
  - 本机开了隐私屏，且 AI 正在工作 → 盖上隐私屏，**远程连接保持**，可以在远程继续看 AI 干活（远程画面
    不包含隐私屏）。
  - 其他情况 → **Cindy 主动锁屏**，检测到锁屏就断开远程连接，断开后不自动重连。
- 必须由 Cindy 主动锁屏，不能等系统自己锁：系统可能设成永不熄屏；即使熄屏，“熄屏后多久需要密码”也可能
  设得很长，屏幕黑了但电脑没锁，远程一操作就能用。
- 远程连接期间不再强制屏幕常亮：有人在远程操作或 AI 在工作时才保持常亮，其余时间按上面的规则处理。
- #7793（2026-10-29）的另外两条保护保留：遥控端电脑锁屏或睡眠、手机切到后台且没开画中画时立即断开；
  因没人操作或失联而断开后不自动恢复，保存的解锁密码不会再自动打开电脑。
- 例外（2026-11-15 用户决定）：因失联（心跳超时、对方离线、信令断开）断开，且这台电脑只盖了隐私屏、
  没有锁屏时，手机可以自动重连。这时电脑没锁也没露出东西，重连和手动重新连接一样。电脑前有人碰过、
  隐私屏已经转成锁屏，或者隐私屏没盖上而退回了锁屏，就仍然不自动恢复，免得用保存的密码把电脑打开。

**取舍**：AI 一直在工作时远程连接会一直保持。手机解锁着、远程画面开着、人走开了，这段时间里拿到手机的人
能看到并操作电脑，直到 AI 停下后离开时长走完；手机锁屏或切到后台仍会立即断开。用户决定（2026-11-14）：
去掉的只是遥控端的「无操作后断开」设置，#7793（2026-10-29）“没人操作就断开并保护”的功能由被控端的离开时长
继续覆盖，不另行确认。

隐私屏防的是被控电脑旁边的人；断开防的是拿到遥控设备的人。断开还会让被控电脑不再录屏编码、不再因连接
而常亮，也不再占用中转带宽和手机电量。

## 引导开启

- 远程退出后被控电脑是真锁屏时，在遥控端提示：「电脑已锁屏。想让 AI 在你离开时继续用它，可以在那台
  电脑的 设置 → 通用 → 离开电脑时 里开启隐私屏。」
- AI 遇到电脑已锁屏、无法操作时，在提示里给出同一个入口。
- 不提供从遥控端远程开启：那会让遥控端修改被控电脑的安全设置，属于新的权限边界，本次不做。

## 平台

| | macOS | Windows | Hyprland |
| --- | --- | --- | --- |
| 版本范围 | 14+ | 10 build 19041+ | 0.56.2，插件 ABI 匹配 |
| 遮罩 | Electron 面板窗口，99% 不透明，从采集中排除 | Electron 窗口，显示后逐窗设置并核验 Windows 的 `WDA_EXCLUDEFROMCAPTURE` | 合成器插件在采集之后绘制，只出现在物理屏幕上 |
| 物理输入拦截与锁屏 | 输入 helper 的事件拦截；系统立即锁屏，快捷键兜底 | 输入 helper 的输入钩子；系统锁屏并以当前会话状态确认，锁屏超时保留钩子 | 插件区分物理与虚拟输入；Omarchy 锁屏 IPC 加合成器 `secure` 确认 |
| 离开检测 | 系统空闲时长，扣除 AI 自己的输入 | 同左 | 插件记录的最后一次物理输入（`idle`），Wayland 下 Electron 的空闲时长不可靠 |
| 「跟随系统」 | 熄屏时间与屏保时间中较早者 | 电源计划的关屏时间（按交流／电池） | 读不到系统时间，按 10 分钟 |
| 画面 | 网页：先亮 10 秒再降到三成，平移漂移，动鼠标恢复 | 同左 | 插件绘制：同样先亮后暗；位置每 90 秒直接换，不做平移动画（避免合成器持续重绘）；动鼠标恢复 |
| 「立即试一下」 | 有 | 有 | 暂无 |
| 实现状态（2026-11-14） | 已实现并开放；锁屏方式与身份验证真机验证过 | 已实现但**默认关闭**（`WINDOWS_PRIVACY_SCREEN_ENABLED`）；原生 helper 仅交叉编译检查，**未在 Windows 上运行** | 已实现并开放；插件只做了片段编译测试，**未完整编译、未在 Hyprland 上运行** |

**Windows 暂不开放**（用户决定，2026-11-14）：代码保留，但在 Windows 真机验证前保持关闭，Windows 用户的行为与
此前正式版一致——只有远程控制中的隐私屏，没有退出后锁屏、无操作后断开、离开时隐私屏和「离开电脑时」里的
隐私屏开关；这些在 Windows 上从未发布过，不能未经实测直接推给用户。验证项：锁屏与锁定确认、离开时自动盖上、
Windows Hello 验证、遮罩是否让后面的应用停止绘制。验证后把开关打开并更新本节。

其他 Linux 桌面（GNOME、KDE、X11）不支持隐私屏，照旧真锁屏（前提是有锁屏能力）；这些被控端不声明
`hostIdle`，遥控端仍显示并发送自己的「无操作后断开」时长。

- **Windows 上遮罩是否会让后面的应用停止绘制**：Chromium 在 Windows 上也有遮挡检测，需要实测并决定是否
  同样用略微透光的遮罩（目前只有 macOS 用 99%）。
- **Windows 与 Hyprland 的真机验证**：见上表“实现状态”。Hyprland 插件的透明度参数（`{.a = alpha}`）按
  0.56.2 的渲染接口写成，需完整编译确认。

## 保护范围之外

- **主动卸载 Hyprland 插件**（用户决定，2026-11-14）：隐私屏盖着时执行 `hyprctl plugin unload`，插件退出时只能
  请求锁屏、等不到锁定完成，遮罩随插件消失，可能短暂露出未锁的桌面。不为此单独设计保护：站在电脑前的人
  按键都会被拦截并转成锁屏，无法输入这条命令；能执行它的程序或远程登录者已经以用户身份控制这台电脑，
  不需要绕过隐私屏也能读写文件和操作桌面。来源为 #9899 的审阅意见。
