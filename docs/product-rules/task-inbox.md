## 分区与动作

- 置顶：桌面和手机保留置顶入口。单独置顶的任务、桌面置顶项目里的任务也按各自状态进入收件箱分区。
  收件箱筛选决定分区内显示哪些任务及其计数。折叠置顶区或置顶项目后，任务仍显示在对应分区。
分区按「现在该谁动」判断，而不是只看是否绑定了自动化。
分区内的任务只按最近活动时间倒序排列（与行尾显示的时间一致），未读、等待回答等状态只决定进哪个分区，不再在分区内提前；「稍后处理」按取回时间先后排列（2026-11-25 用户决定：此前沿用普通列表的优先级排序，已处理里几天前、一周前的未读任务排在刚处理完的任务前面）。
- 待处理（收件箱模式的第一个分区，2026-11-18 由「收件箱」改名，避免与模式名重复）：该用户动的任务——有新结果未看（一轮跑完未读、后台跟进本轮提醒了用户、运行失败）、
  等待用户回复或授权；以及未归档、未稍后处理、不在运行且没有自动跟进的任务。
  普通任务读过结果仍留在这里，只有主动归档才移到已处理。
- 进行中：该 Agent 或后台动的任务——正在执行且无需用户回应，或绑着启用中的自动化（任何自动化，
  不只 PR 跟进）且没有要用户看的东西（包括等待下一次运行的间隔），默认收起（2026-11-18 用户决定，
  取代此前「巡检、整理记忆、发布等例行自动化绑定的任务按普通任务处理」）。后台静默的一轮会自动标为
  已读，不会把任务送回收件箱。
  伙伴自己的任务（伙伴的群聊、IM 专线与例行任务对话，以及伙伴项目里的任务，含它的自动化运行）只在两种时候出现：
  需要用户（等回答、授权或运行出错）时进待处理，正在运行时进进行中；其余时候（包括跑出新结果）不在收件箱
  显示，只在伙伴页与任务列表里，避免闲置的伙伴任务堆在进行中；用户完成或稍后处理过的照常在对应分区
  （2026-11-18 用户决定，起因是手机收件箱被伙伴例行结果占满）。**伙伴开到其他项目里的任务按普通任务处理**，
  跑出结果照常进待处理（2026-11-22 用户决定：此前与任务列表「伙伴」筛选同口径，把伙伴替主人开的正事也挡在收件箱外，
  而交接技能又默认不请任务回报，结果两头都不在，事情做完没人收尾）。不改任务数据；桌面与手机同一规则
  （共享 `isTeammateOwnInboxTask` 决定 `taskInboxSection` 的 `teammate` 信号，返回 null 表示不列入）；任务列表的「伙伴」筛选口径不变。
  用户正打开的任务和其他任务一样立即归类：回复后立即移到进行中，一轮跑完立即回到待处理
  （2026-11-18 用户决定）。这种移动不让左侧任务栏滚动：桌面上行换分区会重新挂载，收件箱里只有
  「变成当前任务」才把行滚进视野，重新挂载不滚（`useScrollActiveRowIntoView`）；原位置下方的行上移补位。
  桌面查看另一台电脑的任务时，运行状态随执行端更新，与行尾指示一致。普通任务收到完成结果后即进入待处理，读过后仍在待处理，新一轮开始再回到进行中。
  手机查看任务时首页不可见，返回即重新归类。
- 稍后处理：指定时间前收起任务，到期回到适合其当前执行状态的分区；支持提前取回。
- 已处理：现有已归档任务，默认收起。恢复、继续消息和自动任务触发仍走现有恢复路径；
  自动化安静的一轮（前置检查跳过或静默完成）结束后放回已处理，只有提醒、失败或用户插话才回到收件箱；
  每轮新建任务的自动化，安静轮次新建的任务同样直接归档，
  见[归档与自动化](archive-pauses-automations.md)。

「已处理」复用完整归档流程，包括共享任务收口和托管工作目录回收；不能只是更改列表标志。
桌面收件箱复用原有行尾操作槽，显示「稍后处理＋完成」，已处理任务显示「取消归档」。
桌面任务点「完成」立即从当前分区移出，计数同步更新；远端核验被拦截、用户取消或写入失败时按实际状态恢复。完成当前打开的任务后，按点击时「待处理」中普通任务和伙伴主对话的显示顺序打开下一项，末项回到上一项，清空待处理后回到新任务页。处理其他行或等待期间已切换页面时，保留正在看的页面。
「完成」单击生效。为避免列表重排时点错，仅当鼠标停在某个「完成」按钮上时
排列冻结：行不换位置、不跨分区，新进来的任务暂不插入；行内状态与分区数字照常更新，移出按钮后立即补上变更。鼠标停在标题、预览、列表空白处或菜单内时，列表实时更新。
完成、稍后处理、取回、取消归档等显式操作立即生效：该行离开原位、下方补位，排到新分区末尾
（2026-11-18 用户决定，取代两步确认；实现见 `taskInboxPlacement.ts` 的 `freezeInboxLayout`）。
不再提醒绑定的自动化会恢复任务（安静的一轮会放回已处理，见[归档与自动化](archive-pauses-automations.md)）；工作目录有未提交改动或预检失败时仍弹确认，
运行中、被 IM 接管的任务仍按原规则拦截。手机收件箱左滑的归档按钮与完整左滑改为「完成」（左滑本身已是第一步）。
单独置顶的任务点「完成」只把本轮结果标为已读，保留置顶和工作目录。空闲且已读时退出待处理，有新结果或需要用户回应时再次进入待处理；正在运行和自动跟进仍按原规则分区。
任务绑着启用中的自动化（以 `targetSessionId` 绑定为准，任何自动化）时，「完成」只把这轮结果标为已读，
任务回到进行中，不归档、不回收工作目录；等任务未置顶且没有启用中的自动化了（例如 PR 合并后跟进结束），再点
「完成」才真正归档。按钮文字不变；正打开的任务也立即离开待处理。读不到绑定时按无绑定处理，照常归档。
原因：归档会回收工作目录，自动化下一轮又从快照重建，安静的一轮放回已归档再删一次，每轮反复重建、删除，
依赖目录和构建产物随之丢失，大仓库每次要重新检出（2026-11-18 用户决定）。
2026-11-18 用户要求。不重复添加外侧按钮，不显示「更多」按钮；其余操作从右键
菜单进入，原有归档确认与写入权限继续生效。任务行在悬停前后均占满可用宽度。
详情见 [归档与自动化](archive-pauses-automations.md)。

稍后处理不归档、不停止 Agent、不暂停自动化、不回收工作目录。唤回时间保存在任务所属
电脑，控制端与手机读取同一份数据。到期本身只影响列表展示，不发送消息或启动 Agent。
桌面菜单左侧显示快捷选项，右侧显示将保存的实际唤回时间：1 小时后、3 小时后、
今晚 18:00、明天 09:00、下周一 09:00；今晚已过则不显示该选项。日历预设按操作设备
本地时区计算，跨夏令时仍保持指定钟点。下周总是下一周的周一。
「无限期」让任务留在稍后处理分区，显示「无限期」且不设到期时间；可手动取回，新输入仍按原规则提前唤回。
分隔线后的「自定义」可选择未来一年内的日期和时间，保存为 ISO 时间戳；无效或已过期
时间不得写入。打开菜单后显示与提交使用同一时刻，避免用户看到的时间和保存值不同。
手机使用相同预设与实际时间，点击稍后处理打开原生底部面板；自定义使用系统日期与时间选择器。
收件箱行左滑显示稍后处理与「完成」，长按保留完整菜单，右滑置顶/已读与完整左滑归档保持原行为。
桌面任务模式切换入口位于侧边栏顶部前进／后退一排的右端，手机位于显示设置菜单。
新输入（包括自动化触发）会提前唤回。
归档和恢复清除延期。置顶任务同样可以稍后处理，入口与其他任务相同（2026-11-25 用户决定，取代此前置顶任务
不提供稍后处理的规则）：延期只写唤回时间，不改置顶状态，任务继续留在置顶区，同时按延期进入稍后处理分区。
入口只在收件箱分区里的那一行：置顶区是快捷入口，不提供稍后处理和「完成」，桌面悬停按钮与右键菜单、
手机左滑与长按菜单都一样（2026-11-25 用户决定）。只有置顶区收起这两个操作；收件箱模式下的共享任务行、
搜索结果行仍按收件箱模式提供稍后处理，与桌面一致。
离线、关闭应用后再打开，按保存的时间重新计算；不能依赖某个窗口一直开着。

## 离线电脑任务的待同步处理

任务所属电脑离线（或尚未连上）时，收件箱仍允许对同账号设备上的任务点「稍后处理」与「完成」（伙伴主对话同样支持离线稍后处理），不因设备离线卡在待处理区：

- 离线操作按账号持久化在当前控制端本机（桌面由主进程按 owner 落盘并多窗口同步，手机按账号存入 AsyncStorage），立即在收件箱投影层把任务移入「稍后处理」或「已处理」，并带轻量的待同步标注；原设备镜像缓存保持不变。
- 目标电脑尚未上线前，用户可在「已处理」点「取消归档」或在「稍后处理」点「立即取回」直接撤销本地待同步意图，无需连网。
- 目标电脑重新上线并拉完最新快照后，控制端按共享判据（`@cindy/maker-shared/offline-inbox-intent`）自动重放：
  - **稍后处理**：若电脑离线期间已有新输入（`userSendAt` 推进）、任务已归档/删除或唤回时间已过，自动丢弃旧意图；否则写入 `snoozedUntil`。
  - **完成**：若离线期间任务有新活动、正在运行中、被接管或处于活跃共享中，撤销离线完成并退回「待处理」轻提示；若为单独置顶任务或绑定了启用中的自动化，按既有规则转为标为已读而不归档；若工作目录预检为 `dirty`（有未提交改动）或无法确认（`unknown`），不静默回收 worktree，退回「待处理」并提示用户确认后再归档；确认 `clean` 后静默完成归档。
- 瞬时断线或超时保留意图，待下次重连继续；设备被移除、撤销或账号登出时同步清理。共享任务访客与普通任务列表的离线写保护保持不变。

## 伙伴主对话（2026-11-20）

每个伙伴的主对话在收件箱里占一行，与任务一样按「现在该谁动」归类（2026-11-20 用户决定，起因是
项目经理型伙伴要用户拍板的事只在伙伴段有未读点，收件箱里看不到）。群聊不在此列；伙伴开的任务仍是
普通任务，沿用上文「伙伴的任务」的规则各自成行。桌面与手机同一规则（共享 `teammateInboxSection`）。

- 待处理：等用户回答或授权、出错，或有未读回复。
- 进行中：正在回话或干活。
- 稍后处理：与任务相同的时间选项、「无限期」与提前取回；到期或主对话有新消息（用户发消息、其他任务的
  来信、伙伴的新回复）时回到当前状态对应的分区，不让之后才出现的待决事项压在稍后处理里。延期时间存在
  主对话所在电脑的任务记录上，各端读同一份。
- 闲着且已读：不在收件箱显示，只在伙伴段。伙伴段在收件箱模式下照常保留，是找伙伴的入口；闲置伙伴
  不进「进行中」，也不进「已处理」（伙伴不归档）。

读过即处理：伙伴没有归档，打开对话读完离开，这一行就离开「待处理」，不必点「完成」。「完成」只把回复
标为已读，沿用伙伴已有的跨设备读位，不归档、不动对话；只在这一行仅剩未读回复时提供。等回答、等授权
或出错的行不能靠「完成」消掉，要去对话里处理或稍后处理。「进行中」的行不提供「完成」，只提供稍后处理。

所在电脑离线不算出错：离线电脑上的伙伴只在留有未读回复时进「待处理」。多台电脑上各有一份的伙伴
（如每台电脑的 Cindy）是各自的对话，各自成行，远程的行在名字后标电脑名。行沿用任务行的几何：行首
是伙伴头像，标题是伙伴名字，行尾状态点与任务同款，悬停换成「稍后处理＋完成」；点击打开伙伴对话。
同一分区里伙伴行排在任务前，按最近活动排序。搜索或筛选只收窄任务，此时收件箱不列伙伴行，伙伴仍可
从伙伴段和侧栏搜索找到。

手机上这一行沿用伙伴段的伙伴行（头像、名字、状态点、最新一句与时间），稍后处理的行在时间位显示取回
时间。左滑显示「稍后处理＋完成」；只能稍后处理的行（进行中、等回答或出错、稍后处理里的取回）只有这一个
按钮，完整左滑即触发。伙伴行不提供右滑（置顶不适用，标为已读与「完成」重复）和长按菜单（任务的长按菜单
是改名、标签、归档等任务操作）；同样的操作以无障碍动作挂在行上，供读屏使用。只在云端有记录、所在电脑未
列出的伙伴没有读位与延期信息，不会因未读或稍后处理出现在收件箱。

旧版电脑不下发主对话的延期信息，对应的行不提供稍后处理，其余归类照常；协议见
[伙伴主对话的稍后处理](../dev-rules/protocol-compatibility/teammate-inbox-snooze.md)。
实现见 Desktop `features/bots/teammateInbox.ts`、`TeammateInboxRow.tsx` 与 `TaskInbox.tsx`，Mobile
`session/InboxTeammates.tsx` 与 `homeSections.ts`（`buildInboxHomeSections`）。

## 验收

- 桌面顶部一排的开关与手机显示设置均可切换任务模式，两种模式互斥，重新打开保留选择。
- 上方目录的分组、排序、折叠和状态筛选保持有效；已处理不受其活跃状态筛选影响。
- 打开任务、清除未读不把任务移到已处理。
- 等待回复与授权的运行中任务保持在收件箱，恢复执行后进入进行中。
- 稍后处理、提前取回与归档在桌面和手机反映同一结果。
- 归档失败留在原分区并显示错误，不伪造已处理成功。
- 旧端不支持稍后处理时明确报告，不把忽略字段的请求当成成功。
- 设备范围、项目筛选、隐藏任务及共享任务权限继续有效。

## 兼容与实现边界

不再读取先前试用版的显示模式偏好。延期时间与设置时间是任务所属电脑的可空字段，
经现有 patch-meta 与 sessions 推送同步，无新增中继通道。旧端读取忽略可选字段；
新版控制端写旧宿主若被拒绝或未返回权威字段，显示失败，不把它当成已经延期。
到期只重算可见分区，不轮询服务器。手机缓存保留同一字段对，重开后按当前时间解释。
本机、同账号远控和手机复用现有任务权限及归档入口，SSH 工作区不参与这次元数据操作。

## 自动跟进归类

自动跟进指当前启用、绑定到该任务（`targetSessionId`）的任何自动化（2026-11-18 用户决定，取代
2026-11-17 起只认 PR 跟进的 `scheduleFollowsPr`，以及随之传给控制端的 `followsPr` 标记）。
判断按当前绑定；暂停、过期、删除或改绑后不再据此归入进行中，历史运行记录不算。多个绑定中任一仍启用即算。自动跟进只在没有待看结果时生效：有未读结果、等待用户回应时回到收件箱（2026-11-17 修正：此前跟进中的任务跑完留下结果仍停在进行中）；稍后处理与归档沿用各自的优先级。需要用户拍板的跟进结果应以待回答的提问呈现，看过也留在收件箱。桌面和手机共用 `taskInboxSection` 分类规则，未读与等待取自查看钉住后的优先级档位、运行取自实时档位，
远程任务的运行、完成未读与等待按收件箱自身的任务范围读取，不依赖普通列表的筛选范围；
从本端向远程任务发送后的「正在启动」，在被控端推来的本轮结束时间前进时立即收掉，不等 2 分钟兜底
（2026-11-18：没收到运行推送就完成的远程任务曾在进行中滞留）；手机折叠的自动化运行逐条展开时各用自己的未读与等待信号。跟进间隔不显示为正在执行。
