# 任务收件箱

> 状态：已实现，待合入。2026-11-15 改为独立模式，替代此前固定放在原列表下方的方案。

桌面和手机的侧边栏显示设置提供「任务模式 → 任务列表 / 收件箱」，默认任务列表。
任务列表显示原设备、项目目录；收件箱只显示四个状态分区，两者互斥。伙伴和置顶入口保留。
选择在当前客户端持久保存，不强制同步其他设备的视图偏好。切换不改变原分组、排序、行样式和筛选设置。
手机移除跳到收件箱按钮。任务状态仍跨设备同步，收件箱独立于任务状态筛选，确保已处理可见。

## 分区与动作

- 置顶：沿用现有置顶；任务不在其他活跃分区重复出现。
分区按「现在该谁动」判断，而不是只看是否绑定了自动化。
- 收件箱：该用户动的任务——有新结果未看（一轮跑完未读、后台跟进本轮提醒了用户、运行失败）、
  等待用户回复或授权；以及未归档、未稍后处理、不在运行且没有自动跟进的任务。
  普通任务读过结果仍留在这里，只有主动归档才移到已处理。
- 进行中：该 Agent 或后台动的任务——正在执行且无需用户回应，或仍启用 PR 自动跟进且没有待看的结果
  （包括等待下一次检查的间隔），默认收起。巡检、整理记忆、发布等例行自动化绑定的任务按普通任务处理。后台静默的一轮会自动标为已读，不会把任务送回收件箱。
  用户正打开的任务看完后保持原分区，离开后再重新归类。
- 稍后处理：指定时间前收起任务，到期回到适合其当前执行状态的分区；支持提前取回。
- 已处理：现有已归档任务，默认收起。恢复、继续消息和自动任务触发仍走现有恢复路径；
  自动化安静的一轮（前置检查跳过或静默完成）结束后放回已处理，只有提醒、失败或用户插话才回到收件箱，
  见[归档与自动化](archive-pauses-automations.md)。

「已处理」复用完整归档流程，包括自动化提醒、共享任务收口和托管工作目录回收；
不能只是更改列表标志。桌面收件箱复用原有行尾操作槽，显示「稍后处理＋归档」，
已处理任务显示「取消归档」。不重复添加外侧按钮，不显示「更多」按钮；其余操作从右键
菜单进入，原有归档确认与写入权限继续生效。任务行在悬停前后均占满可用宽度。
详情见 [归档与自动化](archive-pauses-automations.md)。

稍后处理不归档、不停止 Agent、不暂停自动化、不回收工作目录。唤回时间保存在任务所属
电脑，控制端与手机读取同一份数据。到期本身只影响列表展示，不发送消息或启动 Agent。
桌面菜单左侧显示快捷选项，右侧显示将保存的实际唤回时间：1 小时后、3 小时后、
今晚 18:00、明天 09:00、下周一 09:00；今晚已过则不显示该选项。日历预设按操作设备
本地时区计算，跨夏令时仍保持指定钟点。下周总是下一周的周一。
分隔线后的「自定义」可选择未来一年内的日期和时间，保存为 ISO 时间戳；无效或已过期
时间不得写入。打开菜单后显示与提交使用同一时刻，避免用户看到的时间和保存值不同。
手机使用相同预设与实际时间，点击稍后处理打开原生底部面板；自定义使用系统日期与时间选择器。
收件箱行左滑显示稍后处理与原有归档，长按保留完整菜单，右滑置顶/已读与完整左滑归档保持原行为。
任务模式切换入口位于显示设置菜单。
新输入（包括自动化触发）会提前唤回。
归档和恢复清除延期，置顶任务保持置顶、不提供稍后处理动作。
离线、关闭应用后再打开，按保存的时间重新计算；不能依赖某个窗口一直开着。

## 验收

- 两端设置均提供任务模式切换，两种模式互斥，重新打开保留选择。
- 上方目录的分组、排序、折叠和状态筛选保持有效；已处理不受其活跃状态筛选影响。
- 打开任务、清除未读不把任务移到已处理。
- 等待回复与授权的运行中任务保持在收件箱，恢复执行后进入进行中。
- 稍后处理、提前取回与归档在桌面和手机反映同一结果。
- 归档失败留在原分区并显示错误，不伪造已处理成功。
- 旧端不支持稍后处理时明确报告，不把忽略字段的请求当成成功。
- 设备范围、项目筛选、隐藏任务及共享任务权限继续有效。

## 兼容与实现边界

不再读取先前试用版的显示模式偏好。延期时间与设置时间是任务所属电脑的可空字段，
经现有 patch-meta 与 sessions 推送同步，无新增中继通道。旧端读取忽略可选字段；
新版控制端写旧宿主若被拒绝或未返回权威字段，显示失败，不把它当成已经延期。
到期只重算可见分区，不轮询服务器。手机缓存保留同一字段对，重开后按当前时间解释。
本机、同账号远控和手机复用现有任务权限及归档入口，SSH 工作区不参与这次元数据操作。

## 自动跟进归类

自动跟进只认 PR 跟进：沿用宿主 PR 状态联动（`prFollowWatch`）的既有约定，即当前启用、绑定到该任务、
且前置检查写明 PR／MR 链接的自动化（`scheduleFollowsPr`）。例行自动化不会结束，不能代表任务仍在推进，
2026-11-17 起不再据此归入进行中。远程电脑的绑定镜像只保留由前置检查派生的 `followsPr` 标记，不保存命令正文。
判断按当前绑定；暂停、过期、删除或改绑后不再据此归入进行中，历史运行记录不算。多个绑定中任一仍启用即算。自动跟进只在没有待看结果时生效：有未读结果、等待用户回应时回到收件箱（2026-11-17 修正：此前跟进中的任务跑完留下结果仍停在进行中）；稍后处理与归档沿用各自的优先级。需要用户拍板的跟进结果应以待回答的提问呈现，看过也留在收件箱。桌面和手机共用 `taskInboxSection` 分类规则，信号取自查看钉住后的优先级档位；手机折叠的自动化运行逐条展开时各用自己的未读与等待信号。跟进间隔不显示为正在执行。
