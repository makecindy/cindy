# 模型组：把已有的来源合成路线与模式

> **读取时机**：新增或修改模型组（路线、模式）的配置、选路、选择器入口、任务里的说明，
> 或要让模型组在新任务以外的地方生效之前

## 1. 定位

用户在「模型供应商」里已经连接了多个来源（多个订阅账号、API 密钥、不同供应商），希望开任务时不必
自己挑：快作废的订阅额度先用掉，一个用不了时换下一个。

模型组只做加法（2026-11-11 用户裁决）：

- 「模型供应商」页原样保留，来源仍在那里连接和管理。模型组是设置里单独的一页，只引用已连接的模型。
- 选模型时左侧栏在「全部」之后多一格「模型组」，其余格与列表不变。
- 模型组只回答「这次用哪个已连接的模型」。在哪台电脑运行、用哪个账号，仍由
  [供应商组](provider-groups.md)与订阅账号池各自决定；模型组不保存凭证，也不改变它们的规则。

## 2. 术语

- **模型组**：路线与模式的统称，也是设置页与选择器那一格的名字。
- **路线**：一个名字下的几个来源（引擎 + 供应商连接 + 模型）和一种选法。
- **模式**：一条路线或一个指定的模型，加上可选的推理强度。
- **来源**：模型供应商里一个已连接的模型。同一条路线可以放不同的模型。

「供应商组」选电脑，「模型组」选来源，两者不是一回事。术语登记见 `i18n/glossary.json`
（`model-group`，`proposed`；路线与模式的用法写在它的说明里）。

## 3. 选法

新任务第一条消息发出前选一次，选出的模型只用于这次新建，不改草稿里用户原来选的模型。

候选先过滤：用户在路线里停用的、供应商没有连接或模型现在不可为新任务选用的、对应引擎没有安装的，都跳过。
然后把订阅配额已用完的放到最后，在剩下的里按路线的选法挑：

| 选法 | 规则 |
| --- | --- |
| 快作废的先用（默认） | 与供应商组同一把尺子：剩下的配额 ÷ 剩下的时间，最急的先用；5 小时配额快满、离重置还早的先避开；读不到配额的来源排在读得到的后面；一样急时按列表顺序 |
| 按顺序 | 列表里第一个能用的 |
| 轮流 | 上一次选中的下一个；只在内存里记，重启后从第一个开始 |

配额取自额度总览已有的订阅窗口，不发模型请求。读不到时按未知处理，不当作没用过。
排序复用 `provider-group/scheduler.ts` 与 `usage.ts`，不另写一套。

## 4. 用不了时

- 能用的来源都撞了配额上限：选最早恢复的那个，任务照常建立，之后由
  [撞限额后的等待与自动继续](usage-limit-auto-continue.md)接手。
- 路线里没有任何能用的来源，或选中的路线、模式已被删除：沿用用户原来选的模型。
- 模式指定的推理强度选中的模型不支持：按该模型的默认档运行。

## 5. 让用户看得见

- 第一条消息下方写一行：哪个模型组为这个任务选了哪个模型、哪个来源、为什么；沿用了原来的模型时也写明。
  这行复用「让插件选」的说明卡，手机端同样显示。
- 设置里每条路线有「试一下」：列出每个来源会被选中、备用还是跳过及原因；不发消息、不推进轮流的顺序。

## 6. 范围与现状

- 只用于本机开的新任务（普通发送与新建目标）。远程控制别的电脑、SSH、Agent 在另一台电脑运行、协同模式不提供，
  条件与「让插件选」相同。
- 任务开始后不因模型组中途换来源。
- 伙伴、定时与自动化、子代理、辅助模型暂不经过模型组；要接入时先在这里补规则。
- 配置按账号保存在本机（`model-groups.json`），只存用户建的内容；不随新电脑迁移（供应商连接 ID 各台不同）。
