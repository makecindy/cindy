# 智能路由（原「模型组」）：把已有的来源合成路由

> **叫法（2026-11-24、11-25 用户裁决）**：用户看到的名字改为「智能路由」（整页与选择器那一格，原「模型组」），其中一项叫「路由」
> （原「模式」），路由里的成员叫「来源」。页面并入「模型供应商」，在左栏最上面。下文沿用旧叫法的地方按此对应理解；
> 代码与存储里的 `modelGroups` / `route` 字段名不变。

> **读取时机**：新增或修改模型组（模式）的配置、选路、选择器入口、任务里的说明，
> 或要让模型组在新任务以外的地方生效之前
> **适用路径**：`apps/desktop/src/main/model-groups/**`、`apps/desktop/src/renderer/features/model-groups/**`、
> `apps/desktop/src/shared/{modelGroups,modelGroupDecisions}.ts`、
> `apps/desktop/src/renderer/components/new-chat/**/ModelGroupsPickerSection*`、

## 1. 定位

用户在「模型供应商」里已经连接了多个来源（多个订阅账号、API 密钥、不同供应商），希望开任务时不必
自己挑：快作废的订阅额度先用掉，一个用不了时换下一个。

模型组只做加法（2026-11-11 用户裁决）：

- 来源仍在「模型供应商」里连接和管理。智能路由只引用已连接的模型；2026-11-24 起它不再是设置里单独的一页，而是「模型供应商」
  左栏最上面的一项（旧的 `tab=model-groups` 链接照常打开它）。供应商内账号、跨电脑供应商组与路由共用一套选法与一个选择函数，
  原来账号区的四种分配方式删除，旧配置读取时换算（§3）。
- 至少有一个用户建的模式时，选模型时左侧栏才在「全部」之后多一格「模型组」；一个都没有时不显示，
  其余格与列表不变。自动路由（§3.4）不靠这一格，始终在选择器最上面（2026-11-24 用户裁决，取代 11-21 的自动组口径）。
- 模型组只回答「这次用哪个已连接的模型」。来源可以是本机的，也可以是其他电脑上的或别人分享来的供应商
  （2026-11-11 用户要求）：来源连同运行位置一起存，选中它的新任务就在那里运行 Agent，规则见 §3.1。
  组内电脑怎么分、用哪个账号，仍由[供应商组](provider-groups.md)与订阅账号池各自决定；模型组不保存凭证，
  也不改变它们与[供应商分享](provider-sharing.md)的授权规则。

## 2. 术语

- **模型组**：用户建的模式的统称，也是设置页与选择器那一格的名字。
- **模式**：一个名字下的几个来源（引擎 + 供应商连接 + 模型）、一种选法，以及可选的推理强度。
- **来源**：模型供应商里一个已连接的模型，连同它的运行位置（本机、另一台电脑或分享来的）。同一个模式可以放不同的
  模型；同一个模型在两台电脑上是两个来源。模式的成员也可以是另一个模式（§3.3）。
- **自动路由**：Cindy 内置的一个模式，成员自动维护，在模型选择器最上面（§3.4）。
- **每轮重新选**：模式的一个开关。打开后，任务里每一轮开始时都按模式的规则再选一次来源（§7）；关着时只在开任务时选。

用户只需要理解一个概念：2026-11-11 起原来的「模式」（一组来源或一个模型加推理强度）并入当时叫「路线」的这一项，
推理强度成为它自己的选项——一个概念比两个好懂；按角色分工暂缓。2026-11-13 用户决定这一项改叫「模式」，不再用
「路线」：设置页、选择器、任务里的说明与「最近的选择」都这样写，选择器里的分组叫「模型组」。11-11 之前旧格式存下的
模式、选中的模式、经它建的任务记录与「最近的选择」读取时忽略，不报错，也不需要用户处理。代码与存储里的
`route` / `routes` 字段名不变（只改用户看到的叫法），已有配置原样可用。

「供应商组」选电脑，「模型组」选来源，两者不是一回事。术语登记见 `i18n/glossary.json`
（`model-group`，`proposed`；「模式」的用法写在它的说明里）。

## 3. 选法

选路本身不记「最近的选择」、不推进轮流位置与权重计数；新任务首条消息被接受（斜杠命令建好任务并交接、目标启动成功）或已有任务换模型成功后才提交一次。取消、创建失败、发送未接受与预览不提交。

新任务第一条消息发出前选一次，选出的模型只用于这次新建，不改草稿里用户原来选的模型。

候选先过滤：用户在模式里停用的、供应商没有连接或模型现在不可为新任务选用的、对应引擎没有安装的、
运行位置现在用不了的（§3.1），都跳过。
然后把订阅配额已用完的放到最后，在剩下的里按模式的选法挑：

面向用户的名字与排列（2026-11-26，dash 建议做减法）：「快作废的先用」面向用户叫「**自动**」（说明照旧写它怎么挑）；选择框主推「自动」「按顺序」，几个不同供应商之间再加「最省钱」，轮流、按权重、余量最多、用完再换收在「更多选法」一组里，功能不删、存量配置照常显示（`shared/routeStrategy.ts` 的 `PRIMARY_ROUTE_STRATEGIES`）。下表沿用原名。

| 选法 | 规则 |
| --- | --- |
| 快作废的先用（默认） | 与供应商组同一把尺子：剩下的配额 ÷ 剩下的时间，最急的先用；5 小时配额快满、离重置还早的先避开；读不到配额的来源排在读得到的后面；一样急时按列表顺序 |
| 按顺序 | 列表里第一个能用的 |
| 轮流 | 上一次选中的下一个；只在内存里记，重启后从第一个开始 |
| 最省钱 | 还有配额的订阅不另外花钱，排在最前；其余按该来源这个模型的标价（每百万输出 token，人民币按固定汇率折成美元）从低到高；没有标价的排在有标价的后面，订阅的「价值估算」不算标价；一样便宜时按列表顺序；谁都没有标价时只取第一个，说明里不写「最省钱」 |
| 用完再换 | 一直用上一次选中的来源，直到它配额用完或用不了，再换列表里下一个能用的（到了列表末尾从头找）；之后前面的来源恢复了也不换回去，等这个也用完再往下。只在内存里记，重启后从第一个能用的开始 |
| 余量最多的先用 | 剩余配额占比最高的先用（有周窗口看周，只有 5 小时窗口看 5 小时；几个窗口取最紧的那个，说明里写的余量就是它）；读不到配额的排在读得到的后面；一样多时按列表顺序；谁都读不到时只取第一个，说明里不写「余量最多」 |
| 按权重 | 每个来源可设权重 1–1000（不设为 1，设置页只在选了这个选法时显示权重），新任务按权重比例分到各来源，交错分配（3:1 是 甲甲乙甲），不成批连发；用不了的来源这一轮不参与。计数只在内存里，重启后重新开始 |
| 最快（暂缓，2026-11-24 用户裁决先做接替） | 按这个来源这个模型最近的实测速度：首字时间与输出速度，越新的记录权重越大；相差一成以内的保持列表顺序；一小时内没有实测的来源每五次选一次给它测；没有任何实测的排在有实测的后面 |

配额取自额度总览已有的订阅窗口，不发模型请求。读不到时按未知处理，不当作没用过。另一台电脑上的来源只用
总览里那台电脑、那个连接自己的窗口；本机同 ID 连接的额度不给它用。
本机来源背后是电脑组或几个账号时（2026-11-26，dash 建议），能不能用、快满没、急不急、余量按内层按它自己的选法
「下一个会接任务的」那台电脑或那个账号判断，与内层实际会用的一致：电脑组读组里各台的状态（同一组、同一模型一分钟内只读一次），
几个账号的连接问账号池（只读，不占位、不推进轮流或计数）；说明里写的额度窗口仍是总览里那一份。别的电脑上的来源与分享来的来源
照旧只用对方开放的额度。实现见 `model-groups/desktopResolver.ts` 的 `innerQuota`，回归见 `__tests__/pick.test.ts`。
设置页「现在怎么走」里每个来源格子显示它此刻的余量：打开时对每个模式做一次只看不选的解析（与「试一下」同一份，
不推进轮流、不记录），不轮询；读不到时才退回最近一次选中它时记下的余量。
排序复用 `provider-group/scheduler.ts` 与 `usage.ts`，不另写一套。一个供应商里的几个账号、几台电脑合成的组用的也是这一套选法、
同一套规则（2026-11-26 用户裁决）：只有「快作废的先用」按配额排，选了别的就按它挑，额度用完的照样跳过。标价与模型选择器显示的价格同一来源
（Cindy AI 取网关报价并以目录折后价为准，其余取注册表参考价、连接自带价与用户自定价），经
`getModelPriceQuote` 查询。

### 3.1 其他电脑与分享来的来源

- 设置里「添加来源」与其它模型选择器一样列出其他电脑与分享来的供应商（[统一模型选择器](model-selector-unified.md)），
  选中哪一行，来源就记下那一行的运行位置；旧数据没有位置，照常按本机。模式、总览、「试一下」、任务里的说明与
  「最近的选择」都写「供应商 · 那台电脑」，与模型选择器里远程那几行同一写法。
- 能不能用与插件卡片里的远程模型同一判断（`isGhostCardModelRouteAvailable`）：那个位置现在能选（同账号在线、开了
  远程控制的电脑，或未暂停的分享），模型也在那里允许远程调用的目录里；引擎是否就绪问那台电脑自己的引擎状态（与插件选路同一判断，读不到时按就绪），不看本机装没装：目录里列着模型不代表那台装了对应引擎。
  电脑离线、分享被撤销或暂停、读目录失败（包括只拿到上次留下的旧目录）或超过 2 秒（与等额度同一上限）都算这个来源用不了，按选法换下一个；
  全都用不了沿用原来的模型。模式里没有这种来源时不去读别处。不借本机同名供应商顶替。
- 配额：总览里有那台电脑这个连接的订阅窗口就用；那台此刻读不到只剩上次读数的、与本机是同一个账号而总览只列了本机那份的，
  都按读不到额度处理，排在读得到的后面。分享来的来源用额度总览里那个分享开放给本账号的额度（[供应商分享](provider-sharing.md) §7.5）；
  分享者没开「允许查看剩余额度」、离线或读不到时按读不到处理。分享里有多个账号时用周剩余最多的那个账号的窗口，
  与菜单栏同一个数，不代表那次一定落在这个账号上。
- 「最省钱」：只看那个位置目录里这个模型自带的价格，没有就按没有标价排在后面。
- 选中后新任务（普通发送与新建目标）带着运行位置建立，与「让插件选」选到远程模型同一条路径；任务记录、
  「最近的选择」与撞配额用的记录都带运行位置。

「最快」（2026-11-21 用户裁决要做，取代 11-11 写入的「暂不提供」）：现在每轮的 TPS 只挂在那一轮的用量详情上，
连接测试的延迟是一次性的，所以先要把每轮的首字时间和输出速度按「运行位置 + 供应商连接 + 模型」累积起来，
只在本机记、不上传；不拿模型名字或档位去猜速度。

新增的三种选法与「最快」同样适用于 §3.1 的远程来源：配额与速度都只用那个位置自己的数据。

### 3.2 例外

每个模式可以加最多 8 条例外，在按选法挑之前先看，按列表顺序：

- **消息里有图片时，只用能看图的来源**：第一条消息带图片时，看不了图的来源跳过（试一下里写明）。
  能不能看图与设置里模型的「能看图」开关同一判断（用户改过按用户的，否则按目录，再按模型名推断，
  读不到按不能）。一个能看图的来源都没有时照常选，并在说明里写明。每个模式最多一条。
  打开了每轮重新选的模式按每一轮判断（§7.3）；伙伴也按每一条消息判断（§6.2）。
- **某个时段改走另一个模式**：本机时间落在 [开始, 结束) 的整点时段里（结束早于开始即跨午夜）时，
  改走指定的模式，按那个模式自己的选法和例外选。时间由主进程自己取，不用界面传来的。指向的模式
  已删除或绕回走过的模式时，整条改道作废，按原模式照常选。删除模式时，别的模式里指向它的时段例外一并去掉。
  可以只在一周里的某几天生效（2026-11-21 用户裁决）：不选星期等于每天，七天全选也存成每天；跨午夜的时段按开始那一天算
  （周五 23:00–08:00 包括周六凌晨，不包括周五凌晨）。星期的名字和先后用系统按界面语言给的写法（周一或周日开头）。
- **在某些文件夹里改走另一个模式**（暂缓，2026-11-24 用户裁决；11-21 裁决要做）：任务的工作目录是列出的某个文件夹，或在它里面时，
  改走指定的模式。`~/work/acme` 包含 `~/work/acme/web`，不包含 `~/work/acme-old`；macOS 与 Windows 不分大小写。
  远程来源只看任务实际运行的那台电脑上的路径。指向的模式失效时的处理与时段例外相同。
- **某个时段暂停一个来源**（暂缓，2026-11-24 用户裁决；11-21 裁决要做）：时段（可加星期）内这个来源既不被选中，也不当备用，
  撞配额时也不提议换到它；时段一过自动恢复。已经在用它的任务不被打断。模式里的来源全被暂停时按 §4「没有能用的来源」处理。

新建目标没有附件，图片例外不生效；「试一下」不带消息内容和工作目录，只看时段、星期与暂停。

### 3.3 组里套组（暂缓，2026-11-24 用户裁决；11-21 裁决要做）

- 模式的成员可以是另一个模式，在列表里占一个位置。外层按自己的选法把内层当一个成员排：用内层此刻会先选的那个来源
  去比较；轮到内层时，由内层按它自己的选法、例外和推理强度在自己的来源里挑。内层全都用不了，外层接着往下。
- 同一个来源在外层和内层都出现时，只在第一次出现的位置算。
- 不能套成环（直接或经过别的模式绕回自己），保存时拒绝，添加成员的列表里也不列会成环的模式；最多套 8 层。
- 删除一个被别的模式套用的模式时，确认框列出受影响的模式，确认后从它们里面去掉。
- 推理强度：最终选中的来源用最内层那个模式的设定；它没有指定时逐层往外找。
- 时段与文件夹例外改走的目标也可以是套了别的模式的模式，防环规则共用。

### 3.5 按供应商合并的路由（2026-11-24 用户裁决，已实现）

把几个供应商整个合成一条路由，用起来像一个合并后的供应商：照常选模型、思考深度与 Fast，由路由按选法决定这次用哪个成员。
多个订阅、组织连接、朋友分享来的同一家供应商，过去各占一格、要用户自己挑，现在合成一格。

- **成员**：一整个供应商（它提供的全部模型），可以在本机、自己的其他电脑或别人分享来的；不同的人分享来的同一家各算一个成员。
  同一家有两个以上连接（至少一个此刻能用）时自动合成一条（`auto:<家族>`）：成员跟着连接增减；断开或暂停的连接仍是成员、只是此刻
  不展开它的模型，路由不因一个连接断开就消失，已选这条路由的任务与设置照样解析到剩下的来源、由它接替（2026-11-26 review）。用户不能加减成员，但能调先后、填权重、停用某个成员、
  改选法、关掉「出问题时自动换来源」或隐藏整条；用户排的先后与权重单独记着（`autoSources`），之后新连上的成员排在后面。
  同一份配额只算一个成员（2026-11-27 用户反馈）：自己电脑上的一个连接，账号全都已经在另一个成员里（例如本机账号池有 A、B，
  另一台电脑只登着 A）、模型那个成员也都有时，不自动合进来；账号与模型都相同时留排在前面的（本机优先）。账号只部分重叠的都留；
  分享来的读不到账号身份，不参与。
  用户也可以自己建，成员随意加减。转接多家厂商的付费入口不自动合进去。
- **展开**：在每个模型上展开成一条普通路由（成员里提供这个模型的那些来源；不同写法的同一个模型合成一条），由这台电脑按目录生成、
  不存盘。选路、任务里的说明、撞配额与出问题时换来源都走普通路由已有的那一套，不另写。思考深度与 Fast 用用户在模型行上选的，
  选中的成员不支持时不带。
- **在选择器里**：列成一个普通供应商，排在「智能路由」那一格后面、普通供应商前面，品牌图形右上角带路由角标，名字写
  「Anthropic · 路由（2 个来源）」；成员不再单列。隐藏这条路由后成员恢复单列（想指定只用某一个成员时这样做）。
  新任务、伙伴、定时任务、协同 Worker 选其中的模型：记下一个真实成员的模型，再记下由哪条路由决定成员；输入框下方与模型按钮的说明写
  「这次用哪个来源由路由决定」，不写某个成员所在的电脑。进行中的任务选其中的模型：按这条路由在任务所在的运行位置挑成员换过去，
  不先换到某个成员（§6）。
- **在设置里**：路由列表与「现在怎么走」分成「按模型」「按供应商」两段；合并整个供应商的路由成员一个供应商一格，不按展开出的模型逐个画。
- **跨设备**（2026-11-27 用户裁决，已实现）：控制端（手机与远程控制）在 `model-groups:get` 中显式声明 `{ includeSourceRoutes: true }` 时，被控端下发经净化后的 `sourceRoutes` 与 `expandedRoutes`（仅含同账号目录级标识，不含凭证），控制端选择器与桌面端一致合并展示品牌路由分组；不带该参数的旧控制端仍只收到不含它们的配置，保持向下兼容。

### 3.4 自动路由（待实现，2026-11-24 用户裁决，取代 11-21 的「自动组」）

让没建过模式的用户也一直有模型可用：Cindy 内置一个模式，名字叫「自动路由」，说明写「按可用情况自动选模型，出问题自动换」。

- **在哪**：模型选择器最上面一行，和具体模型并列，不藏在「模型组」那一格里；不需要用户先建过模式。
  对端是不认识它的旧版本时不列，与模式相同。
- **成员自动维护**，每台电脑按自己能用的来源算，用户不用配置：
  1. 首选模型：开启自动路由时任务正在用的那个模型；设置里可以改。
  2. 首选模型的其他来源（别的账号、别的供应商、另一台电脑或分享来的）：换过去还是同一个模型。模型按目录里的模型身份归一，
     不同供应商的写法（带不带厂商前缀）视为同一个；认不出是同一个模型的不合并，不靠名字猜。同一模型的几个来源之间按「快作废的先用」。
  3. 最近 30 天用过、现在能用的其他模型，按最近使用排在后面，最多 5 个。
  来源连上、断开、停用时成员跟着增减。
- **接替**：按 §4。在同一模型的来源之间换不打扰用户；换成另一个模型时照 §4.6 在那一轮下面写明换成了什么。
- **设置**：设置里能看到自动路由的成员与顺序，可以调顺序、去掉某个模型（记下不再自动加回）、改首选模型；不能手动加任意来源，
  想完全自己定就「复制成自己的模式」，复制出的模式与自动路由无关。用户建的模式照旧，与自动路由分开列。
- **出问题时一键开启**：没用自动路由也没用模式的任务遇到 §4.1「换来源」一类报错、而自动路由此刻能选出别的来源时，
  错误横幅写明原因并给两个按钮：「开启自动路由」与「只换这一次」。
  - 开启自动路由：这个任务改用自动路由并马上按 §4 接替；之后的新任务默认也用自动路由（用户随时可以在选择器里改回具体模型）。
  - 只换这一次：这个任务换到自动路由此刻会选的来源继续，不改任何默认。
  - 都不点：与现状相同。
- 跨设备：成员每台电脑各自算，不同步；是否开启、去掉了哪些模型、首选模型随 §8 的同步带到别的电脑。

## 4. 用不了时：接替（2026-11-24 用户裁决）

目标：任务或伙伴选了模式，**只要组里还有一个来源能用，就一直有模型可用**。模式是任务的长期设定，不是开任务时挑一次：
任务每一轮派发前、每次出错后都按模式判断，当前来源能用就留在它上面（保住提示缓存），用不了才换。

### 4.1 报错怎么分

和供应商有关的报错按「原地再试、换个账号、换个来源能不能解决」分开，各交给对的那一层。Cindy 已有的各层接力保留，模型组只接管「换来源」：

| 类别 | 典型报错 | 由谁处理 |
| --- | --- | --- |
| **原地再试** | 网络断、流中途断、过载（529 / `upstream-overload`）、5xx、空响应、卡住没响应、短暂限流（带 1 分钟内的 Retry-After） | 引擎自己的重试、本地网关重试、中断后自动续跑，都在同一个来源上。同一来源**连续两次**原地续跑仍失败，转为来源问题 |
| **换账号** | 一个订阅账号的 5 小时 / 周额度满、一个账号登录失效，而同一供应商里还有别的账号 | 订阅账号池换号、供应商组换电脑（[账号池](subscription-account-pools.md)、[供应商组](provider-groups.md)），模型组不插手 |
| **换来源** | 欠费（402 / 余额不足）、整个来源登录失效或无权限、模型下架或无权使用、来源被断开 / 停用 / 隐藏、另一台电脑离线或路由丢失、引擎启动失败、账号池里所有账号都满或都不可用、原地再试的次数用完 | **模型组立刻换到组里下一个能用的来源，并把这一轮重发**；不等续跑的退避 |
| 换了也没用 | 上下文超长、输出超限、请求参数错（400 / 413 / 422）、内容被拦、用户拒绝、工具循环 | 照现状：压缩上下文或报错，不换来源 |

认不出类别的报错按「原地再试」处理，原地次数用完再换来源；不把认不出的报错直接当成换了也没用。

### 4.2 换到谁

- 按任务记下的模式重新看一遍候选（当下的时段例外照常生效），按模式自己的选法挑。
- 跳过正在用的这个；**换来源**一类的报错再跳过与它同一个供应商连接的所有候选（同一账号、同一份额度，同一个登录），
  只有「单个模型下架或无权使用」时同连接的其他模型仍可接替。
- 已知用不了的不选：断开、停用、隐藏、不可选、额度已用完（窗口显示用满且还没到重置时刻）、所在电脑离线、
  这一轮已经试过失败的。
- 优先同一引擎的来源；没有才跨引擎，跨引擎走任务原有的交接流程（与选择器换模型同一条路径），并保存新选择。
- 只在任务所在的运行位置里挑：本机任务只换到本机来源；Agent 在另一台电脑的任务由那台电脑按它自己的模式接替。
- 一轮最多换到组里每个来源各一次，不回环（A → B → A）。

### 4.3 都用不了时

- 组里所有来源都撞了额度：任务照常停在错误上，按最早恢复的那个排「将于 X 自动继续」，到点由
  [撞限额后的等待与自动继续](usage-limit-auto-continue.md)接手，继续时再按模式选一次（可能已经有别的来源先恢复）。
- 组里所有来源都因别的原因用不了：报错，横幅写明「模式「X」里的来源都用不了」并列出各自的原因；用户重试时再按模式选一次。
- 选中的模式已被删除：沿用任务当前的模型，不再接替。

### 4.4 发送前也按同一套判断（2026-11-27 全面升级为持续托管，已实现）

已知用不了的来源不先发一次再失败：

- **新任务**：第一条消息发出前按模式选（§3、§6）。底层模型的目录没就绪、没有已连接来源、被隐藏，都不挡住选了模式的草稿
  （手机与电脑一致）。
- **进行中的任务（持续托管）**：绑定智能路由的任务在每一轮派发前都执行无阻塞评估（`turnRouting.ts` / `applyTurnRouting.ts`）：
  1. 当前来源已断开、停用、隐藏、额度已知用满或所在电脑离线时，发前自动切换到路由内下一个可用来源（优先同引擎；必要时走跨引擎或跨位置交接，包括本机 ↔ 供应商分享 ↔ 其他电脑）。
  2. 本轮消息包含图片且当前来源不支持看图、而路由内存在支持视觉的可用来源时，发前自动切到视觉来源，并在之后留在该来源上不来回震荡。
  3. 当前来源的供应商提示缓存尚在有效期内（默认 5 分钟）时保留当前来源以保护缓存命中率；缓存窗口过期后按路由策略重新评估。
- **启动失败**：引擎起不来、启动时被拒（登录失效、欠费、模型被停用、账号池没有可用账号），按「换来源」一类换下一个再启动。
- **显式解除托管**：进行中的任务在模型按钮与选择器内清晰展示当前托管路由名称，支持一键「解除托管」（保留当前具体模型、不再自动切换）；手动选择具体模型同样退出托管。
- 「试一下」照旧只看选路，不发消息。

### 4.5 默认开着

- 每个模式各自一个开关「出问题时自动换来源」，在模式详情里，**默认开**（2026-11-24 用户裁决：几个模式可以单独不接替）。
  任务按它记下的那个模式的开关（时段例外改走了别的模式也看原来选的那个）；只在用户关掉时存下（模式里的 `autoSwitch: false`）。
  经模式选了来源的任务、定时任务与自动化、伙伴都按这个开关接替。自动路由（§3.4）同样有这个开关，默认开。
- 「任务模型自动降级」开关只管没经过模型组的普通任务（默认关，规则见[任务运行时控制](session-runtime-control.md)），
  不影响用了模式的任务；用户关掉「中断后自动续跑」也不影响用了模式的任务的原地重试与换来源。
- 关掉某个模式的「出问题时自动换来源」后，用这个模式的任务不再自动换，只在横幅里提议（§6.1）。
- 用户在任务里手动选了一个具体模型，就退出模式，之后按那个模型运行、不再接替；再选模式即重新加入。

### 4.6 让用户看得见

每次接替都在那一轮下面写一行：从哪个来源换到哪个、因为什么（报错的类别与原文摘要），与 §5 的说明卡同一形态，手机端同样显示。
换来源是自动动作，不算用户发送，也不弹确认。

### 4.7 覆盖范围（2026-11-27 用户裁决全面打通，已实现）

除 review 锁定任务外，所有任务类型均统一接入智能路由持续托管与故障接替：普通任务、定时任务与自动化、目标（/goal）任务、协同模式（Lead 与 Worker）、伙伴对话、远程 Agent 任务、共享中的任务（在宿主上下文下以 owner 权执行，不向访客暴露宿主私密信息）、SSH 任务（候选自动过滤为仅该 SSH 主机可运行的来源）、IM / Hook / 插件任务以及 Node Host 无界面服务。

### 推理强度

模式可以指定推理强度，也可以「不指定」。用的是最后实际走的那个模式的：时段例外改走了另一个模式时，按那条
模式的推理强度（它没有指定就不带）。选中的模型不支持这一档时同样不带，按该模型的默认档运行。

## 5. 让用户看得见

- 第一条消息下方写一行：哪个模型组为这个任务选了哪个模型、哪个来源、为什么；例外起了作用（改走了哪条
  模式、只在能看图的来源里选、有图片但没有能看图的来源）时写在原因前面；沿用了原来的模型时也写明。
  这行复用「让插件选」的说明卡，手机端同样显示。
- 设置里每个模式有「试一下」：列出每个来源会被选中、备用还是跳过及原因；不发消息、不推进轮流的顺序。

## 6. 范围与现状

- 本机开的新任务（普通发送与新建目标）：选中一个模式，第一条消息发出前按它的规则选一个来源。草稿本身是远程控制
  别的电脑时，现状不提供，2026-11-21 用户裁决要提供（§6.3）；SSH 草稿仍不提供。桌面和手机新建协同 Lead 时也能选模式（§6.3）。草稿此刻选着在另一台电脑运行的模型时照样提供：选了模式就由模式决定这次在哪台
  运行（§3.1），这一点与「让插件选」不同。选了模式（或「让插件选」）时一律先选路再检查：输入框不按草稿底层模型禁用
  发送——底层模型在本机没有已连接来源、或草稿那台电脑的模型目录没读好，都不挡住模式；只有模式里都用不了、沿用原模型时，
  发送才检查原模型（目录已就绪、有已连接来源，否则提示先连接来源，输入保留）。入口：`ChatInput.tsx` 的
  `sendRoutesOwnModel`、`NewMakerDraftRoute.tsx` 的 `handleSend` 与 `handleCreateGoal` 选路之后。
- 进行中的任务（2026-11-13 确立，2026-11-27 升级为持续托管）：选择器里同样列出智能路由与按供应商合并路由。选一个路由会按其规则挑出可用来源，走同一换模型/跨引擎/跨位置交接路径，并把该任务持续绑定到这条路由：后续每轮发前评估（§4.4）与出错接替（§4.1–§4.2）自动生效，直到用户一键「解除托管」或手动改选具体模型。普通任务、远程控制、手机端、SSH（自动过滤为目标 SSH 主机可用来源）、伙伴对话（支持任务中换模型/路由）均已打通；只读查看或 review 锁定任务不提供。
- 选择器里的位置（2026-11-13 用户裁决）：左侧「模型组」一格；「全部」最上方整段列出所有模式（搜索时只列命中的）；
  每个模式行尾有 ☆，收藏的模式出现在「收藏」最上方。模式的收藏只记模式 id，按账号存在这台电脑，现状不跨设备同步
  （模式本身也只在这台电脑），不进模型收藏的同步协议；模式删除后收藏自动不再显示。§8 的同步做好后，收藏随模式一起同步。
- 出错与用不了时的接替见 §4（2026-11-24 用户裁决，取代 11-21「经模型组开的任务默认自动降级」与 11-23 的现状描述）。
  现状（2026-11-26 核对）：本机普通任务与定时任务、自动化建的任务出错后按 §4.1 分类、§4.2 换到谁接替，按模式自己的
  「出问题时自动换来源」开关，不看「任务模型自动降级」；自动接替先在同一引擎的来源里挑；「这一轮已经试过的」从下一条消息
  （用户发的或自动化发来的，自动续跑那条不算）起重新算；选路本身出错时按存下的具体模型建任务，不挡住建任务。
  还没做的：§4.4 的发送前判断与启动失败立即换（现在是发出、失败后再换），§4.3 横幅列出各来源原因，§4.7 列出的任务。
  原模型恢复不会打断正在工作的候选，用户可以在任务选择器中切回。
- 从新建页发送时，在首条消息派发前登记本机任务所用的模型组，使首轮故障也能接替。首条消息被接受后才提交本次选路历史。
- 伙伴可以用模型组（2026-11-20 用户裁决，见 §6.2），本机、远程控制它的电脑与手机都能选。其余选择器的接入见 §6.3。
  辅助模型、Subagent 与伙伴的模型也能选路由，设置都在智能路由页里（§6.4，2026-11-26 用户裁决）。
- 配置按账号保存在本机（`model-groups.json`），只存用户建的内容。现状不随新电脑迁移（供应商连接 ID 各台不同）；
  2026-11-21 用户裁决要跨设备同步，取代 11-11 写入的「不随新电脑迁移」，规则见 §8。

### 6.1 撞配额时提议换来源继续

任务所用模式的「出问题时自动换来源」被关掉（§4.5）时，这个任务撞上 §4.1「换来源」一类的报错，原有的报错、「将于 X 自动继续 · 取消」、
到点自动继续、重试都照旧；如果同一个模式里还有别的来源现在能用，错误横幅里多一个「换到 {模型 · 来源} 继续」
（2026-11-11 用户裁决；2026-11-24 起不只撞配额，§4.1「换来源」一类都提议）。默认开着自动接替时不需要这个提议。

- **关掉「出问题时自动换来源」时**：没有计时、没有重试循环；用户不点，一切与没有模型组时相同。
- 点了 = 用户在这个任务的模型选择器里点中那一行，再点横幅原有的「重试」：同一引擎走普通的换模型路径；
  换到另一个引擎登记切换意图，发送重试消息时生效（2026-11-18 用户裁决）。换模型本身按
  [撞限额后的等待与自动继续](usage-limit-auto-continue.md)算用户接手，撤销等待。横幅没有重试入口时不提议。
- 提议谁：按任务建立时记下的模式（当下的时段例外照常生效）重新看一遍候选，跳过正在用的这个，
  以及与它**同一个供应商连接**的所有候选（同一账号、同一份配额），跳过运行位置与任务现在不同的（只提议本机的来源：
  把运行中的任务挪到另一台电脑不是这个提议做的事，也不去读那边的目录），再跳过停用的、现在不可选的、配额已用完的，
  按模式自己的选法挑一个（「轮流」从正在用的这个往后数）。不推进新任务用的「轮流」位置，也不记进「最近的选择」。
  都不行就不提议。换成了以后把记录改成新来源，之后再撞配额接着提议下一个。
- 任务此刻的模型或来源不是记下的那个（用户自己换的或别处换的），就不提议；记录保留，任务回到这个来源时照旧提议。
  跨引擎换模型时可能只登记了「下一条消息再换」，任务还在旧模型上跑，记录不能因此丢掉。
- 定时任务与自动化建的任务同样按本节提议、按自动降级接替（2026-11-22 用户裁决「模式跟着任务走，接替是所有任务公共的事」，
  已实现）；自动化发到已有任务时，任务当前来源是记下的那个才接替，自动化指定了别的模型时不换。
- 现状不提议：目标（/goal）任务、伙伴、IM 等还没接入模式选择的来源，SSH、Agent 在另一台电脑（包括经模式选到
  另一台电脑上的来源建的任务）、被控电脑上的任务，协同模式，共享中的任务。伙伴另有自己的接替（§6.2）。
  §6.3 让 IM、Hook、团队成员、插件任务和远程控制也能选模式后，这些任务按同一裁决默认同样接替（待实现）；
  Agent 在另一台电脑上的任务由那台电脑按自己的模式提议和接替。
- 记录：`owners/<账号>/model-group-session-bindings.json`，按任务 id 记组的 id 与正在用的候选（不在本机时含运行位置），最多 2000 条，
  只在本机；不含消息、任务标题、账号或凭证。

### 6.2 伙伴用模型组（2026-11-20 用户裁决）

- **在哪里选**：伙伴的模型与「伙伴默认模型」（2026-11-26 起都在智能路由页「伙伴的模型」，伙伴只用一个模型、没有备用，见
  [伙伴运行时](cindy-bots-runtime.md)「伙伴只用一个模型」），都是同一个模型选择器，「模型组」一格与
  新任务相同；选中后按钮显示组名。手动选一个普通模型即取消。模型组属于伙伴所在的那台电脑：远程控制它的电脑与
  手机（伙伴设置、新建伙伴）列出那台电脑的组，选中只记下组，
  保存时由那台电脑把具体模型换成组此刻会选的来源；
  「管理模型组」只在本机提供。那台电脑是旧版本时不列模型组。SSH 伙伴不提供。协议约定见
  [伙伴模型链里的模型组](../dev-rules/protocol-compatibility/teammate-model-groups.md)。
- **存什么**：链里的这一项存组的 id，外加选中那一刻按组的规则预览出的具体模型。组被删掉、组里来源全停用、
  旧版本客户端或伙伴搬到另一台电脑（云同步只带具体模型，不带组）时，都按这个具体模型运行。旧版本的手机或电脑
  改动并保存伙伴模型时会丢掉组、留下具体模型。
- **什么时候选**：伙伴的每条对话（主对话、群、IM 频道、话题、例行任务）在这项设置第一次用上时按组的规则选一个
  来源（与新任务同一套选法、时段例外与额度判断，套用成功后记进「最近的选择」，「轮流」随之推进）；组此刻没有能用的
  来源时按存下的具体模型。新建伙伴对话（群、频道、话题、重建主对话）先以组此刻会选的来源通过模型准入，存下的模型
  断开了也不挡住。图片例外不按「第一条消息」用于伙伴：伙伴选中的来源要沿用到之后所有消息，不应由恰好触发选路的
  那一条决定。改为按条判断（待实现，2026-11-21 用户裁决，取代 11-20 写入的「另行立项」）：组里有图片例外时，伙伴收到
  带图的消息而当前来源看不了图，就在这一条换到组里能看图的来源，之后留在它上面（与 §7.3 同一做法）；组里没有能看图的
  来源时照常发并在说明里写明。除此之外同一条对话一直用它，与伙伴的其他设置一样不会自己再换。改了伙伴的模型设置，或改了
  它用到的组（来源、选法、例外、推理强度，以及时段例外能改走到的组），下一轮重新选；别的组改了不影响它。
  时段例外在选的那一刻生效，不会到点自己切换。
- **出错时**：伙伴的故障接替本来就按链走、不看「任务模型自动降级」开关。这一项展开成：此刻生效的组（时段例外
  改走的那条）没停用的来源、原组没停用的来源、时段例外能改走到的其他组的来源（选的时候可能还在另一个时段）、
  存下的具体模型，依次去重。当前来源失败后先换这一段里的下一个，
  到末尾再绕回前面的，都试过即止（伙伴没有备用模型）。组内来源可以在另一台电脑，沿用伙伴链已有的运行位置路径。
- 设置页里选中组立刻记下（紧接着保存或新建伙伴都带上组，暂以原来的模型作存下的具体模型），再预览一次把组此刻会选的
  来源（连同组的推理强度，不沿用原模型的档位）换进来；预览回来时这一项已不是「这个组 + 原来的模型」（又选了普通模型，
  哪怕是同一个，或又选了别的组）就作废。预览补全存下的模型算同一次选择：伙伴只按组的规则选一次，不因补全再选、再记一次。
  链还是空的（「请先选择模型」页）时，由预览直接建出第一项。组此刻用不了（预览失败）时这一项退回选之前的状态，原来选的组不丢。
  组此刻一个能用的来源都没有时提示一句并取消这次选择。
- 实现：`main/model-groups/botRoutes.ts`（展开）、`desktopResolver.ts` 的 `pickModelGroupRoute`、
  `maker-ipc/botModelRouteReconciler.ts` 的 `pickModelGroup`、`shared/botModelChain.ts` 的 `nextBotModelRoute`；
  界面 `renderer/features/bots/BotModelChainEditor.tsx`；回归见 `main/model-groups/__tests__/botRoutes.test.ts`、
  `maker-ipc/__tests__/botModelRouteReconciler.test.ts`。

### 6.3 所有模型选择器都能选模式（部分已实现，2026-11-21 用户裁决）

原则：凡是用户能挑模型的地方都列出「模型组」，与新任务同一套选法、例外与说明；模式属于任务实际运行的那台电脑，由那台电脑选路。

模式跟着任务走，不跟着业务走（2026-11-22 用户裁决）：Cindy 里落地的都是任务，模式是任务的一个属性，与模型平级。
开任务时按模式选第一个来源、记下这个任务经哪个模式建的、派发那一刻记账并在这条消息下面写说明、运行中撞配额或故障时接替，
都在新建任务与任务运行这一层统一做一次。各入口（定时任务、IM、Hook 偏好、团队成员、子代理……）只负责存下「用户选了哪个模式」，
建任务时原样传给新建任务，与传一个具体模型一样；入口里不写模型组专属的选路、接替或说明逻辑，模型组设置里也不出现按业务区分的配置。
连接的那台电脑是旧版本、不认识模型组时不列，与 §6.2 伙伴的做法相同。表里标「已实现」的入口已上线，其余待实现。

### 6.4 其他地方用的模型（2026-11-26 用户裁决，已实现）

Subagent、辅助模型与伙伴的模型设置都在智能路由页下方直接改，不再是跳去别处的入口；个性化里不再重复。旧的
`tab=personalization&section=…` 链接自动落到这一页的对应位置。

- **Subagent**：见 §6.3 表里「子代理模型设置」。只列自己排的、含本机 Claude Code 来源的路由；合并整个供应商的路由对它等于直接选模型，不另列。
- **辅助模型**（标题、摘要、推荐指令等系统内部的一次性请求）：三格里的每一格除了具体模型也能选一条路由，存为 `route:<路由 id>`。
  用的时候换成路由里本机、没停用的来源（辅助请求在本机直接调 API，别的电脑与分享来的来源用不了），路由此刻会选的排第一，其余依次兜底，
  再接下一格。「此刻会选的」是一次只看不选的解析（不推进轮流、不记进「最近的选择」），读链时同步给出、后台最多 30 秒更新一次，
  所以「轮流」「按权重」在辅助模型里不会逐次轮换。保存前测路由此刻会先用的那个模型；本机一个能用的成员都没有算这一格不可用。
  路由删掉后这一格显示「已删除的路由」，执行时跳过。Node Host 没有智能路由，这种设置在那里展开为空。
- **伙伴**：上面是「伙伴默认模型」，下面列出单独设置了模型的本机伙伴，可从下拉里给跟随默认的伙伴单独设一个；存下的形状与
  以前伙伴页相同（`botModelChainPatch`）。其他电脑上的伙伴按电脑各占一行，点开进入那台电脑的伙伴模型页，模型在那台电脑的目录里选。

## 7. 每轮重新选（待实现，2026-11-21 用户裁决）

### 7.1 开关与缓存

- 每个模式单独一个「每轮重新选」开关，默认关。关着时一切按 §3–§6，只在开任务时选。
- 打开时提示一句：中途换来源会让供应商的提示缓存失效，费用和首字时间都会上升。不弹确认，只提醒。
- **缓存命中率是第一位的**。默认停留「自动」：同一轮里（Agent 来回调用工具）一定不换；跨轮时，只要原来源的缓存
  还值得保留就留在原来源，只有规则命中、原来源用不了或缓存已过期时才换。「还值得保留」指距上一轮不超过那个供应商的
  缓存有效期（知道的按供应商的，不知道的按 5 分钟）。可选的停留方式：
  | 停留 | 规则 |
  | --- | --- |
  | 自动（默认） | 如上 |
  | 整个任务 | 只要原来源还能用就一直用它；只有规则命中才换 |
  | 一轮内 | 每次用户发新消息都重新选 |
- 设置页每个模式显示它最近 7 天的缓存命中率与换来源次数，让用户判断值不值得开。

### 7.2 每轮能用的规则

在 §3.2 的例外之外，打开每轮重新选的模式还可以加：

- **长度**：这一轮的上下文估算达到 N token 时，先用指定的来源。估算取请求大小与上一轮供应商实际计数的较大者。
- **按上下文大小**：作为一种选法，每轮选窗口装得下这一轮的来源里最小的那个，大窗口留给长任务；装不下的来源这一轮跳过。
- **推理档**：这一轮要求的推理强度达到某一档（或关掉推理）时，先用指定的来源。
- **意图**：用户用几个字描述一类请求（如「写测试」「简单问题」），每轮开始时由用户选的一个小模型判断这条消息属于哪一类；
  只发这条消息，不发整段对话；判断失败或超时（默认 15 秒）按没命中。这次调用记进用量，标为模型组的辅助调用。
- **压缩上下文**：Agent 压缩对话时，这次压缩用指定的来源（便宜、快的），对话本身留在原来源。

规则从上往下看，第一条命中的决定这一轮先用谁，组里其他来源排在它后面做备用；没有命中的按模式的选法与停留方式。
换来源优先在同一引擎内；需要跨引擎时走现有的交接流程（§6 进行中任务的同一条路径）。

### 7.3 带图的那一轮

- 打开每轮重新选、且模式里有图片例外时：这一轮消息带图而当前来源看不了图，这一轮换到组里能看图的来源；
  **之后留在这个能看图的来源上**，按停留方式继续，不自动换回（2026-11-21 用户裁决：只换一次，缓存只丢一次）。
- 组里没有能看图的来源时照常发，并在说明里写明。
- 只在模型组里生效：没经过模型组的普通任务保持现状，不自动换模型（2026-11-21 用户裁决）。已退役的视觉桥不恢复。

### 7.4 让用户看得见

每次换来源都在那一轮下方写一行：从哪个来源换到哪个、因为哪条规则（或原来源用不了），与 §5 的说明卡同一形态，手机端同样显示。

## 8. 跨设备同步（待实现，2026-11-21 用户裁决）
