# 模型组：把已有的来源合成路线

> **读取时机**：新增或修改模型组（路线）的配置、选路、选择器入口、任务里的说明，
> 或要让模型组在新任务以外的地方生效之前

## 1. 定位

用户在「模型供应商」里已经连接了多个来源（多个订阅账号、API 密钥、不同供应商），希望开任务时不必
自己挑：快作废的订阅额度先用掉，一个用不了时换下一个。

模型组只做加法（2026-11-11 用户裁决）：

- 「模型供应商」页原样保留，来源仍在那里连接和管理。模型组是设置里单独的一页，只引用已连接的模型。
- 选模型时左侧栏在「全部」之后多一格「模型组」，其余格与列表不变。
- 模型组只回答「这次用哪个已连接的模型」。来源可以是本机的，也可以是其他电脑上的或别人分享来的供应商
  （2026-11-11 用户要求）：来源连同运行位置一起存，选中它的新任务就在那里运行 Agent，规则见 §3.1。
  组内电脑怎么分、用哪个账号，仍由[供应商组](provider-groups.md)与订阅账号池各自决定；模型组不保存凭证，
  也不改变它们与[供应商分享](provider-sharing.md)的授权规则。

## 2. 术语

- **模型组**：用户建的路线的统称，也是设置页与选择器那一格的名字。
- **路线**：一个名字下的几个来源（引擎 + 供应商连接 + 模型）、一种选法，以及可选的推理强度。
- **来源**：模型供应商里一个已连接的模型，连同它的运行位置（本机、另一台电脑或分享来的）。同一条路线可以放不同的
  模型；同一个模型在两台电脑上是两个来源。

用户只需要理解一个概念：2026-11-11 起原来的「模式」（一条路线或一个模型加推理强度）并入路线，推理强度成为
路线自己的选项——一个概念比两个好懂；按角色分工（不同工作用不同路线）暂缓。旧版存下的模式、选中的模式、
经模式建的任务记录与「最近的选择」读取时忽略，不报错，也不需要用户处理。

「供应商组」选电脑，「模型组」选来源，两者不是一回事。术语登记见 `i18n/glossary.json`
（`model-group`，`proposed`；路线的用法写在它的说明里）。

## 3. 选法

新任务第一条消息发出前选一次，选出的模型只用于这次新建，不改草稿里用户原来选的模型。

候选先过滤：用户在路线里停用的、供应商没有连接或模型现在不可为新任务选用的、对应引擎没有安装的、
运行位置现在用不了的（§3.1），都跳过。
然后把订阅配额已用完的放到最后，在剩下的里按路线的选法挑：

| 选法 | 规则 |
| --- | --- |
| 快作废的先用（默认） | 与供应商组同一把尺子：剩下的配额 ÷ 剩下的时间，最急的先用；5 小时配额快满、离重置还早的先避开；读不到配额的来源排在读得到的后面；一样急时按列表顺序 |
| 按顺序 | 列表里第一个能用的 |
| 轮流 | 上一次选中的下一个；只在内存里记，重启后从第一个开始 |
| 最省钱 | 还有配额的订阅不另外花钱，排在最前；其余按该来源这个模型的标价（每百万输出 token，人民币按固定汇率折成美元）从低到高；没有标价的排在有标价的后面，订阅的「价值估算」不算标价；一样便宜时按列表顺序；谁都没有标价时只取第一个，说明里不写「最省钱」 |

配额取自额度总览已有的订阅窗口，不发模型请求。读不到时按未知处理，不当作没用过。另一台电脑上的来源只用
总览里那台电脑、那个连接自己的窗口；本机同 ID 连接的额度不给它用。
排序复用 `provider-group/scheduler.ts` 与 `usage.ts`，不另写一套。标价与模型选择器显示的价格同一来源
（Cindy AI 取网关报价并以目录折后价为准，其余取注册表参考价、连接自带价与用户自定价），经
`getModelPriceQuote` 查询。

### 3.1 其他电脑与分享来的来源

- 设置里「添加来源」与其它模型选择器一样列出其他电脑与分享来的供应商（[统一模型选择器](model-selector-unified.md)），
  选中哪一行，来源就记下那一行的运行位置；旧数据没有位置，照常按本机。路线、总览、「试一下」、任务里的说明与
  「最近的选择」都写「供应商 · 那台电脑」，与模型选择器里远程那几行同一写法。
- 能不能用与插件卡片里的远程模型同一判断（`isGhostCardModelRouteAvailable`）：那个位置现在能选（同账号在线、开了
  远程控制的电脑，或未暂停的分享），模型也在那里允许远程调用的目录里；引擎是否就绪问那台电脑自己的引擎状态（与插件选路同一判断，读不到时按就绪），不看本机装没装：目录里列着模型不代表那台装了对应引擎。
  电脑离线、分享被撤销或暂停、读目录失败（包括只拿到上次留下的旧目录）或超过 2 秒（与等额度同一上限）都算这个来源用不了，按选法换下一个；
  全都用不了沿用原来的模型。路线里没有这种来源时不去读别处。不借本机同名供应商顶替。
- 配额：总览里有那台电脑这个连接的订阅窗口就用；那台此刻读不到只剩上次读数的、与本机是同一个账号而总览只列了本机那份的、
  以及分享来的来源，都按读不到额度处理，排在读得到的后面。
- 「最省钱」：只看那个位置目录里这个模型自带的价格，没有就按没有标价排在后面。
- 选中后新任务（普通发送与新建目标）带着运行位置建立，与「让插件选」选到远程模型同一条路径；任务记录、
  「最近的选择」与撞配额用的记录都带运行位置。

暂不提供「最快」：本机没有按来源累积的实测速度（每轮的 TPS 只挂在那一轮的用量详情上，连接测试的延迟
是一次性的），不拿名字或档位去猜。

### 例外

每条路线可以加最多 8 条例外，在按选法挑之前先看，按列表顺序：

- **消息里有图片时，只用能看图的来源**：第一条消息带图片时，看不了图的来源跳过（试一下里写明）。
  能不能看图与设置里模型的「能看图」开关同一判断（用户改过按用户的，否则按目录，再按模型名推断，
  读不到按不能）。一个能看图的来源都没有时照常选，并在说明里写明。每条路线最多一条。
- **某个时段改走另一条路线**：本机时间落在 [开始, 结束) 的整点时段里（结束早于开始即跨午夜）时，
  改走指定的路线，按那条路线自己的选法和例外选。时间由主进程自己取，不用界面传来的。指向的路线
  已删除或绕回走过的路线时，整条改道作废，按原路线照常选。删除路线时，别的路线里指向它的时段例外一并去掉。

新建目标没有附件，图片例外不生效；「试一下」不带消息内容，也只看时段例外。

## 4. 用不了时

- 能用的来源都撞了配额上限：选最早恢复的那个，任务照常建立，之后由
  [撞限额后的等待与自动继续](usage-limit-auto-continue.md)接手。
- 路线里没有任何能用的来源，或选中的路线已被删除：沿用用户原来选的模型。

### 推理强度

路线可以指定推理强度，也可以「不指定」。用的是最后实际走的那条路线的：时段例外改走了另一条路线时，按那条
路线的推理强度（它没有指定就不带）。选中的模型不支持这一档时同样不带，按该模型的默认档运行。

## 5. 让用户看得见

- 第一条消息下方写一行：哪个模型组为这个任务选了哪个模型、哪个来源、为什么；例外起了作用（改走了哪条
  路线、只在能看图的来源里选、有图片但没有能看图的来源）时写在原因前面；沿用了原来的模型时也写明。
  这行复用「让插件选」的说明卡，手机端同样显示。
- 设置里每条路线有「试一下」：列出每个来源会被选中、备用还是跳过及原因；不发消息、不推进轮流的顺序。

## 6. 范围与现状

- 只用于本机开的新任务（普通发送与新建目标）。草稿本身是远程控制别的电脑、SSH、协同模式时不提供。草稿此刻选着
  在另一台电脑运行的模型时照样提供：选了路线就由路线决定这次在哪台运行（§3.1），这一点与「让插件选」不同。
  这时先选路再检查：那台电脑的模型目录没读好不挡住路线；只有路线里都用不了、沿用原模型时，才要求那台的目录已就绪。
- 任务开始后模型组不会自己换来源；撞上配额时只**提议**换到同一条路线里的下一个来源，用户点了才换（见 §6.1）。
- 伙伴、定时与自动化、子代理、辅助模型暂不经过模型组；要接入时先在这里补规则。
- 配置按账号保存在本机（`model-groups.json`），只存用户建的内容；不随新电脑迁移（供应商连接 ID 各台不同）。

### 6.1 撞配额时提议换来源继续

经路线建的任务撞上账号配额时，原有的报错、「将于 X 自动继续 · 取消」、到点自动继续、重试都照旧；
如果同一条路线里还有别的来源现在能用，错误横幅里多一个「换到 {模型 · 来源} 继续」（2026-11-11 用户裁决）。

- **从不自动换**：没有计时、没有重试循环；用户不点，一切与没有模型组时相同。
- 点了 = 用户在这个任务的模型选择器里点中那一行，再点横幅原有的「重试」：同一引擎走普通的换模型路径；
  换到另一个引擎走原有的切换引擎路径，**照常弹出切换确认**，取消了就什么都不做。换模型本身按
  [撞限额后的等待与自动继续](usage-limit-auto-continue.md)算用户接手，撤销等待。横幅没有重试入口时不提议。
- 提议谁：按任务建立时记下的路线（当下的时段例外照常生效）重新看一遍候选，跳过正在用的这个，
  以及与它**同一个供应商连接**的所有候选（同一账号、同一份配额），跳过运行位置与任务现在不同的（只提议本机的来源：
  把运行中的任务挪到另一台电脑不是这个提议做的事，也不去读那边的目录），再跳过停用的、现在不可选的、配额已用完的，
  按路线自己的选法挑一个（「轮流」从正在用的这个往后数）。不推进新任务用的「轮流」位置，也不记进「最近的选择」。
  都不行就不提议。换成了以后把记录改成新来源，之后再撞配额接着提议下一个。
- 任务的模型或来源已被换过（用户自己换的或别处换的），这个任务就不再按模型组提议，记录随之删除。
- 不提议：目标（/goal）任务、定时与自动化、伙伴、IM 等非本机直接开的任务，SSH、Agent 在另一台电脑（包括经路线选到
  另一台电脑上的来源建的任务）、被控电脑上的任务，协同模式，共享中的任务。
- 记录：`owners/<账号>/model-group-session-bindings.json`，按任务 id 记组的 id 与正在用的候选（不在本机时含运行位置），最多 2000 条，
  只在本机；不含消息、任务标题、账号或凭证。
