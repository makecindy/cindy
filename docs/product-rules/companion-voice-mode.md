# 桌面伙伴语音模式

## 范围与行为

- 入口位于本机伙伴的一对一对话标题栏。沿用伙伴 canonical 任务、模型、上下文、工作目录和工具权限，不创建第二条任务或切换聊天模型。
- 用户明确点击开始后采集麦克风。使用现有语音输入的 ASR 设置和当前账号的服务模式；不启用听写润色，不修改原有听写行为。
- 停顿约 900ms 后等待 ASR 的最终文字，再用短暂的稳定窗口合并同一段发言。只有最终、非空文字能自动发送；声音活动检测本身不能产生消息。
- 原任务空闲时正常发送，仍在运行时沿既有插话路径投递。语音是本机用户本人输入，不盖自动化或远程设备来源标签，不增加系统提示词。识别结果按普通文字发送，不执行桌面斜杠命令。
- 最终回复经过持久化完成标记确认后才朗读。按本次语音发送的 clientId 关联，不朗读历史、过程文字、工具、子代理、内部协调或群来源私信。文本消息始终是对话记录的正本。
- 独立选择朗读模型和音色。只展示当前账号可用、未停用的 Cindy AI `audio_speech` 模型；账号无模型时显示空状态，不能开始。刷新复用现有 Cindy AI 目录刷新。
- 朗读结束继续监听。用户开口时立即取消待生成及正在播放的声音；新的文字仍投递到原任务。停止朗读不会取消 Agent 工具、清空任务队列或代答权限确认。
- 需要确认权限、问题或计划，或任务队列暂停时，关闭麦克风并暂停语音模式；用户完成确认后显式继续。静音、锁屏、休眠、切走任务、关面板、账号切换同样释放采集和播放资源，不在后台重新开始。
- 未发送的文字在可恢复错误或暂停后留在面板内；用户可选中复制或明确重新连接并发送。TTS 失败保留任务中的文字回复，不自动重发用户消息。

## 交互与动效

面板保留伙伴头像和姓名，持续显示连接、监听、思考、准备语音、朗读或暂停状态。音量条反映实际输入或输出音量，没有循环伪造的声波。进入动效和音量条只变换 opacity/transform，使用现有 motion token，并支持减少动态效果。模型和音色可在开始前或暂停后更换；进行中的结束、静音及面板关闭按钮不随内容滚走，暂停后可继续或关闭。面板最多占视口高度的 65%，中间内容独立滚动。Light/Dark 使用语义颜色。

设计依据为 `DESIGN.md` §4 标准控件、§5 圆角分层、§14.4 动效与 `design-governance.md` §13 点击层分类：标题栏语音入口是 32px 的普通动作按钮，沿用同栏的 pill；面板和未发送文字框属于容器，使用 12px 圆角；音量条是无交互的指示层，不是按钮。设置、开始、静音、结束等操作复用现有 Button / Select / Input。

## 执行边界

- 当前仅支持 Desktop、本机伙伴一对一。群聊、Mobile、远程控制的麦克风、原生 Realtime speech-to-speech 不在此实现内。
- 新 IPC 只接受可信应用顶层 Renderer，按窗口、账号代次、callId 和 canonical 任务绑定。callId 在发起请求前生成，使结束按钮也能取消连接过程；它不是授权凭证。接口不加入 device-link 或插件白名单。模型权限在开始和每次 TTS 请求、读取时复核。
- ASR 适配器额外提供按上游 utterance/item ID 标识的分段事件，现有累积 `AsrEvent` 合同保持不变。连接在 150 秒轮换，沿用 voice-server 的 dictation 协议；切换期间最多缓存 5 秒输入，不能无声丢弃或重复发送前文。
- Gateway 执行合同为 OpenAI 兼容 `POST <下发的 baseUrl>/audio/speech`，body 包含 `model`、`voice`、`input`、`response_format: pcm`。PCM 固定为该协议规定的 24kHz、单声道、16bit little-endian。显式声明其他 native API 或 `null` 未验证 API 的模型不进入选择器；未声明协议的 Gateway 新模型沿用此端点合同。下发 `mode` 只代表能力分类，不证明具体音色、音频格式或端点可用。
- 凭证只在 Main，使用当前账号配对的 Gateway baseUrl 和密钥；不自动改走 BYOK 或系统朗读。响应按 Renderer 播放速度读取，播放只预排约 300ms；中断丢弃旧请求和迟到音频。原始音频只在内存，不新增录音文件或对话音频归档。
- 初始实现的声音活动判断是带迟滞的音量检测，配合浏览器回声消除与降噪。它不是语义 VAD，不能保证所有扬声器、蓝牙或噪声环境都能准确分辨插话。

## 验证

自动化覆盖分段去重、乱序完成、空转写、连接轮换、权限与账号边界、取消启动、插话抢占、迟到音频、PCM 字节边界、回复关联、无模型空状态及现有 ASR 回归。

Gateway 尚未给测试账号开放真实 TTS 模型时，自动化使用明确的测试替身；产品目录不添加演示模型。真实模型开放后，还需验证其音色和 PCM 合同，并在 macOS/Windows 的耳机、扬声器、蓝牙设备上验证连续多轮、回声与插话延迟。测试替身不构成这些项目已通过的证据。
