# 开始引导：首次登录后的综合引导

> **读取时机**：修改开始引导的出现条件、步骤与顺序、各步骤复用的能力、旧版数据迁移与引导的衔接，
> 或新增一类「首次使用时该带进来」的内容前。
> 迁移助理的范围与安全边界见 [`new-device-setup-migration.md`](new-device-setup-migration.md)，
> 区域规则见 [`region-and-editions.md`](region-and-editions.md)。

## 1. 用户心智

第一次在一台电脑上开始用 Cindy 时，由一个窗口把「该带进来的东西」和「开始前要做的事」一次引导完：
只出现与这个人有关的步骤，每一步都能跳过，窗口随时能关。引导不发明新的导入能力，每一步都复用
已有功能——它只负责发现、排好顺序、把人带过去再带回来。

## 2. 何时出现

- **触发**：本次运行中完成的登录，或进入本机模式。启动时恢复的登录状态不算，升级不会触发。
  触发约 6 秒后由 Main 判定；旧版数据迁移（见 §4）正在确认、复制或显示失败时，等它结束再判定。
- **条件**：这台电脑看起来是新电脑（没有用户自己装的插件、自定义供应商和自定义 MCP），或者本次
  登录刚把旧版本的数据带过来。
- **只出现一次**：每个账号在每台电脑上自动出现至多一次，Main 在决定显示时即记录（沿用迁移助理
  状态文件的 `suggestionDismissed`，旧版本点过「以后再说」或完成过一次迁移的账号不再出现）。
- **重新打开**：设置 → 通用 →「开始引导」。手动打开时提供全部步骤，不看检测结果。
- **不处理的情况**：同账号的其他电脑当时读不到（离线、未开启「允许同账号设备控制本机」、版本
  过旧）时，不提供迁移这一步，之后也不再补判；用户可随时从设置打开迁移助理。

## 3. 步骤

Main 的判定给出两条路；界面再按本机检测结果去掉无事可做的步骤。步骤在窗口打开、检测返回后定下，
之后不再变动。

| 步骤 | 何时出现 | 复用的能力 |
|---|---|---|
| 旧版数据 | 本次登录刚迁移过旧版本数据 | 只说明已带过来的内容；迁移本身见 §4 |
| 认识 Cindy | 新用户（没有可迁移的电脑，也没有旧版数据） | 欢迎页：品牌标识、一句定位和三点说明，不做多页轮播 |
| 从旧电脑迁移 | 同账号另一台电脑有值得迁移的内容（判据见迁移助理规则） | 迁移助理；仍由用户选择来源与内容 |
| 连接模型 | 新用户总是出现；老用户仅在还没有可用模型时出现 | 现有的供应商连接流程与本机订阅检测；页面内容见下 |
| 导入已有内容 | 本机其他 AI 工具里有任务，或有可导入的 Agent | 任务导入（按工具勾选，默认不勾选）；伙伴导入（OpenClaw / Hermes） |
| 完成 | 总是 | 小结已做的事，进入新建任务 |

- **老用户不再介绍产品**：有可迁移的电脑或刚迁移过旧版数据的人，跳过「认识 Cindy」，直接从迁移
  或旧版数据开始。
- **连接模型这一页说明两种方式，并写明可以一起用**（用户裁决，2026-11-11）：
  - **Cindy AI**：官方提供的模型服务，登录后自带，不需要开通，页面上不出现「开通」动作。新账号有
    免费赠送的余额，用来试用；付费后几乎所有模型都可以用，不付费时可用的模型范围会受限。
    - **显示当前余额**（用户裁决，2026-11-11）：个人账号在卡片里显示当前可用余额。余额全部来自
      赠送时，标注「免费赠送的金额，欢迎试用」；已有订阅或充值余额时，标注「可用余额」，其中有赠送
      部分的单独写出金额。不把付过费的余额说成免费。旁边给「余额与订阅」入口。
    - 余额在第一次显示这一页时读取一次（账单页同一个接口），不轮询、不重试；读取失败或账号没有
      余额（组织账号）时不显示数字，只写明可以直接使用。
    - 本机模式下给出登录入口；账号目录里没有官方服务时不显示这张卡片。
  - **用你自己的套餐**：已有 Claude、ChatGPT 等订阅或 API Key 的人，非常推荐接进来配合使用，这样
    体验最好。已经连接的供应商排在最前，和可添加的供应商用同一种行：图标、名称、「已连接」标记，
    下面一行是账号和套餐类型（与供应商设置页显示的相同，读不到时留空）。随后是本机检测到的已登录
    订阅和主推供应商，合计最多三行，其余走「其他供应商与 API Key」。

  官方服务随账号自带，所以已登录的新用户到这一页时通常已有可用模型；这一页仍然出现，用来说明官方
  服务的付费与免费范围，并推荐接上自己的套餐。两段文案是产品口径，改动须与官方服务的实际权益一致。
- **任务默认不勾选**：一次导入大量任务会塞满任务列表；用户按工具勾选，要逐个挑选时跳到
  「设置 → 任务导入」。超过任务导入既有的数量或体积阈值时，沿用它的确认。
- **技能、MCP、规则不设导入步骤**：Claude Code / Codex / Pi 的技能目录由 Cindy 直接识别，各工具
  自己配置的 MCP 在对应引擎的任务里直接生效；完成页在检测到 Claude Code 或 Codex 时写明这一点。
- **不读取其他工具里的 API Key**：模型这一步只用现有的检测与连接流程，不从其他工具的配置里
  读取密钥或供应商配置。
- **离开窗口去别处完成的步骤**：连接模型、逐个挑选任务、导入伙伴都在各自原有页面完成。此时引导
  收起为底部一条「回到引导」，保留所在步骤；模型连接流程完成，或迁移助理
  关闭后，自动回到引导。连接向导与完整表单等待实际完成退出；查看余额保持收起，已有可用模型不会
  触发自动返回。余额请求属于整次引导，切换步骤不丢弃结果。退出或切换账号时关闭引导，
  旧版数据迁移的成功结果也只属于执行迁移的账号。

## 3.1 界面

- **欢迎页与其余步骤不同**：欢迎页不显示步骤条，居中放品牌标识（与新建任务页相同的标识块）、
  标题、一句定位、三张说明卡片和一个「开始」按钮，按钮下写明接下来有哪几步。三张卡片各配一幅
  用界面自身元素拼成的小场景（正在完成的任务、Anthropic／OpenAI／DeepSeek 三个模型标志加一把
  钥匙、电脑与手机上的同一个任务；三个标志是固定的，两个版本相同，只作示意，不等于下一页
  列出的供应商），不用通用图标（用户裁决，2026-11-11）。其余步骤沿用多步弹窗的步骤条与底部导航，
  每页以图标、标题和一句说明开头；内容少的页面（旧版数据、从旧电脑迁移、完成）整体居中。
- **窗口大小固定**，步骤之间不跳动；内容超出时在窗口内滚动。
- **动效**（用户裁决，2026-11-11）：每一步出现时，页面上的几块内容按阅读顺序依次淡入。欢迎页是
  一段一秒多的编排：标识、标题、三张卡片和「开始」按钮利落地依次到场（半秒内全部就位，不拖慢，
  避免显得刻意），随后三幅小场景各播放一次——任务一项项写出并打勾，供应商标志逐个出现，任务
  从电脑传到手机。编排期间随时可以点「开始」。只在这一步出现时播放一次，不循环；系统开启「减弱动态效果」时直接显示
  最终画面。
- 除欢迎页的品牌标识外不使用插画与彩色，颜色全部走语义 Token。登记见
  [`../design-rules/DESIGN.md`](../design-rules/DESIGN.md) §4「Get-started guide」与 §15.7。

## 4. 与旧版数据迁移的衔接

旧版本数据的迁移（`legacyUserDataMigration.ts`）必须在本地数据库打开之前完成：它复制的正是主库
文件，因此仍在登录后、进入应用前单独确认并执行，界面与规则不变。引导在它之后接上：

- 迁移成功 → 引导立即出现（不受「看起来是新电脑」限制），第一步列出已带过来的内容，并按老用户
  的路继续。
- 迁移失败 → 沿用原有的失败提示与「下次登录重试」；引导不把失败当成已迁移。
- 引导本身不复制、不删除旧目录里的任何内容，也不改变迁移的触发条件。

## 5. 区域

引导的出现条件、步骤、顺序和文案在 Global 与中国大陆版完全一致，引导代码里没有区域分支。两处由
被复用的能力带来的既有差异保持不变，不属于引导自己的分支：

- **旧版数据迁移只在中国大陆版执行**。旧的 `xdt-maker` 数据属于中国大陆版的账号体系；Global 是
  另一套账号与后端，把那份主库导入 Global 账号会让两套账号的任务与凭证串在一起。这是数据归属
  边界，不是界面差异：Global 上没有属于它的旧版数据，这一步自然不出现。改动此边界属于用户数据
  安全决策，须单独确认。
- **供应商列表的排序**沿用「连接供应商」卡片既有的按区域排序（见
  [`region-and-editions.md`](region-and-editions.md) §2.6）。

## 6. 不变量

1. **只引导，不代做。** 引导不安装、不写设置、不保存密钥；所有写入都发生在被复用的原有流程里，
   沿用它们的确认、权限与失败处理。
2. **检测只读、有界。** 本机检测只调用任务导入与伙伴导入已有的只读扫描，4 秒内没有返回按「没有
   发现」处理；对其他电脑的读取沿用迁移助理的只读快照通道，最多 3 台，读到值得迁移的内容即停。
3. **不叠窗。** 迁移助理或引导已经打开时不再自动打开；迁移助理打开期间引导收起。
4. **一次性。** 自动出现与否由 Main 按账号持久记录，界面不能绕过；手动打开不受此限制。

## 7. 多端

- 手机：不提供入口。引导针对的是这台电脑上的首次使用；手机仍可远程打开电脑的设置页。
- 服务器请求：模型页为个人账号读取一次官方服务余额（每次打开引导至多一次，进入该页才读）。
- 设备互联：不新增通道。判定复用迁移助理的 `maker:setup-snapshot`（后台优先级）：一次设备目录
  读取，加最多 3 台电脑各一次 `caps` + `snapshot`，顺序执行，不重试、不轮询；每个账号在每台电脑上
  至多一次。本机模式没有账号目录，不读取其他电脑。
- SSH 远程工作区：不涉及。

## 9. 连接返回的状态约束

不变量：**向导完成退出前引导不能自动返回；OAuth 已连接仍可能停在模型选择阶段。**
供应商／预设路由 ID 不等于最终连接 ID；引导不推测向导内部步骤。

`firstRunGuideStore` 唯一持有本次连接交接（离开前已连接 ID 集合，以及是否已交给弹窗）。
连接向导和完整连接表单挂载时认领交接，复用已有 `useDialogExit` 完成退出后才提交成功／取消。
内置详情页没有弹窗时，新增可用连接仍可完成交接。组件不再维护另一份连接等待或完成判据。
每次打开、手动返回、账单、关闭、换号都清除交接；旧弹窗的回调按交接对象身份隔离。

| 事件 | 详情页等待 | 向导／表单等待 | 非连接停放／已关闭 |
| --- | --- | --- | --- |
| 旧连接刷新／未连接草稿出现 | 保持收起 | 保持收起 | 无操作 |
| 新连接可用／OAuth 授权成功 | 返回引导 | 保持收起，继续选模型 | 无操作 |
| 完成并退出向导／保存表单 | 无操作 | 清除交接并返回 | 无操作 |
| 失败／取消／卸载 | 保持收起 | 保持收起，不把迟到结果当完成 | 无操作 |
| 向导与完整表单相互切换 | 接收弹窗认领 | 同一交接继续等待 | 无操作 |
| 手动返回／关闭／换号 | 清除交接 | 清除交接 | 清除交接 |
| 旧弹窗迟到成功／重复回调 | 不影响新交接 | 不影响新交接 | 无操作 |

对称路径审计：内置详情页、API Key 预设、OAuth 预设、通用向导及完整表单共用该交接；
成功在弹窗退出后返回，取消、失败、卸载不返回。回归在真实引导组件与原有 OAuth 向导测试中验证，
包括凭证先于模型保存生效，以及取消、手动返回、关闭再打开后的迟到结果。

## 10. 导入完成后的列表可见性

不变量：**本次导入只要产生了可见任务，完成时就通知任务列表重拉，不依赖引导或设置页仍然挂载。**
导入执行器唯一负责这次通知：批次结束、写库完成且仍属于发起账号时，复用
`emitSessionCreated` 的本机／设备互联通知一次。列表按既有逻辑重拉所有已加载分组；不为引导
增加订阅、缓存或重试。设置页只展示进度，移除它原有的完成刷新，避免重复通知。

| 事件 | 仍在导入 | 批次结束且账号未变 | 账号已变 |
| --- | --- | --- | --- |
| 导入受理／单项进度 | 不刷新 | 无操作 | 不推送 |
| 有 ready／action 任务（含部分失败或取消） | 等待批次结束 | 已提交任务中任选一个 ID 通知一次列表重拉 | 不推送 |
| 全部失败／取消／来源为空 | 不刷新 | 不刷新（没有新增可见任务） | 不推送 |
| 引导关闭／离开设置／没有进度订阅者 | 执行器继续 | 同上，不由页面决定是否刷新 | 不推送 |
| 中断后恢复／重试 | 复用同一执行路径 | 同上 | 暂停并保留原账号回执 |

对称路径审计：引导、设置、手机及 Agent 的导入入口共用执行器；完成、部分失败、部分取消、
缺目录待处理和恢复均在同一批次收尾判断，换号沿用原有账号与数据库代次校验。
`executorNotifications.test.ts` 从 `startImport` 进入真实执行器，验证通知发生在可见任务提交后、
多项只通知一次、全部失败不通知、取消保留成功项，以及换号不串推；成功与部分取消用例在修复前失败。
