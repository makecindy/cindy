# IM 消息呈现

> 权威产品规则。适用于所有 IM 渠道的入站上下文与 App 完成提醒。

## IM 入站上下文展示

所有 IM 渠道共用同一套上下文展示规则，不为 Telegram、Slack、飞书或后续渠道分别设计：

- 用户原话直接显示；随本条消息附带的内容放入默认收起的「本条附带的上下文」。
- 展开后按「引用消息」与「群聊背景」分组，没有内容的组不显示，不另加背景框。
- 展示该条消息当时保存的快照，不查询当前群历史补造；技术指引不混入背景内容。
- 总入口显示附带消息合计，各分组显示自己的条数。新快照的数量由生产端在文本组装前
  按实际纳入的消息记录保存；多行正文、附件说明与省略标记不另计条数。
- 旧记录缺少准确数量时不猜数；任一非空组数量未知，总入口不显示假精确合计。
  仍保留已有省略说明，数字不代表群历史总量。
- 渠道没有保存快照属于数据接入缺口，不是采用另一套展示规则的理由；不得为视觉统一
  擅自扩大持久化范围，受保护内容不落库等边界仍然有效。

## IM 交互的 App 未读提示

IM 侧发起的交互主要在 IM 平台查看，成功回复默认不在 Cindy App 产生完成未读绿点，
也不重复发送 App 完成提醒；桌面、手机和远程控制端使用同一口径。按本轮输入来源判断，
同一任务改由 App 发起的后续交互仍正常提醒。消息历史保留，已有未读、错误及待确认提示
不因这次成功回复被清除或静默。

来源身份见[消息来源](message-source.md)，权限交互见[IM 权限确认](im-permission-confirmation.md)。
