# 消息来源：界面标签与模型说明同源

2026-10-05 裁决。非本机用户亲手输入的消息，界面上显示的来源与模型收到的来源说明必须来自
同一份 host 盖章的数据、说同一件事。新增任何自动发送或远程发送路径时，两侧一起补。

## 两个维度

- **谁发的**：自动化、任务、伙伴、插件、Orca Lead / Worker、IM 渠道、共享任务成员。
  插件在某个任务里派发（`agent.run` 新建 / 继续 / 分叉、errand）时同时带来源任务，**以插件为准**：
  真正的发送方是插件，任务只是它运行的地方。
- **用户在哪台设备上**：手机或另一台电脑通过 device-link 远程操作被控电脑时，由被控端按
  服务端认证的控制端设备 id 盖章（`agentMeta.sourceDevice`）。被控电脑本机输入不盖章。

## 数据

- 沿用既有字段：`origin`（scheduler / session / orca）、`imSource`、`hookSource`、
  `sharedTaskAuthor`；新增 `sourceDevice`、`sourcePlugin`；群内显式发给主人的私聊消息使用 `sourceGroup` 保存群名与 ID，桌面和手机的 assistant 消息均显示此来源。
- 本机应用的可见任务复用 `sourcePlugin` 的保留前缀 `local-app:<client-id>`，与既有
  `mcp-app:` 一样是应用来源的兼容投影；名称来自已授权连接，桌面与手机显示本机应用，
  模型说明及交接使用 `app_id`，不链接到插件详情。它不改变应用授权或工具范围。
- 新数据**不进** `origin`：多处 host 逻辑把任何 `origin.kind` 当作非人工派发。
- 全部只用于归属展示，**不是**权限或信任判据；wire 传入的同名字段一律丢弃，由 host 重写。
- 共享任务访客收到脱敏后的数据：任务来源去掉 id 与标题，自动化只保留「由自动化发送」，
  不下发设备、插件与群聊来源。群来源私聊脱敏后只保留不含身份的 `explicitDelivery` 可见性标记；它不代表主任务模型轮次结束，不封存相邻过程正文。
- 共享读写与说明构造在 `packages/maker-shared/src/messageSource.ts`。

## 发给模型的说明

- 只进当次发给模型的用户消息；不进系统提示词、落库正文、排队正文，也不进
  `getAgentFacingText`（它被自动标题和 Ghost 钩子共用）。
- 只陈述事实、尽量短，怎么处理交给模型判断；名字一律配 id：`「名字」(xxx_id: …)`。
  名字按不可信文本清洗。
- 首句声明不是用户消息（`[客户端说明]`、`[渠道说明]`），或本身就是来源事实
  （`[消息来源] 本条由任务「X」(session_id: …) 发送，不是用户本人输入。`）。
- 现有说明：`[客户端说明]`（手机 / 另一台电脑）、`[消息来源]`（任务 / 伙伴 / 插件 /
  共享成员）、`[Scheduled run context]` 内的 `schedule:` 行、Orca
  `[From Orca Lead]` / `[From Orca Worker <角色> (worker_id: …)]`、IM `[渠道说明]`。
- 切换引擎、上下文滚动、重建式分叉从落库数据重建交接摘要时，按 `agentMeta` 重新生成
  来源标记；`[UI_ACTION_TRIGGER]` 合成行仍不进交接。

### 代输入续接（2026-10-13）

- 代输入结束时宿主给 Agent 发一条隐藏续接，首句 `[Input handoff ended]` 声明这是宿主事实、
  不是用户消息；只含状态、结束方式、步数、最终应用 / origin 与作答设备类别，**不含主人填写的任何值**
  （`packages/maker-shared/src/syntheticTrigger.ts`）。
- 界面不显示续接原文，桌面与手机从同一行派生一条可见留痕「主人在 iPhone 完成了 3 步输入 ·
  <域名>」；IM 渠道只收固定指引，不收续接。产品规则见 [代输入](input-handoff.md)。

## 另一台电脑上的任务发来的消息

Agent 用 `send_to_session` 把消息发给另一台电脑上的既有任务时（2026-10-14），接收电脑按任务来源
盖章，界面标签与 `[消息来源]` 说明都是「由任务「X」发送」，不是「用户在另一台电脑上操作」，
因此不写 `sourceDevice`。来源任务 id 记为 `deviceId::sessionId`：设备前缀由接收电脑按服务端认证的
控制端设备 id 填写，发送方自带的前缀被拒绝；接收方 Agent 可原样用这个 id 回信。任务标题来自
对端，按不可信文本清洗。它同样只用于归属展示，不是权限判据。
来源任务不在查看者能直接打开的位置，标签只显示来源与 id，不提供跳转。

## 跨任务请求与伙伴通话的原话（2026-10-20，2026-10-21 收窄）

伙伴或普通任务代主人下达要求时，宿主附上当前已接受输入中可核实的用户原话，Agent 仅作必要的轻度补充，
不得改写原意或扩大范围。适用于 `send_to_session`、插话、后台任务启动与追问、`send_to_agent`；
自动化通知、结果和交互回传、自主讨论保持正常正文。继续转交已核实请求时保留同一来源。
没有可核实原话时同样直接发送正文，不生成空的「用户原话」栏或「来源缺失」提示。
这不改变仅在当次派发添加的 `[消息来源]` 说明和界面的来源标签。

- 原话来自伙伴当前已接收输入的宿主记录，优先于尚未消费的排队消息；来源回执与正文分开。
  自动化输入不从更早的用户消息补造本轮原话。模型工具不提供填写或改写原话的参数。
- 有原话的伙伴委派仍使用「用户原话 / Agent补充」两栏和 JSON 字符串引用，保留换行、引号和
  首尾空格；补充里的同名标签不成为原话。标签使用发送宿主的界面语言，原话与补充不翻译。
- 桌面与手机在显示时仅对完整的宿主转发包装解码一层 JSON 字符串，恢复段落并去掉序列化引号，
  保留来源说明及原话／补充标签。五语和旧中文历史格式均适用；普通用户文本、代码示例、
  残缺包装及有意书写的转义不做全局替换。存储、重放和来源校验继续使用原始正文。
  会话搜索摘要及伙伴回复引用摘要沿用该显示投影，并从原消息来源判断是否适用；FTS 索引仍用
  原文。已截断、没有可加载原消息的旧引用快照不猜测解码。
- 编辑已有委派队列只改补充，原话保持不变；启动与重试沿用该轮来源快照。普通队列编辑仍为
  正常正文。历史消息不批量改写。
- `agentMeta.autoReviewUserText` 的 `agent-request` 回执只记录来源，不恢复旧授权、不授予新权限；
  原有内部委派续接保留独立语义。共享访客不接收回执里的私有任务标识。
- 2026-10-23：只有伙伴在宿主核实的主人代办轮里转达时，回执带 `ownerVerified`。接收任务的 Auto
  审核以这句原话为意图，`[消息来源]` 说明写明原话就是主人对本任务的请求、补充只是背景；正文三行
  格式不变（旧接收端逐字比对）。2026-10-28 修订：当前已接受输入里的凭证随同一请求继续传递，不能因交接降权；历史回看本身不恢复旧授权。规则见 [伙伴代表谁](teammate-authority.md)。
- 同账号跨电脑仅在带真实原话时附可选 `requestSource`；接收端继续校验它与正文一致，兼容
  五语及最初中文格式。没有回执时保留原始正文，不猜原话。旧接收端仍可能添加旧空栏，消除
  该显示需要接收端更新；不新增必填协议字段或数据库迁移。
- 后台任务启动提示只包含任务信息及必要内容，不追加通用执行、沟通或交付教程。

## 供应商重启后的自动续跑（2026-10-29）

原轮次因供应商进程消失而中断后，续跑沿用输入协调器的 `autoResume` 与
`autoResumeInfo.agentReconnect`：隐藏合成指令气泡，桌面和手机显示既有重新连接活动行，
不记作用户新发送。模型收到的同一续跑说明明确这是 Cindy 自动恢复，并提示本机工具可能已执行、
先核对当前状态再继续（英文使用 provider）；保留原消息的权限与 Plan 设置。新版供应商主人主动
断开使用既有 `user-revoked` 判定，不产生自动续跑消息，不恢复已经撤销的用户意图。
原轮原因是 `remote_agent_restarted` 时，自动续跑记录不附原始 `error` 摘要，桌面和手机都只显示
既有本地化重连说明；其它重连、限额或供应商组故障仍保留各自错误详情。

## 界面

- 桌面与手机同一文案；Android 跟随 iOS。
- 设备标签只标别的设备发来的消息：查看者就是发送设备时不显示；本机输入任何设备上都不显示。
  点击进入对应设备管理，名字按 id 取实时值，撞名时附短 id。
- 各来源标签的悬停 / 长按提示给出对应 id。
- Hook 消息显示渠道，不显示「由自动化「Hook · …」发送」。
- 本地 IM 消息的卡头默认「Cindy · 来自 {平台}」，表示主人经该渠道发来。伙伴自有 bot 的隐藏专线里别人的消息
  （群成员、外部用户私聊）由 `imSource.origin` 标出发言人与群名（`{发言人} · 来自 {平台} 群「{群名}」` /
  `… 私聊（非主人）`），悬停给 user_id；不以主人名义显示，与模型收到的 `[渠道说明]` / `[发言人]` 同源。
  旧记录与手机端没有 `origin` 时按主人显示。
- 机器发来的排队消息只能删除和调整顺序；合成指令行只显示标签，不显示原文。
- 分享图片不显示任何消息来源。

## 委派任务的内部协调

`send_to_session` 的 `message_purpose` 区分 `coordination` 与 `user-visible`。
只有宿主从当前账号数据库核实「委派子任务 → 该委派的发起伙伴 canonical 任务」时，
省略用途才默认内部协调；其它任务来信仍默认可见。显式 `coordination` 没有匹配关系时拒绝，
显式 `user-visible` 保留给用户的结果与必要介入。群专线不是 canonical 收件人，不套用这个默认值。
来源标签不能作为关系证明，MCP 调用方身份来自绑定的任务上下文。

内部输入沿既有持久队列消费，落库保留来源与宿主委派回执，正文使用既有隐藏输入标记；
当次模型输入另附协调用途和发送方身份。排队恢复与派发前重新核实委派执行代次；
校验失败沿正常错误/重试路径处理，不能丢弃后假报送达。用途回执不接受 renderer/device-link 自报，
也不为工具执行提供新授权；共享访客投影移除回执里的私有标识。

**2026-10-25：内部输入与对用户的回复分开。** 原始协调输入继续隐藏，伙伴处理后的进度与结果
直接走普通助手消息的落库、广播和历史读取；不再丢弃整轮文字、思考或清空结束事件的答复。
有重要进展就直接说明，没有值得汇报的信息可以不发言；需要用户决定时使用交互工具。
不要求伙伴通过 `send_to_session` 给自己发消息来汇报，也不扩大任务写工具的权限。
协调轮次成功结束的通知静默规则保持原样；通知静默不等于隐藏聊天记录。
进度运行中可见，最终答复后沿用普通任务折叠规则；工具审计、交互、权限请求、错误和恢复说明保留。
委派正常完成仍走原本独立的结果记录和隐藏 completion 唤醒，不改成内部协调。

本轮结束仅释放当前任务的输入通道，不代表委派工作或用户目标已完成；后台任务继续运行时，
用户仍可给主任务发送下一条消息。主任务运行中沿用原有排队／插话，结束后正常开始下一轮。
无需数据库迁移或新协议。旧消息不重新分类，也不补造此前已被过滤的正文；新消息使用已有
桌面／手机消息通道。旧宿主仍会过滤协调回复，需更新宿主才能恢复该路径的进度显示。

## 对话使用的模型

只有实际派发的模型与上一段可见对话不同，才显示轻量分隔提示「原模型 → 当前模型」；
同一模型连续回复不重复标记。记录来自宿主派发时的实际模型，不能用当前选择器的值回填历史。
跨引擎沿用已有交接分隔，隐藏的例行检查和内部协调不额外产生可见模型提示。
桌面与手机使用同一份历史记录。缺少实际模型记录的旧消息不推测补标。

### 伙伴私信回复可见性（2026-11-01 修订）

`bot-dm:` 的普通助手答复恢复为内部回复（`botPrivateReply`），不制造主人聊天、预览、未读、云镜像和完成提醒。
单行收发痕迹保留，点击查看显式往来；自动重试延续内部归属，主人插话后恢复正常回复。
这仅调整呈现与提醒，不回退已核实主人请求的多跳交接授权。审批、提问、执行错误及宿主恢复提示仍可见；
后台任务、普通任务转交、群专线的已有合同不变。不批量改写历史记录。
实现见 `sessionEventPreparation.ts`、`agent-island/service.ts`；回归见对应既有测试。

本机 `send_to_agent` 已入队、但接收侧没有持久化消息回执时，数据库保持 `pending`；只有接收队列仍持有该消息才在私聊视图显示「排队中」。队列确认不再持有该消息（包括重启恢复确认队列中不存在）后，先为队列快照写入同一 client id 的取消墓碑，再将私聊记录标记为未送达并释放往来上限预留。墓碑失败时保留待恢复状态；不得让旧队列快照复活已结算的消息。发送侧任务时间线显示未送达状态卡，使主人仍能进入只读记录查看消息和状态。接收伙伴时间线不伪造一条已收到的消息；状态卡和失败行不触发未读或自动重试。若发起方不在本机，状态卡落在本机接收侧。
