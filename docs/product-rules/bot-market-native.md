## UI Implementation Contract

- 版式以用户 2026-10-15 重发的列表/详情设计图为结构基准，叠加之后的明确修改：小圆头像、简洁头部、去掉查看原作、不恢复搜索；列表不显示创作者署名（包内署名数据仍随包保存，界面与目录投影都不读取）。
- 列表：标题“发现伙伴”（伙伴添加菜单里的入口用同一个文案，不用英文名 Bot Market）；双列，列间竖分隔、行间横分隔；每项为小圆头像、名称、一句话，“邀请加入”与名称同一行靠右，已加入为“打开伙伴”。
- 详情：顶部“返回列表”与关闭；身份组（大圆头像、名称，不显示一句话副标题，它在列表页保留）与右侧主按钮同一行；其下横向三项关键能力；再下“一起工作的方式”，按顺序纵向展示技能、知识与记忆、工作工具、例行任务四个模块（某模块包内没有数据就整块隐藏）。
  - 数据来源：所有展示字段都是包作者专为页面撰写的 `presentation.detailZh`、`bubbleZh`、`starterOptionsZh` 与 `i18n`（`en`/`ja`/`ko`/`zh-TW` 四种语言必须齐全，每种都带 bubble），**一律必填，缺任何一项或任何一种语言，整个包拒绝读取（`INVALID_PACKAGE`）**。读取时校验字数、引用、能力白名单图标和维护者措辞；例行任务行不带 `icon` 字段（读取时拒绝，编译器同样拒绝）；客户端不从技能步骤、方法文档正文或例行任务指令里截取内容。以上字段随既有 `botMarket.list` 返回，没有新增 IPC；头像只接受 WebP（`assets/avatar.webp`，读取时校验文件头与 `profile.avatar` 的 asset 类型）。
  - 模块图标：四个模块标题前各带一枚与伙伴设置同源的图标（技能 = 设置里「能力」的图标，知识与记忆 = 记忆图标，例行任务 = 例行任务图标，均引用 `botSettingsIcons.ts`；工作工具就是插件，引用侧栏「插件」导航项的 `SIDEBAR_NAVIGATION_ITEM_ICONS.plugins`）。
  - 技能：名称 + 描述，描述最多两行。开场设置技能是宿主开场流程，已由头部气泡体现，不在技能里列出。
  - 知识与记忆：知识标题 + 最多三行说明；其下一行带小标题“会记住你的”和偏好标签（开场确认后会记住的偏好，如时区、关注的主题）。
  - 工作工具：一张卡内逐个插件一行，名称 + 作者写的一句用途在同一行，行首不放插件图标或占位块，与其它模块卡片内文字左对齐（窄宽度时用途换行）。安装状态在右，只读取已安装/目录投影，不触发安装、授权或模型调用；投影晚到时只淡入状态文字，行高不变。没有插件依赖则整块隐藏。投影没拿到时显示 `bundledPluginNames`（`botMarketDisplay.ts`）里的正式名称，新包依赖新插件时必须登记（测试逐包校验）。包只能依赖插件市场公开的插件（不得依赖组织内插件或仅本机已装的插件）。
  - 工具声明只用于展示：`dependencies.plugins` 与“工作工具”只列有代表性的几个插件（全部 `required: false`），运行时不据此限制伙伴能用什么（读取时只校验详情工具行与它一一对应、顺序一致）。伙伴按能力类别用工具（代码托管、表格、邮箱、文档与知识库、云盘、网页检索、出图与设计、设备与模拟器）：先看用户已有的同类工具，有什么用什么，本机已有的 CLI 与现有工具（git、gh、glab、浏览器等）也可用；默认只读，写入前须用户确认，不索要密码或令牌。具体插件名在技能里只作举例，GitHub 读 PR、GitLab 读 MR 各用各的说法。插件的发现、安装和连接不在包里复写：起步技能的“工具”一节只指向宿主伙伴指南（`teammateGuide.ts`），由它按运行时给出完整规则（有 cindy 网关时的发现与市场安装、有连接卡时的 `connect_account` 与等待完成通知、远程会话没有连接卡时引导到可信桌面的插件页、没有 cindy 网关时整段隐藏）。技能里不出现 `ghost_*` / `connect_account` 等工具名，也不写进身份提示（`identitySource` 会进入 system 段，改动受 system prompt 门禁约束，需与 0.5.0 保持一致）。
  - 例行任务：标题 +“·”+ 人话节奏（只是包内示例节奏，不带时区；用当前语言说不出来的节奏，如按月份或周末的写法，只隐藏节奏，不显示英文或 cron 原文）同一行，下一行单行省略的说明，右侧“默认关闭”。
  - 滚动与加载：大头像滚出视野后，顶栏淡入小头像、名称和紧凑主按钮（与身份区按钮共用状态）。加载超过 300ms 才显示静态占位。
  - 开场气泡：在身份组下方，做成不带头像的对话气泡，左下角带同色小尾巴（仅此一处，见设计决策日志）。样式与主按钮明显区分：底 `--surface-elevated`、1px `--border-default` 描边、正文 `--text-primary`，与用户自己的消息气泡 `--msg-user-*` 同配方；悬停/键盘焦点底色升到 `--surface-hover`；尾部小发送图标 `--text-secondary-mid`；尾巴的填充随气泡底色，描边续接气泡边框。
  - 气泡内容：包作者写的一句话短句 `presentation.bubbleZh`（各语言 `i18n.<lang>.bubble`，不含问候，简体/繁体 ≤20 字、日韩 ≤30、英文 ≤60 字符；读取时校验）。开场流程里辅助模型改写与纯脚本兜底用的是 welcome，不受 bubble 影响。
  - 气泡点击：未加入走邀请流程并进入伙伴对话，已加入直接打开伙伴对话（输入框沿用对话页的自动聚焦）。
  - 边界：能力、名称与开场白均来自包 manifest，不在界面另写。无源网页按钮、工程标记、配置向导或空案例页；插件与模型沿用既有设置与授权，不暗中连接。
- 弹窗在 800×600 内完整保留标题、返回、关闭与主操作，内容区滚动；常用窗口增加留白。共享 Button、Radix Dialog、语义颜色 token，Light/Dark 同时实现，键盘焦点与状态播报可用；不提供搜索或筛选。
- 安装从打包资源读取原 schemaVersion=2 manifest/integrity，全文件校验后由原 import/transfer 写 Profile/Home/Skill/reference 与停用自动化。原 receipt 绑定包身份；安装不执行脚本、不投首任务、不启日程。欢迎沿原邀请 owner，移除沿原生命周期。
- 邀请后的开场不跑伙伴主模型：宿主用与会话标题同一套的辅助文本解析，只走辅助链、不回落伙伴自身 agent（用户正盯着聊天，冷启动 agent 赶不上预算，只会白等；整段总预算 4 秒上限）一次生成问候和与包内起步选项等量的选项，校验后写成一条普通伙伴消息（正文 = 问候 + 纯文本选项列表，供手机与旧客户端；`agentMeta.botStarterOptions` 保存选项）。桌面把选项渲染成消息下方的共享次要胶囊按钮（淡入用 `animate-fade-in`），点击即以用户身份经会话自己的发送路径发出该文字；用户一旦在任务里发过消息就收起。伙伴已有可用模型路由而辅助链失败或无候选（立即，不等预算）、4 秒预算用尽或输出不合格时，用包内（按邀请语言的）welcome + 起步选项，不再调用模型；开场写入前聊天里显示既有的“正在准备第一声问候”（`bots.invitation.welcome` + Spinner，状态行，不拦截点击），开场写入、邀请离开 `welcome`（ready/failed）或用户先发言即消失，只出现在该伙伴主聊天（canonical）里；伙伴没有有效模型路由时，和普通伙伴一致先进入“连接供应商 / 选择模型”，选好后才写开场。用户先开口则不写（写入前会再查一次）；写入失败会改用脚本版重试。用户的第一条回复交给伙伴主模型，getting-started 技能再查记忆、检查连接并发连接卡。
- 手机保留原伙伴使用能力，本次不增加手机市场。外部 Add 仅选择已有包详情，不增加分享服务、任意 URL 或任意本地归档载入。

## 文件责任与验证

`main/bot-import/nativePackage.ts` 负责受信内置包解析与目录投影；`host.ts`、`transfer.ts` 沿用唯一导入请求与恢复；Desktop shared/preload 提供最小 typed IPC；`renderer/features/bots/BotMarketDialog.tsx` 实现列表/详情并沿原伙伴导航和删除确认。`resources/bot-packages` 只内置十包 0.5.2（工程交付、代码审计、产品巡检、选题策划、研究信号、视频剪辑、原型开发、投放监控、搜索广告复盘、游戏美术）。十语文案改变 manifest hash，随包版本同步递增；旧 0.5.1 的未完成导入继续使用原回执和持久快照，不覆盖已安装伙伴。已从目录移除的包，已安装的伙伴按原回执照常使用与删除，目录不再列出它。旧版本构建源保存在设计资料目录，不随仓库分发。

每个内置包是离线编译器产出的「客户端发布版」，只含客户端会读的文件：`manifest.json`（紧凑 JSON，`integrity.files` 只列随包文件，例行任务不带 `sourcePaths`）、`assets/avatar.webp`、`knowledge/method.md` 和 `skills/<slug>/` 下各技能的全部文件（共 10 个文件）。身份提示读 manifest 里的 `profile.identitySource`，署名、来源、适配与行为评估等审计记录不随包进入仓库，留在设计资料目录的完整包里。`packageHash` 是 manifest 规范化 JSON 的哈希，与缩进、键序无关；发布版与完整包的 manifest 不同，所以哈希也不同。十个包合计约 409 KB（单文件均小于 100 KB），逐字节核对见 `nativePackage.test`。头像进入伙伴后沿既有路径：`avatarImageBase64` → `decodeBotAvatarImage`（PNG/JPEG/WebP 白名单）→ `toSdrAvatarImage`（SDR 原样保留）→ 托管媒体（`.webp`）；列表与详情的 `<img>`、云端头像上传（oss avatar 场景允许 webp）、通知头像（sharp 转 JPEG）和手机缩略图（本就是 WebP）都接受 WebP。

验证边界：定向测试（import/transfer/registration、真实数据库邀请与生命周期、市场与删除确认、设计清单、i18n/glossary）与 Desktop typecheck 是代码层证据，全量 lint 对照 HEAD 基线有旧错误；真实 Electron（独立 userData、Global DEV、passive 模式）曾实际获取十包并目检 Light/Dark、1280×800 与 800×600 渲染。passive 模式下原 routine engine 拒绝初始化，停用定义的安装与原生命周期 pause/delete 无法在该模式完整验收，未绕过此保护。owner 隔离/安装恢复、真实模型成果、OAuth、日程启用/触发、跨进程重启、手机及端侧移除仍未验证，不得从静态测试推定通过。

## 发现伙伴入口

- 2026-10-25 用户决定移除“发现伙伴”的「新」标签与「+」上的提示点，无障碍名称也不再追加「· 新」。入口本身保留。
- 伙伴段展开或收起时，「+」均沿用段头动作的悬停、键盘焦点与菜单打开时可见规则，不再因首次访问而常驻。
- 不再记录或读取是否看过入口。空状态的大按钮“添加”仍直接打开创建弹窗。

## 已知限制

- 内置包随安装包分发：`forge.config.ts` 的 extraResources 含 `resources/bot-packages`，安装包从 `process.resourcesPath` 读取，源码运行从 `app.getAppPath()/resources` 读取（`host.ts` 的 `packageRoot`）。从 extraResources 去掉该项会让安装包里目录为空且邀请失败。
