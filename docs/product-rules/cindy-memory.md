# Cindy 记忆（普通任务的长期记忆）

> **读取时机**：改动 Cindy 记忆的作用域、索引、写入与读取工具、整理、记忆页或保存回执前。
> 伙伴的记忆是另一套契约，见[伙伴运行时](cindy-bots-runtime.md)；进入模型 system 段的文字
> 另受 [system prompt 改动门禁](../dev-rules/maker-core-and-agent-behavior.md)约束。

Cindy 记忆让普通任务跨任务记住关于用户和项目的事。它由设置里的「Cindy」开关控制（默认开），
Claude Code、Codex、Pi 共用。开着时各 harness 的原生记忆不生效，相应的设置也不显示，见 §6。实现在
`packages/maker-core/src/memory/`，工具在 `packages/lizi-mcps/src/memory/`。

## 1. 两份记忆

| | 账号级（`user`） | 项目（`project`） |
| --- | --- | --- |
| 记什么 | 关于用户本人、在每个项目都成立的事：称呼、语言、通用的做事偏好与纠正 | 只属于这个仓库或目录的事：决定、约束、外部资料指向 |
| 作用域 | 每个账号一份 | 每个仓库一份；不在 Git 仓库里的目录按目录 |
| 落盘 | `<账号目录>/user-memory/` | `<账号目录>/maker-memory/<由路径派生的目录名>/` |

- **任务启动时两份索引都注入**，账号级在前。正文按需用工具读取。
- **写到哪一份**由工具的 `scope` 参数决定；不传时 `user` 类进账号级，其余进项目。改已有条目时
  跟着文件走。这条规则写在代码里，不靠提示词劝。
- **一次性对话的目录不属于任何项目**：目录用完即弃，记在它名下以后读不到，所以这类任务只读写
  账号级记忆。判定由宿主注入（桌面端按对话目录的根）。
- **伙伴不读 Cindy 记忆，Cindy 记忆也不注入伙伴**；伙伴的记忆不受总开关和「清空全部」影响。伙伴的
  记忆放在它自己的项目文件夹里（V2，见[伙伴运行时](cindy-bots-runtime.md) §4），不出现在 Cindy 记忆页，
  也不参与下面的归并和整理。
- 「清空全部」同时清空账号级和所有项目记忆。记忆只存本机，不跨电脑同步。

### 项目按仓库归并

同一仓库的子目录、linked worktree、submodule 都归到**主工作树根**，在仓库任何位置开任务拿到的
是同一份记忆（`scope-resolver.ts`）。SSH 远程目录仍按「主机 + 远端路径」，不在本机解析远端 Git。

旧版本按工作目录隔离，子目录各有一份。升级后第一次打开某个仓库的记忆时，宿主把今天仍解析到
这个仓库的旧子目录记忆并入仓库根：同名同内容跳过，同名不同内容换名并入，来源文件保留并留下
回执。嵌套的独立仓库不动；仓库里已不存在的目录，按它最近一层还在的上级目录判断属于哪个仓库
（普通文件夹不这样做，删掉的子文件夹不并进上级）。一次性对话目录名下的旧记忆，在第一次打开
账号级记忆时按同样的规则并入「关于你」。**这是存量数据迁移，改作用域规则必须带同等的自动
并入，不能让用户升级后丢记忆。**

## 2. 索引

- `MEMORY.md` 由宿主从分片派生，模型不手写。每行以该条最后更新的日期结尾：记忆是当时记下的
  线索，模型要能看出它有多旧，用前核对。日期只到天，同一天内改写不改变索引文本。
- 索引整份进 system prompt，所以有预算：软上限 4KB 返回警告；**硬上限 12KB**，会让索引变大并
  越过硬上限的写入被拒绝，模型先合并或删除再写。不让索引变大的写入（改正文、删除、合并）始终
  放行，否则已超限的记忆再也整理不回来。
- 伙伴的记忆不设硬上限：它有自己的整理流程和导入入口。
- 索引是任务启动时的快照，任务中途不刷新（保持请求前缀稳定）。

## 3. 需要时才整理

没有定时任务。伙伴的项目每晚整理一次记忆（它的项目自动化），是因为一个伙伴每天都有对话；项目很多且大多长期没有动静，按天
跑要么空转，要么得给每个项目挂一条定时任务。

- **什么时候检查**：任务在某一份记忆里写过东西，这一轮成功结束时检查那一份。没写过记忆的任务
  结束时什么都不做（`memoryTidyTrigger.ts`）。
- **触发线**（任一满足，且距上次尝试超过 24 小时）：上次整理后新增或改动满 10 条；或索引达到
  硬上限的 80% 且上次整理后至少有一条改动。
- **只整理已有记忆**：合并说同一件事的条目，处理互相矛盾的条目（较新的为准）。不回读对话提炼
  新记忆——那仍由对话当场写入；不判断一条记忆是否仍然属实。
- **模型只提议，宿主校验后落盘**（`tidy.ts`）：一次辅助模型调用；只能动快照里有的文件，一次
  合并的来源必须同类，每个文件最多参与一项改动，删除必须指明被哪一条覆盖；落盘时核对快照时的
  更新时间，整理期间被改过的跳过。记忆正文可能含不可信文本，提议的能力面因此固定为「本份记忆
  内合并、删除」，没有新建任意内容或跨份写入的路径。
- **整项核对、整项落盘**：模型思考的几秒里记忆可能被改过，所以一项操作用到的**每一条**记忆
  （合并的保留条与并入条，「已被覆盖」删除里的覆盖方）都在存储锁内按快照版本核对，任一变了整项
  跳过、什么都不改；覆盖方被删或改写时，被它覆盖的那条也不删。索引预算按合并完成后的结果算——
  满额的记忆正是最需要整理的。
- **可撤销**：每条改动存前后内容，每份记忆保留最近 20 次记录。撤销不覆盖整理之后又被改过的
  条目；恢复的是整理前已经存在过的内容，**不受索引硬上限限制**（旧记忆并入后索引可以原本就超限）。
  整理与撤销提交状态时都读最新状态再合并，不互相冲掉对方刚写下的记录或「已撤销」标记。
- 整理在宿主后台进行，不进任务对话，不发通知；结果在记忆页的整理记录里。跟随总开关，没有单独
  的开关。用户也可以在记忆页点「现在整理」，不看触发线。

## 4. 可见与可改

- 设置 › 个性化 › 记忆里可以查看账号级和各项目的记忆，搜索、打开、编辑、删除；总开关关着也能
  看和删。与伙伴记忆页共用同一套列表、编辑和冲突处理。
- 普通任务的回复里写入了记忆时，回复下方显示与伙伴相同的保存回执，点开进入对应的记忆页。
- 编辑或删除后，正在运行的任务仍用启动时的索引快照，新任务生效。

### 记忆页（仅桌面）

入口是「Cindy」行的「查看记忆」，打开同页的子页（`/settings?tab=personalization&openPanel=memory`）。

- **先选范围**：「关于你」（账号级）恒在首位，空的也列；之后是至少有一条记忆、或还有没撤销整理记录的项目（记忆删光了也要能进去撤销整理），显示文件夹名，
  路径作次要文字，SSH 项目另带主机；每个范围显示条数。范围列表只来自
  `MakerMemoryManager.listScopes()`。
- **范围内与伙伴记忆页是同一个组件**（`MemoryEntriesView`）：按关于你 / 你的要求 / 项目 / 参考分组，
  标题加正文开头，搜索复用记忆检索，内部 `digest` 不展示；详情显示全文；编辑自动保存，标题与正文
  沿用存储上限；改正文时摘要按正文首句确定性刷新，不调用模型；保存与删除前核对打开时的更新时间，
  期间被任务改过就不覆盖，由用户选最新内容或保留自己的修改；删除先确认。伙伴页与这里只在
  「记忆属于谁」上不同，规则改一处两边同时生效（main 侧 `memoryEntries.ts`）。
- **范围键不可信**：页面带回的范围键每次都对照 `listScopes()` 校验，不在列表里就拒绝，不为任意
  路径打开存储。打开存储时跳过总开关检查，所以关着也能看、改、删。
- **整理**：选中的范围下有「整理记忆」一行，说明整理做什么、会自己发生、可以撤销；「现在整理」在
  总开关关闭或不足两条记忆时不可用并说明原因，进行中不挡列表，结束后用提示告知结果（整理了几条 /
  没有需要整理的 / 没整理成、记忆没有改动）并刷新列表、条数和记录。「整理记录」默认收起，这份记忆
  没有记录时不显示；每次整理列出时间、自动或手动、动到几条，展开看哪几条合并成了哪一条、哪条被
  移除及模型给的理由。未撤销的记录可以「撤销」（先确认），总开关关着也能撤销；整理之后又被改过
  的条目不恢复，并在提示里说明条数。界面只拿到摘要，整理前后的正文不离开 main
  （`MemoryTidyCard.tsx`、`makerMemoryEntriesService.ts`）。
- **不刷新运行中的任务**：这里改完不通知任何任务。界面写「下次 Agent 会话生效」，不写「新建任务
  才生效」（见[命名规则](task-and-conversation-naming.md)）。
- **只在本机**：`maker:memory-entries:scopes / list / read / update / delete / tidy / tidy-runs /
  tidy-undo` 只接受本机可信窗口，不进设备互联白名单；手机和远程控制端没有这个页面。要开放给它们时
  走 Remote Resource，不直接放行这些通道（[远程与手机适配](../dev-rules/remote-and-mobile-adaptation.md)）。

### 保存回执

与伙伴的保存回执是同一条链路、同一个消息字段（`agent_meta.botLearning`，字段名不改）：记忆工具
写入前记下来源轮次，写入成功后等这一轮的收尾回复落库，再把回执附在那条回复上；迟到的写入只补
原回复。位置、样式与文案（「已记住：标题」，同一条回复的多次保存并成一行）与伙伴相同。

- **哪些回复有回执**：普通任务（不是伙伴 Session、也没有关联伙伴的 Session）里未被回退、未被
  清空的 assistant 回复；子 Agent 消息没有。伙伴一侧的规则不变（只有主对话与历史对话；私下回复、
  群专线、渠道、话题、例行任务、委派出去的任务都没有），见[伙伴运行时](cindy-bots-runtime.md)。
- **只有记忆一行**：普通任务不产生技能回执。
- **回执只带「写进了哪一份」**（`scope`：关于你 / 项目），不带路径：回执存在消息上，会随消息到
  手机和共享任务的访客那里。
- **点开去哪**：本机任务点开记忆页；写进项目记忆的，页面带上这个任务的工作目录，由 main 解析出
  它的项目并落在那一份（旧回执、一次性对话，或那个项目已不在范围列表里时落在「关于你」）。任务在
  另一台电脑上（远程控制、共享任务）时记忆也在那台电脑上，回执只显示文字、不可点。伙伴 Session
  被当作普通任务打开时不显示回执。
- **手机**：普通任务的回执显示为一行文字，不可点，也不进入伙伴设置；伙伴对话里的回执行为不变。

## 5. 不做的事

- 不用向量检索：主流编码类 harness 都不用，现有规模全文检索够用。
- 不要求每条写入审批：对话中直接写、事后可见可改可撤销。
- 不按时间硬过期：整理时由模型结合更新时间判断矛盾，旧而仍然正确的记忆不该被删。
- 不在压缩前抢救记忆：当场写入加历史对话检索已覆盖；只打日志的 `flush-controller` 已移除。
- 不把 Pi 的压缩摘要存进记忆（2026-11-11 移除，原「压缩即记忆」）：那是对话内容的一份副本，界面上
  看不到、不能单条删除、删除任务后仍在，也不会过期；被压缩掉的内容用历史对话检索找回。`digest`
  类型保留，只为识别和清空旧版本存下的摘要：它们仍可检索，随「清空全部」一起清掉。

## 6. Cindy 记忆与各 harness 的原生记忆（2026-11-11 裁决）

目标是由 Cindy 统一为所有 harness 管理记忆；各 harness 自己的记忆选项保留，但平时不出现。

- **Cindy 记忆开着（默认）**：Claude Code、Codex、Pi 的普通任务共用 Cindy 记忆，Claude Code、Codex
  的原生记忆不生效。设置里只显示「Cindy」一行，原生记忆的两行**不显示**。
- **Cindy 记忆关着**：设置里才出现「Claude Code」「Codex」两行，各有开关和重置，控制各自的原生记忆
  （默认开，即关掉 Cindy 后回落到原生记忆）。再打开 Cindy，两行收起，已存的选择保留。
- **Pi 没有自己的记忆**，也没有单独一行：Pi 任务用不用记忆只看 Cindy 开关。
- **存量设置**：`memory-settings.json` 里的 `claudeCode` / `codex` 照旧生效；旧版本的 `pi` 字段读取时
  忽略，不改写文件，也不算「改过设置」。
- Agent 可调的设置项（`memory` 设置分区）是 `maker`、`claudeCode`、`codex` 三个字段；与界面一致，
  Cindy 开着时不能改后两个。
- 伙伴的记忆开关在伙伴自己的设置里，与此无关。

## 7. 渠道里别人也能说话的对话（2026-11-12 裁决）

渠道自有任务（Telegram、飞书、钉钉、Discord、iMessage 等渠道里不属于伙伴的任务）用的是 Cindy
记忆，其中「关于你」是主人账号级的。群成员、外部用户也能在这些对话里说话，所以：

- **访客读写记忆要主人确认**：发起这一轮的人不是主人时，这一轮里对 `cindy_memory` 的调用
  （读、列出、搜索、写、合并、删除、历史对话检索；只读的 `list_tools` 除外）都进入审批，由主人
  在确认卡上决定。「不是主人」指宿主核实为访客，或群里身份没能核实的人。
  - Ask 档：直接问主人。Auto 档：不交给模型判断风险，直接转给主人确认 —— 读记忆在风险表里是
    低风险的读，交给模型会被当成访客的普通只读放行。
  - Full access 档：主人对这个任务的明确授权，逐轮策略在该档下不生效（各渠道既有规则），记忆
    调用同样不再确认。个人 Telegram 的访客轮次在该档下按既有规则临时按 Auto 受理，仍会确认。
- **主人自己的轮次不变**：主人在群里或私聊里发起的轮次，读写记忆不需要确认。
- **个人微信不在此列**：只有私聊，身份恒为未核实，对话另一端就是用它的人；逐次确认只会让主人
  自己每次用记忆都被打断。
- **伙伴任务不在此列**：伙伴用的是它自己的记忆（`bot:` 作用域），不读写账号级记忆；访客轮次
  里伙伴读写自己的记忆照旧。伙伴不可用、回落到渠道自有任务时按本节处理。
- **这类对话的任务启动时不带「关于你」的索引**：索引（每条记忆的标题和一句话摘要）是任务启动时
  写进系统提示词的，之后每一轮都看得见，逐轮确认管不到它。群聊，或有过访客发起轮次的对话，
  登记为「别人也能说话」（`channel-shared-sessions.json`，按账号存放，登记后不撤销）；登记过的
  任务无论从哪里启动（渠道、桌面端接着聊、重启恢复），提示词里账号级那一份只有一句说明（这里
  不列、需要时用记忆工具查、别人发起的查询要等主人确认），项目那一份照常。主人的私聊不登记，
  照常带索引。
- **远程设备**：任务托管在另一台电脑上时，「访客轮次的记忆调用要确认」随逐轮策略一起过线；
  旧版本不认识这个字段时行为与它原来一致（账号级记忆与本规则同一版本上线）。

- **对话在任务启动之后才变成别人也能说话的**（把正在运行的桌面任务接管到群里；升级前就在运行
  的群聊任务）：任务启动时已经带了索引。渠道在派发这段对话的下一轮之前，先把任务重新启动一次
  （与项目资源变化后的回收走同一条路），重启后的提示词不带索引，然后才发出这一轮。任务里已有
  的对话历史不受影响、也不会被清掉。

已知边界：主人在群里发起的轮次里，群成员写在群消息里的文字仍可能诱导 Agent 读记忆并回到群里
—— 这与各渠道对主人轮次的既有信任模型一致，本节不改。任务重新启动失败时（记日志）这一轮照常
发出，提示词里仍带索引。
