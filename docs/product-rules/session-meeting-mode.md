# 共享任务：远程连接的多人版本

> 产品裁决更新：2026-09-16。实现与验证进度见文末；本文不代表已上线。
> 本文替代早期“会议模式”方案；内部 sessionMeeting / meeting 名称保留。

## 定位

房主分享一个现有任务，其他已登录用户通过邀请进入同一个远程任务页面，共享完整历史、上下文和 Agent。复用现有远程连接、输入队列、附件、语音输入和断线恢复，不做独立会议产品或普通讨论频道。

用户明确要求减少复杂度：访客与房主触发的 Agent 调用使用相同任务权限。加入方式选择最简单方案，采用邀请即授权。

## 用户流程

1. 房主在任务内点击“共享任务”，开启共享并复制邀请。
2. 访客在菜单“加入共享任务”粘贴邀请，登录后直接加入，无申请或批准步骤。
3. 双方进入现有任务页面，查看全部历史、工具结果、上下文和附件，向同一个 Agent 发消息。
4. 房主可复制新邀请、移除访客、停止共享；访客可退出。

不增加申请记录、审批通知、在线人数、正在输入、编辑标记或独立会议页面。成员列表和消息作者只用于识别参与者。

## 权限与顺序

- 任务由原桌面运行，模型费用沿用房主连接；同账号远控行为不变。
- 访客可发消息、使用附件和语音输入、修改 Agent/模型/推理设置、停止 Agent。
- Agent 工具、shell、已有插件/MCP 沿用任务现有权限，Full Access 语义不变；已有需审批操作仍由房主处理。不添加访客专属沙箱、per-turn 权限或工具审批。邀请意味着房主信任访客使用该任务的 Agent 能力。
- 房主保留共享管理、归档/删除/导出/分支、权限模式、工作目录、插件/MCP 配置和后台/定时任务管理权限。
- 访客通过客户端接口只能直接访问共享任务及其资源，不能调用全局凭证、其他任务或任意主机文件接口。Agent 原生工具不承诺工作目录硬隔离。
- 消息按主机现有输入队列顺序处理，保留 clientId 幂等。访客仅编辑/撤回自己未处理消息，房主可处理全部未处理消息；直接更新内容，不显示“已编辑”。
- 发言者身份来自经过验证的账号和成员关系，不能信任消息正文或客户端自报的身份。

## 邀请、成员和生命周期

- 邀请可转发，持有邀请的登录用户即可加入；最多 3 位访客，按账号计数。房主账号同时最多共享 3 个任务。
- 同一账号重复加入幂等，多个设备不重复占用名额。邀请令牌只存摘要，不进入日志。
- 移除或退出立即撤权；原邀请不可重入，房主生成新邀请后才能再次加入。
- 停止共享、归档、房主登出使旧邀请和成员关系失效。重新共享产生新的共享 ID。
- 归档后恢复为活动任务，可以显式重新开启共享；须先完成旧共享关闭，旧代次的请求仍然失效。
- 关闭客户端、重启或临时离线不等于停止共享；重启后从服务端恢复有效成员。主机离线时不可访问。
- 服务端是成员关系权威；主机保存恢复与关闭记录。迟到响应、旧快照、缓存和重连不能恢复已撤销访问。
- 网络故障沿用远程连接重试；不能把某个访客的断线放大为整个 relay 的重启。
- 不承诺撤回访客已经看到或下载的内容。

## 实现约束

- 复用 packages/device-link；新增跨账号的单任务授权，禁止降级为旧版全设备远控。
- 同时校验 invoke、push、历史、附件、嵌套引用、离线补发与结果缓存的任务及成员归属。
- Desktop 与 Mobile 复用现有任务页面；房主在手机上通过既有同账号远控管理共享。网页端和匿名访客不在范围内。
- 新协议以能力协商开放；缺少能力提示升级。两区域独立，不默认跨区域加入。
- 关闭记录必须落入原 profile 的 journal 后才能释放数据库；本地同步撤权，服务端失败下次恢复重试。
- 登出时等待已发出的创建请求收尾，迟到的创建 ID 也必须先落关闭记录；在线关闭仅使用退出账号的固定凭证与端点，不刷新或影响新账号。
- 移除请求未获确认前暂停该成员访问；网络失败须以服务端状态恢复。临时暂停或同账号新增设备造成的旧授权失效返回可重试错误，只有确认撤权才从访客端移除任务。
- 本仓只改客户端；服务端实现位于独立 cindy-server 的本任务 worktree。两仓协议需一致。

## 版本兼容与发布顺序

- 先执行服务端增量 migration，再升级全部 device-link relay 实例，最后发布客户端。服务端新增共享关系表，不改写既有同账号设备关系；滚动升级期间不能把尚未具备共享能力的 relay 当作已支持。
- 新客户端连接旧 relay 时，普通同账号远控继续使用原协议；共享入口提示升级，Mobile 不轮询旧 relay 的共享 API。新 relay 连接旧房主时，房主缺少共享 channel 的错误也提示升级，不能降级为全设备访问。
- 错误处理只把明确的能力缺失或版本不兼容映射为升级提示，断网或超时错误仍提示重试。Mobile 连接未建立时将能力视为未知，显示重试；重新连接后重新读取能力，升级后可恢复共享。
- Desktop 的本地 SQLite migration 0108 为增量建表，但“可从旧版升级”不等于“可用旧版打开新库”。既有 migration manifest / schema 校验会拒绝旧程序打开已升级数据库；本功能不放宽该保护。
- 发布前保留升级前数据库备份。需要回退时优先修复新版；如必须恢复旧程序，应使用升级前的对应备份，并明确接受备份之后的数据不会随之保留。不得通过降低 schema 版本、删表或改历史 migration 强行回退。服务端回退时保留增量表，不执行破坏性 down migration。
- 新旧版本真实混合部署尚未端到端实测；能力协商与错误提示的自动化回归不能替代该发布验收。

## 验收

- 房主与两个不同账号访客进入同一任务，访客加入无需审批，完整历史可读，多人发言进入同一 Agent。
- 原同账号远控、正常任务权限、Full Access、串行队列和重复输入幂等不退化。
- 访客无法直接访问其他任务、伪造作者、改他人队列或响应房主审批。
- 退出/移除/停止共享/归档/登出立即阻断后续访问，旧邀请和迟到响应不复活权限。
- 重启恢复、断线补发、附件上传下载、SSH 工作区、Desktop/Mobile 和旧版拒绝有相应验证。
- 一个访客停止 ACK 时其他访客和房主控制端仍可工作。
- UI 使用语义 token 支持 Light/Dark，实际验证结果如实记录，不以类型检查代替联调。

## 本地联调

最小组合是一套测试服务、一个房主 Desktop 和一个访客客户端。验证多人并发时增加第二个访客，使用三个不同 Cindy 账号；同账号的两个实例走既有远控，不能用于验收跨账号共享。

1. 在独立测试数据库和 Redis 上启动本任务版本的 device-link-server，并执行该服务的 Prisma migration。登录需使用同一测试区域的 auth-server；附件上传下载还需要可用的测试对象存储配置。不要把测试指向生产数据库。
2. 两个 Desktop 使用不同 checkout、不同命名沙箱和独立端口。分别从各自 checkout 使用仓库根安全启动入口：

       pnpm restart:desktop:local --region=global --isolated=sharing-host
       pnpm restart:desktop:local --region=global --isolated=sharing-guest

   启动参数、端点与端口以 [Desktop 开发规则](../dev-rules/desktop-development.md) 为准；包装脚本会停止当前 checkout 的旧开发实例，因此不要在同一个 checkout 连续执行两次来模拟双客户端。也可用 Desktop 房主加 Mobile 访客；手机端点必须是手机可达的测试服务地址。
3. 房主打开已有任务，开启共享并复制邀请。访客从菜单加入，确认无需审批即可进入普通任务页，能够查看加入前的消息、工具结果和附件。
4. 同时发送不同内容，确认两个客户端看到同一 Agent 输出及正确作者。Agent 忙时编辑或撤回自己的待发送消息；修改其他成员的待发送消息应失败。编辑带图片的消息，保留旧附件并增加新附件，确认发送后和重载后都可打开。
5. 分别验证切换 Agent、模型和推理设置、停止 Agent、普通权限与 Full Access。已有审批由房主处理，访客能查看请求并继续排队发消息。
6. 访客断网后重连、房主重启，确认共享与历史恢复；让其中一个访客断线，另一个访客及同账号远控应继续工作。
7. 验证移除、退出、停止共享、归档和登出。旧邀请不能恢复已退出或移除的身份，新邀请可以重新加入；未共享任务与主机全局设置不可经访客客户端访问。
8. 验证本地工作区及 SSH 工作区的图片、音频、视频，检查 Light/Dark 和小屏。旧服务端或旧客户端应提示升级，不得退化成全设备控制。

## 验证记录（2026-09-16）

### 真实双账号 Desktop 联调

使用两个真实 Electron 开发客户端、不同账号和独立沙箱，连接隔离的 auth-server、device-link-server、PostgreSQL 与 Redis。Agent 使用真实模型并在房主执行工具；以下结果不是模拟 IPC 或 HTML 页面验证。

- 房主开启共享并复制邀请；访客无需审批即可加入，能读取加入前历史并准确回答其中的测试暗号。
- 访客发言进入同一个 Agent；房主和访客均显示访客作者、实时回复、工具活动和处理状态。
- 访客触发真实 PowerShell 工具；Agent 忙时，访客编辑自己的待发送消息，撤回另一条待发送消息；最终只处理编辑后仍保留的消息，不显示编辑标记。
- 房主移除访客后，访客立即离开任务、共享列表项消失；旧邀请被拒绝，房主生成新邀请后可以重新加入并读取历史。
- 房主独立重启，访客窗口保持打开且未刷新；连接自动恢复，新消息收到 HOST_RESTART_RECOVERED。观察到可信连接来源代次从 1 递增到 2，房主进程代次从 2 回落到 1，推送仍正常接收。
- 房主停止共享后，访客立即退出并看到远程任务已结束；原邀请无法重新加入。
- 每个关键步骤均保存真实 PNG 截图，并通过手机可打开的文件图片链接发送。

### 本轮修复与自动化验证

- 修复跨账号房主推送被同账号过滤器丢弃：绑定服务端已验证的房主身份，同时保留访客本地账号边界和房主来源代次校验。

### 三轮独立 Review 与逐轮修复（2026-09-16）
