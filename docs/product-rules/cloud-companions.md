# 云端伙伴：同一个伙伴、主力电脑与切换

> 修改伙伴的跨电脑身份、主力电脑、云端对话、切换电脑继续或相关 Chat Server 合同前必须先读本文。
> 伙伴运行时其余规则见 [cindy-bots-runtime.md](cindy-bots-runtime.md)，群聊见 [bot-group-chat.md](bot-group-chat.md)。

## 1. 用户心智

伙伴属于账号，不属于某台电脑。用户在任意电脑或手机上看到的是**同一个伙伴**：同一个名字、头像、
性格、记忆、技能和连续的对话。

每个伙伴有一台**主力电脑**：伙伴的 Agent 只在这台电脑上运行，工作目录、登录状态、模型连接和
本机文件都在这里。其他电脑和手机是看和说的入口，不另起一个同名伙伴。

2026-10-13 产品裁决（Dash 确认）：

1. 服务器按区域分开部署，伙伴数据不跨境，不为此另做加密方案。
2. 云端只存**对话层**：用户看得到的消息和伙伴的最终回复。工具调用明细、思考过程和完整运行记录
   留在主力电脑。
3. 主力电脑离线时明确告诉用户，并提供「在这台电脑继续」；默认不自动换电脑。
4. 迁移：每台电脑上的默认 Cindy 合并成一个云端 Cindy，第一台升级并登记的电脑成为主力电脑；
   其他电脑上原有的 Cindy 对话作为本机历史保留，可回看、可搜索，不再继续运行。其他伙伴本来就只
   存在于一台电脑，那台电脑就是它的主力电脑。

2026-10-16 产品裁决（Dash 确认）：

1. 每个伙伴都是跨设备存在的同一个伙伴，主力电脑只决定 Agent 在哪台电脑上运行；用户在**任何一台电脑**上
   都能手动更换主力电脑，换完仍是同一个伙伴、同一段聊天（§3.1）。
2. 多台电脑上原有的 Cindy 合成一个：统一身份与聊天，保留旧记录的来源，资料冲突时由用户选择保留哪份
   （替代上面第 4 条里「其他电脑上的 Cindy 对话只作本机历史」的做法，分批落地，见 §6「未覆盖」）。

## 2. 数据归属

| 存在服务器（跟着伙伴走） | 只留在主力电脑 |
|---|---|
| 身份：名字、头像（Chat Server actor） | 工作目录 `workspace/` 与其中文件 |
| 资料：简介、SOUL、自定义提示词、关于用户（USER.md）、来自哪个预设（`templateId`） | 模型连接、登录凭证、MCP 配置、权限档 |
| 记忆：`memories/*.md` 每条一份 | 完整运行记录（工具调用、思考） |
| 自有技能：`skills/<slug>/SKILL.md` | 例行任务的执行与运行记录（只在主力电脑运行） |
| 1:1 对话层：用户消息与伙伴最终回复，以及主人发送的附件原件 | 待办里在途的投递、插件的游标与回执 |
| 待办（未完成、设为稍后、近 30 天内完成的，最多 500 条，每条一份） | 工作台项目的文件本身 |
| 例行任务的定义（每条一份，不含运行记录） | |
| 工作台：项目目录（标明在哪台电脑上）与 PR / issue / 想法的判断 | |
| 主力电脑（`homeDeviceId`） | |

- 服务器是对话层与资料快照的权威副本；主力电脑是运行与写入的唯一来源。
- **只有主力电脑写云端资料**。其他电脑修改伙伴设置时，经现有远程设置（device-link）写到主力电脑，
  再由主力电脑上传。主力电脑离线时，其他端只读显示云端资料，不提供离线编辑，避免两端改出冲突。
- 模型候选链引用的是主力电脑的连接与型号，不跨电脑复用。换主力电脑后，新电脑先跟随本机默认模型，
  用户可再在设置里选。

## 3. 主力电脑

- 新建伙伴时，创建它的电脑就是主力电脑。存量伙伴在首次登记到服务器时，由登记的电脑成为主力电脑
  （服务器上为空才写入，不抢已有主力电脑）。
- 服务器只把伙伴的执行（群聊发言、1:1 离线排队的消息）派给主力电脑；其他电脑即使持有同一账号的
  凭证也领取不到。主力电脑用登录凭证里的设备标识（device-link 的 deviceId）表示。开启后，主力电脑尚未登记
  成功的伙伴在支持该功能的客户端上都不领取执行，直到某台电脑登记成功（之后每轮登记重试；服务端对空主力电脑保持原行为）。
- 其他电脑上同一伙伴的本机副本（例如合并前各电脑的 Cindy、换走主力电脑后的旧电脑）不再出现在伙伴
  列表里，也不运行例行任务；它的历史对话保留为本机历史。
- 桌面与手机的伙伴列表里，已知主力电脑的伙伴只在主力电脑名下列一行：其他电脑列出（或缓存着）的同一伙伴不显示；
  这台设备从没列到过主力电脑时（例如新手机、主力电脑一直离线），按云端伙伴补一行离线入口，用于打开云端对话。

### 3.1 离线与切换

- 像 IM 一样，主力电脑一时连不上不打扰浏览：伙伴列表和聊天头部不显示离线文字、离线圆点，头像不变暗；
  已打开的聊天保持原样（手机照常显示本机缓存的聊天，桌面在连不上的头 15 秒内保留当前聊天）。连接状态会随重连
  抖动，不能把一次断线当成主力电脑离线。
- 真的用不了时才提示：
  - 手机：发出的消息持续 15 秒仍送不到主力电脑，聊天区出现「消息还没送到主力电脑「<名字>」…」与「换一台电脑继续」；
    消息送达后提示立即消失。
  - 桌面：主力电脑持续连不上超过 15 秒，或打开时就连不上，聊天区改为云端对话（只读）与横幅
    「主力电脑「<名字>」离线 · 在这台电脑继续」。
  - 这台设备从没列到过主力电脑名下的伙伴（只能从云端补行），点开直接进入云端对话。
- 云端对话与在线聊天显示同样的消息：主人发的消息（包括主人在主力电脑上直接输入的）都上云；别的来源
  （任务、其他伙伴、插件、共享成员、定时任务、IM 渠道、群聊）发进来的消息加「〔来自…〕」前缀；只有不在聊天里
  显示的内部续接输入不上云。
- 点「在这台电脑继续」：
  1. 服务器把主力电脑改成这台电脑（带原主力电脑做比较，避免两端同时抢）；
  2. 这台电脑按云端资料、记忆和技能建立（或更新）本机伙伴，伙伴 ID 与云端一致；
  3. 把云端对话导入本机主任务作为历史，并以持久交接重建模型上下文，不重放任何旧请求；
  4. 打开这台电脑上的伙伴聊天，用户可以直接继续说话。
- 手机上同样显示离线横幅，「换一台电脑继续」列出在线且已允许远程控制的电脑；选中后服务器改主力
  电脑，那台电脑收到变化后自动完成第 2、3 步，手机随即打开那台电脑上的伙伴。
- 原主力电脑重新上线后，发现主力电脑已换走：停止领取执行，隐藏本机副本，伙伴改为显示在新主力
  电脑名下。它离线期间没来得及上传的资料以服务器版本为准，不回写覆盖。
- 伙伴设置的「主力电脑」一行和聊天头部的「在「X」上运行」显示当前主力电脑，任何一台电脑上都能点开更换：
  - 本机就是主力电脑：列出可接手的其他电脑，由本机交出（下面 §6 的交出规则）。
  - 主力电脑是另一台在线、可远程控制的电脑：列出那台电脑视角下可接手的电脑（包括这台），选中后经 device-link
    请主力电脑按同一套交出规则交出（`maker:companion-cloud:targets` / `maker:companion-cloud:hand-over`）；
    还在回复、资料没传完等情况由主力电脑拒绝并原样提示。换到这台电脑时，交出完成后立即重读主力电脑，
    本机按自动接管建立伙伴，建好后打开本机伙伴（约 2 分钟内没建好则提示稍后出现在列表里）。
  - 主力电脑离线或连不上：只能「在这台电脑继续」（上面的接管）。
  - 主力电脑上的 Cindy 版本不支持被远程请求交出：提示先更新那台电脑或在那台电脑上更换。
- 伙伴已暂停时不交出，提示先恢复。

### 3.2 头像

- 伙伴头像是身份的一部分，跟着伙伴存在服务器（主力电脑上传为公开图片地址），供群聊成员、手机、主力电脑离线时的
  其他电脑和换电脑时恢复使用。
- 读过的头像在本机缓存一份，显示时先读本机副本，没有才去主力电脑或服务器取，取到后保存；因此主力电脑离线、
  服务器暂时连不上或重启之后，读过的头像照常显示。缓存可回收，回收后下次重新获取。实现与存储边界见
  [媒体存储](../dev-rules/media-storage-and-protocols.md)「伙伴头像的本机副本」。
- 头像只把单个表情或字符当作文字显示；网址等其他内容加载不了时显示名字首字，不会把地址画成文字。

## 4. 1:1 对话层同步

- 每个伙伴在 Chat Server 上有一个固定的私聊房间（主人 ↔ 伙伴），房间 ID 由伙伴 actor ID 确定，
  任意电脑并发创建得到同一个房间。
- 主力电脑把主任务里用户可见的消息和伙伴的最终回复按顺序导入这个房间（导入不触发伙伴执行、不发通知），
  以本机消息 ID 去重，断网后从上次位置续传。主人发送的图片和文件经房间附件上传，其他设备可以打开，换电脑时下载到新电脑；
  只有永远传不了（文件已不在、超过大小、旧格式地址、聊天服务器拒绝）时才退回文件名占位；暂时失败（断网、服务器 5xx、超时、
  签名地址过期——对象存储返回 401/403）时这一轮停下、下一轮连同这条消息重试，换电脑时的下载与合并 Cindy 时的搬运同样按这条区分（暂时失败则
  接管或合并本次失败、稍后重试）。只发附件没有文字的消息同样同步。伙伴回复里引用的文件暂不上传。
- 房间保存完整对话：开始同步之前的本机历史（包括这台电脑接管前自己的历史）在后台按时间从旧到新补传，每轮有上限，
  交出前补完。房间按到达顺序排列，读取时（离线查看、接管导入、手机）按消息时间排序。
- 主力电脑在线时，其他电脑与手机继续用现有远程方式（device-link）直接看和发主任务，体验不变。
- 主力电脑离线时，其他端从房间读取对话层；用户在离线横幅里选择切换电脑后再继续。
- 房间里由主人直接发出的消息（例如未来的离线排队）在主力电脑上线后由它领取，作为「来自其他设备」的
  消息投递进主任务；伙伴回复由导入同步回房间，不重复写。主任务未在运行时按它保存的权限档唤醒，不借后台唤醒的默认完全访问。房间消息等同同账号设备远程操作这台电脑，只在这台电脑开启「允许同账号设备控制本机」时投递（否则该条执行失败、不进主任务）；房间消息没有经认证的设备标识，无法按「已撤销的控制设备」逐台拒绝。

## 5. 管理用户开放的其他电脑

- 伙伴可以在用户开放的其他电脑上干活：沿用协同（Orca）的跨电脑执行，`get_workspace_info` 返回的
  `execution_devices` 即可用电脑，`create_worker` 传 `execution_device_id` 把任务、目录与命令放到那台电脑上。
- 「开放」沿用每台电脑设置里的「允许同账号设备控制本机」，不新增授权开关；关闭后伙伴立即用不了那台电脑。
- 共享伙伴指南只说明这条路径与限制，不暗示能直接读写别的电脑上的任意文件。

## 6. 兼容与发布

- 新功能以服务器 `GET /me` 返回的 `capabilities.companionHome` 为开关；旧服务器上客户端保持原有
  按电脑工作的方式，不登记主力电脑、不导入对话。
- 旧客户端不认识主力电脑：服务器对它们的执行领取同样按主力电脑过滤，因此旧电脑不会再抢新主力电脑的
  群聊发言；旧客户端的本机伙伴列表不受影响。
- 对话导入、资料上传都是幂等、可重试的后台工作，失败不影响本机聊天；不新增本机数据库表，
  映射与游标存于账号隔离的状态文件。
- 在主力电脑上删除伙伴时，同时在服务器停用它的 actor（带「主力电脑仍是本机」的比较，期间已被别的电脑接走就只删本机副本），其他电脑与手机不再显示；失败时在状态文件记下
  `retirePending`，之后每轮登记重试直到成功；重试前伙伴已被别的电脑接走时清掉这条记录（与比较失败一样只删本机副本），以后交回来也不会被停用。删除已降级的本机副本只删本机，不动云端伙伴；同一台电脑上另一个 Cindy
  安装认领了伙伴时同样只删本机；本安装尚未确认认领（检查未完成，或伙伴刚被交到这台电脑）时，先按自动接管的方式认领，
  抢到才停用，被另一个安装抢先则只删本机。其他电脑（包括删除时离线、之后才上线的）
  看到云端伙伴已停用时，把本机副本转为降级：隐藏、只读、不运行。
- 接管时导入房间里的全部对话为本机历史（读到房间第一条为止，读不完整则这次接管失败、稍后重试；合并 Cindy 同样如此；云端对话查看最多读最近约 5 万条），附件一起下载。服务器不回传导入来源 ID，本机按「角色 + 消息时间（毫秒）」
  识别这台电脑当初导入上去的消息；已插入的云端历史（`cloud-history:<消息>`）和房间里直接发给伙伴、已投递进本机主任务的消息（`chat-direct:<执行>:<消息>`）按房间消息 ID 识别，都不重复插入（接管中途失败重试时，同一时间的拆分片段不会被误跳过）；之后像「重启伙伴」一样从历史重建上下文，伙伴还有一轮在跑时等它结束再重建，期间副本保持降级。
- 已降级的本机副本：不领取执行、不上传、不导入对话，不同步名字与头像，不出现在伙伴列表、主入口选择、
  Cindy 多设备合并、本机 `list_agents` 和远程资源 `teammates` 列表（因此也不出现在其他设备的 `list_agents`），
  例行任务跳过但定义保留。主任务的所有发送通路（界面、内部派发、插件、队列出队）都在真正发送前拒绝。降级名单另存于账号隔离的 `companion-cloud/shadowed.json`，切换账号后的第一次读取就换成新账号的名单（不沿用上一个账号的主力电脑与降级状态），启动后、服务器不可达
  或功能关闭时同样生效；写盘失败时本次运行照样隐藏，并在之后每轮登记时重试写入，直到写入成功。打开它的主任务时只读（本机的设置抽屉不打开，设置从主力电脑上的伙伴进入）：横幅「这个伙伴已在「X」上运行」，可打开主力电脑上的伙伴或
  「在这台电脑继续」；主进程向降级副本主任务的发送一律拒绝。
- 只有主力电脑上、未降级、且本安装已确认运行该伙伴的副本才把名字与头像同步到云端 actor，并且在主力电脑登记之后才同步。
- 接管总以缓存里的主力电脑做比较再写入，即使缓存显示本机已是主力电脑（离线期间可能已被别的电脑接走）。
  自动接管（被手机或另一台电脑交过来）先以「本机→本机」比较确认主力电脑仍是本机，再解除降级。
- 接管期间本机副本保持降级（不运行、不上传、不导入），在本安装认领伙伴之前、第一次本机写入之前就发布降级（发送拦截、例行任务、列表立即生效），资料、头像、记忆和技能全部写入成功、历史导入且上下文重建完成后才解除
  （伙伴还有一轮在跑时等它结束再重建，期间保持降级）；重建失败同样保持降级重试（已有副本的头像
  也换成云端头像，云端没有头像时用新建伙伴的默认头像，避免新主力电脑把旧头像回写覆盖云端身份）；任一条写入失败或头像下载失败
  时保留已写入的部分并保持降级，由自动接管约每分钟重试，避免残缺副本运行或把旧文件上传覆盖云端。云端还没有
  主力电脑上传的完整资料快照（`companion.profile.v1`，`name` / `description` / `soul` / `systemPrompt` / `user` 都是字符串）时不改主力电脑：「在这台电脑继续」和手机「换一台电脑继续」都先检查
  快照，没有就提示失败、主力电脑不变；万一已被交过来（例如旧版本）也保持降级重试，不把这台电脑的旧资料当成伙伴身份发布。
- 接管的本机写入（资料、文件、记忆、技能、历史、重建）都绑定发起时的账号，切换账号即中止；头像经共用的公网图片下载（逐跳拒绝内网 / 本机地址，边读边限 5 MB）获取，15 秒超时，
  账号结束时取消。
- 接管已有的本机副本（例如第二台电脑自己的 Cindy、曾经交出去的旧副本）前，先把它的伙伴目录（不含 workspace）
  备份到账号隔离的 `companion-cloud-backups/<伙伴>-<时间>/`，并写日志；每次接管只备份一次，接管失败后的重试不再备份。
  接管以云端为准：云端有值的记忆 / 技能覆盖本机，云端墓碑删除本机同名文件（内容不同也删，原件在备份里），之后上传
  不会把已删除的内容带回云端。资料上传只给本机曾上传或曾接管写入过的键写墓碑，服务器上仅存在的键（含本机未能写入的
  记忆）从不被墓碑。云端既没有值也没有墓碑、只存在于这台电脑的记忆 / 技能（例如第二台电脑 Cindy 自己积累的）接管后保留，
  并作为新内容上传、合入伙伴（Dash 2026-10-13 确认：合并，不按云端删除）。
- 技能按 `SKILL.md` 原文（含 Cindy 不认识的原生 frontmatter）上传与恢复，停用状态一并恢复（整个技能目录在启用 / 停用之间移动），换电脑后技能语义不变。
- 接管后对话镜像从本机最后一条自有消息（不含导入的云端历史）之后开始，本机接管前的旧对话不上传到房间。
- 资料上传遇到版本冲突时先确认本机仍是主力电脑（否则停止并重新读取），再按服务器当前值最多重写一次；读本机资料（SOUL / USER / 自定义提示词）、
  记忆与技能时只有「不存在」视为空，其它读取错误跳过本轮且不写墓碑；接管时读不到本机文件同样中止、保持降级重试；首次升级的大批写入每轮每台电脑最多约 30 条，其余下一轮。
- 对话导入与伙伴聊天里看到的一致（2026-10-17 Dash 确认：离线时的显示要和在线一样）：主人输入的用户消息（含其他设备上的输入；`agentMeta.autoReviewUserText` 是主人本人输入的标记，不是其他来源）、伙伴回复（不含私有协调回复、过程旁白 `assistantPhase: commentary` 与子 Agent 输出（`parentToolUseId` / `parent_tool_use_id`，以及与界面同一判据的 Claude `parentUuid`）；一轮还没结束时、工具调用前的旁白仍按普通回复导入），以及聊天里可见的其他来源输入（其他任务、伙伴、插件、IM、定时任务、协同、共享成员、群聊）。后者在正文前加一行与聊天标签同口径的来源，如「〔来自飞书〕」；IM 只取本人原话，不带宿主拼接的上下文。聊天里本来就隐藏的自动续跑（`autoResume`）、伙伴间协调（`botTaskCoordination`）与委派续跑不上云。游标之外每轮回扫最近 10 分钟（从窗口开头起最多 200 行；10 分钟内超过 200 行时，排在后面的晚落库回复可能漏掉、只留在本机），
  补上晚落库的回复；接管导入的 `cloud-history:` 行不推进游标。首次同步先导入本机最近 1,000 行里最近 200 条可上云的消息，
  更早的由补传带上（见 §4）。已回退或删除的本机消息不导入，接管时也不再插回。
- 已暂停的伙伴不交出（不同步资料与对话）：设置里的「主力电脑」行提示先恢复再换电脑。
- 伙伴在任一任务里（主任务、群聊 / 群分工专线、委派）还有一轮在运行或排队时默认不交出，界面问用户「等回复完再换」
  （主力电脑上最多等约 4 分钟，期间这一轮的回复照常同步）或「停止并换」（按用户的停止停掉各任务里的这一轮，再交出）；
  从其他电脑或手机发起时同样由主力电脑执行这两种选择；已领取、尚未投递的 1:1 房间消息在投递前再确认本机仍是主力电脑，交出后不再投递（提示「还在回复，等这一轮结束再换电脑」），在同步前和改主力电脑前各检查一次，避免交出后旧电脑上的这一轮继续调用工具、改文件、产生不会同步的回复。
- 交出伙伴前先把积压的对话全部导入房间（不受平时每轮最多 10 页的限制），再上传全部资料并重复上传直到一轮没有新变化，再立即同步伙伴的名字与头像（不再等下一轮登记；这个伙伴的头像上传失败同样不交出；别的伙伴头像有问题不影响，各伙伴的名字与头像分别同步），然后才改主力电脑（连续变化时不交出、提示失败），导入期间改动的资料也会带上；交出期间后台的定时上传与导入暂停（先等正在进行的一轮结束），
  不会有旧的一轮在交出之后再写入云端；有超过上传
  上限的值（例如过大的技能）时同样不交出，原主力电脑保持不变。
- 交出伙伴前探测目标电脑的 `maker:companion-cloud:caps`（device-link 只读通道，返回 `{companionCloud: <版本>}`；
  1 = 能接手伙伴，2 = 另外接受其他电脑请它交出伙伴），版本低于 1 则拒绝该目标；可选目标列表同样只列支持的电脑。
  其他电脑和手机请主力电脑交出前同样探测：低于 2 时不提供更换，提示先更新主力电脑。手机端离线横幅的「换一台电脑继续」暂未探测（见下）。
- 请主力电脑交出（`maker:companion-cloud:hand-over`）是同账号远程控制写操作：只在主力电脑开启「允许同账号设备控制
  本机」时可用，不进共享任务访客白名单；隧道超时放宽到 7 分钟，因为交出前可能先等这一轮结束，再传完积压对话与全部资料。回执丢失时
  发起方立即重读主力电脑，按服务器上的实际主力电脑显示。
- 同一台电脑上的两个 Cindy 安装（例如开发版与正式版）共用设备标识。每个安装在自己的 userData 生成随机安装 ID，
  主力电脑上的安装把伙伴偏好 `companion.install.v1 = {installationId, deviceId}` 写为自己的；设备相同但安装 ID 不同的
  安装把伙伴视为降级（隐藏、不领取、不上传、不导入、不自动接管）。在那个安装里「在这台电脑继续」会改写这条记录；
  另一个安装最多约 2 分钟后发现并转为降级。记录还未读到（或读取失败）时不领取执行，但不隐藏本机副本、不拦本机发送（离线的主力电脑必须照常可用）；因此伙伴刚被交到这台电脑、本机恰有一份从未同步的副本时，在读到记录之前的一次请求往返里，这份副本仍可在本机使用，读到后才转入自动接管。记录来自另一台电脑时，说明伙伴
  刚被交到这台电脑：即使本机已有一份从未同步、也未降级的副本，也按自动接管完成（先备份）。自动接管只替换来自其他电脑的
  记录，不抢同一电脑上另一个安装已认领的伙伴；要换安装只能在该安装里手动「在这台电脑继续」。
- 1:1 房间的执行只在开启该功能、且房间是这个伙伴自己的房间（已记录的房间 ID，或成员恰为主人与该伙伴的 `direct`
  房间）时投递进主任务；其它 `direct` 房间不按群聊回答。所有 `direct` 房间都不出现在群聊列表。
- 端到端验证：`apps/desktop/src/main/companion-cloud/__tests__/twoDevices.harness.test.ts`，设置
  `CINDY_CHAT_HARNESS_URL` 指向一次性的本地 chat-server 时运行，CI 跳过。
- 当前未覆盖：从房间投递到主任务的消息暂不标注
  「来自其他设备」，因为房间消息没有经认证的设备标识，不满足 [消息来源](message-source.md) 的盖章条件。
- 手机换电脑后，只有在等待期间从目标电脑读到的列表行才算接管完成，缓存里的旧行不算。手机伙伴列表在列出的行变化
  （新行出现或已有行内容更新）和下拉刷新时重新读取各伙伴的主力电脑，停留在列表上也能跟上别处发起的换电脑。
- 已知限制：主力电脑在第一次上传资料之前就离线时，其他电脑和手机暂时不能换电脑继续，要等主力电脑重新上线上传后。
- 已知限制：交出伙伴时，对话导入完成之后产生的对话，以及最后一轮上传之后、服务器改主力电脑的请求返回之前（一次请求往返）
  写入的资料或记忆不会上传，只留在原电脑的本机副本里；不为此冻结伙伴的本机写入。原主力电脑仍在线时被别处「在这台电脑继续」接走，
  它正在进行的那一轮上传（资料，或一批对话导入）可能在接走之后才写入云端；迟到的对话留在房间里，新主力电脑已完成的历史导入不会再吸收它，直到下次接管。资料方面：新主力电脑本机仍是接管时的值，且不会覆盖这次写入（首次同步只更新版本号，不把云端较新的值当成本机修改；本机真正改了这一项才会上传），下次接管时才拿到；
  服务器的偏好写入不校验主力电脑，不为此新增服务端契约。
- 已知限制：哪些云端值由本机上传或接管写入，只记在账号隔离的状态文件里（只有这些键会写墓碑）。状态文件丢失或损坏后，
  重建的记录不带这个归属：此后在本机删除的记忆、技能、例行任务、工作台内容，以及超出随行范围的待办，不会在云端清掉，
  下次接管会带回来（原值仍在，不丢数据）；不为此另存一份归属，也不按服务器上的键补写墓碑——状态丢失时分不清
  「本机删过」和「本机还没恢复」（例如接管途中丢失），补写可能删掉云端唯一的一份（2026-10-17 取舍：宁可多带回，不误删）。状态文件写入失败（例如磁盘已满）时，本次运行里的状态照常生效（降级立即生效），下一次更新时连同写入；
  在写入成功前退出则丢失这些记录，按上面的状态文件丢失处理。降级名单（`shadowed.json`）读不出来或内容损坏时按空名单处理：服务器可达且功能开启时会按主力电脑
  重新降级；在服务器不可达或功能关闭的那次启动里，旧副本可能暂时显示并可在本机使用。状态文件损坏不另做保护。
- 已知限制：「在这台电脑继续」用于原主力电脑离线（或被认为离线）时接管，不能等待或停止原电脑上正在运行的一轮。原电脑其实
  还在跑时，它下一次同步就会降级、不再接新工作，但已在进行的那一轮会跑完，期间的工具调用、文件改动和回复只留在原电脑本机；
  不为此在降级时强行中断运行中的一轮。
- 已知限制：`/me` 返回的设备标识变化（例如重新绑定设备）会让这台电脑上所有伙伴转为降级；房间里的占位文字
  （如 `[附件: …]`）固定为中文；降级发生时正在进行的那一轮不会导入；已导入房间后又在本机回退的消息仍留在房间；
  删除伙伴时若当时没有可用的云端连接（未登录或旧服务器），不会记下待停用；手机换电脑不探测目标版本。
- 待办、例行任务与工作台跟着伙伴走：换电脑时在新电脑上按 ID 恢复（云端为准；例行任务的墓碑删除本机同一条，待办的
  删除本身是一条标记、随值走，待办的墓碑只表示它已超出随行范围（关闭超过 30 天或排在 500 条之外），云端清掉、本机保留）。
  旧工作台判断转成的待办到新电脑后按同一 ID 重新挂回那条判断，不另生成一条。例行任务的计时从
  恢复时开始，不补跑错过的；带有原电脑检查命令的、一次性触发时间已过的，到新电脑先关闭。工作台里原电脑上的项目目录
  显示为「在「X」上」，不作为这台电脑的授权范围；回到原电脑时恢复为本机目录。待办里尚在投递的动作不带走。
- 伙伴列表与未读计数：伙伴已知在别的电脑上运行时，本机副本立即不再列出（不必等降级发布），每个伙伴只出现一行；
  已接入云端的 Cindy 不再进入按电脑列出的旧 Cindy 合并入口，只有未接入云端的才保留它。
- 合并多台电脑上的 Cindy（2026-10-16 裁决第 2 条）：只认由 Cindy 预设创建的伙伴（资料快照里的 `templateId`、默认身份
  或 `cindy-default`），从不按名字。Cindy 的设置里出现「合并重复的 Cindy」，用户选一个作为名字、性格与设置的基准；
  由它的主力电脑执行（在别的电脑上发起时经 `maker:companion-cloud:merge` 请它执行，连不上或版本较旧时提示）：
  先请每个被合并的 Cindy 的主力电脑把还没上传的对话与资料传完（本机直接做；别的电脑经 `maker:companion-cloud:flush`；
  还在回复时提示等回复完再合并，有 Cindy 已暂停（保留的或被合并的）时提示先恢复，同步失败则不合并；那台电脑连不上或版本较旧时按云端已有的合并，没传上来的留在那台电脑上）。
  然后其他 Cindy 的记忆、自有技能、待办、例行任务、工作台与全部对话并进来，对话保留原时间，附件重新上传；

  按来源派生的新稳定 ID（同 key 的待办另起稳定 key），不会互相覆盖。全部并完、保留的 Cindy 本机任务也导入完成后，再请各来源同步一次：期间
  开始回复或有了新内容（云端的资料或对话比读取时新）时这次不停用、提示稍后再合并；确认没有新内容后其余 Cindy 才在云端停用，
  它们的电脑把本机副本转为降级，资料仍在云端与原电脑上；在此之前失败，来源都保持可用，再合并一次即可，不会重复。
  服务器不需要改动。
