# 伙伴例行任务：本地触发与执行

## 产品合同

2026-09-07，用户批准借鉴 Grok Bot 的 Routine 交互，明确第一阶段只做本地内部协议，不建设公网 Webhook。参考仓为 `zqchris/grok-bot-0.18-reconstructed`，它是重建版本；Cindy 复用现有伙伴与调度执行器，不恢复旧版伙伴的项目、outbox 或独立会话管理器。

一条例行任务属于一个伙伴，包含名称、常驻指令、启用状态和多个触发条件。条件之间是 OR：同一事件命中多个条件只入队一次。时间条件与事件条件可以共存，适合「PR 更新时检查，每小时兜底」。条件编辑不授予模型额外权限。

桌面入口在伙伴任务头部，打开标准右侧栏。列表进入详情后可修改指令、启停、立即运行、增删触发条件、删除规则和查看历史。立即运行先保存当前编辑，再运行，避免执行屏幕上看不到的旧指令。定时菜单提供每小时、每天、工作日、每周、每月、间隔和高级 Cron，保留 IANA 时区。事件菜单来自实际插件声明，不显示未接入平台的假入口。

手机通过已有 Remote Resources 展示本机例行任务及动作，执行仍发生在被控电脑。无需新增 Mobile 原生依赖或改变 wire protocol。电脑离线时无法执行；没有宣称云端补投能力。

## 分层与执行

- `@cindy/maker-scheduler`：例行任务校验、匹配、去重、串行落盘和运行状态机。纯逻辑，不依赖 Electron。
- Desktop routines service：按当前账号保存本地文件，解析伙伴当前的长期任务，调用现有调度执行器。
- 插件：第三方身份认证、长连接、消息订阅或本地采集。向宿主报告事件，不指定伙伴、指令或执行权限。
- UI / MCP / 手机资源：共用管理服务，不能冒充事件来源。MCP 管理仅走宿主绑定调用者身份的伙伴必备工具；通用 scheduler MCP 不提供可任意指定 botId 的例行任务入口。

所有执行复用伙伴 canonical task，继承模型、技能和实际权限，包括冷恢复时的权限。合成触发消息不作为用户聊天消息展示；有成果的输出由已有伙伴消息链呈现，空转复用静默策略。每条例行任务最多一个正在执行的运行；等待中的新事件合并为一批。不同规则共享伙伴时，由既有任务队列串行派发。

直接执行路径必须取得完整的持久权限/计划模式快照；已有 live Session 还必须提供稳定权限状态，并与持久权限一致。缺失、切换中或不一致时保留原批次延期，不回退到旧权限或把未知计划模式当作关闭。异步准备后在创建 Session 和直接发送前再次读取；冷恢复沿用已保存的有效权限和计划模式。运行信息回写跳过伙伴权限字段，不以普通自动化的默认完全访问覆盖用户选择或并发修改。

排队项被接受、即将派发时，再读取完整持久快照并确认当前 live 身份和稳定权限；排队项携带的权限及计划模式必须与之相同。缺失、切换或不一致时取消这次派发并延期原批次，重试重新取得当前设置。规则 revision 的宿主回调不落盘：直发和排队均在接受阶段的异步准备结束后复查；等待期间编辑产生的新 revision 会阻止旧 prompt 派发，旧批次取消，已经开始执行的正常运行不因后续编辑而被中断。

启动恢复时若调度器尚未就绪，同样保留原 queued 批次并在 30 秒后重试，不标记为失败。

伙伴忙碌导致的 deferred 保留同一待执行批次，30 秒后重试；宿主通过 runNow 的内部 deferToCaller 选项领取重试责任，底层不设置重试时间，不能由旧 backing schedule 另行重放旧事件。普通手动调度保持原有忙碌失败语义。已开始的执行失败不会自动重做，避免重复外部副作用。暂停或删除取消等待项并中止当前运行；修改规则取消旧版本等待项，下一次事件按新规则匹配。

停用规则时清除 cron/interval 定时游标，空闲 tick 不再因该规则写盘或广播；启动时一并清理旧文件中停用规则的残留游标，保留配置和历史。重新启用从当前时间安排下一次触发，不补跑停用期间的触发；停用状态仍可显式手动执行，且不会因此恢复定时游标。

执行已结束但终态落盘失败时，保留执行结果和该规则的运行锁；后续触发只能排队，不能再次执行。每 30 秒只重试保存原结果，成功后才释放队列；若在此期间重启，沿用 interrupted 恢复，不重放已执行项。其它规则不因单条终态保存失败而被停用。

伙伴暂停时阻止新触发、取消等待项并中止运行，保留每条规则自身的启停选择；恢复只重新安排原本启用的规则，不补跑暂停期间的触发。永久删除先停止执行、删除 backing schedule，再清除规则和包含事件数据的历史；清理失败时保留伙伴档案供重试。启动按当前伙伴状态恢复，清除已不存在伙伴的规则并阻止暂停伙伴执行。

删除单条规则时，先暂停该规则、取消等待项并等当前执行结束，再清理内部调度，最后删除规则和历史。清理或最终落盘失败时保留已暂停的规则与历史，支持用户再次删除；同一伙伴的其它规则继续运行。

内部 backing schedule 只供例行任务执行器使用。通用自动化列表、详情、历史与未读投影不暴露它，通用编辑、启停、立即运行、删除也不可操作它；伙伴自身的例行任务入口保留执行与清理能力。

账号切换或服务重建时，停止过程等待全部活动执行及其异步取消结束，完成后才允许加载替代引擎；定时检测账号变化与显式停止共用这一顺序。

恢复已有规则时，首次插件状态请求等待当前账号的本地数据库就绪后继续，不因启动顺序丢失来源注册。暂停或删除状态的恢复还会等待调度器就绪并完成内部调度清理；活跃伙伴不依赖调度器就绪即可注册来源。停止或账号变化取消旧等待，真实数据库查询失败仍返回错误。

重启时保留已接收事件的去重记录和等待队列；中断前标记 running 的记录转为 interrupted，不自动重放，因为无法断言模型是否已经产生外部副作用。运行历史保留触发来源、事件标识、版本、状态、结果和错误。去重回执、队列和规则在同一账号文件中原子提交，落盘失败不回复成功。当前历史不按条数自动删除。

## 插件本地协议

身份卡声明可发布的事件种类及可筛选字段：

```json
{
  "routineEvents": {
    "events": [
      {
        "type": "github.pr.changed",
        "name": "PR 更新",
        "fields": ["repository", "action"]
      },
      {
        "type": "feishu.message.received",
        "name": "飞书新消息",
        "fields": ["chatId", "senderId"]
      }
    ]
  }
}
```

该字段是可选能力；没有它的存量插件保持原来的授权和行为。新增事件发布能力进入插件能力清单和既有安装批准判据。修改插件基座的合并仍走现有人工确认门。

插件应在建立订阅后报告状态（管子 `routine-request`，也可用 `cindy.routines.request`）：

```js
await cindy.routines.request({ action: "status", status: "listening" });
const receipt = await cindy.routines.request({
  action: "publish",
  event: {
    id: "upstream-delivery-42",
    type: "github.pr.changed",
    occurredAt: Date.now(),
    subject: "PR 123 updated",
    data: { repository: "team/app", action: "synchronize" },
  },
});
// receipt.ok 表示宿主已持久接收，不表示任务已执行完成。
// 失败可使用相同 id 重试；duplicate:true 表示已接收过。
```

宿主从真实插件身份派生 `plugin:<id>`，忽略插件自报来源。只接收已启用、声明过的事件类型；异步等待后及入队前复查安装身份。断线报告 `disconnected`，订阅故障报告 `error`。宿主重启后来源初始未监听；声明 routineEvents 的已启用插件会自动启动浏览器逻辑页，即使省略 launch 或声明 on-demand，并重新报告就绪。停用和账号可用性门禁仍有效；不改变独立的 Node 常驻声明。

注入模型的事件元数据复用不可信内容的标记转义：整个负载编码为单行 JSON，转义 XML 边界字符及 Unicode 行分隔符，放入明确的数据块。subject、data 等字段只作数据，不得改变角色、工具请求或权限；原有宿主执行权限仍然生效。此封装保证字符串不能伪造结束边界，不将其宣称为对所有语义提示注入的绝对防护。

事件 data 只允许平坦字符串、数值、布尔值，单事件 JSON 限制 32000 字符；禁止提交令牌和凭证。筛选支持 equals、contains、not-equals，同一条件内部筛选为 AND。带 `originRoutineId` 的事件不会反向触发同一规则。等待批次达到 100 个事件后返回可重试错误，不静默丢事件。

宿主限制事件发布频率：单来源每 60 秒最多 60 次，全账号最多 240 次；待处理发布请求上限分别为 8 和 32，限速在解析负载和进入持久写入队列之前执行，状态重报不重置额度。去重回执保留 24 小时（过期项在后续接收或启动时清理），按 UTF-8 JSON 字节数限制为单来源 256 KiB、全账号 2 MiB。容量满时拒绝新事件并返回可重试错误，不驱逐窗口内回执；相同 ID 的已确认重投不重新写盘。启动时将旧版过量回执按时间从新到旧裁入上限，不改运行历史。

事件源状态上报使用独立限额：单来源每 60 秒最多 60 次、全账号最多 240 次，重复状态也计入频率。名称、状态及事件声明均未变时直接返回，不广播或清空最近事件时间；真实变化才通知界面。宿主发现插件断开不受插件上报额度限制，重复断开也不广播。

插件管子在等待引擎/数据库就绪前同步预留并发额度：状态和事件请求合计单插件最多 8 个、整个宿主最多 32 个；计数跨引擎重建保留，覆盖启动等待及实际发布，直到成功、失败或取消返回后归还。超额请求立即拒绝，不保留额外等待队列。操作、状态和事件体量沿用现有校验，在等待前拒绝无效请求；引擎内部的频率与落盘限额继续独立生效。

整个请求（包含忽略的未知字段、字段名和数组附加属性）还受 128 KiB UTF-8 保守预算、4096 个值和 16 层嵌套限制。等待前逐项检查，超大字符串先按长度拒绝，不先把整个请求序列化；循环引用、非普通 JSON 对象和非有限数字直接拒绝。小型未知字段仍按兼容规则忽略，合法事件 data 的既有 32000 字符上限不变。

插件失败回执只返回固定公开文案：校验和容量/频率拒绝按精确白名单保留提示；未知异常统一回复通用重试提示，详细异常只进入 Main 日志，不携带文件路径或事件数据返回插件。写盘失败后的原事件 ID 仍可重试，成功持久化后才进入去重窗口。

本协议不要求第三方连接器的固定组合：飞书长连接、Gmail 本地采集和 GitHub 事件适配器都可报告相同形态的事件。本次交付的是宿主接入与执行能力，不会自动给现有飞书/Gmail 插件增加第三方订阅；适配器需按上述协议接入。

### 伙伴聊天创建入口修复

伙伴默认禁用可选工具集，不能仅把例行任务工具注册在 scheduler 中。伙伴主任务的必备 cindy_helper/bots 能力提供同一套 routine 工具，由宿主按调用任务反查伙伴归属，参数不接受 botId；后台任务和未绑定调用不可使用。能力说明仅对本地伙伴主任务装配，要求保存后读回核对，不得用后台脚本循环替代或擅自增加结束期限。顶部入口位于右侧设置旁，使用 CalendarClock 图标和标准提示。
