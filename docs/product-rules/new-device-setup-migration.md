# 新电脑设置：迁移助理

> **读取时机**：修改「迁移助理」（从其他电脑迁移）的入口、迁移范围、`maker:setup-snapshot` 协议、
> 计划与应用规则、一次性配置清单，或新增一类可迁移的设置前。
> 跨电脑通道见 [`../dev-rules/remote-and-mobile-adaptation.md`](../dev-rules/remote-and-mobile-adaptation.md)，
> 凭证边界见 [`../dev-rules/credentials-and-local-storage.md`](../dev-rules/credentials-and-local-storage.md)，
> 插件安装确认见 [`../dev-rules/plugin-security-and-authoring.md`](../dev-rules/plugin-security-and-authoring.md) §3.1。

## 1. 用户心智

像新 Mac 登录 Apple ID 后「从另一台 Mac 迁移」：在新电脑上登录同一个 Cindy 账号，选一台
已经用顺手的电脑，把它的插件、技能、设置和连接一次搬过来。API Key 等密钥在那台电脑上有人点
「允许」后一起复制；SSH 服务器由那台电脑为新电脑的新密钥授权并测通。真正必须在这台电脑上做的事
（重新登录账号、授予系统权限）列成一份清单，可以「依次完成」逐项跳到对应设置页。

- **入口**：设置 → 通用 →「迁移助理」→「打开迁移助理」。功能名称统一为「迁移助理」；入口只写一句描述：在一台新电脑上，把其他旧机器上 Cindy 所有接入的功能、插件和设置复制过来，成为成品能用。实际迁移范围仍以下文第 2 节为准。看起来是新电脑（没有用户自己装的
  插件、自定义供应商和自定义 MCP）且有可读取的同账号电脑时，登录后约 6 秒建议一次；
  「以后再说」后不再自动建议，设置入口一直在。
- **前提**：两台电脑都登录同一账号、都在线；被读取的电脑开启了「允许同账号设备控制本机」
  （与远程控制同一个开关，不新增授权）；两台都是支持本功能的版本。
- **不影响原电脑**：读取是只读快照，原电脑的配置、插件、凭证与任务都不变。复制密钥只读不改；
  SSH 一步只在原电脑能连上的服务器的 `authorized_keys` 末尾追加新电脑的公钥（已存在则不动）。

## 2. 迁移范围

| 类别 | 处理 | 说明 |
|---|---|---|
| 插件市场插件（含组织插件、默认下发插件） | 自动安装 | 用这台电脑的市场按 `pluginId` 重新下载、校验、落位，版本取这台电脑市场的当前版本；保持原电脑的启用/停用 |
| 自定义 Git 插件市场及其插件 | 自动添加后安装 | 只迁移不含凭证的 https / ssh 地址；带 token 的地址与本地文件夹市场列入清单 |
| 本地导入 / Forge 插件 | 清单 | 只有安装目录，没有可重建的来源；提示在原电脑导出 `.cindy` |
| SkillHub 技能 | 自动安装 | 按名称与目录范围安装最新版；保持原电脑的停用状态。这台电脑已装的同名技能只同步启用/停用 |
| 手写 / 导入 / 学习得到的技能 | 清单 | 不在 SkillHub，只存在于原电脑 |
| 设置（21 组，见 `settingsGroups.ts`） | 自动写入 | 只复制原电脑**改过**的值；这台电脑已改过的键一律保留 |
| 界面偏好（主题、语言、通知、对话显示、返回窗口时的误点保护、实验开关、自定义提示） | 自动写入 | 白名单见 `shared/setupMigration.ts`；只写这台电脑没有设过的键；自定义提示只迁移当前账号自己的；写入后需刷新界面。误点保护的开关与 Windows 点击处理以界面存储为准，设置文件里的同名值只供 macOS 建窗读取，两处一起迁移 |
| 内置工具开关 | 自动写入 | 「自动操作」与 Android 需要系统权限，改为清单 |
| 自定义模型供应商、自定义 MCP | 自动创建；勾选「密钥」时连同密钥 | 快照本身不含密钥：MCP 的请求头与地址中的用户名、密码、查询参数，供应商 runtime 的 `baseUrl` / `modelsUrl` / 请求路径、模型路由地址与 OAuth 端点里的用户名、密码、查询参数和片段都不进快照（只在导出边界处理，不限制本机配置）。勾选「密钥」且原电脑允许后，API Key 连接与 MCP 按原样（含地址、请求头、Key / 访问令牌）由 Main 创建；没有复制到的仍按快照创建，密钥列入清单。OAuth / 订阅登录的连接一律重新登录。本机回环地址的本地模型列入清单 |
| 内置工具与插件的 API Key（Brave、Tavily、Mivo、Gemini、OpenAI 图像；插件声明由用户填写的 Key / PAT） | 勾选「密钥」时复制 | 只写这台电脑还没有的；插件须已装在这台电脑且声明了同名 Key。插件 OAuth 账号、登录邮箱派生、主机托管凭证、xAI 订阅登录与语音识别凭证不复制 |
| 允许同账号设备控制本机、保持电脑唤醒 | 可选开启 | 只在原电脑开着、这台电脑关着时出现，默认勾选，用户可取消；从不替用户关闭 |
| 远程桌面 | 清单 | 需要单独开启并授予屏幕录制权限 |
| IM 机器人（Telegram、飞书、企业微信、钉钉、Discord） | 清单 | 凭证不迁移；同一机器人同时只在一台电脑收消息 |
| SSH 服务器（Cindy 列出的主机，含 `~/.ssh/config` 中的） | 自动添加并测通 | 只迁移别名、地址、端口、用户与原电脑已信任的主机指纹；`ProxyCommand` 等会在本机执行命令的字段与密钥路径不迁移，回环地址不迁移。新电脑生成自己的 ed25519 密钥，原电脑在人允许后用已有连接把新公钥追加到各服务器，新电脑以新密钥写入 Cindy 的 SSH 文件并逐台连接一次；连不上或授权失败的列入清单。私钥不离开各自的电脑 |
| 伙伴、记忆、伙伴技能、待办、例行任务定义 | 已随账号同步 | 见 [`cloud-companions.md`](cloud-companions.md)，本功能不重复处理 |
| 任务 | 不迁移 | 需要时用任务菜单「复制到其他电脑」 |
| 定时任务、项目目录、工作目录、窗口布局、麦克风与手柄、浏览器资料、声纹 | 不迁移 | 绑定电脑、绝对路径或硬件，或按规则只留本机 |
| 伙伴模型链 | 不迁移 | 规则：模型候选链引用主力电脑的连接，不跨电脑复用 |

## 3. 不变量

1. **秘密只在人允许后、只以一次性加密离开原电脑。** 快照只含非秘密配置与「是否已配置」的布尔
   提示。API Key / PAT 只在新电脑勾选「密钥」、原电脑的人在本机弹窗里点「允许」后复制：弹窗列出
   请求电脑、每一项名称（取自原电脑自己的数据）与六位校验码，两台电脑显示同一校验码；2 分钟无人
   回应即拒绝；同一时间只处理一个请求。密钥以本次请求的临时 X25519 公钥加密（HKDF-SHA256 +
   AES-256-GCM），只在新电脑 Main 内存中解开后写入各自原有的安全存储，不进入渲染进程、日志、
   清单或界面。转发请求的中转与插件授权相同，仍是信任根之一。OAuth 刷新令牌会轮换，复制到两台
   电脑会互相作废；Claude 订阅凭证按「Claude 订阅只经 Claude Code 自己的登录」不得读取或中转；
   IM 凭证同一机器人只能在一台电脑接收。这些一律不复制，改为新电脑上的「依次完成」清单。SSH
   私钥从不复制。
2. **只读快照，写入只发生在这台电脑。** 快照通道只有 `caps` / `snapshot` 两个动作；所有
   安装和写入走这台电脑原有的安装器、设置存储与设置页 API，沿用它们的锁、校验、规范化与
   刷新。没有通用导入、裸写库或任意路径写入。唯一的例外是 SSH 一步：原电脑在人允许后，只在
   请求里列出的、它已能连上的服务器上追加一行新电脑的 ed25519 公钥。
3. **插件权限一次确认，按真实包复核。** 计划里每个插件的权限由这台电脑的 Main 按市场
   release 的 manifest 计算；用户在迁移窗口里看过并确认后，安装时只有真实包算出的权限与
   确认时完全一致才视为已确认；任何不一致（版本变化、来自刚添加的自定义市场）回落到普通的
   逐个确认。确认结论仍由安装锁内的 `assertGhostInstallConsent` 绑定包摘要。
4. **不覆盖这台电脑已改过的设置。** 只写原电脑改过、这台电脑没改过的键；读取这台电脑的最新自定义键、
   排除已改过的键和写入在同一把跨进程写锁内完成，预览后用户或其他进程又改过的键同样保留。原电脑上与默认值相同的显式选择仍按显式写入。
5. **访问开关只开不关。** 「允许同账号设备控制本机」「保持电脑唤醒」只在原电脑开着时出现，
   作为单独一行由用户确认；迁移从不关闭这台电脑的任何访问开关。
6. **账号与窗口绑定。** 计划绑定发起预览的账号与窗口，30 分钟内有效、只能应用一次；
   切换账号后剩余项目以 `SETUP_PLAN_EXPIRED` 停止，已完成的项目不回滚。界面侧负责的项目
   （供应商、MCP、内置工具、访问开关、界面偏好）同样先经 Main 校验计划，校验失败则一项都不写。
7. **单项失败不影响其他项。** 每一项各自返回 `done / skipped / failed` 与错误码，完成页逐项
   说明；不自动重试会产生副作用的写入。

## 4. 协议与兼容

- 通道：`maker:setup-snapshot`（`packages/device-link/src/setupSnapshot.ts`），同账号、
  被读取端开启远程控制、未被撤销；共享任务访客与供应商分享受邀者在 dispatch 拒绝。
- 快照单帧上限约 1.5 MB；超出时依次丢弃界面偏好、供应商、设置、技能并标记为本次未读到。
- 旧版本被读取端返回 `CHANNEL_NOT_ALLOWED` → 提示更新那台电脑（`SETUP_SOURCE_OUTDATED`），
  不回退到其他通道。快照字段只追加；未知字段与未知设置组在新电脑上忽略。
- 密钥与 SSH：`maker:setup-transfer`（`packages/device-link/src/setupTransfer.ts`），`caps` 与
  `transfer` 两个动作，一次请求同时带要复制的密钥项与要授权的 SSH 主机；同账号、共享任务访客与
  供应商分享受邀者在 dispatch 拒绝；超时 5 分钟（含最多 2 分钟等人确认）。快照的 `transfer`
  字段声明原电脑支持的版本，旧电脑没有该字段，新电脑不提供这两项，SSH 仍是数量清单。
- 新增一类设置：在对应 store 模块导出 `portableOverrideSettings(store, { omitKeys })`（默认值里没有的
  可选键用 `optionalKeys` 声明，否则全新电脑会丢弃），
  在 `setup-migration/settingsGroups.ts` 登记，并在五种语言补 `setupMigration.settingsGroups.<id>`。
  含绝对路径、硬件标识、本机生成的密钥或安全授权的键不得登记。

## 5. 多端

- SSH 远程工作区：不涉及。迁移的是 Desktop 本机配置，不读写工作区文件。
- 设备互联：新增只读通道并登记 allowlist 与超时；控制端本地 IPC 只对受信主窗口开放。
- 手机：不提供入口。新电脑的设置在新电脑上完成；手机仍可远程打开那台电脑的设置页。

## 6. 尚未覆盖（需要单独决策或后续实现）

| 方向 | 现状 | 需要的决定 |
|---|---|---|
| 密钥复制的设备身份钉扎 | 校验码只由新电脑临时公钥派生，转发中转仍是信任根 | 是否复用插件授权的持久 Ed25519 设备身份做签名钉扎 |
| 本地导入插件包 | 列入清单 | 复用文件直传把原电脑的 `.cindy` 导出包带过来，仍走本机安装确认 |
| 手写技能文件 | 列入清单 | 复用文件直传复制技能目录，按技能导入流程落位 |
| 插件内的业务偏好（插件 `/kv`） | 不迁移 | 按插件实例映射后迁移，需确认插件契约里 KV 不含凭证 |
| 原电脑离线 | 无法读取 | 是否在服务端保存加密快照 |
| 默认下发插件的退订记录 | 不迁移 | 退订只记在原电脑，新电脑仍会自动安装 |

## 7. 实现与回归

- 协议：`packages/device-link/src/setupSnapshot.ts`、`__tests__/setupSnapshot.test.ts`。
- Main：`apps/desktop/src/main/setup-migration/`（`snapshot.ts` 原电脑快照、`plan.ts` 计划、
  `apply.ts` 插件/技能/设置写入、`transfer.ts` 密钥与 SSH 请求（原电脑确认、加密）、
  `transferApply.ts` 新电脑写入、`transferPrompt.ts` 原电脑确认弹窗、`service.ts` 编排与状态、
  `register.ts` 接线、`rendererPrefsHost.ts` 界面偏好读取），测试在同目录 `__tests__/`。
  SSH：`remote-ssh/setupMigrationSsh.ts`（列主机、追加公钥、添加并测通）。
- 设置导出：`maker-host/override-settings-file.ts` 的 `portableOverrideSettings`，测试
  `maker-host/__tests__/portableOverrideSettings.test.ts`。
- Renderer：`features/setup-migration/`（迁移窗口、清单、「依次完成」底栏、主窗 host）、
  `components/settings/SetupMigrationSection.tsx`。
- 状态文件：`userData/owners/<账号>/setup-migration-state.json`（上次迁移的来源名称、时间与
  一次性清单，不含秘密）。

两台真实电脑的端到端迁移、Windows 实机与 Light/Dark 实际目检以 PR 记录为准；单元测试不替代这些验证。
