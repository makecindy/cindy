# 供应商内的订阅账号

2026-11-07 用户要求：Anthropic / OpenAI 的本机订阅连接各保留一个供应商，内部可登录多个账号。
（「各保留一个供应商」已被 2026-11-13 裁决取代：是否合并由用户决定，见下节。）

## 账号平等与额度持久化（2026-11-16 用户裁决）

Claude Code 与 Codex 都不再有面向用户的「默认账号」或「设为默认」操作。同一供应商内的账号
共用分配策略、暂停、移除与移动操作；一个账号不可用时由同供应商中的可用账号接替，只剩一个就使用
该账号，没有账号时显示未连接。新分配按已有策略执行，正常的已有任务保留绑定；换号先保存上下文交接，
不能在另一目录恢复同一个原生会话 ID。移除仅停止 Cindy 使用该账号，保留官方 CLI 登录与历史文件。

内部 `default` 账号 ID、官方目录与旧协议字段仅作历史兼容，不代表调度优先级或操作特权。
额度在当前 Cindy 用户的数据库中，以 `claude-code:<accountId>` / `codex:<accountId>` 保存；移动账号
不更换存储键。旧用量入口的 native/WHAM 投影存在同一行的 `legacySnapshot` 槽，不能覆盖账号池的已验证身份与额度；清除该兼容槽不清除已验证额度，移除账号才清整行。换登录身份后不沿用另一身份的兼容槽。移动官方 CLI 账号仍要求当前 owner 的原有 native binding，移动记录不能授予使用系统登录的权限，显式撤销仍生效。旧键只在新键不存在时读取，清除留下空值阻止旧数据复活。恢复额度先核对官方 CLI 当前账号身份，
Codex 同时核对工作区；缓存不能证明登录有效。新额度观测落盘，普通缓存读取不重复写，迟到观测不跨用户或复活已移除账号。

Claude 保留官方 `subscriptionType` 与 `planTier`，另存可选 `planDisplayName`。显示名来自官方 CLI，
有值时优先显示（例如机器代码仍为 `pro`、显示名为 `Ultra`）；显示名缺失或只报通用 Max 时，已知具体档位显示为 Max 5× / Max 20×，
未知档位只显示已知套餐，不从用量或旧机器代码猜测 Ultra。Codex 保留 `planType`；旧 `plan` 字段仍兼容。桌面、任务账号查询、
模型选择器、菜单栏和手机沿用同一份元数据与格式化规则。供应商组与分享额度也逐账号读取，不为官方 CLI 账号另取一份供应商额度。实现见 `subscription-accounts/runtime.ts`、
`usage/accountUsageStorage.ts` 和 `maker-shared/src/subscriptionPlanLabel.ts`。

## 合池后的组调度（2026-11-16）

同一供应商中的多个订阅账号应尽量与多台电脑各一个账号同等调度，不能仅因合到一台电脑而丢掉空闲账号。
物理电脑仍负责连接、授权、影子目录和整机预算；账号负责模型、冷却、并发与选号。添加账号不放大已设的
组成员上限、远程宿主每控制设备上限或总实例上限，也不把账号伪装成设备；宿主留存的空闲实例仍按原规则计数。

组主为本机及已支持的同账号执行电脑读取**匿名新分配摘要**，与额度预览分开：按实际新任务入口核对登录、暂停、
归属、模型、远程授权、真实冷却和账号硬上限，并沿用同身份去重。最少占用比较账号池下一次选号的负载，整机总负载
继续用于整机硬上限；轮询为当前配额候选带内每个可接单账号分一轮，再轮到下一台。执行端仍在实际启动时原子预约，
摘要不是预约或授权；并发竞争、状态变化和硬件共故障不承诺与多台物理机器完全相同。

本机任务、同账号控制端与受邀者的启动前预选分别计数，不被其他忙碌账号的总负载抵消；同账号的预选在报告到达或
原有超时到期后退回实际负载，受邀者的初始预选在首份执行状态或释放时结束。本机任务选择同账号远程执行电脑时，
摘要与冷却恢复复用最终启动的 own-computer 授权范围；受邀者继续严格核对远程账号授权，不继承这一范围。

账号池自己的策略保留；显式机器权重不乘账号数。随机权重账号池无法只读预测下一账号，保守沿用物理成员调度，
不替用户改策略。旧端、摘要未知、目录连续性缓存及别人分享来的成员也沿用原来的物理成员调度，不猜额外容量。
组主替同账号控制端、手机或分享受邀者分配时共用此判定；匿名摘要仅在 owner 内部使用，不向受邀者返回账号身份、
目录、指纹、额度或该摘要。额度预览仍展示满并发账号的余量，忙碌／冷却账号的代表额度不替可接单账号抬高优先级。

实现见 `provider-group/router.ts`、`scheduler.ts` 和 `subscription-accounts/runtime.ts`；协议与旧端降级见
[多订阅账号协议](../dev-rules/protocol-compatibility/provider-multi-subscription-accounts.md#匿名新分配摘要2026-11-16)。
回归从真实 router → remote host → acquire 入口复现 4+0 对 3 的选择差异，另覆盖轮询、满载、暂停、退出登录、冷却、
模型差异、重复登录、旧端回包及显式整机预算；依赖为合成数据，没有真实付费推理或双设备实号验收。

## 插件读取订阅用量（2026-11-16）

`cindy.host.call('cindy_helper', 'get_subscription_usage', {providerId?})` 使用独立
`agent.hostTools:['usage']` 声明与安装批准，只读当前 Cindy 账号在执行电脑上的已连接账号。
与界面共用 `runtime.ts` 的逐账号读取、身份校验与缓存；`usageView.ts` 逐字段投影账号标识、套餐、
额度窗口、观测时间及新鲜度，未知值不冒充 0。不返回邮箱、目录、凭证、身份指纹、其他电脑与分享供应商。
异步读取后复核 owner、账号存在、原供应商归属与原生授权，插件网关继续复核安装批准和启用状态。
调用与字段约定见[插件宿主工具手册](../../apps/desktop/resources/system-skills/cindy-plugin-creator/references/plugin-host-tools.md#读取订阅用量)。

## 合并与拿出由用户决定（2026-11-13 用户裁决，分批实现）

用户把同类订阅拆成几个供应商，往往是想自己决定哪个任务用哪个账号；合并后新任务只能由账号池按策略分配，
用户无法指定账号。因此取消两条默认做法：11-07「Anthropic / OpenAI 各保留一个供应商」与 11-11「升级时把旧 Codex
单独连接自动归并进 OpenAI」。是否合并交给用户：添加时默认单独，之后可以主动并入或拿出。

**实现状态**：账号池与自动归并已随 v0.1.135 正式版发布。本节已在桌面端实现（尚未发布）：不再自动归并、升级后还原
已归并的旧 Codex 连接、任务跟着账号走、每个供应商只分配和统计自己的账号；添加时选择放在哪里、主动并入／移动／拿出、
任意同类供应商作为合并目标、Cindy 新建的 GPT 与 Claude 单独供应商，以及 Helper 的同等操作。下文标注
「已被 2026-11-13 裁决取代」的条目只作历史说明。未做：真实双账号端到端登录，以及新旧版本两台电脑混用的实机互通。
2026-11-14 用户补充：之前被合在一起的账号都要拆回独立供应商，包含旧版经添加向导或账号区直接加入内置池的账号；
这部分按下文「旧版直接加入账号池的账号也拆开」执行。
2026-11-18 用户裁决：升级不再自动拆分；已被拆坏的按下文「升级拆坏的自动并回」恢复。

**账号归属的存放**：账号属于哪个供应商单独记在 owner 本机的 `subscription-account-placement.json`，不写进
`subscription-accounts.json`——本裁决之前的客户端每次写账号池文件（任务启动写绑定即会写）都会丢掉它不认识的字段，
会悄悄抹掉用户的安排；旧客户端不读写新文件。没有记录的账号属于内置供应商，与旧客户端的理解一致；官方 CLI 账号移动后也写明归属。
新文件读不了时按「没有记录」理解且不做还原，下次加载再试。实现见 `subscription-accounts/placement.ts`。

- **范围**：OpenAI（Codex）与 Anthropic（Claude Code）的本机订阅。Grok、API key、自定义中转与 SSH 不在本节范围。
- **一类订阅可以有多个供应商，每个供应商有一个或多个账号。**只有一个账号的是单独供应商，新任务选了它就固定用这个账号；
  两个及以上账号的供应商按本文账号池规则（分配策略、并发上限、权重、账号间自动换号）只在**它自己的账号里**分配。
  内置 OpenAI／Anthropic 供应商是存放官方默认登录（`~/.codex`／`~/.claude`）的那一个，同样可以作为合并目标；
  用户自己的同类供应商也都可以作为合并目标，例如两个单独的 OpenAI 供应商各自再并入一个账号。
- **选账号就是选供应商**：每个供应商在模型选择器里都是独立来源。想让某个任务用某个账号，就把这个账号放在单独供应商里，
  新建任务时选它。
- **添加供应商**：只读检测不变，默认账号仍进内置供应商。2026-11-14 用户裁决：添加窗口不列出、也不统计已登录的账号——
  已加进 Cindy 的账号本来就在供应商列表里，再列一遍没有用处。只有命令行自己的登录（默认账号）还没加进 Cindy 时，才给一个
  「使用这台电脑上的 Codex／Claude Code 账号」快捷按钮，按钮上带它的身份；内置供应商已在用它，或同一身份仍是同类供应商里未断开的
  其他账号，就不再提供，只剩「登录另一个账号」；旧版已授权使用默认账号、尚无账号池记录的连接也算已加入。内置供应商被关掉后，
  留在其中的同身份账号不挡快捷入口；已放在其他供应商里的同身份账号仍按其自身连接判断。选「登录另一个账号」后，在启动浏览器登录前
  弹出选择这个账号放在哪里：「作为单独的供应商」（默认选中）或「并入现有供应商」，后者列出这台电脑上已连接的同类供应商
  （含内置的那一个）。没有已连接的同类供应商时不弹出，直接作为单独供应商。取消或登录失败不创建供应商，也不改动目标供应商。
  供应商详情账号区的「添加账号」本身就是往这个供应商里加，不再询问。
- **单独供应商的名字**沿用[供应商设置](provider-settings.md)中同品牌重复添加的默认名称规则，未改名时随账号身份更新。
  名称只作显示；Claude 与 Codex 的认证、模型发现和路由始终按供应商内部 ID、账号归属及原 CLI 目录处理。
  独立供应商应在内置默认账号未登录或已断开时照常发现自己的模型，新发现结果按账号隔离。
  选择器、启动刷新和手动重新发现共用这些结果；普通供应商视图和完整路由目录都保留
  原有 Claude 元数据，按内部 ID 合入对应供应商的新发现。发现失败或暂未列出的历史型号不能成为新增的续聊、恢复、换号或切模型门槛，
  原有登录、账号绑定与授权检查照常生效。
- **主动并入／移动**：单独供应商的更多菜单提供「并入其他供应商…」，多账号供应商的账号行更多菜单提供「移到其他供应商…」；
  目标只列这台电脑上已连接的同类供应商。账号连同自己的暂停状态、并发上限和权重一起移过去，账号目录与官方 CLI 登录不动。
  并入后原单独供应商从供应商列表与新任务来源中消失，原 ID 按下文「归并后的旧连接」各条继续供历史任务、分叉、自动化、
  模型组、旧分享与供应商组引用：固定原账号，不扩大授权。
- **主动拿出**：多账号供应商的账号行更多菜单提供「拿出来作为单独供应商」，生成只含该账号的新单独供应商。
  模型停用沿用原供应商当时的设置；远程调用、分享与供应商组成员默认关闭，由用户自己打开——拿出不能让账号获得比原来更多的授权。
  原供应商只剩一个账号时按单账号显示。
- **同一账号的重复登录（2026-11-16 修复）**：用户主动合到同一个供应商里的 OpenAI 登录，只有经官方登录确认
  是同一账号及同一工作区时才算一个账号。列表、匿名用量、分配权重与轮询只计一次；运行数累计所有保留目录，
  并发上限取原记录中最小的有效上限，暂停、设置上限／权重、移动、拿出与移除作用于这一账号的所有重复记录。
  移动、拿出和并入的归属在一次原子写入中保存，失败时不留下同一账号被拆到两个供应商的中间状态。
  已有任务仍使用原登录目录及绑定，不搬运或删除原生会话；任务专属查询保留原绑定 ID。新分配先逐目录校验模型
  与远程权限，再选一个可用目录；相同身份不授予额外权限，也不能通过另一个目录绕过本轮重试排除或冷却。
  工作区不同、无法核实身份的记录保持独立；不同供应商不因身份相同被自动合并。当前 Claude 未提供同等工作区
  身份证据，不能仅按邮箱去重。清空的原供应商继续按既有别名规则从列表与新任务来源中退出。
- **官方 CLI 账号也是普通账号**（2026-11-16 取代固定规则）：可以移除、移动或拿出；历史任务跟随账号，
  官方目录不变。内置供应商保留其兼容路由，不整体并入；需要整理时移动其账号。
- **任务跟着账号走**：并入、移动、拿出只改账号所在的供应商，不改任务与账号的绑定。已建立的任务继续用原账号续上原生会话，
  不做上下文交接，任务里显示的账号不变；运行中的任务不受影响。之后的自动换号按账号当前所在的供应商判断：
  单独供应商的任务不换到别的账号，撞限时等原账号重置或照常报错；在多账号供应商里才按「账号间自动换号」在该供应商内换。
  用户把已有任务改选到同类的另一个供应商时，是主动换账号：下一次发送把上下文交接到那个供应商的账号
  （与暂停账号的交接同一路径）；原账号已经在那个供应商里时不交接。
- **已被自动归并的账号在升级后还原**：11-11 起（v0.1.135 正式版）因升级被自动归并进 OpenAI 的旧 Codex 单独连接，
  升级到实现本节的版本后自动还原为原来的单独供应商：原 ID、名称、模型停用、远程调用与逐模型权限、分享都恢复原样。
  归并期间在 OpenAI 里暂停或移出的，还原后为停用，由用户再启用或删除，不悄悄恢复使用。归并期间分到这个账号的任务跟着账号
  回到还原后的供应商；已交接到 OpenAI 其他账号的任务留在 OpenAI。只还原升级时自动归并的账号，用户主动的合并不还原。
  降级到旧版时，旧版会按它自己的规则再次自动归并；再升级回来仍会还原，用户的主动选择不丢。还原写入失败时保持原状、
  下次加载再试；任何时候一个账号只属于一个供应商。
- **旧版直接加入账号池的账号也拆开（2026-11-14 用户更正，已被 2026-11-18 裁决取代）**：v0.1.137～v0.1.139 加载供应商时，
  把 OpenAI 与 Anthropic 池里没有明确归属记录的非默认账号拆成各自的单独供应商，ID 由账号推导
  （`<kind>-sub-` 加 `sha256("<kind>:<账号>:n")` 前 8 位，n 从 0 起跳过已占用的）；默认账号留在内置供应商，
  拆出的供应商继承模型停用，分享与逐供应商远程调用不打开。
- **升级不再自动拆分（2026-11-18 用户裁决）**：2026-11-17 用户反馈：一台电脑从 v0.1.136 直接升到 v0.1.139，
  内置 Anthropic 里唯一能用的号被拆走，只剩已退出、已暂停的默认账号，内置供应商变成未连接；另一台电脑上的供应商组
  仍登记这台电脑的内置 Anthropic，显示「这个供应商没有配额信息」，用它的分享与自动化同样失去这个号，界面上也并不回去
  （「并入」只列已连接的目标）。拆分只改这台电脑，却改变了别处依赖的内置供应商能用哪些号。因此加载供应商时不再拆分：
  没有归属记录的账号仍属于内置供应商（与旧客户端的理解一致），升级前怎样、升级后仍怎样，想单独用的账号由用户自己「拿出」。
  已经拆出的供应商保持现状（下一条除外），用户之后的并入、移动、拿出照常记录。
- **升级拆坏的自动并回（2026-11-18 用户裁决）**：被上一条之前的升级拆坏的，自动做一遍用户的「并入其他供应商」（与界面、Helper
  同一个命令），把拆出的供应商并回内置供应商。只在以下条件全部成立时进行，任何一条不满足就不动：内置供应商没有被用户断开，
  也没有被「停用供应商」关掉，且其中每个账号都已暂停或已确认退出登录（还没读到登录状态的等下次判断，读取失败不算退出）；
  供应商 ID 是升级按账号推导的那个（用户新拿出的供应商用随机 ID，不会匹配）；它的账号自本版本开始记录以来一直在它里面；
  其中仍只有那一个账号；用户没有改名、设分配策略、停用、打开逐供应商的远程调用、分享，也没有在它上面建供应商组；分享名单要读到完整的才判断。
  并入沿用既有语义：原 ID 作为别名继续供历史任务、自动化、模型组、旧分享与供应商组引用，固定原账号；账号目录、登录、任务绑定、
  暂停、并发上限与权重不变；内置供应商恢复已连接，别的电脑上登记它的组与分享随之恢复。
  **不和用户拉扯**：并回后原 ID 留作别名，账号之后被「拿出」会回到同一个 ID。owner 本机的 `subscription-upgrade-split-repairs.json`
  记录每个升级拆出的供应商：开始并入前记「进行中」；每次检查前后，凡账号已不在它里面的（这里并回的、用户自己并回或移走的）记为「已完成」，
  已完成的永不再自动并回；「进行中」而账号仍在里面的（并入失败、中途退出）下次再试。只按当前 owner 写记录，不写进别的账号。
  已知边界：在 v0.1.137～v0.1.139 上自己并回、又在本版本之前拿出的，没有记录可区分，会被自动并回一次，之后再拿出即保持单独。
  一次只并一个，写入账号归属前在写锁内复核条件，每并完一个重新判断下一个。由窗口进程在每次加载供应商后（不阻塞加载）、
  账号放置或暂停变化后、账号登录状态或分享快照变化后检查；
  Host 客户端模式不启动，Host 只读结果。实现见 `subscription-accounts/upgradeSplitRepair.ts`（判断与记录）与
  `upgradeSplitRepair.desktop.ts`（接线），回归见 `subscription-accounts/__tests__/ipc.test.ts`（判断与记录）与
  `__tests__/upgradeSplitRepair.desktop.test.ts`（先记录再并入、失败后收尾、逐个复核、各条件读对设置）；不再拆分见
  `maker-host/__tests__/providerCatalogRealmReload.test.ts`。
- **拆出账号后的旧任务不显示断开（2026-11-14 回归修复）**：拆分后内置供应商可能只剩未登录的默认账号，选择列表把它算作
  未连接；选了内置供应商的旧任务因此显示「模型来源已断开」并被禁止发送，尽管执行端仍按任务绑定的账号续上原生会话。
  修复后，本机任务账号查询在账号已不在任务来源里时附带它现在所在的供应商（`ownerProviderId`，只给本机界面，不经设备互联
  回包）；输入框和模型选择器只为这一个已建立的任务，把原来源显示为已连接，只补任务已生效的引擎与型号，发送仍带原来源 ID。
  型号资料优先保留原来源的条目，缺失时才借账号所在供应商的该条；不借出其他型号或引擎，不跟随待生效选择，避免重新开放旧来源停用的模型。
  只放开、不收紧：原来源本来已连接或被停用、账号已暂停／未登录／不可用、账号所在供应商未连接或被停用时一律不改；新任务、
  草稿、远程与 SSH 任务不受影响，不改写任务记录。手机端暂未接入，这类任务在手机上仍把来源标红，但可以照常发送。
  回归见 `subscription-accounts/__tests__/runtime.test.ts`、`renderer/__tests__/sourceSwitch.test.ts`、
  `renderer/__tests__/modelSelectorProviderGroups.test.tsx` 与 `new-chat/__tests__/chatInputModelLoading.test.tsx`。
- **Claude 单独供应商**：以前单独添加的 Claude 连接用的是 Cindy 自己保存的登录凭证，已于 2026-09-24 停用（只能查看和删除），
  不复活、不并入、不迁移凭证。新的 Claude 单独供应商与账号池账号一样只经官方 CLI 登录，每个账号一个独立的
  `CLAUDE_CONFIG_DIR` 目录，Cindy 不读取、不复制 Claude 凭证（见[凭证与本地存储](../dev-rules/credentials-and-local-storage.md)）。
  新条目必须与已停用的旧 Claude 连接区分开，任何版本都不能把它当成旧连接走 Cindy 自己的登录。
- **分享、供应商组与远程**：每个供应商各自开放远程调用和分享；多账号供应商的额度展示与分享沿用本文账号池规则（不合计、不带身份）。
  合并与拿出只改这台电脑上的供应商，不自动改供应商组成员、分享对象或其他电脑。同账号远控可以在执行电脑上做这些操作；
  执行电脑版本过旧时明确提示需要更新，不退回成别的操作。
- **Agent 与用户能力对齐**：Helper `configure_model_provider` 的 `subscriptionAccounts` 同步提供「添加到指定位置
  （单独或并入某个供应商）」、并入、移动与拿出，与界面共用校验和执行服务；落地后更新
  [用户与 Agent 能力对齐](agent-user-parity.md)台账。
- **新旧版本混用**：旧版客户端或旧版执行电脑读到新数据时，最多只看到原账号或把新条目显示为不可用，不能因此让其他供应商
  读不出、把账号算进错误的供应商，或丢掉账号与任务的绑定；回到新版后恢复。字段与降级约定落地时写入
  [多订阅账号协议约定](../dev-rules/protocol-compatibility/provider-multi-subscription-accounts.md)。

## 账号池的既有规则

- **同机多账号的故障隔离（2026-11-16）**：已有任务及显式账号只等待自己的认证与所需模型发现；
  真正需要换号时才读取同供应商的其它候选。新分配让相关候选并行完成认证、用量及模型发现，共用最多
  2 秒的等待窗口，再在已完成验证的可用账号中沿用原策略、并发上限、权重和冷却；不按回复先后抢号。
  没有可准入候选时继续等待原有读取及其原有超时，不把冷启动的单账号误报为登出。慢读取在后台沿用
  原在途去重，完成后可重新参加后续分配；未完成的读取、未知认证和仅有旧模型缓存都不授予准入。
  派发和切模型不等待其它命名供应商或暂停账号的历史模型发现。owner、逐账号模型及远程授权仍实时核验。
  只读控制租约（含旧 Codex 连接的模型刷新）可以读取已认证的暂停账号，不占用并发名额；暂停仍禁止新任务准入。
  同机的物理离线、CPU、网络和整机上限仍是共同约束；此规则不承诺消除这些差异。
- **Codex 启动不等额度读取（2026-11-19 用户裁决）**：用户反馈 Codex 发消息卡 1–2 秒。原因是每次启动运行时
  都要等每个账号的额度读取（单独启动一次官方 CLI，并请求 chatgpt.com），而 ChatGPT 额度只用于展示和新分配
  排序（见下文「ChatGPT credits 准入修复」）。Codex 选号和启动时的认证检查都可使用已完成的登录读取，
  包括套餐信息需要等额度回填的旧版默认账号。已绑定账号的任务（续聊、重启后
  第一条、闲置后再发）和只剩一个可选账号的新任务，登录读完即启动；多账号新分配在同一登录 5 分钟内读到过
  额度时，先按这份额度排序（排序本身只信 10 分钟内的额度），更旧时仍在上条的 2 秒窗口内等新读取。
  额度照常在同一次读取里读完、写回缓存；设置页、用量卡、分享与组查询以及额度摘要照旧等这次读取的结果，
  看到的额度与改动前一致，也不多启动 CLI。登录、模型成员、暂停、并发上限、冷却与准入全部照旧。
  Claude Code 的套餐窗口决定能否启动，不在此列。实现与回归见 `subscription-accounts/runtime.ts`
  （`CodexSelectionQuota`）及 `__tests__/runtime.test.ts` 的 starting while an account quota read is still running；
  选号超过 0.5 秒时记一条 `subscription account selection was slow`（登录与模型读取耗时，不含身份与目录）。
- **添加与重登分开（2026-11-16）**：普通 `add` 遇到已保存、已授权、有任务绑定／原生历史，或无法确认
  是否为空的默认账号时，一律新建独立登录目录。旧版首次 `add` 只在无账号记录、无授权与绑定、官方目录
  确认缺失或为空且 CLI 明确未登录时初始化默认目录；仍兼容只读认领已检测到的默认登录。向导明确选择
  使用 CLI 默认账号及对指定账号重登沿用原目录。失败和取消仅撤销新账号登记，不删除、搬移官方登录或历史。
- **登录完成须确认（2026-11-16）**：官方 CLI 登录控制流程结束后，在同一目录确认已认证，才返回完成、
  重连及清除冷却。读不到状态返回暂时不可用，明确未认证返回登录失败；两者都不清除冷却，不自动登出或无限重试。

- **ChatGPT credits 准入修复（2026-11-13）**：账号池不能把套餐 5 小时／周窗口用满当成请求不可用。
  新任务、原账号续聊、旧连接固定账号、同账号远程与供应商组入口都交给上游判断是否能使用 credits；
  缓存余额有值、未知或显示耗尽均不代替上游准入。窗口仍用于展示与新分配排序，不能仅凭窗口用满
  交接已有任务。真实限额、登录和过载错误仍按原规则冷却、换号与等待，不因显示有 credits 立即重试。
  Anthropic 保持窗口准入；重置卡提前唤醒仍须确认实际账号的套餐额度恢复。实现与回归见
  `subscription-accounts/runtime.ts`、`provider-group/usage.ts`、`subscription-accounts/__tests__/runtime.test.ts`
  及 `provider-group/__tests__/router.usage.test.ts`。

- 首次空目录登录或明确使用 CLI 默认账号时使用官方默认目录（`~/.claude` / `~/.codex`）；新增账号使用用户目录下带 Cindy 随机标识的兄弟目录。目录名不含邮箱，不接受 Renderer 或远程传入任意路径。
- 登录交给未修改的官方 CLI。Claude 使用 `CLAUDE_CONFIG_DIR`，Codex 使用 `CODEX_HOME`。Cindy 不实现 Claude OAuth，也不读取或复制 Claude 凭证。
- Codex `account/read` 明确返回 `account: null` 且 `requiresOpenaiAuth: false` 时，表示当前供应商管理认证，不能当作普通未登录再启动登录。连接及重连在所选目录预检并给出独立账号的操作指引；不改写原生配置、不按供应商名称拒绝、不读取凭证来猜账号。已有 ChatGPT 账号及缺少该标志的旧 CLI 保持原判定。实现与回归见 `nativeCli.ts`、`runtime.ts` 及对应测试。
- 添加供应商时先只读检测默认账号，在快捷按钮上展示身份并让用户明确选择使用它或「登录另一个账号」；默认账号已加进 Cindy 时
  不再提供快捷按钮（2026-11-14，见上文「添加供应商」）。检测不创建账号池、不绑定授权；选择另一个账号始终使用新的后缀目录，即使默认账号尚未接入 Cindy 或已失效。未检测到登录时，首次登录仍使用默认目录；旧版 Codex 私有目录保留为兼容默认账号。
  2026-11-13 起选「登录另一个账号」后先选择放在哪里（默认单独供应商），见上文「合并与拿出」。
- 管理信息按 Cindy owner 保存在本机 `subscription-accounts.json`，只存策略、账号标识及任务归属。账号目录不进入项目或同步；同账号远控管理界面可以查看目录，执行协议只传供应商与模型，不传账号能力对象。默认登录仍受现有 native provider binding 约束。
- 添加、重连、暂停及移出操作针对账号；移出仅撤销 Cindy 调度，不删除 CLI 登录或历史。一个供应商内展示账号、连接状态、额度、运行数、并发上限及权重。
- **Claude 登录到期与重新登录**（2026-11-12 用户裁决）：在供应商详情的每个账号状态行展示它自己的预计到期时间；用执行电脑上该账号目录的官方 `claude auth status --json` 的 `loginExpiresAt`，不读取 Claude 凭证文件，不借用默认账号或其他电脑的日期。七天内（含估计日期已过）用警示文字并显示该账号的「重新登录」按钮；未知日期明确显示未知。官方给的是估计值，实际登录可能提前失效，因此日期已过只提示「可能已到期」，不据此把账号判成退出登录。旧 CLI／旧执行电脑缺少可选字段时照常使用，不猜日期。
  点击重新登录必须真正启动这个账号目录的官方浏览器登录，即使当前仍已登录。宿主从该账号已知身份提供邮箱提示，完成后重新查询并核对身份；邮箱提示不是身份校验。登录成别的账号、无法确认身份或取消都不算成功，不清除原账号冷却，不更新其他账号。已知原身份在开始前写入 owner 本机账号元数据 `reloginIdentity`，失败后保留，直到原账号登录确认成功才清除；这样刷新／重启后误登的身份也不能作为原账号分配给任务。元数据不含令牌，CLI 登录文件仍完全由官方 CLI 管理。运行中的账号不能重新登录，浏览器流程仍需用户完成，不宣称静默自动续登。
  正常读取到已认证身份时，把最后确认的身份保存在 owner 本机元数据 `lastConfirmedIdentity`，退出登录、读取失败或重启不清除；重登时优先使用已保存的原身份，不能依赖只在内存里的邮箱。没有任何可确认原身份时，在启动浏览器前停止并提示通过「添加账号」重新连接；初次添加／连接仍可正常登录。两种身份元数据不进入账号管理视图，未绑定默认账号的只读检测不创建或修改账号池。
  已有空闲运行时的下一次发送同样检查所选账号：正在登录时拒绝发送；重登前的快照已失效，未完成的重登须有此后按原身份校验的账号快照才可继续。误登后的旧运行时不能绕过新任务的身份保护；取消后仍确认原身份或原账号登录恢复后可继续。
  UI 沿用现有每分钟／聚焦／账号变更刷新与宿主缓存，不新增后台轮询或服务器请求。账号管理仍走 owner 专用的既有通道；到期字段是可选追加，分享用量不传账号身份或到期日期。手机没有新增原生账号管理页，同账号远控调用由执行电脑处理。
- 用量沿用供应商原有用量卡：每个账号用同一张卡显示自己的全部窗口（含各自的 Codex 重置次数）（5 小时、每周及分模型每周，Codex 含余额），不再另画单条用量或在底部重复一个账号。用量页入口属于供应商，只在账号区标题旁出现一次。
- 账号行与供应商组成员行同一结构：身份、套餐和状态在左，并发上限、权重、分配开关和更多菜单在右；用量放在账号名下方，所有账号共用一套列宽，进度条跨账号对齐。账号目录在更多菜单里打开（悬停可看完整路径），不再在每个账号下常驻展开项。
- 2026-11-09 用户要求精简账号区文字：标题下不放说明段，2026-11-16 起不再显示「默认」账号标记；设置页用量行只显示百分比和剩余时长，「剩余」「后重置」放在悬停提示和读屏文案里。
- 2026-11-10 用户要求没有账号时不占位：池里只有尚未登录、身份未知且无运行任务的默认目录时，账号区只留标题和「添加账号」，不画「账号 1 · 需要登录」行、不显示数量；登录走供应商标题栏或「添加账号」。已知身份待重新登录、仍有任务或池内还有其他账号时照常列出。分配策略和权重只在两个及以上账号时显示。
- 开放额度分享时，池内超过一个可分配账号（已登录且未暂停）就按「账号 1、账号 2…」分别列出各自窗口，不合计、不含身份；只有默认账号时保持单账号显示。
- 供应商组里展开一台电脑时，两个及以上账号分别列出各自用量，见[供应商组 §10](provider-groups.md)；组调度仍按账号池可用额度。已暂停账号不在组用量列表出现；全部暂停时不回退显示默认账号的缓存额度。本机变更和同账号远程变更通知触发列表刷新，异步额度读取结束后复核最新开关。
- 新任务复用供应商组调度器（最少占用、轮询、顺序、权重）和配额优先规则。选择时立即预约，实际 turn 结束释放运行占用。暂停立即阻止新任务分配；已有任务按下文在下一次发送前交接换号，不中断进行中的回合。
- **并发上限**（2026-11-11 用户裁决，与[供应商组 §5](provider-groups.md#5-组策略)同一判定）：每个账号可选「不限制」或 1～16。没设置过的账号不限制并发，旧版存下的默认 4 视为没设置过；设置过的数字是硬上限，达到上限的账号不再分新任务，所有可分配账号都满时新任务提示已满载（`SUBSCRIPTION_ACCOUNTS_FULL`），不再分给最空的账号。已绑定的任务继续发消息不受上限影响。选「不限制」时存回旧版默认值，新版另记是否设置过；旧版读到的与以前相同，同账号远控的旧版执行电脑不接受「不限制」并照常报错。Helper 的 `limit: null` 同样表示不限制。
- 所有模型选择入口（含已有任务切换、设置、桌面和手机）共用账号解析：任务已记录的绑定优先；未绑定也分别展示未暂停、已登录账号的已知余量，并发满或限额耗尽不隐藏额度。多个账号在来源标题旁显示周余量的等权平均，展开再列各自百分比和重置时间，快重置且余量较多时轻提醒；不把平均值冒充绝对总额度或已分配账号；读取中、读取失败或没有可展示账号时只显示供应商名，不显示「账号待分配」（2026-11-16 用户反馈：选择器不负责分配，账号在发出消息时分配）。身份、套餐和额度同源。具体权限与兼容规则见[模型选择器统一准入](model-selector-unified.md#01-统一准入与账号归属2026-11-11)。预览不预约、不换号；执行仍按原调度与绑定校验。
- 已建立的任务、重开、续聊和分叉在账号正常时固定账号，禁止在另一个目录用同一个原生 session id 恢复。账号失效不能静默回退默认账号；换号只按下面的「账号间自动换号」进行。替代账号按新分配重新校验供应商和模型权限；同账号远程接手按任务模型的额度桶判断。
- **禁用账号后的续聊**（2026-11-11 用户要求）：用户在供应商内暂停／移出账号后，本机已有任务下一次发送或重试先按原账号池策略预约一个可用账号，再沿用上下文重建交接流程关闭本任务的空闲运行时、保存交接并清空原生会话 id，最后只改任务绑定。原生历史 id 的账号归属不改，不复制登录凭证。聊天记录和项目文件保留；新运行时接收近期上下文、已完成工具结果与更早历史的检索指引，而不是把整个原生会话文件移到另一账号。
  没有可用账号、任务仍在运行（含主回合结束后的后台测试、构建或子任务）、关闭或交接失败时不改绑定；先保存交接再写绑定，绑定写入失败可重试，不丢原记录。停用后的旧 live handle 不接受下一轮，避免准备期间的竞态继续用旧账号。额度耗尽、登录失效和过载的换号见下条「账号间自动换号」；本条不自动重放消息。
  Desktop、手机／同账号远控以及 IM 的本机执行路径共用发送前准备；SSH 不借用本机账号，归并进 OpenAI 的旧独立连接 ID 交接后改走 OpenAI（2026-11-13，见「账号间自动换号」），其他自定义供应商 ID 不借用；同账号远程 Agent 通过既有查询确认执行电脑的账号状态，再复用执行端按模型可用性查询统一校验额度、登录及新分配权限；仅明确可用才交接。拒绝、失败、旧端不支持或回包不匹配时保留原生恢复路径，不使用本机账号代替。换号后实际账号与用量通过既有任务查询和账号变更推送更新，无新增界面或 wire 字段。
  账号底层不依赖设备互联或供应商组的宿主运行时：远程查询由 `maker-ipc/register.ts` 从既有装配层传入；组目录在自身运行时监听现有账号变更事件并清理缓存。
  实现与回归见 `subscription-accounts/prepareSend.ts`、`runtime.ts`、`agent.ts` 及 `runtime.test.ts`，上下文交接见 `maker-ipc/contextOverflowRollover.ts`。
- **账号间自动换号**（2026-11-11 用户裁决：一个供应商内的多账号按供应商组选电脑的规则与失败重试口径处理，见[供应商组 §5、§6.1](provider-groups.md#61-自动换电脑)）。判定共用 `decideProviderGroupFailure`：
  - 新任务启动失败且属于组会换电脑的原因（额度、登录、过载、启动失败等）：不显示错误，直接按组策略换下一个账号重新启动；每个账号最多试一次，都失败才把最后一次真实错误交回。进程未确认退出的失败不换，避免同一任务并存两个运行时。续聊（恢复原生会话）和旧独立连接 ID 的任务不在启动时换。
  - **已绑定任务新开原生会话**（2026-11-12 事故补齐：组把任务换到另一台电脑后，那台新开会话仍死守已撞限的账号，报 `SUBSCRIPTION_ACCOUNT_LIMITED`，组随即判定没电脑可换）：交接后、换电脑兜底、清空后等不恢复原生会话的启动，绑定账号此刻接不了这个模型（同上判定）时按池策略换一个可用账号并改任务绑定，启动失败可继续换下一个；旧原生 id 仍归原账号。其他账号都不能接或都满载时仍用原账号，报原账号的真实原因。暂停与移出沿用原规则；显式账号路由（含旧连接 ID 固定的账号）在此不换，旧连接 ID 的任务由发送前换号改走 OpenAI 后再按本条选号（2026-11-13，见下文「归并来的账号与旧连接任务同样换号」）。
  - 已绑定的任务在下一次发送前（用户发消息、重试、自动续跑、IM、Hook 共用同一入口）核对绑定账号：记着这个模型的真实失败、可信快照显示该模型额度耗尽、或已退出登录时，按组策略在其他账号里选一个，带上下文交接重开原生会话后再发；旧原生 id 仍归原账号，只改任务绑定。正在运行（含主回合结束后的后台工作）不换；其他账号都不能接或都满载时照常发到原账号。暂停与移出另按暂停交接规则处理。
  - 运行中撞到用量上限：另一个账号此刻能接时不等重置，约 2 秒后自动续跑并在发送前换号（沿用额度重置后自动继续的次数上限）；供应商组已核实的组额度耗尽仍等重置。其他账号都不能接时照常等原账号重置。
  - **同账号远程 Agent 任务同样换号**（2026-11-12）：任务在本账号另一台电脑上运行时，发送前已有的那次任务账号查询（`maker:subscription-accounts` 的 `session`）附带任务模型，新版执行电脑回报绑定账号是否接不了（`blocked`，与本机同一判定），以及排除该账号后能否按真实选号准入换号（`switchAvailable`，包括并发名额与新路线权限，只读不预约）。两者都明确为真时，按暂停交接同一路径重开原生会话，由那台新开会话时按池策略选号；不再追加配额查询。运行中撞限时同样用这一次查询判断能否不等重置、约 2 秒后续跑。那台没有别的可用账号或准入读不到时照常发到原账号、不让可选探测阻止发送；owner 变化仍拒绝。旧版执行电脑缺少新回执，不交接、行为不变。分享来的供应商与 SSH 不在此列。
