# 供应商内的订阅账号

2026-11-07 用户要求：Anthropic / OpenAI 的本机订阅连接各保留一个供应商，内部可登录多个账号。

- **ChatGPT credits 准入修复（2026-11-13）**：账号池不能把套餐 5 小时／周窗口用满当成请求不可用。
  新任务、原账号续聊、旧连接固定账号、同账号远程与供应商组入口都交给上游判断是否能使用 credits；
  缓存余额有值、未知或显示耗尽均不代替上游准入。窗口仍用于展示与新分配排序，不能仅凭窗口用满
  交接已有任务。真实限额、登录和过载错误仍按原规则冷却、换号与等待，不因显示有 credits 立即重试。
  Anthropic 保持窗口准入；重置卡提前唤醒仍须确认实际账号的套餐额度恢复。实现与回归见
  `subscription-accounts/runtime.ts`、`provider-group/usage.ts`、`subscription-accounts/__tests__/runtime.test.ts`
  及 `provider-group/__tests__/router.usage.test.ts`。

- 首个账号使用官方默认目录（`~/.claude` / `~/.codex`）；新增账号使用用户目录下带 Cindy 随机标识的兄弟目录。目录名不含邮箱，不接受 Renderer 或远程传入任意路径。
- 登录交给未修改的官方 CLI。Claude 使用 `CLAUDE_CONFIG_DIR`，Codex 使用 `CODEX_HOME`。Cindy 不实现 Claude OAuth，也不读取或复制 Claude 凭证。
- Codex `account/read` 明确返回 `account: null` 且 `requiresOpenaiAuth: false` 时，表示当前供应商管理认证，不能当作普通未登录再启动登录。连接及重连在所选目录预检并给出独立账号的操作指引；不改写原生配置、不按供应商名称拒绝、不读取凭证来猜账号。已有 ChatGPT 账号及缺少该标志的旧 CLI 保持原判定。实现与回归见 `nativeCli.ts`、`runtime.ts` 及对应测试。
- 添加供应商时先只读检测默认账号，展示身份并让用户明确选择「使用此账号」或「登录另一个账号」。检测不创建账号池、不绑定授权；选择另一个账号始终使用新的后缀目录，即使默认账号尚未接入 Cindy 或已失效。未检测到登录时，首次登录仍使用默认目录；旧版 Codex 私有目录保留为兼容默认账号。
- 管理信息按 Cindy owner 保存在本机 `subscription-accounts.json`，只存策略、账号标识及任务归属。账号目录不进入项目或同步；同账号远控管理界面可以查看目录，执行协议只传供应商与模型，不传账号能力对象。默认登录仍受现有 native provider binding 约束。
- 添加、重连、暂停及移出操作针对账号；移出仅撤销 Cindy 调度，不删除 CLI 登录或历史。一个供应商内展示账号、连接状态、额度、运行数、并发上限及权重。
- **Claude 登录到期与重新登录**（2026-11-12 用户裁决）：在供应商详情的每个账号状态行展示它自己的预计到期时间；用执行电脑上该账号目录的官方 `claude auth status --json` 的 `loginExpiresAt`，不读取 Claude 凭证文件，不借用默认账号或其他电脑的日期。七天内（含估计日期已过）用警示文字并显示该账号的「重新登录」按钮；未知日期明确显示未知。官方给的是估计值，实际登录可能提前失效，因此日期已过只提示「可能已到期」，不据此把账号判成退出登录。旧 CLI／旧执行电脑缺少可选字段时照常使用，不猜日期。
  点击重新登录必须真正启动这个账号目录的官方浏览器登录，即使当前仍已登录。宿主从该账号已知身份提供邮箱提示，完成后重新查询并核对身份；邮箱提示不是身份校验。登录成别的账号、无法确认身份或取消都不算成功，不清除原账号冷却，不更新其他账号。已知原身份在开始前写入 owner 本机账号元数据 `reloginIdentity`，失败后保留，直到原账号登录确认成功才清除；这样刷新／重启后误登的身份也不能作为原账号分配给任务。元数据不含令牌，CLI 登录文件仍完全由官方 CLI 管理。运行中的账号不能重新登录，浏览器流程仍需用户完成，不宣称静默自动续登。
  正常读取到已认证身份时，把最后确认的身份保存在 owner 本机元数据 `lastConfirmedIdentity`，退出登录、读取失败或重启不清除；重登时优先使用已保存的原身份，不能依赖只在内存里的邮箱。没有任何可确认原身份时，在启动浏览器前停止并提示通过「添加账号」重新连接；初次添加／连接仍可正常登录。两种身份元数据不进入账号管理视图，未绑定默认账号的只读检测不创建或修改账号池。
  已有空闲运行时的下一次发送同样检查所选账号：正在登录时拒绝发送；重登前的快照已失效，未完成的重登须有此后按原身份校验的账号快照才可继续。误登后的旧运行时不能绕过新任务的身份保护；取消后仍确认原身份或原账号登录恢复后可继续。
  UI 沿用现有每分钟／聚焦／账号变更刷新与宿主缓存，不新增后台轮询或服务器请求。账号管理仍走 owner 专用的既有通道；到期字段是可选追加，分享用量不传账号身份或到期日期。手机没有新增原生账号管理页，同账号远控调用由执行电脑处理。
- 用量沿用供应商原有用量卡：默认账号行放原卡（含 Codex 重置次数），新增账号用同一张卡显示自己的全部窗口（5 小时、每周及分模型每周，Codex 含余额），不再另画单条用量或在底部重复一个账号。用量页入口属于供应商，只在账号区标题旁出现一次。
- 账号行与供应商组成员行同一结构：身份、套餐和状态在左，并发上限、权重、分配开关和更多菜单在右；用量放在账号名下方，所有账号共用一套列宽，进度条跨账号对齐。账号目录在更多菜单里打开（悬停可看完整路径），不再在每个账号下常驻展开项。
- 2026-11-09 用户要求精简账号区文字：标题下不放说明段，默认账号只标「默认」；设置页用量行只显示百分比和剩余时长，「剩余」「后重置」放在悬停提示和读屏文案里。
- 2026-11-10 用户要求没有账号时不占位：池里只有尚未登录、身份未知且无运行任务的默认目录时，账号区只留标题和「添加账号」，不画「账号 1 · 需要登录」行、不显示数量；登录走供应商标题栏或「添加账号」。已知身份待重新登录、仍有任务或池内还有其他账号时照常列出。分配策略和权重只在两个及以上账号时显示。
- 开放额度分享时，池内超过一个可分配账号（已登录且未暂停）就按「账号 1、账号 2…」分别列出各自窗口，不合计、不含身份；只有默认账号时保持单账号显示。
- 供应商组里展开一台电脑时，两个及以上账号分别列出各自用量，见[供应商组 §10](provider-groups.md)；组调度仍按账号池可用额度。已暂停账号不在组用量列表出现；全部暂停时不回退显示默认账号的缓存额度。本机变更和同账号远程变更通知触发列表刷新，异步额度读取结束后复核最新开关。
- 新任务复用供应商组调度器（最少占用、轮询、顺序、权重）和配额优先规则。选择时立即预约，实际 turn 结束释放运行占用。暂停立即阻止新任务分配；已有任务按下文在下一次发送前交接换号，不中断进行中的回合。
- **并发上限**（2026-11-11 用户裁决，与[供应商组 §5](provider-groups.md#5-组策略)同一判定）：每个账号可选「不限制」或 1～16。没设置过的账号不限制并发，旧版存下的默认 4 视为没设置过；设置过的数字是硬上限，达到上限的账号不再分新任务，所有可分配账号都满时新任务提示已满载（`SUBSCRIPTION_ACCOUNTS_FULL`），不再分给最空的账号。已绑定的任务继续发消息不受上限影响。选「不限制」时存回旧版默认值，新版另记是否设置过；旧版读到的与以前相同，同账号远控的旧版执行电脑不接受「不限制」并照常报错。Helper 的 `limit: null` 同样表示不限制。
- 所有模型选择入口（含已有任务切换、设置、桌面和手机）共用账号解析：任务已记录的绑定优先；未绑定也分别展示未暂停、已登录账号的已知余量，并发满或限额耗尽不隐藏额度。多个账号在来源标题旁显示周余量的等权平均，展开再列各自百分比和重置时间，快重置且余量较多时轻提醒；不把平均值冒充绝对总额度或已分配账号；没有可展示账号或读取失败时才显示「账号待分配」。身份、套餐和额度同源。具体权限与兼容规则见[模型选择器统一准入](model-selector-unified.md#01-统一准入与账号归属2026-11-11)。预览不预约、不换号；执行仍按原调度与绑定校验。
- 已建立的任务、重开、续聊和分叉在账号正常时固定账号，禁止在另一个目录用同一个原生 session id 恢复。账号失效不能静默回退默认账号；换号只按下面的「账号间自动换号」进行。替代账号按新分配重新校验供应商和模型权限；同账号远程接手按任务模型的额度桶判断。
- **禁用账号后的续聊**（2026-11-11 用户要求）：用户在供应商内暂停／移出账号后，本机已有任务下一次发送或重试先按原账号池策略预约一个可用账号，再沿用上下文重建交接流程关闭本任务的空闲运行时、保存交接并清空原生会话 id，最后只改任务绑定。原生历史 id 的账号归属不改，不复制登录凭证。聊天记录和项目文件保留；新运行时接收近期上下文、已完成工具结果与更早历史的检索指引，而不是把整个原生会话文件移到另一账号。
  没有可用账号、任务仍在运行（含主回合结束后的后台测试、构建或子任务）、关闭或交接失败时不改绑定；先保存交接再写绑定，绑定写入失败可重试，不丢原记录。停用后的旧 live handle 不接受下一轮，避免准备期间的竞态继续用旧账号。额度耗尽、登录失效和过载的换号见下条「账号间自动换号」；本条不自动重放消息。
  Desktop、手机／同账号远控以及 IM 的本机执行路径共用发送前准备；SSH 不借用本机账号，归并进 OpenAI 的旧独立连接 ID 交接后改走 OpenAI（2026-11-13，见「账号间自动换号」），其他自定义供应商 ID 不借用；同账号远程 Agent 通过既有查询确认执行电脑的账号状态，再复用执行端按模型可用性查询统一校验额度、登录及新分配权限；仅明确可用才交接。拒绝、失败、旧端不支持或回包不匹配时保留原生恢复路径，不使用本机账号代替。换号后实际账号与用量通过既有任务查询和账号变更推送更新，无新增界面或 wire 字段。
  账号底层不依赖设备互联或供应商组的宿主运行时：远程查询由 `maker-ipc/register.ts` 从既有装配层传入；组目录在自身运行时监听现有账号变更事件并清理缓存。
  实现与回归见 `subscription-accounts/prepareSend.ts`、`runtime.ts`、`agent.ts` 及 `runtime.test.ts`，上下文交接见 `maker-ipc/contextOverflowRollover.ts`。
- **账号间自动换号**（2026-11-11 用户裁决：一个供应商内的多账号按供应商组选电脑的规则与失败重试口径处理，见[供应商组 §5、§6.1](provider-groups.md#61-自动换电脑)）。判定共用 `decideProviderGroupFailure`：
  - 新任务启动失败且属于组会换电脑的原因（额度、登录、过载、启动失败等）：不显示错误，直接按组策略换下一个账号重新启动；每个账号最多试一次，都失败才把最后一次真实错误交回。进程未确认退出的失败不换，避免同一任务并存两个运行时。续聊（恢复原生会话）和旧独立连接 ID 的任务不在启动时换。
  - **已绑定任务新开原生会话**（2026-11-12 事故补齐：组把任务换到另一台电脑后，那台新开会话仍死守已撞限的账号，报 `SUBSCRIPTION_ACCOUNT_LIMITED`，组随即判定没电脑可换）：交接后、换电脑兜底、清空后等不恢复原生会话的启动，绑定账号此刻接不了这个模型（同上判定）时按池策略换一个可用账号并改任务绑定，启动失败可继续换下一个；旧原生 id 仍归原账号。其他账号都不能接或都满载时仍用原账号，报原账号的真实原因。暂停与移出沿用原规则；显式账号路由（含旧连接 ID 固定的账号）在此不换，旧连接 ID 的任务由发送前换号改走 OpenAI 后再按本条选号（2026-11-13，见下文「归并来的账号与旧连接任务同样换号」）。
  - 已绑定的任务在下一次发送前（用户发消息、重试、自动续跑、IM、Hook 共用同一入口）核对绑定账号：记着这个模型的真实失败、可信快照显示该模型额度耗尽、或已退出登录时，按组策略在其他账号里选一个，带上下文交接重开原生会话后再发；旧原生 id 仍归原账号，只改任务绑定。正在运行（含主回合结束后的后台工作）不换；其他账号都不能接或都满载时照常发到原账号。暂停与移出另按暂停交接规则处理。
  - 运行中撞到用量上限：另一个账号此刻能接时不等重置，约 2 秒后自动续跑并在发送前换号（沿用额度重置后自动继续的次数上限）；供应商组已核实的组额度耗尽仍等重置。其他账号都不能接时照常等原账号重置。
  - **同账号远程 Agent 任务同样换号**（2026-11-12）：任务在本账号另一台电脑上运行时，发送前已有的那次任务账号查询（`maker:subscription-accounts` 的 `session`）附带任务模型，新版执行电脑回报绑定账号是否接不了（`blocked`，与本机同一判定），以及排除该账号后能否按真实选号准入换号（`switchAvailable`，包括并发名额与新路线权限，只读不预约）。两者都明确为真时，按暂停交接同一路径重开原生会话，由那台新开会话时按池策略选号；不再追加配额查询。运行中撞限时同样用这一次查询判断能否不等重置、约 2 秒后续跑。那台没有别的可用账号或准入读不到时照常发到原账号、不让可选探测阻止发送；owner 变化仍拒绝。旧版执行电脑缺少新回执，不交接、行为不变。分享来的供应商与 SSH 不在此列。
  - **供应商组里同一台电脑换账号**（2026-11-12）：见[供应商组 §6.1](provider-groups.md#61-自动换电脑)。组内电脑撞了用量上限或登录失效、而它的账号池里另一个账号此刻能接时，这台不冷却、不记「这一轮试过」，与其他电脑一起按组策略挑；挑中它就留在原电脑，续跑的发送前检查完成换号。同一个账号这一轮换下来后又出问题，不再原地换，照常换电脑。
  - 故障半径：① 换号准入读不到或旧版执行电脑都按「不能换」处理，回到原有换电脑／等待重置；可选准入从查询开始共用 2 秒预算，原账号读取已耗尽预算时不再启动额外探测，原读取的行为不变；② 不新增轮询或重试，只在发送前已有的查询上附带模型和执行端准入回执，撞限时读一次；组内检查后交回原恢复流程时复用本次判断，不重复探测，尝试交接或续跑前即失效；③ 只改这个任务的账号绑定，原生历史仍归原账号，不影响其他任务和账号。
  - **归并来的账号与旧连接任务同样换号**（2026-11-13 用户裁决：归并后用户已不能手动换连接，归并不能让任何任务失去自动换号）：
    新开会话换号、发送前换号、撞限立即续跑、暂停／移出交接与同账号远程 Agent 的执行端回报，都不再排除归并来的账号——
    绑在归并账号上的 `openai` 任务与其他账号一样换走。仍用旧连接 ID 的本机任务（归并前创建、归并后还没换过号；没有绑定时按
    旧 ID 的账号映射认定原账号）在原账号撞限、登录失效、暂停或被移出时，同样按池策略选另一个账号，上下文交接后把任务来源改为
    归并后的 OpenAI（与换模型同样写运行路由和任务来源），再改任务绑定；旧 ID 本身固定原账号，留在旧 ID 上会再次选回原账号。
    不扩大授权：改走 OpenAI 前先核对 OpenAI 自己的供应商与模型停用，目标账号若也来自旧连接，仍按它原连接的新路线权限选号；
    任一不允许就不换，照常等原账号或按暂停规则报错。分享来的供应商、SSH 与显式账号路由不在此列。顺序为：交接 → 改来源 → 改绑定，
    中途失败可在下次发送重试，原生历史仍归原账号；改来源前会话来源已被别处改动时放弃本次换号。同账号远程 Agent 任务仍用执行
    电脑的旧连接 ID 时，也由那台在既有 `session` 查询中识别映射、核对原生绑定及原来源／OpenAI 的远程和模型权限、确认实际替代账号
    准入，再明确回报 `replacementProviderId: openai`。控制端复核任务来源、执行电脑、原生 ID、模型、owner 和空闲状态后交接并改来源，
    新运行仍在同一执行电脑选号；耗尽、暂停与移出均覆盖。旧执行端缺少明确替代来源回执时保留原任务，不把普通 `blocked` 当成换来源许可。
    内部发送、官方 Hook 与个人 IM 冷启动均在创建运行实例前完成交接，并使用交接后保存的来源。自动化的单次模型选择同样刷新执行来源；
    每次新建的任务在首次启动前检查账号，首次启动才发现失败时，仅在确认旧进程退出、另一账号获准接手后重试一次。
    自动化保存的旧连接选择保留；已交接任务后续触发或恢复用户原模型时，复核原连接模型许可后继续用 OpenAI，清理临时选择时写入实际恢复的来源，
    不把任务重新固定到旧账号；同账号远程原连接的许可由执行电脑的实时授权模型目录确认。

    并使旧的运行时修改凭据失效。临时来源不同于用户保存的来源时，不改写用户偏好；Hook 与个人 IM 恢复也按同一有效配置启动和鉴权。

- Claude 历史定位（分叉、回退、导出、跨电脑转录复制和工作目录移动）按每个原生会话的账号绑定选择目录；新增账号缺失历史时不拿默认账号的同名文件替代。默认账号与未绑定的旧任务保持原有目录查找和恢复行为。

- 解除冷却的可用容量必须满足新分配的原连接模型授权；远程执行还须满足原连接远程调用及逐模型许可。本机与远程查询按实际执行上下文分别判断，不共享在途授权结论；读取配额后复查当前授权，不能只凭旧连接的健康额度解除冷却。
