# 供应商内的订阅账号

2026-11-07 用户要求：Anthropic / OpenAI 的本机订阅连接各保留一个供应商，内部可登录多个账号。

- 首个账号使用官方默认目录（`~/.claude` / `~/.codex`）；新增账号使用用户目录下带 Cindy 随机标识的兄弟目录。目录名不含邮箱，不接受 Renderer 或远程传入任意路径。
- 登录交给未修改的官方 CLI。Claude 使用 `CLAUDE_CONFIG_DIR`，Codex 使用 `CODEX_HOME`。Cindy 不实现 Claude OAuth，也不读取或复制 Claude 凭证。
- Codex `account/read` 明确返回 `account: null` 且 `requiresOpenaiAuth: false` 时，表示当前供应商管理认证，不能当作普通未登录再启动登录。连接及重连在所选目录预检并给出独立账号的操作指引；不改写原生配置、不按供应商名称拒绝、不读取凭证来猜账号。已有 ChatGPT 账号及缺少该标志的旧 CLI 保持原判定。实现与回归见 `nativeCli.ts`、`runtime.ts` 及对应测试。
- 添加供应商时先只读检测默认账号，展示身份并让用户明确选择「使用此账号」或「登录另一个账号」。检测不创建账号池、不绑定授权；选择另一个账号始终使用新的后缀目录，即使默认账号尚未接入 Cindy 或已失效。未检测到登录时，首次登录仍使用默认目录；旧版 Codex 私有目录保留为兼容默认账号。
- 管理信息按 Cindy owner 保存在本机 `subscription-accounts.json`，只存策略、账号标识及任务归属。账号目录不进入项目或同步；同账号远控管理界面可以查看目录，执行协议只传供应商与模型，不传账号能力对象。默认登录仍受现有 native provider binding 约束。
- 添加、重连、暂停及移出操作针对账号；移出仅撤销 Cindy 调度，不删除 CLI 登录或历史。一个供应商内展示账号、连接状态、额度、运行数、并发上限及权重。
- 用量沿用供应商原有用量卡：默认账号行放原卡（含 Codex 重置次数），新增账号用同一张卡显示自己的全部窗口（5 小时、每周及分模型每周，Codex 含余额），不再另画单条用量或在底部重复一个账号。用量页入口属于供应商，只在账号区标题旁出现一次。
- 账号行与供应商组成员行同一结构：身份、套餐和状态在左，并发上限、权重、分配开关和更多菜单在右；用量放在账号名下方，所有账号共用一套列宽，进度条跨账号对齐。账号目录在更多菜单里打开（悬停可看完整路径），不再在每个账号下常驻展开项。
- 2026-11-09 用户要求精简账号区文字：标题下不放说明段，默认账号只标「默认」；设置页用量行只显示百分比和剩余时长，「剩余」「后重置」放在悬停提示和读屏文案里。
- 2026-11-10 用户要求没有账号时不占位：池里只有尚未登录、身份未知且无运行任务的默认目录时，账号区只留标题和「添加账号」，不画「账号 1 · 需要登录」行、不显示数量；登录走供应商标题栏或「添加账号」。已知身份待重新登录、仍有任务或池内还有其他账号时照常列出。分配策略和权重只在两个及以上账号时显示。
- 开放额度分享时，池内超过一个可分配账号（已登录且未暂停）就按「账号 1、账号 2…」分别列出各自窗口，不合计、不含身份；只有默认账号时保持单账号显示。
- 供应商组里展开一台电脑时，两个及以上账号分别列出各自用量，见[供应商组 §10](provider-groups.md)；组调度仍按账号池可用额度。
- 新任务复用供应商组调度器（最少占用、轮询、顺序、权重）和配额优先规则。选择时立即预约，实际 turn 结束释放运行占用。暂停立即阻止新任务分配；已有任务按下文在下一次发送前交接换号，不中断进行中的回合。
- 所有模型选择入口（含已有任务切换、设置、桌面和手机）共用账号解析：任务已记录的绑定优先；未绑定也分别展示未暂停、已登录账号的已知余量，并发满或限额耗尽不隐藏额度。多个账号在来源标题旁显示周余量的等权平均，展开再列各自百分比和重置时间，快重置且余量较多时轻提醒；不把平均值冒充绝对总额度或已分配账号；没有可展示账号或读取失败时才显示「账号待分配」。身份、套餐和额度同源。具体权限与兼容规则见[模型选择器统一准入](model-selector-unified.md#01-统一准入与账号归属2026-11-11)。预览不预约、不换号；执行仍按原调度与绑定校验。
- 已建立的任务、重开、续聊和分叉默认固定账号，禁止在另一个目录用同一个原生 session id 恢复。账号失效或单纯额度耗尽仍明确失败，不静默换号。
- **禁用账号后的续聊**（2026-11-11 用户要求）：用户在供应商内暂停／移出账号后，本机已有任务下一次发送或重试先按原账号池策略预约一个可用账号，再沿用上下文重建交接流程关闭本任务的空闲运行时、保存交接并清空原生会话 id，最后只改任务绑定。原生历史 id 的账号归属不改，不复制登录凭证。聊天记录和项目文件保留；新运行时接收近期上下文、已完成工具结果与更早历史的检索指引，而不是把整个原生会话文件移到另一账号。
  没有可用账号、任务仍在运行（含主回合结束后的后台测试、构建或子任务）、关闭或交接失败时不改绑定；先保存交接再写绑定，绑定写入失败可重试，不丢原记录。停用后的旧 live handle 不接受下一轮，避免准备期间的竞态继续用旧账号。额度耗尽本身不触发此换号，也不自动重放消息。
  Desktop、手机／同账号远控以及 IM 的本机执行路径共用发送前准备；SSH、在另一台电脑运行的 Agent、旧独立供应商 ID 不借用本机账号，仍保持原执行边界。换号后实际账号与用量通过既有任务查询和账号变更推送更新，无新增界面或 wire 字段。
  实现与回归见 `subscription-accounts/prepareSend.ts`、`runtime.ts`、`agent.ts` 及 `runtime.test.ts`，上下文交接见 `maker-ipc/contextOverflowRollover.ts`。
- **已建立任务的账号与用量**（2026-11-11 用户反馈：模型列表与输入框下方的用量默认显示了第一个账号）：任务里模型列表的
  左栏用量条与悬停提示、模型行的「供应商 · 账号 · 套餐」与配额，以及输入框下方的用量和悬停卡片的账号名，都按这个任务固定的
  账号显示。账号在执行任务的电脑上查：本机任务问本机，远程 Agent、远程控制与供应商组问那台（供应商组见
  [供应商组 §10](provider-groups.md)）；查找顺序与恢复任务时相同（先任务、再原生会话）。默认账号、没有账号池、旧任务继续用
  原来的读取（Codex 重置次数只在默认账号显示）；还没运行过的任务显示「账号待分配」，绑定的账号已移出或供应商已断开时显示
  「账号已不可用」，都不借用默认账号的名字和用量。执行任务的电脑版本较旧、不认识这个查询时（同日实测：组里的 Mac 仍显示
  它第一个账号的周限 0%），改用它已有的「按原生会话读所在账号用量」：用量按任务的账号显示，读不到账号名就不写，不拿默认账号的
  名字凑；连这个也不认识的更旧版本才沿用原显示。实现见
  `renderer/components/new-chat/SessionSubscriptionAccount.tsx` 与 `main/subscription-accounts/runtime.ts` 的
  `readSubscriptionSessionAccount`。
- 任务账号读取临时失败时保留当前 owner 代次的已知结果；没有结果则隐藏其他账号并继续刷新，不能据此推断成默认账号。
  同账号重新同步代次后重新读取。OpenAI 账号池中的 `chatgpt/` 桥接模型按去前缀的模型选择该账号原生额度桶，不把通用桶伪装成 WHAM。
- Claude 历史定位（分叉、回退、导出、跨电脑转录复制和工作目录移动）按每个原生会话的账号绑定选择目录；新增账号缺失历史时不拿默认账号的同名文件替代。默认账号与未绑定的旧任务保持原有目录查找和恢复行为。
- 选择发生在实际执行电脑的本机 Agent 入口；外层远程供应商组仅选择供应商/电脑，内部继续选择账号。账号身份、路径与凭证不传给组成员或访客。
- 单个账号撞限不能长期封住同机同模型的健康账号。外组分配遇到模型错误冷却时，可通过 owner 专用查询确认多账号池仍有明确可用容量，清除该模型冷却后再选址；未知或耗尽不解除。已有任务的账号绑定不变，详见[供应商组 §5](provider-groups.md#5-组策略)。
- 解除冷却的可用容量必须满足新分配的原连接模型授权；远程执行还须满足原连接远程调用及逐模型许可。本机与远程查询按实际执行上下文分别判断，不共享在途授权结论；读取配额后复查当前授权，不能只凭旧连接的健康额度解除冷却。
- 执行端在启动、发送或终态限额错误时，按实际租用的账号和模型记住本次失败；即使尚未收到用量事件，也不能用该账号旧的健康快照解除外组冷却或给多账号池的新任务重新分配它。记录仅在当前 owner 内存中有效，沿用错误重置时刻或组默认 30 分钟，到期重验；过载和可重试的非终态错误不算。既有任务的手动重试仍固定原账号，不因此迁移历史。
- 双端不要求同步升级。旧使用端连接新版提供端时，原有 Claude / Codex 额度查询仍以旧格式返回账号池可用额度，不能因首账号用满就把整个供应商判为不可用；不累加百分比，不把池内账号身份或重置操作交给旧端。新版使用端连接旧提供端时，池查询不受支持便沿用原单账号查询。默认账号自身的用量查询以追加的可选 scope 区分，旧提供端忽略 scope 仍返回原账号；本机查询及默认账号目录不变。
- API key、自定义中转及 SSH daemon 的登录目录和调度不受此功能影响。新添加入口不再产生独立供应商。
- 2026-11-11 升级归并：加载当前 owner 的自定义供应商后，将 `auth.method: oauth`、`auth.native: codex` 的旧独立连接自动登记到 OpenAI 账号池。只写 owner 内的账号映射，不复制或移动登录文件，不采用未绑定的系统默认账号；已有池的策略、暂停和账号移出记录保持不变。超过账号池容量、写入失败或切账号时，未成功归并的旧连接保留原入口。
- 归并后的旧连接保留原 ID 与运行路由，供历史任务、分叉、自动任务和旧分享引用；本机供应商列表及新任务来源栏统一展示 OpenAI。重复来源只在标准模型清单中隐藏，已保存路由的连接校验仍认可旧 ID，历史选中行仍可展示。旧 ID 恢复时固定原账号，账号已移出则明确失败。OpenAI 的模型成员并入已登录且未暂停的旧账号现有成员，不借用其它系统登录。原连接的模型禁用、远程调用开关及逐模型权限继续生效，不能通过池扩大授权；整个池尚未开放远程调用或没有覆盖旧连接全部已开放模型时，旧远程连接仍保留独立入口。跨账号分享清除仅用于 owner 归并展示的标记，旧分享仍只使用原账号。
- 归并后的模型成员同时用于选择器和完整路由目录：后台调度、保存校验及恢复运行显式读取活动目录时，仍须经过同一账号池投影，不能把仅在归并账号中发现的型号误判为不可用。投影在供应商连接读取后、模型禁用等准入覆盖前执行；完整路由目录保留隐藏能力条目。实现见 `maker-host/provider-service.ts` 与 `createDesktopProviderService.ts`，回归见 `providerCatalogRealmReload.test.ts` 和 `providerService.test.ts`。
- 归并账号用于远程任务时，切换模型前必须按目标模型检查原连接授权；后续发送与凭证桥接按当前实际模型复查，不能沿用启动模型的许可。三种 OpenAI 引擎共用账号 lease 的检查，见 `subscription-accounts/agent.ts`、`runtime.ts` 与运行期回归测试。
- 旧连接已有跨账号分享时，仅在「我分享的供应商」保留其管理入口，继续按原 ID 逐人撤销；断连或暂停不隐藏「远程与分享」。普通供应商列表仍只展示归并后的 OpenAI；不要求先移出整个账号，也不扩大旧分享的账号范围。
- 安装升级、打开账号界面不会改写原单账号授权；未创建账号池时任务仍走原入口。首次配置账号池时，已经授权的 Codex 私有目录作为兼容首账号保留原位置，通过持久元数据记录来源；添加后续账号失败或取消也不能遮蔽它。新安装的首账号仍用 `~/.codex`，后续新增账号一律用带后缀的独立目录。
- 旧 Codex 任务可能来自 Cindy 私有目录，不能假定为 `~/.codex`。没有账号池绑定的旧默认账号续聊、分叉保持原路径；新建任务进入账号池。旧私有登录不自动授权系统默认目录。旧独立连接的元数据与 CLI 目录保留，归并仅改变管理与新任务来源的展示；回退不支持映射的旧客户端时，仍可经保留的独立连接使用原账号。
- Codex 正常执行与登录使用 CLI 原生凭证存储；跨历史目录的 external-auth、Claude Code 使用 OpenAI 模型及 Pi 的 HTTP/WebSocket 请求复用现有 host-only bridge，只读选定账号的 `auth.json`。仅钥匙串存储而没有该文件时明确失败，不能拿默认账号 token 顶替。Anthropic 订阅不使用此 bridge。
- OpenAI 账号选择贯穿三种引擎；Pi 将账号能力绑定到已鉴权的运行令牌，Claude Code 通过已有原生会话到业务会话的映射取回。关闭清理对应登记；换供应商重建并重新选账号。同一账号的上游认证作废不会断开其它账号。
- Helper 的 `configure_model_provider` 提供 `subscriptionAccounts` 操作（本机任务范围），与 UI 共用校验及执行服务；登录仍在执行电脑的官方浏览器流程完成。

验证：不接触真实账号的 CLI 管道模拟覆盖目录分离、取消和错误脱敏；实际 SDK fork 验证自定义目录；账号池、远程组、Core host 隔离和 UI 多语言/主题场景分别测试。真实两个订阅账号、macOS 钥匙串登录需在安装后的客户端验收。
