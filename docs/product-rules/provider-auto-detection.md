# 根据地址识别供应商并复用连接流程

适用：Desktop 新增自定义连接，Global / 中国大陆版、macOS / Windows 共用同一实现。
现有连接的编辑、订阅登录和保存格式保持原有合同。供应商名称遵循
[供应商设置](./provider-settings.md)，模型覆盖顺序遵循
[模型目录维护](../dev-rules/model-catalog-maintenance.md)。

## 用户流程

1. 添加页遵循已确认的 `simple-add-preview.html`：只填写显示名称、一组默认基础 URL 和 API key；请求头可选。
   不展示预设下拉、鉴权方式、引擎页签或协议设置；独立引擎配置留在保存后的编辑入口。
   未识别的自定义连接默认只保存 Pi；已有独立引擎草稿字段不覆盖，已识别预设仍按预设绑定。
2. 输入稳定 400 ms 后，先按当前供应商目录匹配完整官方地址；未匹配时执行固定系统探测，
   同时读取通用模型目录。名称、模型勾选变化不重新探测。
3. 只有唯一结果且该预设含可用引擎配置时显示“已识别为…”，等待用户点击前往按钮，
   才进入已有供应商连接步骤。不倒计时或自动跳转；用户也可继续自定义，不会自动保存。
4. 名称、URL、key、请求头、各 Runtime 草稿和模型选择随跳转保留。返回自定义后保留草稿并停留在表单。
   用户打开模型选择等子弹层或正在保存时不强制跳转。
5. 未识别、证据冲突、预设没有可绑定的引擎配置时保留自定义。成功取得的模型首次直接加入模型区；
   没有结果时由用户点击“获取模型列表”重试，也可手动添加。失败显示分类原因，不能据此断言站点不能调用。
6. 模型区域直接展示已配置数量、模型 ID、类型和移除按钮；数量随选择变化。“手动添加模型”使用默认折叠的胶囊入口。
   “测试连接”和“获取模型列表”位于请求头之后、连接区域底部。“获取模型列表”优先使用当前输入的成功结果，保留完整勾选弹层。已有的选择、手动模型与显式能力配置优先；
   后续获取出现的新模型不重新自动全选，已配置但目录不再返回的模型保留。
7. URL、key、请求头、协议或 Runtime 变化使旧结果过期；旧请求不得修改新输入的界面或触发跳转。
   关闭弹窗、取消、新探测会取消对应的固定系统请求。官方模型读取沿用现有 IPC 的超时，界面丢弃迟到结果。

识别指选择兼容预设，不证明中转服务背后的真实上游厂商；模型目录也不证明每个模型都有调用权限。
本流程只读目录和服务信息，不自动生成内容或逐模型试调用。“测试连接”仍由用户明确点击。

## 地址匹配与绑定

- 遍历当前目录的预设（包括生成目录与已有官方 API 入口），不复制一份地区供应商白名单。
- 官方地址按规范化后的完整 origin/path 匹配，保留业务路径；同域不同路径不能混用。
- Azure 等受约束资源模板只在默认端口参与自动识别，非默认端口保留自定义，不进入会重写端口的模板绑定流程。原有手动模板绑定行为不在本次修改范围。任意 `{endpoint}`、回环地址及端口不能作为身份依据。
- 同地址对应多个套餐时不任意挑选，提示存在多个匹配，保留自定义流程；需要指定套餐时可返回供应商选择入口。
- 固定系统只有下面五类。用户部署地址替换预设端点，保留部署前缀和各模型路由；
  不能把用户的地址替换成预设中的 localhost。识别后带入对应预设支持的各引擎配置，沿用各引擎的地址与协议规则，不创建兄弟账号。
- Global 与中国大陆版仍使用原来的区域排序与可用目录，识别算法不按地区另写一套。

## 固定系统证据

规则版本：`2026-10-19`。所有条件均须满足，不根据 HTTP 200、普通模型 ID、网页标题或 key 前缀判定。
以下是兼容特征规则，不承诺所有历史版本、关闭诊断接口的部署都可识别。

| 系统 | 读取位置（相对部署根） | 充分条件 |
| --- | --- | --- |
| Sub2API | `/api/v1/settings/public`、`/v1/sub2api/billing` | 公开数据 `code=0`、非空版本与三个布尔设置字段；账单 `object=sub2api.key_billing`、`schema_version=1` |
| LiteLLM | `/health/readiness/details`、`/v1/model/info` | 非空 `litellm_version`、healthy、callbacks 数组；非空模型详情，每项有 `model_name`、`litellm_params`、`model_info` |
| LM Studio | `/lmstudio-greeting`、`/api/v1/models` | 原生 models 结构含 key/type/publisher/loaded_instances；非空原生列表，或合法空列表同时 greeting 的 `lmstudio=true` |
| llama.cpp | `/props`、`/v1/models` | generation settings、非负整数 slots、非空 build_info，以及合法模型目录（允许空） |
| vLLM | `/version`、`/v1/models` | 非空版本；非空列表每项 owned_by=vllm、非空 id/root、正整数 max_model_len |

LiteLLM 详情只按对外 `model_name` 关联已取得的账号模型；同别名多个后端只补全一致的能力。
LM Studio 详情按 key 或 loaded_instances.id 关联，不把本机所有已下载模型直接当成可调用列表。
缺失或禁止访问的诊断接口只使识别失败，不能丢弃已经成功取得的通用目录。
同时出现多个充分证据时回到自定义，不按探测完成顺序抢占结果。

## 请求边界

- 仅 http(s)，不接受 URL 内嵌用户名/密码、片段、未绑定模板；有 query 或完整调用路径时不派生探测地址。
- 部署根只去掉末尾 `/v1`，不会从 `/team/relay/v1` 爬到域名根。所有探测禁止重定向。
- 公开诊断请求不带 key 或自定义请求头。需要认证的诊断使用用户提供的 Bearer key；
  可选认证用于 LM Studio 原生目录和 llama.cpp props。不要求管理员 key。
- 最多八个身份请求，同时最多两个，每个 3 秒，总身份预算 8 秒，单响应不超过 1 MiB。
  在该预算内继续检查固定队列，不因先命中一种系统而跳过其他系统的冲突证据。
- 通用模型目录使用现有解析器、认证、分页和超时机制，响应上限 8 MiB；它与身份预算分别计时。
- 返回 Renderer 的只有候选、模型元数据和分类错误，绝不返回账单、诊断原文或凭证。
- IPC 复用供应商配置的可信本机窗口校验，按真实 sender 隔离取消；页面销毁、账号代次变化后结果不可复用。
  不扩大 device-link 的凭证通道。Mobile / 远程页面保持已有配置边界，不新增远程写密钥能力。
- 无鉴权模式保持现有 loopback-only 规则；不因自动识别放宽。新增简化表单仅在所有已填引擎地址和目录地址都是回环地址、且没有密钥或自定义请求头时自动使用无鉴权；密钥框仍保留，填写凭证或改成远程地址立即恢复 API key 模式。发现、测试、交接向导和保存使用同一有效鉴权方式；编辑已有连接不自动推断。

## 协议与保存

匹配后复用预设及 `providerInterfaceDefaultRoute`，再叠加用户显式配置和模型路由。
未匹配时默认使用 Pi，尚未测试时以 Chat 为初始值。用户点击“测试连接”后，未显式指定模型接口的
新自定义连接按地址特征、上次成功结果优先，最多串行验证 Chat、Responses、Messages、Google 四种协议。
成功需要有效生成内容与合法结束，并将实际测通的地址和协议带回表单；用户保存时写入相同的 Pi 模型路由。
已有预设、保存连接和显式模型接口保留各自的单次测试路径。

只有明确、尚未进入生成的协议或路由拒绝允许继续。认证、额度、限流和模型错误立即停止；
超时、断流、空流、HTML、5xx 或其它不确定结果停止并说明未能确认，不自动重复生成。
每候选最多一次请求，SDK 不重试，自动探测单次 8 秒、整轮 15 秒；明确指定单一路由的测试沿用原时间预算。修改输入、关闭或主动停止后旧结果不回填。
测试可能产生少量费用，基础生成成功不证明所有模型、工具或图片能力可用。

Pi 由保存流程写入已验证或用户保留的协议，不在真实任务运行中猜测或轮换。创建后仍可在编辑连接中调整协议和路径。

探测结果与凭证只在当前表单内存中传递，保存仍走原来的连接创建和密钥存储。
即使识别为 LM Studio，手工添加的远程地址也创建独立连接，不覆盖托管的本地 LM Studio。

## 验证与限制

自动化覆盖五种充分/不足/冲突证据、路径绑定、区域排序、鉴权隔离、超时/取消/超限响应、
模型别名补全、等待不跳转、点击后交接、陈旧响应、模型选择和返回草稿。
UI 单页夹具使用真实组件和模拟 Host，覆盖官方匹配、Sub2API 匹配、自定义目录成功、失败后手动添加。
浅色/深色、窄窗口、各语言及模拟 Windows 平台的结果随 PR 附证据。

模拟返回与单页检查不等于实站账号调用、Windows 原生运行或所有 Harness 端到端通过。
最终 PR 必须分别记录实测项目、未验证项目和原因；诊断关闭或版本结构变化时继续自定义，不扩大猜测范围。
