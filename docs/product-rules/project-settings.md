# 项目资料设置

桌面项目菜单的「项目设置」与手机首页项目行的设置按钮提供项目预览、显示名称、图标、
所在电脑和可复制的完整目录。已有项目主目录作为身份只读显示，不移动文件或改名文件夹；目录统一在此维护。新建项目使用同一表单，可选择主目录。桌面项目菜单统一通过「项目设置」修改名称，不再单列「重命名」；双击项目名称仍直接进入行内重命名。
视觉使用 Cindy 现有字体、语义色与表单控件；手机使用原生 FormSheet、系统相册和裁剪。

## 展示位置

桌面侧栏与手机首页的项目分组保留文件夹图标，随展开／收起切换打开／关闭状态。
项目身份图标用于项目设置预览、新建任务的项目选择器及已选项目按钮、任务顶部标题旁，以及平铺任务列表中项目来源名称之前；两端均按项目所在电脑读取对应项目资料。对话标题左侧显示与对话分组一致的 MessagesSquare 对话图标，项目任务标题显示项目图标；worktree 任务使用 projectDir 指向的原项目图标，SSH 项目保留主机身份。
任务标题左侧的项目图标可点击打开对应项目设置，桌面按钮排除窗口拖拽区域，手机按钮与标题双击重命名分别响应。worktree 打开原项目设置，远端项目使用所属电脑与 SSH 主机身份。对话图标只作身份提示。标题左侧统一 20px 占位，项目图标 20px、对话图标 16px 居中且使用细线；手机点击区域通过 hitSlop 扩大到 44pt。
选择器中的普通目录浏览、上级目录和添加目录继续使用文件夹语义，不套用项目头像。
侧栏仍提供项目设置入口；此展示调整不删除已保存图标，也不改变自动识别与手动覆盖规则。

## 编辑与保存

2026-11-16 交互调整：编辑页的名称输入框直接可编辑，不再点击名称进入行内编辑状态。名称、图标和目录保持同一份草稿，Enter 结束输入，Escape／关闭统一处理整份草稿的放弃确认。编辑页不提供创建来源切换，也不重新克隆或移动主目录。

新建页只有「本地文件夹」「仓库导入」两个选项，默认本地文件夹。本地方式填写名称即可自动分配目录，也可以点击主目录卡片内的「更改」选择已有文件夹；取消选择保留原草稿和自动目录。桌面本机使用系统选择器，其他电脑和手机使用目标电脑的目录浏览器。仓库方式必须填写有效链接，默认自动分配目录。切换来源清除上一步的目录列表和仓库链接，避免把已有项目当成克隆目标；名称和图标仍按表单草稿及已选项目资料规则处理。向名称粘贴明确的仓库地址自动切入仓库方式，普通名称不触发。两种来源共用身份与目录编辑器，创建／保存期间锁定操作。

来源使用紧凑的两段切换；桌面复用 SegmentedControl，手机复用 MainWindowOptionButton 的 segmented 外观。名称是有标签的常驻输入，图标缩为辅助身份入口。自动分配的主目录直接呈现在目录列表第一项，标注「主目录 · 自动创建」，不提供复制或移除未创建路径；手选主目录后才显示「添加目录」，用于增加其他目录。本地方式的「更改」与路径、主目录标记放在同一张卡片里，专门选择或替换主目录，不在列表外另放选择按钮。目录预览不是已落盘承诺，创建后的实际目录仍以主机回执为准。同账号远端选择器和手机的两个入口遵守相同分工。

主页面顶部直接编辑项目身份：点击图标打开选择器，名称使用常驻输入框。名称 Enter／失焦结束输入并保留草稿；不重复显示「更换图标」文字按钮和下方名称表单。
主页面维护名称、图标和目录草稿，以一次「保存」提交修改。图标选择子页有独立草稿，
「使用图标」仅返回主页面预览；取消子页丢弃该次图标选择。主页面存在未保存修改时，
关闭会提示放弃或继续编辑。保存期间禁止重复提交和关闭，失败保留草稿。
恢复图标默认值会删除覆盖并使用自动识别结果（没有结果时显示由当前项目名生成、按项目名稳定选色的字母方块），保存后生效。

选择器顶部以紧凑预览显示项目名称和恢复默认入口；图标、表情、字母、图片分为四个选项。图片上传和格式提示仅出现在图片页。颜色入口显示当前色及色名，桌面展开浮层、手机在当前页展开色板，选择后收起；默认色入口持续标注跟随主题。手机保持 44pt 触摸区域，保存操作固定在表单页眉。

切到「字母」时，若当前选择器还没有字母草稿，使用当前显示名称（空时用目录名）生成并立即预览：单词取首字母，多词或驼峰名称取首尾词首字母，连续中日韩文字取前两字，字母转大写且最多两字符。已有字母草稿与已保存字母保留，可继续修改；仅切换不落盘，仍随使用图标／保存／取消流程。

图标支持可搜索的 Lucide 线性图标、预设或粘贴的单个 Emoji、1–2 个文字／数字，以及图片。
线性图标和字母复用标签的十二种颜色、顺序及多语言名称：红、橙、黄、绿、蓝、紫、灰、粉、珊瑚、青、靛蓝、白。直接消费已有 task-tag / taskTag Token，不维护独立色板；默认色是色板上方的首个明确选项，以实际中性色样、选中标记和「跟随主题」说明呈现；浅色模式用 text-primary / textPrimary 深色图形，深色模式用对应浅色图形，保存时不固化黑色或白色值。白色沿标签的白底、细边框和深色图形保证浅色模式可见。选色即时更新预览及图标网格，换图标保留当前颜色，颜色与图形或字母
一起参与子页草稿、主页面保存、取消与恢复默认。图片和 Emoji 不染色。
Emoji 支持肤色、旗帜、键帽与 ZWJ 序列，校验不依赖 Hermes 尚未提供的 Intl.Segmenter。
图片在控制端裁为 256px 正方形缩略图，上传主机后再次验证解码并规范为 PNG；
禁止 SVG、任意文件路径或其它项目的媒体地址作为上传输入。桌面接受 PNG/JPG/WebP、
原文件不超过 10MiB；上传 data URI 最多 300000 字符。复杂照片必要时先压为 JPEG。
显示顺序为用户自定义图标 → 自动识别的项目图片 → 根据当前显示名称生成的字母方块。无图片、图片加载中或解码失败均使用字母方块；名字编辑即时更新预览，不把生成结果写入图标覆盖。字母方块按 NFKC 标准化、去首尾空格、转小写后的项目名，以乘 31 的滚动哈希从 Cindy 现有十一种非白色身份色中稳定选色；同名同色，改名可能换色。前景在浅色主题混入 20% 黑色、深色混入 20% 白色，背景为前景色的 14% 透明混合，圆角为边长 25%。手动文字颜色继续保留；显式默认色仍跟随主题中性色，白色保留白底深色字。旧主机无需支持自动图片通道也能显示本地生成的字母。

未手动覆盖时自动识别项目图标：优先声明的 app.json / manifest 图片和常见本地 icon，也检查 monorepo 的 apps/desktop/resources/icon.png、apps/mobile/assets/icon.png，之后查询 package.json 官网、GitHub origin/repository 元数据中的官网 favicon。无根包或应用配置、无 GitHub 仓库线索的项目库会从根 README.md 开头 32 KiB 的本地链接中取最多八个候选目录，检查其 package.json。只有唯一包名（忽略 npm scope 和大小写）匹配项目目录名时，才按同样的本地图标规则读取该包。GitHub 账号头像仅作主动采用的候选，不能自动替代仓库身份。

自动结果独立缓存于项目归属电脑的账号设置，图片仍进入 cindy-media；手动 override 不受识别刷新影响。识别结果直接作为默认图标，无需点击采用；设置页仅显示来源、查找中和无结果状态，不提供额外的「使用项目图标」选项。用户通过更换图标覆盖默认值，通过选择器里的恢复默认删除覆盖。选择候选头像产生手动图片草稿，恢复默认仍回到自动识别。缓存命中不再请求网站，成功结果 24 小时、无结果 1 小时，离线保留旧图。控制端按账号／设备／项目合并请求，主机限制并发与总预算，不阻塞列表。

只读取当前账号已有项目内的有限候选，不执行 JS 配置或网页；SSH 通过已有远程文件服务，不能将远端路径当成本机路径。Desktop 注入 SSH 文件读取与系统代理，Node Host 使用无 Electron 的环境代理出站实现，缺少 SSH 文件适配时回退缓存或默认图标。网络只接受公开 HTTPS，无账号 Cookie／Authorization，逐跳经过 DNS/IP 出站保护，限制 1MiB 响应和 20 秒发现预算；不可解码图片安全回退。SVG 在主机拒绝外部资源／活动内容后栅格化；ICO 支持 PNG 条目，不支持的旧位图条目继续尝试其他候选。

## 新建与目录（2026-11-15）

桌面侧栏「新建项目」与新建任务的项目选择器、手机新建任务的项目选择器，都先打开项目表单。
桌面按设备分组时，设备行右侧提供「文件夹＋」（FolderPlus）新建项目入口，位于远程桌面按钮左侧：鼠标悬浮或按钮获得键盘焦点时显示，无悬浮能力的触控设备常驻显示。点击不折叠设备分组，直接打开该设备的项目表单；创建回执、项目筛选和后续任务草稿沿用同一设备身份。离线设备的入口不可执行。
目录列表只保留一个「添加目录」按钮，主表单不再常驻路径输入框或「浏览目录」按钮。本机使用系统目录选择器（路径输入沿用系统能力），手机与远端选择器内支持输入路径；SSH 无目录浏览适配时，点击添加后显示路径输入选择步骤。
项目目录可以留空：按名称创建空白目录，或粘贴 GitHub、GitLab（含自建实例）的 HTTPS / SSH 仓库链接克隆；名称输入处也支持直接粘贴链接并提取仓库名。
新建默认选本地文件夹，仓库输入框与 Git 平台说明仅在仓库来源下显示。直接向名称输入粘贴明确仓库链接会切换来源，但 `Design/2027` 之类的普通名称不按 GitHub 简写解析。仓库方式必须提供有效链接；切换回本地方式清除链接与旧目录，恢复自动目录，防止隐藏草稿触发克隆。存放位置预览归在电脑与目录区域，桌面和手机一致。
主表单提前显示自动分配位置，优先使用项目存放位置设置，其次是已登记且未隐藏项目最常见的父目录，最后为 `~/Projects`。推断仅查询项目路径列，不扫描任务历史或逐目录检查磁盘；实际创建时再验证位置。
同名目录以 `-2`、`-3` 递增，使用独占创建，不覆盖已有目录。也可以选择已存在的目录：桌面本机走原生目录选择器、其它电脑走固定目标的远端浏览，手机浏览选中的电脑。手选目录用于克隆时必须为空。
选择主目录时，名称为空就直接在输入框填入文件夹名；已有项目优先填入其保存的名称。自动填入的名称随主目录更换或首项移除后的提升更新，手动编辑过的非空名称保留，添加其它目录不改变名称。名称留空提交时仍使用目录名；可以同时设置图标和目录；界面只有一个「项目目录」列表，第一项标记为「主目录」，其余依次排列，不提供只读或读写切换。新建时首次添加的目录成为主目录，删除第一项后下一项自动成为主目录；已有项目的首项保持固定，避免改变项目身份。点击创建后才注册项目，
进入该项目的新任务草稿；不会替用户发送消息。已有目录若已经是项目，先读回其保存的资料，不用空表单覆盖。
保存与取消遵守同一个草稿流程；新建验证复用项目注册的主目录检查，托管对话目录和任务 worktree 不能另注册为项目。

除主目录外，每个项目最多添加 10 个目录，新增目录默认可读写；路径归属项目所在电脑，不能把控制端的目录当作远端目录。
主机验证绝对路径、存在且为目录、与主目录以及其它条目不重叠；同时检查选择路径和实际目标的重叠，保存实际目录。每轮使用前重新核验，目标变化时须重新选择。
SSH 在所选主机上解析并验证物理目录。
SSH 界面用手动绝对路径，不打开本机或 Device Link 电脑的选择器；缺少 SSH 文件适配时明确拒绝保存。

目录保存到项目所在主机当前账号的 `project-directories.json`，空数组是明确撤销，不等同于缺失。
只在 Session 取得下一轮发送占位后读取项目目录并安装运行期授权；Desktop 和 Node Host 共用实现。
保存时不修改正在执行的轮次。worktree 使用所属项目的 projectDir；review 任务保持隔离。
旧任务 DB 中的 extraDirs／writableDirs 保留独立来源，与项目配置合并后下发，不把继承值反写进任务。
已有只读目录保留原授权，不因这次界面简化自动升级；移除后重新添加使用新的可读写默认值。发生读写冲突时只读优先，不把旧的只读授权自动提升为可写；知识库槽继续保留来源身份。

桌面本机任务的输入框保留「添加目录…」，所选目录仅用于当前任务。项目任务的「项目设置」排在目录分组最后，管理项目共用目录。远程任务沿用项目设置入口，手机项目任务从任务信息进入项目设置；旧任务的单独目录仍可查看和移除。
无项目的对话保留原有任务级入口。已有任务的 UI 列表仍表示其单独目录；项目共用目录在项目设置查看。
桌面本机任务已继承项目目录时，中途添加的任务目录从下一轮生效。移除任务目录会即时撤销该目录单独授予的写权限，当前轮次仍保留项目授予的目录。

## 第一次新建项目的介绍（2026-11-18）

还没有项目的人第一次打开新建项目表单时，先出现一页介绍（用户要求，2026-11-18；页面结构与小动画沿用
[功能介绍](../design-rules/feature-introduction.md)），让人明白项目有什么用、接下来怎么建。

- **讲什么**（用户裁决，2026-11-19：要把项目的意义讲透，不讲「什么时候不用项目」）：先讲好处，不讲
  结构。说明一句讲清「要持续做的事交给一个项目，文件在你电脑的一个文件夹里，Cindy 接着上次的成果做，
  不用重新交代背景」；三张卡片各讲一个好处——成果都是你的文件、新任务不用重新交代、几件事各归各。
  怎么建只在按钮下的一行小字里说（起个名字就能建，已有文件夹或代码仓库也能用），细节交给紧接着的表单。
  这三点取自普通用户对同类功能最看重的东西：不必反复交代背景、AI 直接在自己的文件上干活且成果留在
  手里、不同的事分开不混。文案只承诺项目本身做得到的事：「沿用这个项目里记下的要求」指项目里的规则
  文件与按工作目录保存的记忆，记忆可以被关闭，所以不写成「Cindy 永远记得」。
- **只对还没有项目的人出现**（用户裁决，2026-11-19）：这台电脑的项目列表为空，并且当前已知的其他电脑
  上也没有项目任务时才出现。本机列表未读到、远端设备发现未完成、远端任务仍在读取或读取失败时，
  均按「不确定」处理：不出现，也不记为已显示，留到下次。已经
  在用项目的人不出现。
- **出现时机**：桌面上任何一个新建项目入口（侧栏「新建项目」、设备行的新建按钮、新建任务的项目选择器）都
  打开同一张表单，所以由表单判断，不在各入口分别接。打开已有项目的「项目设置」不出现；把任务移到新项目的
  小弹窗不是这张表单，也不出现。
- **只出现一次**：按本机记录（`featureIntro.project.seen`），在显示时就记下。
- **先介绍、后表单**：介绍显示期间表单不出现，两个弹窗不叠在一起。「继续新建项目」、右上角 × 和 Esc 都
  关闭介绍并进入表单，不会取消这次新建；表单在介绍期间已开始读取项目资料，关掉介绍即可填写。
- **只介绍、不代做**：介绍不创建项目、不选目录，也不改变表单的默认值与授权流程。
- 手机暂不提供。

## 归属与兼容

`settingsVersion >= 7` 支持默认目录与仓库克隆，快照的 `creationRoot` 用于预览，创建回执的 `createdProjectKey` 决定实际打开位置（包括重名编号）。v6 主机保留手选已有目录的新建流程；v5 及以下主机继续使用原有文件夹选择与任务级添加目录入口，不将这些入口替换为不受支持的项目表单。Mobile Web 的项目目录选择复用相同远程读取回调并提供可见的目录列表和路径输入，关闭后恢复表单。
仓库克隆复用目标电脑现有 Git 凭证与 SSH 配置，GitHub HTTPS 额外使用已有 gh 登录；不收集或保存 token，不弹终端交互，不执行仓库钩子。
克隆期间显示忙碌状态并禁止重复提交，失败保留表单。克隆预算五分钟，跨电脑调用预算六分钟且不自动重试写入。
失败仅清理本次独占分配且身份未改变的目录，不删除手选目录。资料保存出现不确定失败时保留已完成目录供恢复，不能宣称跨文件与数据库原子创建。
`create_project` 与界面共用创建入口，支持可选 `working_dir`、`name`、`repository_url`、`icon`、`directories` 与同账号电脑 `device`；不额外发送任务消息或发布仓库。

设置归属项目所在电脑和当前账号，不同电脑、SSH 主机及目录不互相覆盖。
只编辑身份唯一的项目，混合身份的分组不提供设置入口。
`settingsVersion >= 6` 支持目录与统一新建表单，旧主机不发送新字段、不显示目录编辑；`>= 2` 支持组合保存、图片与选择器；`>= 3` 额外支持线性图标颜色，`>= 4` 支持自动图标查询，`>= 5` 支持字母颜色（`text:CY:blue`）；默认色仍用无后缀的 `text:CY`。连接 v2–v4 主机时字母仅使用默认色。连接 v2 主机保留资料编辑但不提供选色；缺少 v2 能力的主机禁用编辑并提示升级。

主机串行处理该入口的写入：先完整校验，再导入媒体、保存图标、执行现有别名事务。
别名事务失败时恢复旧图标及目录并释放未采用图片引用；新建注册失败时补偿已写入的名称、图标和目录；文件与数据库是补偿流程，不宣称跨存储原子事务。
所有异步边界检查账号代次，过期请求不允许写入新账号。图片存入现有 cindy-media 总仓，
项目设置只保存内容地址；其它电脑按项目身份读取缩略图，不直接访问主机文件路径。
保存成功沿现有项目别名失效通知刷新两端列表。

Agent 的 `get_project_info` 读取指定项目已保存的名称、图标与目录权限；`get_project_icon` 返回同一自动图标及来源，`update_project_info` 使用同一入口，支持本机或已连接电脑、单项或 `profile` 组合保存，
支持同样的图标表示、图片上传与 `profile.directories` 完整列表更新（`[]` 撤销项目目录）；共享任务访客沿用已有拒绝规则。

## 授权与 AI 工具（2026-11-18）

不变量：新增项目目录访问或克隆仓库必须来自宿主认可的调用；本地 Renderer 的路径选择还须有 Main 保存的原生选择凭据，不能由请求里的来源／已授权字段替代。

本机选择文件夹后，表单显示实际目标。手动导入仓库时，本机系统确认框显示规范化仓库地址、最终保存位置及可能使用本机登录账号的说明；确认后才启动 Git。取消保留表单。
本机 Main 保存一次性的选择凭据，绑定窗口、表单、账号代次、路径及 realpath。取消选择不产生凭据；
桌面连接独立 Node Host 时，Host 在执行同一写入期间通过现有平台连接向发起窗口核验选择或请求系统确认；只有本次请求有效。旧桌面代理仍可编辑项目名称、图标。
跨窗口、跨表单、过期、账号切换或符号链接目标变化均不能借用。账号和表单标识本身不是授权。
远程控制端沿既有同账号认证入口进入；共享访客不能进入。本机界面为 SSH 项目增加目录或提高权限时，由系统确认框列出 SSH 主机、项目、实际路径和权限，再写入本次确认的目录。仅保留或移除已有目录时直接保存。项目资料 Core 在已有写锁内比较旧目录与新目录；保留、撤销与新增／读升写分别处理。

AI 的创建、仓库导入和目录列表修改统一走任务现有的权限流程：Full Access 直接执行，Auto 按本次调用审核，
Ask 按已有权限交互确认。工具传入链接路径时会收到实际目标，须用该目标重新发起授权调用。不能因为工具属于可信 helper 服务而静默放行，也不额外添加 AI 专属能力限制。
普通身份编辑继续沿既有流程。自动任务缺少可复用运行期权限时，使用原有任务操作授权；授权撤回后不继续提交。

| 事件／状态 | 预期结果 |
| --- | --- |
| 原生选择成功且账号未变 | 保存当前窗口、表单与真实目录的一次性凭据 |
| 选择取消／凭据过期／来源不匹配／目标变化 | 不扩大目录访问；保存失败保留草稿，可重新选择 |
| 保留或撤销旧目录 | 保留原权限或移除，无需新的路径凭据 |
| 新增目录／已有只读目录改为可写 | 在写入前核验本次选择或工具调用授权 |
| 自动建目录／仓库导入 | 分配或调用 Git 前核验来源及显式目录；自动目录仅在本次调用内获准 |
| 等待文件锁、远程发送或落盘前账号／任务授权变化 | 拒绝继续写入，不改写新账号 |
| 创建完成但资料写入结果不确定 | 保留已生成目录供恢复，沿既有补偿语义报告失败 |

`create_project` 一次支持本地文件夹、自动分配、仓库导入及完整资料；返回 `project_key`、`project_path`、
`working_dir` 和 `device`，可直接用于后续查询与编辑。`get_project_info` 同时返回 `main_directory`、
`settings_version`、目录顺序及 access。`update_project_info` 的目录列表不含固定主目录：完整替换可实现
添加、移除和调整顺序，`[]` 清空，省略则保留。读取后保留已有 access，不擅自升级旧只读目录。

桌面与 Node Host 的工具使用同一个 `createProjectToolCallbacks`，创建、目录验证及资料写入继续共用 Core。
Node Host 提供上述本机工具；跨电脑调用需要执行宿主已有的出站 Device Link 连接，未接通时明确报错，
不回落到本机。桌面出站调用检查目标 v6／v7 能力并携带目标账号代次。查询列表、改名和移除入口继续可用；
本次不改变已有项目主目录，不新增全局默认存放位置的 AI 写入入口。
